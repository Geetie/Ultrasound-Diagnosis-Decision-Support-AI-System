# 临床评价报告框架（CER）

> **状态：框架（仅目录与要求）**。
>
> **重要**：本文件**不包含任何临床数据、统计结果或结论**。临床评价必须由具备资质的
> 机构使用真实临床数据、按适用法规（如《医疗器械临床评价技术指导原则》）完成，
> 并附伦理审批与数据来源说明。任何以开发期模拟/构造数据充填本报告的做法都是违规的。
>
> 本框架的作用只有两个：① 让开发侧清楚"需要向临床评价方提供什么证据"；
> ② 把已就绪的技术证据（可追溯性、测试、性能基线）与临床结论**明确分开**。

- 若走同品种比对：对比器械信息、差异项与支持性资料：待填

## 3. 技术证据（**开发侧可提供，均为技术事实而非临床结论**）

| 证据 | 位置 | 说明 |
|---|---|---|
| 需求→设计→代码→测试追溯 | `docs/合规/可追溯性矩阵.md` | 证明每条需求都有实现与验证锚点（未挂锚点的条目单列） |
| 测试与门禁实测 | `docs/合规/发布就绪报告.md` | 后端分轨测试、前端测试、覆盖率、静态检查水位 |
| 性能基线（离线部分） | `scripts/bench_suite.py` | 纯函数热路径、并发放大倍数、显存维度（无 GPU 时记 SKIP） |
| 安全机制验证 | 测试集（脱敏/审计链/同意撤回/密钥轮换） | 含失败开放语义等**已知行为的显式记录** |
| 真机/数据待验证项 | `docs/合规/覆盖率豁免清单.json` | 6 项，逐条写明现场验证动作——**未验证项须在本报告中如实列出** |

## 4. 临床数据（由临床评价方填写）

1. 数据来源与采集流程（含伦理审批号）
2. 入组/排除标准、样本量依据
3. 评价指标定义（敏感度/特异度/AUC/一致率/Kappa 等）与统计方法
4. 结果：待填（**不得引用开发期任何模拟数据**）
5. 安全性/不良事件分析：待填
6. 结论与适用范围：待填

## 5. 与预期用途的一致性核对（本框架建议的必查项）

- 输出是否**只作为辅助**、是否有"必须由执业医师复核"的强制性提示（对照 SAD 的数据流与前端界面）
- 是否存在超适应范围输出（如未覆盖器官、儿科/孕产妇人群）
- **患者解释话术**是否可能被误当作诊断结论（当前设计：默认不入正式报告、界面标注"非正式报告内容"）
- 拒绝输出（E4005B）与降级行为是否在说明书中如实披露

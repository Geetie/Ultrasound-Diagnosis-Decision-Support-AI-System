## 一、先说清楚：为什么我们非得有数据不可

系统里所有"好不好"的判断，最后都要落在一个问题上：**拿什么当标准答案？**

- 想证明"检索准"，得有一批"这个描述该找到哪段资料"的标准答案
- 想证明"分级对"，得有一批"这个结节该判几类"的医生定论
- 想证明"报告写得好"，得有一批医生打过分
- 想证明"没漏诊"，得有一批病人后来到底是不是癌的结局

**没有这些，所有指标都是自说自话。** 2026-11-08 我们已经吃过这个教训：
14 个自造测试集，没有一个能用，于是 7 个核心指标全部作废。

所以这份台账的顺序就是：**先把标准答案搞出来，再谈模型好不好。**

### A4. CACTUS —— 心脏切面分类

| 项 | 内容 |
|---|---|
| **要用它干什么** | 测 T2b"这张图是哪个切面"认得准不准 |
| 为什么需要 | 切面识别错了，后面所有测量都错。这是心脏流程的第一道关 |
| 从哪来 | CACTUS，**CC BY 4.0，可商用** |
| 有多少 | 29,963 张影像（7.8 GB） |
| 标注是什么 | 切面类别标签 |
| 现在状态 | ✅ **已首次评测**（2026-11-08），但**官方 test 集有严重泄漏，两个数字都不能当泛化能力** |
| 数字①（受污染上界） | `p86_cactus_view_formal.py`：部署中的 8003 在官方 test.csv（n=4494，失败 0）上切面准确率 **0.9786（95%CI 0.9742–0.9826）**，宏 F1 0.9789；质量分级 MAE 0.8779。**这个数虚高** |
| 泄漏实证 | 29,963 张图只来自 **117 段视频**，而 `t2b_cactus_prep.py` 是**按图像**随机切的：官方 test 里 **96.1%** 的图所属视频在 train 出现过、**93.8%** 与 train 中同视频某帧**帧号相差 ≤5 帧**（审计在 `p87 --audit-only`） |
| 数字②（视频不交集重训） | `p87_cactus_video_disjoint.py`：按视频 80/19/17 整段切分、同配方重训 → 切面准确率 **0.2099（95%CI 0.1982–0.2221）**，而多数类基线恰为 **0.2099** —— 微调后退化成只猜 A4C |
| 数字③（无泄漏基线，可辩护） | `p89_cactus_baselines.py`（同一划分，**不训练**）：冻结 BiomedCLIP 特征 + LR = **0.8628（95%CI 0.8530–0.8721，宏 F1 0.8623）**；zero-shot 文本对齐 = 0.6881 |
| 结论 | 任务本身可分（冻结特征 86.3%），**是 T2b 的微调配方（3 epoch/lr 3e-6/batch 256 对比损失）把 BiomedCLIP 特征训坏了**（86.3% → 21.0%）。**部署中的 8003 T2b 切面头在未见视频上不可用**，必须重训 |
| 已知局限 | ①发布版缺 PSAV（README 虚标 6 类，实收 5 类）；②Random（非标准切面）是模型自己的一类而非拒识类；③只有 117 段视频，视频级划分下 test 仅 17 段/4511 张，方差大；④切面准确率≠临床可用性（还要求单帧置信度与拒识） |

## 六、每份数据集的规矩（防再犯）

新数据集必须带 `manifest.json`，写清：来源 / 许可 / 能不能商用 / 怎么造的 / 多少条 / **能测什么、不能测什么**。

进评测前必须过四道自动检查（`scripts/audit/p79_dataset_quality_gate.py`）：

| 检查 | 门槛 | 为什么 |
|---|---|---|
| 重复率 | **必须 0** | 同一句话重复出现，会让"两次回答一致率"虚高 |
| 模板污染 | ≤10% | 模板拼出来的数据，模型答得好看但测不出真实能力 |
| 影像术语覆盖 | ≥50% | 不含影像术语的查询，测不出本系统的本事 |
| 自相矛盾 | **必须 0** | 一句话里既说清晰又说欠清晰，根本没法判读 |

**任何一项不过，这份数据不许进评测。**

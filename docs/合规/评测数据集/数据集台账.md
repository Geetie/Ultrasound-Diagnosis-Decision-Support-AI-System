# 数据集台账 —— 本项目要用的每一份数据

> 建档：2026-11-08｜一句话：**这份台账里每一项都是一份"要用的数据"，不是"要修的缺陷"。**
> 每项都写清：**要它干什么（大白话）** / 从哪来 / 现在有没有 / 卡在哪。

---

## 一、先说清楚：为什么我们非得有数据不可

系统里所有"好不好"的判断，最后都要落在一个问题上：**拿什么当标准答案？**

- 想证明"检索准"，得有一批"这个描述该找到哪段资料"的标准答案
- 想证明"分级对"，得有一批"这个结节该判几类"的医生定论
- 想证明"报告写得好"，得有一批医生打过分
- 想证明"没漏诊"，得有一批病人后来到底是不是癌的结局

**没有这些，所有指标都是自说自话。** 2026-11-08 我们已经吃过这个教训：
14 个自造测试集，没有一个能用，于是 7 个核心指标全部作废。

所以这份台账的顺序就是：**先把标准答案搞出来，再谈模型好不好。**

## 二、可以直接用的（公开数据，已有或可下）

### A1. AUL —— 肝脏超声良恶性标注

| 项 | 内容 |
|---|---|
| **要用它干什么** | 测"肝脏病灶是良性还是恶性"这个判断准不准。这是目前**唯一**能给出可辩护数字的数据集 |
| 为什么需要 | 肝脏模块要证明自己能分辨良恶性。没有标注好的图，就只能靠人说"看起来还行" |
| 从哪来 | AUL（Abdominal Ultrasound Lesions），公开集，**CC-BY 4.0，可商用** |
| 有多少 | 全量 11,468 张；我们已下 **735 张**（151 MB） |
| 标注是什么 | 每张图有：良性/恶性/正常；部分有分割掩码 |
| 现在状态 | ✅ **已下载、已在用**。T2a 分类器在它上面测出 AUC **0.895**（置信区间 0.871–0.917） |
| 已知局限 | 是**肝脏**不是甲状腺；735 张是子集，可能不代表全量分布 |

### A2. TN3K —— 甲状腺结节分割

| 项 | 内容 |
|---|---|
| **要用它干什么** | ①测"能不能把结节轮廓圈准"；②当甲状腺影像检索的标准答案 |
| 为什么需要 | 甲状腺是我们的**主科室**，但现在连一张公开标注图都没有。分割做得好不好、检索找得对不对，全靠拍脑袋 |
| 从哪来 | TN3K，**CC BY-NC 3.0**（非商用，只能评测用） |
| 有多少 | 3,493 张 / 2,421 例 |
| 标注是什么 | 结节二值分割掩码（只标"这里有个结节"，不标良恶性） |
| 现在状态 | ❌ **未下载**。代码里已登记许可，`scripts/audit/p67_public_hard_set.py` 已支持 |
| 优先级 | **最高**。甲状腺是主线科室，这份数据补的是最大的空白 |

## 三、必须我们自己造的（公开集不提供）

> **共同原因**：公开集给的是**图像 + 影像学标签**，但我们的系统要吃的是
> **中文临床描述**，要吐的是**分级结论**。中间这一步"这句话该怎么判"，
> 全世界没有现成的中文超声数据集。

### B1. 临床文本 → 分级金标准 ⭐ 最卡的一环

| 项 | 内容 |
|---|---|
| **要用它干什么** | 判断"系统给的分级对不对"。**这是整个系统最重要的一个数字，现在完全算不出来** |
| 为什么需要 | 举例：医生说"右叶低回声结节 8×6mm，边界清，形态规则，无钙化"，系统该判 TI-RADS 2 还是 3？没有标准答案，就永远不知道系统判得对不对 |
| 从哪来 | **只能靠医生标**。给出描述 + 医生定论（分级 / 是否建议穿刺） |
| 要多少 | **≥200 例**，覆盖甲状腺/肝/心三科室 |
| 现在状态 | ❌ **零**。库里 `final_diagnosis` 非空 **0/1056** |
| 卡在哪 | **必须医生参与**，这是全项目唯一的硬卡点 |
| 没有它的后果 | 分级准确率、漏诊率、一致率——所有"准不准"的指标全部算不出来 |

### B2. 中文检索评测集（chunk 级）

| 项 | 内容 |
|---|---|
| **要用它干什么** | 判断"医生输入一句话，系统找回来的资料对不对" |
| 为什么需要 | 现有测试集拿患者问诊当查询（"去哪家医院治""要多少钱"），根本不是医生会问的。**含影像术语的只有 11.8%** |
| 从哪来 | **半自动可造**：从生产 1056 条判读里筛出 314 条有真结论的，人工挑 ≥100 条，配上"该找到哪一段" |
| 要什么规格 | ≥100 条查询，**≥50% 含影像术语**；标准答案到**段落级**（不是"整篇文档"） |
| 现在状态 | ❌ 无。旧的 `kb_qa_golden_v1` 已作废 |
| 能不能自己做 | ✅ **能，不需要医生**。这是最快能落地的一项 |

### B3. 报告话术质量评审集

| 项 | 内容 |
|---|---|
| **要用它干什么** | 判断"给病人看的解释写得好不好"（是否说人话、有没有吓人、有没有说清下一步） |
| 为什么需要 | 现在只能查"有没有用绝对化用语""是不是中文"这类规则，但"写得好不好"规则判不了 |
| 从哪来 | 需医生按 5 分制打分（1=完全不能给病人看，5=可以直接发） |
| 要多少 | ≥100 份报告 |
| 现在状态 | ❌ 零。规则级 5 项检查已生效，但主观评分没有 |

### B4. 随访 / 病理结局

| 项 | 内容 |
|---|---|
| **要用它干什么** | 算"漏诊率"——系统说没问题、后来查出是癌的比例 |
| 为什么需要 | 这是医疗 AI 最不能回避的数字。现在**完全算不出来**，因为没人知道病人后来怎么样 |
| 从哪来 | 医院随访记录 / 病理报告 |
| 要多少 | ≥300 例有结局的 |
| 现在状态 | ❌ 零 |
| 卡在哪 | 需临床方提供，涉及患者隐私与伦理审批 |

## 六、每份数据集的规矩（防再犯）

新数据集必须带 `manifest.json`，写清：来源 / 许可 / 能不能商用 / 怎么造的 / 多少条 / **能测什么、不能测什么**。

进评测前必须过四道自动检查（`scripts/audit/p79_dataset_quality_gate.py`）：

| 检查 | 门槛 | 为什么 |
|---|---|---|
| 重复率 | **必须 0** | 同一句话重复出现，会让"两次回答一致率"虚高 |
| 模板污染 | ≤10% | 模板拼出来的数据，模型答得好看但测不出真实能力 |
| 影像术语覆盖 | ≥50% | 不含影像术语的查询，测不出本系统的本事 |
| 自相矛盾 | **必须 0** | 一句话里既说清晰又说欠清晰，根本没法判读 |

**任何一项不过，这份数据不许进评测。**

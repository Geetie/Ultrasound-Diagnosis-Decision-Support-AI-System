> 建档：2026-11-08｜一句话：**这份台账里每一项都是一份"要用的数据"，不是"要修的缺陷"。**
> 每项都写清：**要它干什么（大白话）** / 从哪来 / 现在有没有 / 卡在哪。
> **怎么下载/怎么校验 → 见 [下载清单.md](下载清单.md)**（逐集 URL、命令、sha256 与实测验收数字）。

## 一、先说清楚：为什么我们非得有数据不可

系统里所有"好不好"的判断，最后都要落在一个问题上：**拿什么当标准答案？**

- 想证明"检索准"，得有一批"这个描述该找到哪段资料"的标准答案
- 想证明"分级对"，得有一批"这个结节该判几类"的医生定论
- 想证明"报告写得好"，得有一批医生打过分
- 想证明"没漏诊"，得有一批病人后来到底是不是癌的结局

**没有这些，所有指标都是自说自话。** 2026-11-08 我们已经吃过这个教训：
14 个自造测试集，没有一个能用，于是 7 个核心指标全部作废。

所以这份台账的顺序就是：**先把标准答案搞出来，再谈模型好不好。**

## 三、必须我们自己造的（公开集不提供）

> **共同原因**：公开集给的是**图像 + 影像学标签**，但我们的系统要吃的是
> **中文临床描述**，要吐的是**分级结论**。中间这一步"这句话该怎么判"，
> 全世界没有现成的中文超声数据集。

### B1. 临床文本 → 分级金标准 ⭐ 最卡的一环

| 项 | 内容 |
|---|---|
| **要用它干什么** | 判断"系统给的分级对不对"。**这是整个系统最重要的一个数字，现在完全算不出来** |
| 为什么需要 | 举例：医生说"右叶低回声结节 8×6mm，边界清，形态规则，无钙化"，系统该判 TI-RADS 2 还是 3？没有标准答案，就永远不知道系统判得对不对 |
| 从哪来 | **只能靠医生标**。给出描述 + 医生定论（分级 / 是否建议穿刺） |
| 要多少 | **≥200 例**，覆盖甲状腺/肝/心三科室 |
| 现在状态 | ❌ **零**。库里 `final_diagnosis` 非空 **0/1056** |
| 卡在哪 | **必须医生参与**，这是全项目唯一的硬卡点 |
| 没有它的后果 | 分级准确率、漏诊率、一致率——所有"准不准"的指标全部算不出来 |

### B2. 中文检索评测集（chunk 级）

| 项 | 内容 |
|---|---|
| **要用它干什么** | 判断"医生输入一句话，系统找回来的资料对不对" |
| 为什么需要 | 现有测试集拿患者问诊当查询（"去哪家医院治""要多少钱"），根本不是医生会问的。**含影像术语的只有 11.8%** |
| 从哪来 | **半自动可造**：从生产 1056 条判读里筛出 314 条有真结论的，人工挑 ≥100 条，配上"该找到哪一段" |
| 要什么规格 | ≥100 条查询，**≥50% 含影像术语**；标准答案到**段落级**（不是"整篇文档"） |
| 现在状态 | ❌ 无。旧的 `kb_qa_golden_v1` 已作废 |
| 能不能自己做 | ✅ **能，不需要医生**。这是最快能落地的一项 |

### B3. 报告话术质量 —— **拆分后不需要医生了**

> **更正（2026-11-08，用户指出）**：原来写"需医生 5 分制打分"，是把两件事混为一谈了。

| 问题 | 需要谁 | 为什么 |
|---|---|---|
| 这段话说得**对不对**（医学正确性） | 医生 | 只有医生能判断结节该判几类 |
| 这段话说得**清不清楚** | **不需要医生** | 科普写作有**研究验证过的客观标准** |

**领域专家是怎么做的**（已查证）：
- **CDC Clear Communication Index**（20 项，基于 Plain Writing Act 2010 与
  National Action Plan to Improve Health Literacy）：
  One Main Message / Common words / Active voice / Call to Action /
  Explain the nature of the risk / What We Know and Don't Know
  → https://www.cdc.gov/ccindex/tool/index.html
- **AMA / NIH 患者教育材料标准**：六年级阅读水平、短句、第二人称。
- **中文对应做法**：健康科普规范四原则——通俗、准确、不夸大、给出下一步。

**这些全都能离线确定性计算**，不需要模型、不需要医生、不花钱。
已实现 `app/knowledge/explanation_readability.py`（9 项检查 + 已接入生产链路）：

| 检查 | 判据 | 依据 |
|---|---|---|
| `no_main_message` | 首句未给结论 | CDC Part A #1 One Main Message |
| `too_many_ideas` | 一句里并列分句 ≥4 | CDC Part A #9 Chunks |
| `long_sentence` | 单句 > 40 字 | 六年级阅读水平 |
| `jargon_density` | 未解释术语 > 3 个/100 字 | CDC Part A #7 Common words |
| `passive_or_vague` | 通篇无「您/你」 | CDC Part B #12 |
| `no_next_step` | 未给复查/就诊指引 | CDC Part A #5 Call To Action |
| `risk_not_explained` | 提风险但没说含义 | CDC Part D #18 |
| `uncertainty_hidden` | 「可能」与「一定」并存 | CDC Part A #11 What We Know |
| `scare_language` | 恐吓性措辞 | 医学伦理 |

**实测区分度**：
- 反面（把整段报告塞给患者）→ 抓出 5 个问题（想法太多/90 字长句/术语密度 9.9/无第二人称/风险没解释）
- 正面（「您这次检查发现…建议您 6 个月后再来复查」）→ **全部通过**

**现在状态**：✅ **规则级已生效并接入生产**。仍缺的只有"医生认可这批话术可以发给病人"
这一层背书，那属于医疗责任流程，不是数据缺口。

**还需要自己造的（不需要医生）**：一份**人工标注的黄金集**（比如 50 份，人工标"能发/不能发"），
用来验证上面的自动检查本身准不准（敏感度/特异度）。这个谁都能标，只要懂中文。

> **2026-11-08 已造出**：`data/eval/v2/patient_explanation_golden_v1.jsonl`（50 条，逐条手写，
> 26 pass / 24 fail，含 18 条"预判检查器会判错"的难例）。**首测结果：准确率 0.640**
> （TP=23 / FP=17 / TN=9 / FN=1，召回 0.958 但特异度仅 0.346）——即检查器严重偏向"宁可错杀"。
> 逐项与修复建议见 `data/eval/v2/readability_checker_defects_20261108.md`；
> 复现：`python scripts/audit/p82_readability_golden_eval.py`。
> ⚠️ 质量闸 `imaging_term_coverage` 0.22 < 0.5 未过，属**口径不适用**（见该集 manifest 的
> `quality_gate_note`），其余三项全过。**"规则级已生效"的结论不变，但"规则本身准确度"此前
> 从未验证，现已证明需要修（候选补丁离线仿真 acc 0.64 → 0.92，既有单测 10/10 仍过）。**

| `kb_golden_v1` | 200 | 早期检索评测。查询是文章标题，还带 `[REDACTED]` | **B2 同上**（与上一份同源，一并替换） |

answer_relevancy。它们的新家分别是：
- 检索三项 → **B2 + A1/A2**
- 一致率两项 → **B1 副产品**

## 六、每份数据集的规矩（防再犯）

新数据集必须带 `manifest.json`，写清：来源 / 许可 / 能不能商用 / 怎么造的 / 多少条 / **能测什么、不能测什么**。

进评测前必须过四道自动检查（`scripts/audit/p79_dataset_quality_gate.py`）：

| 检查 | 门槛 | 为什么 |
|---|---|---|
| 重复率 | **必须 0** | 同一句话重复出现，会让"两次回答一致率"虚高 |
| 模板污染 | ≤10% | 模板拼出来的数据，模型答得好看但测不出真实能力 |
| 影像术语覆盖 | ≥50% | 不含影像术语的查询，测不出本系统的本事 |
| 自相矛盾 | **必须 0** | 一句话里既说清晰又说欠清晰，根本没法判读 |

**任何一项不过，这份数据不许进评测。**

## 0. 三条先读

1. **许可优先看保守值**。同一份数据在不同地方可能标不同许可（TN3K 就是实例：
   HF 卡片写 `license: mit`，论文与学术界引用写 `CC BY-NC 3.0`）。
   本项目一律**取更保守的那条**，判据由其机器可判实现兜住：
   `scripts/audit/p67_public_hard_set.py::license_gate()`。
2. **`commercial_ok=false` 的数据集一律"仅评测"**：不得训练、不得进注册申报路径。
   本文每份都单独标注。
3. **校验以官方清单为权威**，不以 README 里的宣传数字为准
   （历史教训：CACTUS 发布版 README 虚标，实际缺 PSAV 5,832 张）。
   TN3K 的权威清单是 HF tree API 里的 LFS `oid`（即 sha256）。

## 3. TN3K —— 甲状腺结节分割（★ 主线科室，最高优先）

### 3.1 事实

| 项 | 值 |
|---|---|
| 图像 | **3,493 张**（test-image 614 + trainval-image 2,879） |
| 掩码 | **3,493 张**，与图像**逐张配对且尺寸完全一致**（6,986 个文件） |
| 病例数 | 2,421 例（论文口径；本地按图像粒度使用） |
| 分类标签 | `label4test.csv` 614 行 + `label4trainval.csv` 2,879 行 = **3,493**，无缺号<br>标签：良性 2,283 / 恶性 1,210（0=良性，1=恶性） |
| 图像性质 | 灰度 `L` 模式，尺寸不固定（临床原始比例，非固定裁剪） |
| 许可 | **CC BY-NC 3.0（非商用，仅评测）**；HF 卡片同时写 `license: mit` → **取保守值，按 NC 用** |
| 可以拿来干什么 | 结节分割 Dice / IoU 评测；甲状腺影像检索的 gold（图-图配对） |
| 不可以干什么 | 训练、微调、进注册申报材料 |

### 3.2 权威下载源

- 主源：`https://hf-mirror.com/datasets/haifan-gong/TN3K`（HF 镜像，**无需账号**）
- 打包备用：同 repo 根目录 `TN3K.rar`（184,398,942 B），
  sha256 = `407fe2b4992e83b037621214aaaa39d86072e03d4ee3765f3c68d06e546e4ad4`
- 论文给的 Google Drive / 百度网盘链接：**本网络不可达，不作为可复现路径**

> **LFS 坑（必须知道）**：该 repo 图像与掩码是 Git LFS 托管。
> 直接 `git clone` 只会拿到 130 字节的**指针文件**（内容是 `version https://git-lfs...` + `oid sha256:` + `size`），
> 不是图像。必须逐文件走 `resolve` 端点取真实内容，并按指针里的 `oid` 做 sha256 校验。
> 仓库已有两份踩坑脚本：`scripts/tn3k_lfs_fix.py`（test 集）、`scripts/tn3k_lfs_fix_trainval.py`（trainval 集）。

脚本行为（`scripts/tn3k_download.py`，幂等，可重复跑）：

1. 走 HF tree API（**跟随 `Link: rel="next"` 分页**，每页 1000 条 —— 不跟分页只会拿到 3,228/6,986）；
2. 每个文件对照本地 sha256，已正确则跳过；
3. 缺失则 `GET resolve` 下载，按 LFS 声明的 `size` 与 `sha256` 双向校验，不符重试 3 次；
4. 结束时打印 `PIL readability` 与磁盘占用。

### 4.4 标注格式（要在代码里用就必须知道）

```xml
<case>
  <number>100</number><age>39</age><sex>F</sex>
  <composition>predominantly solid</composition><echogenicity>isoechogenicity</echogenicity>
  <margins>well defined</margins><calcifications>macrocalcifications</calcifications>
  <tirads>4a</tirads>
  <mark>
    <image>1</image>                       <!-- 对应文件 100_1.jpg -->
    <svg>[{"points":[{"x":164,"y":31}, ...], "regionType":"freehand"}]</svg>
  </mark>
</case>
```

- 影像号 `<image>N</image>` ↔ 文件名 `{number}_{N}.jpg`（这是唯一可靠的配对规则）；
- `svg` 是 JSON 数组，一个 mark 里可以有多段多边形（多结节）；
- 生成的分割金标准在 `~/uai/data/ddti/mask/*.png`（0/255 二值），解析结果在
  `~/uai/data/ddti/meta/ddti_cases.json`。

## 7. 值不值得下：TG3K 与 TNSCUI 的判断

判断标准只有一条：**能不能回答我们现在的空白**。
现状是甲状腺"一张公开标注图都没有"，而 TN3K+DDTI 落地后，
**图像级分割与图像级检索的 gold 已经齐了**。所以要看的是"新增了什么别人没有的能力"。

| 数据集 | 能用于"结节分割 Dice"？ | 能当"影像检索 gold"？ | 是否与 TN3K 重复 | 建议 |
|---|---|---|---|---|
| **TN3K** | ✅ 3,493 张配对掩码，已校验 | ✅ 图-图配对 | — | 已落地，主线 |
| **DDTI** | ✅ 466 张掩码（多结节、含 TI-RADS） | ✅ 另带临床字段，可做"图+文"配对检索 | **不重复**：独立来源、多结节标注、带 TI-RADS 分级与影像征象 | 已落地，交叉验证用 |
| **TG3K** | ⚠️ 帧级掩码质量未知（未取到，无法核实） | ❌ 视频不适合当"单图检索 gold" | **用途不同**（时序一致性），非重复 | **可下但优先级低**：只在验证"同一病人多帧判断一致性"时不可替代；当前无此评测需求 → **不建议现在花 gated 申请成本** |
| **TNSCUI** | ✅ 3,644+910 张，规模最大 | ✅ 可用 | **实证不重复**（见下） | **不建议下**：①官方公开源无数据，需 grand-challenge 注册；②**CC BY-ND 4.0 禁止改作**，与我们"掩码需按需重采样/统一格式"的用法冲突；③增量价值仅"第三份甲状腺分割"，而 TN3K+DDTI 已覆盖该用途 |

### TNSCUI 与 TN3K 是否重复 —— 实证而非推测

拿 TNSCUI2020 仓库公开的样图 `benign-12_demo.png`（434×216，sha256 `fdf8f386…`），
与 TN3K 全部 3,493 张做两级比对（整图 / 左半 / 右半 / 上半 / 下半 五种切法 × dHash 8×8 汉明距离）：

```
TN3K images to scan: 3493
最近距离 dist=13（trainval-image/1602.jpg）
距离<=5 的候选数 = 0 / 3493
RESULT: NO_OVERLAP_DETECTED
```

**结论：这批像素与 TN3K 无近重复。** 但由于 TNSCUI 完整图像取不到，
该结论的边界必须说清：**它只证明了"这一张 TNSCUI 样图不在 TN3K 里"，
不等于"TNSCUI 全集与 TN3K 无交叠"**——完整结论需拿到全量图后才能下。

> 另需注意用途口径：TN3K 是 `CC BY-NC 3.0`（可改作、不可商用），
> TNSCUI 是 `CC BY-ND 4.0`（不可改作、可商用）。
> 两者**不能混在同一个数据集里合并发布**：ND 的"不可改作"会污染合并后的产物。

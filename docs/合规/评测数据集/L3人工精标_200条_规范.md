# L3 人工精标 200 条：撰写规范

> 2026-11-09｜用户决定：改用人工写 200 条带 persona 标注的数据，替代失败的 L2 合成

## 一、为什么写这 200 条

现有 484 条（B2 升级）的 `organ × query_type` 分布已经很均衡，
**唯一缺的是 `persona` 维度**（全部 `unassigned`）。

`persona` 是 Ragas 要求的分层维度，也是**真实临床差异的来源**：
- 住院医师问「这个征象算不算可疑」
- 主治医师问「边界情况怎么定」
- 临床科室医生问「报告这分级我该怎么处理病人」
- 医务处问「我们该用哪套指南」

**这 200 条的任务：把 persona 这一维补上，且每条都由人工逐字核对 KB。**

## 二、四个 persona 的定义（写题时必须贴合）

| persona | 身份 | 关心什么 | 典型问法 |
|---|---|---|---|
| `resident` | 超声科住院医师（1-3 年） | 规则怎么用、积几分、归几类 | 「这个征象算不算可疑？」「实性+微钙化积几分？」 |
| `attending` | 超声科主治医师 | 边界、例外、争议、取舍 | 「这条规则有没有例外？」「同样 4 分两套怎么取舍？」 |
| `clinician` | 临床科室医生（非超声） | 报告含义、下一步处置 | 「报告写 4A，我要不要安排穿刺？」「这个分级严不严重？」 |
| `qa` | 医务处质控 | 体系一致性、可追溯 | 「本院用哪套？」「两套并存会不会同一病人两结论？」 |

## 四、每条的硬性要求

### 4.1 `query`

- **必须贴合 persona 的视角**（见第二节）
- 15-60 字
- **必须含具体锚点**：分级码（4A / LR-5 / TR4）、数值（13mm / 2%）或解剖部位
- 不许写「这份原文能否回答…」这类询问

### 4.2 `reference_answer`

- **逐字摘录 KB 原文**，每个字都要能在 gold 的 chunk 里找到
- 以「原文提到：」开头
- **≥40 字**
- 可以拼接同一 chunk 的多句，但**不许改写、不许补充、不许推断**

### 4.3 `gold`

- `chunk_id` 必须真实存在
- `evidence_quote` 必须**真的在那个 chunk 里**（这条我吃过 74% 标错的亏）
- 引文 ≥15 字

### 4.4 `metadata`

- `organ` / `persona` / `hop` / `specificity` / `length` 全部填**具体值**
  （不像 B2 那样标 unassigned —— 这次是我写的，我知道是谁在问）
- `source`: `"manual_l3"`
- `dataset_version`: `"rag-eval-v3.0.0-l3"`

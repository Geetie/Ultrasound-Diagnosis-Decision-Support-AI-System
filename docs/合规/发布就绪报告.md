## 三、补测过程中修好的真实缺陷（不是"测试凑数"）

1. **指标 p99 恒为 None**：`_calculate_histogram_p99` 假设 `hist._buckets` 是 dict，而
   prometheus-client 0.25 已是列表 → `AttributeError` 被 `except: pass` 吞掉。
   看板 4 个 p99 面板一直空白，且"算不出来"与"没样本"表现相同，无从察觉。
2. **带标签直方图的 p99 永远取不到**：`diagnosis_latency` / `multi_organ_latency` 是
   `labels(...)`，桶计数在子指标上、父对象为空 → `diag_p99` / `multi_p99` 永远为空。
3. **`dicom-parser` 访问器从未声明**：`image.data.string(tag)` / `uint16(tag)` 靠 `any` 兜着，
   写错标签名或访问器名不会被发现（患者在 PHI 去标识化路径上）。
4. **`.gitignore` 的 `data/` 无锚点模式**吞掉了 `tests/unit/data` 与 `tests/integration/data`
   整目录 → 3 个测试文件**只存在于本机、CI 从未运行过**（其中 `test_desensitization.py` 有 31KB）。
   ruff 默认遵循 .gitignore，因此这些文件此前对 ruff 也是隐形的。
5. **SG 同意直查用例的顺序依赖**：全局单例熔断器 `sg_db_consent` 被前面用例打到 OPEN 后，
   `breaker.execute()` 直接抛 `CircuitBreakerError`，根本走不到被替换的 `_retry_query`
   → "单跑绿、全套红、CI 随机红"。

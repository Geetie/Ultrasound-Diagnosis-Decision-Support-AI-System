> 涉及现场环境的项标注 `[现场]`，需部署时按实际拓扑补充（IP、证书、端口、备份介质）。

| 服务 | 入口 | 说明 |

## 2. 健康检查与关键指标

- 健康接口：`app/api/v1/health.py`（依赖可用性、降级状态）。
- 看板接口：`app/api/v1/obs_dashboard.py` —— 含 GPU 资源、幻觉率、**延迟 P99（导航/评估/诊断/多器官）**、
  灰度放量、修正率、漂移等面板。
  > 注意：P99 面板依赖 `get_histogram_p99()`。此前该方法**恒返回 None**（库版本变更导致静默失败），
  > 已修复并加"读取侧守卫"测试；若面板再次为空，先看该守卫是否报警。
- 指标推送：VictoriaMetrics 由 `app/observability/metrics_collector/pusher.py` 周期推送
  （失败退避、达阈值退避到最大间隔——`circuit_open` 是**最长间隔**而非停推）。

## 3. 常见故障与处置

| 现象 | 判定 | 处置 |
|---|---|---|
| 诊断输出被拒（E4005B） | 安全网关判定 PG/同意不可用 | 先恢复 PG 与同意数据链路；**不要**用 Redis 缓存绕过（设计上禁止） |
| 同意撤回未即时生效 | 撤回端到端时延越线（目标 <500ms） | 查指标 `consent_withdrawal_latency_seconds` 与越线计数；在途诊断由登记表取消，确认消费者在线 |
| 熔断器打开（SG 侧） | `sg_db_consent` 连续失败 | 排查下游；熔断为保护措施，**不要**强制复位后立即放量 |
| HSM 降级 | 密钥服务不可用 | 进入应急签名流程（双人审批 + 每日配额）；恢复后执行密钥轮换（支持断点续跑） |
| 显存碎片高 | 碎片率超阈值触发热重载 | 查看 GPU 面板与 `bench_suite --suite vram`（无 GPU 时该套件记 SKIP，不是 PASS） |
| 灰度异常 | 放量轨道指标劣化 | 关闭 `rollout_enabled` 或降低放量比例；灰度判定会落库，可用其比例核对实际放量 |
| 审计链校验失败 | 周期任务报 `audit_chain_integrity_violation` | **按安全事件处理**：定位断链 session_id 与日志 ID，保全证据后再修复 |

## 5. 发布与回退

- 门禁（CI 阻断项）：ruff 全量风格门禁、后端分轨测试、覆盖率（整体/核心阈值见
  `.github/workflows/ci.yml`）、前端 eslint（水位）+ tsc + vitest + build、性能基准。
- **发布前必看**：`docs/合规/发布就绪报告.md`（当前门禁实测与已知偏离）
  与 `docs/合规/覆盖率豁免清单.md`（需现场验证的项，未验证不得宣称达标）。
- 回退：模型回退走模型版本管理；功能回退用灰度开关；**不要**回退既有安全修复
  （知识库导出契约、嵌入重试参数、kb_version 契约）。

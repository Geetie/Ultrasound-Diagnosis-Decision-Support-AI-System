**② 缺口（为什么没通）**

一条一句：

1. **【接了但默认关】** `settings.py:416` 默认 `False`，且是**有意裁决**（`settings.py:409-413`），不是遗漏。答辩说"影像腿默认关"——**准确**，但归因（"没打通"）不准确：这是 A.80/A.81 判过"塞进知识上下文会被 `_wrap_search_results` 按 chunk_id 丢弃"之后的设计选择。
2. **【打开也无效 —— 数据层没实现】** 即使打开，`_image_chunk_text:1042-1061` 只能产出元数据；payload（`build_image_vectors.py:49-58`）无特征字段 → 影像块对 prompt 的信息增益≈0。
3. **【RRF 分槽缺陷（新发现）】** `retriever.py:290-297` 把影像腿也 key 成 `DENSE`，与 dense 腿**同槽**。`_rrf_fuse:944-952` 对同一 key 的两条腿是**顺序累加进同一个 dict**（等价于把两条腿拼成一个长列表再按 rank 计分），不是"两条独立腿各贡献 1/(k+rank)"。后果：影像块与 dense 块在同一排名序列里**互相挤位**，高分的 dense 块会把影像块推到 rank 20+，`k=60` 下分差被压平 → 影像腿即便命中也在 top-5 之外。
4. **【两道后处理挤掉】** `service.py:288` 截 top-5、`service.py:291-306` BM25 兜底可整批替换 —— A.95 实测 **P1（可达）100% 但 P1b（送达）仅 40%**（`16 号:8151`；`p65` 脚本 `:344-352` 已把 P1b 落成诊断口径，"不计入裁决"）。
5. **【真正该走的通道也没进 prompt】** `diagnosis_pipeline.py:357` 的 `similar_cases` 只写进结果载荷（`:1277`），**不进 `AgentContext`/prompt**；`imaging_metadata`（`:425`）只有分割开启时才有量化特征。所以"影像信息到达模型"的三条路（检索腿 / 相似病例 / 分割元数据）**没有一条把特征文本送进 prompt**。

**已知教训（必须写进方案）**：本仓库实测两次「打开开关 ≠ 能力生效」——
- 影像腿 P1 可达 100%、P1b 送达 40%（`16 号:8149-8152`）
- 打开 `rag_use_multimodal` 后判读 **N=20 无增益**，且"缺特征"70%→15%↓ 换来"分不出级"0%→60%↑，**总数不变**（`progress.md:11`、`16 号:8144-8146`）

故本项的"打通"判据**不是** `enabled=true`，而是 **P1b 送达率 > 0 且"无法判断率"绝对值下降**。

**阶梯①（需要存在吗）**：**影像检索腿这条路不需要"打通"** —— 它已被 A.80/A.81/A.82 判决改道，且 N=20 实测 `NO_GAIN`。为它补 payload、调 RRF、改后处理，是给一条被判决淘汰的支线续命。

**阶梯③-⑦**：无需标准库/新依赖。特征文本的来源按"零模型成本优先"排序：

**判定结论（关键，且与答辩方向一致但理由不同）**：
`docs/合规/双引擎一致性正式判定-Gate0A口径.md` 明确写：

- 完整文本一致率 **20.51%**（要求 ≥90%）→ **❌**

**② 缺口（为什么没通）**

1. **【不是缺口，是判决】** 答辩说"是离线脚本、未进主链"——**准确**。但把它列为"未打通"隐含了"应该进主链"的假设；`Gate0A 判定书` 已经把这条路**判死**（不通过 → 统一单一框架）。真正的缺口是**这个判决没有被写进答辩/文档的状态口径**，于是一项"已判决不做"的设计被算成了"未打通"。
2. **【结构性不可能】** `factory.py` 按 `inference_engine` 二选一；同一请求不可能同时过两栈。要"进主链"就得对每次判读跑两遍 LLM → 成本 ×2、延迟 ×2，与 01-5 的三档延迟目标**直接冲突**。

**结论：不做（进主链）+ 保留为发布门禁用例。** 0 行生产代码改动。

## 3. God nodes Top 10 及架构含义

`graphify god-nodes --top 15` 实际输出（前 10）：

| # | 节点 | 度 | 位置 | 所在社区 |
|---|---|---|---|---|

| 2 | `RetrievalRequest` | 236 | `app/rag/protocols.py:89` | Retrieval Interfaces |
| 3 | `AgentResponse` | 217 | `app/agents/protocols.py:97` | Agent Response Models |
| 4 | `KnowledgeChunk` | 189 | `app/knowledge/protocols.py:75` | Knowledge Agent Retrieval |
| 5 | `FusionRequest` | 156 | `app/fusion/protocols.py:157` | Consistency Checker |
| 6 | `AuditService` | 147 | `app/services/audit_service.py:47` | Audit Chain Service |
| 7 | `make_response()` | 145 | `tests/unit/fus/conftest.py:39` | Conflict Detector |
| 8 | `Retriever` | 130 | `app/rag/retriever.py:214` | Retrieval Interfaces |
| 9 | `InferenceRequest` | 129 | `app/inference/protocols.py:142` | llama.cpp Engine |
| 10 | `RedisKey` | 129 | `app/config/redis_keys.py:8` | Redis Key Registry |

**这 10 个节点说明架构的什么**（三条可直接写进答辩的判断）：

1. **架构是「协议/数据契约驱动」的管道，不是继承驱动的**。10 个 god node 里 6 个是 `protocols.py` / `schemas.py` 里的请求-响应数据类型（`RetrievalRequest`、`AgentResponse`、`KnowledgeChunk`、`FusionRequest`、`InferenceRequest`、`Organ`），实现类只有 2 个（`Retriever`、`AuditService`）。检索 → 智能体 → 融合 → 推理的每段链路靠**同一批数据契约**衔接，因此**改动这些类型的爆炸半径是全仓**（`Organ` 一改影响 327 条边）。
2. **横切关注点的耦合度高于业务服务**。`AuditService`（147）与 `RedisKey`（129）挤进 Top 10：审计与 Redis 键空间是**全局硬依赖**，不是某个模块的私有实现 —— 与"独立 SafetyGateway + 全链路审计"的设计一致，也意味着**审计/缓存键是单点风险**。
3. **测试基建反向主导了生产契约的形状**。`make_response()`（`tests/unit/fus/conftest.py:39`）以 145 度排第 7，是 Top 10 里唯一的非生产代码；同时 tests 占全图 56% 节点（13,910/24,799）。这说明融合层的响应对象由**统一测试夹具**批量构造 —— 它是最有价值的回归资产，也是**最脆弱的单点**（实测 131 条 calls / 143 条入边，夹具一改这一片用例同时变）。

## 5. 三条查询用法（均已实测）

**① 自然语言 / 符号检索（原生 CLI）**

```bash

graphify god-nodes --top 15                 # §3 那张表就是它的输出
```

- **必须用 Python ≥3.10**：`query_graph.py` 用了 `dict | None` 注解，用本机默认 `python3`（3.9.6）直接跑会失败，实测原文：
  `TypeError: unsupported operand type(s) for |: 'type' and 'NoneType'`（`query_graph.py:53`）。故一律用 `uv python find 3.11` 找到的解释器执行。
- **本版本（0.9.97）没有 `graphify status` 子命令**；等价的"图是否新鲜/规模多大"用 `graphify god-nodes` + `graphify-out/.graphify_analysis.json` + `GRAPH_REPORT.md` 的 Summary 段。
- **必须用兼容视图**：`graphifyy 0.9.97` 输出的 `graph.json` 是 networkx node-link 结构（`nodes[].source_file` / `links[].relation='calls'` / `confidence='EXTRACTED'`），而 skill 0.4.x 的 `query_graph.py` 读的是 `nodes[].file` / `nodes[].degree` / `edges[]` / `communities[]`。`graphify-out/schema_compat.py`（60 行、纯 stdlib、只读 graph.json）生成 `graph.compat.json` 做桥接，**原始 `graph.json` 未被改动**。因此这个 20MB 文件**不是冗余产物，是 `query_graph.py` 的唯一入口**（删除后该脚本无法运行）。

**③ 两节点最短路（影响面分析）**

```bash
graphify path "RAGServiceImpl" "CRAGHandler" --undirected
# Shortest path (2 hops):
#   RAGServiceImpl <--imports [EXTRACTED]-- app/main.py --imports [EXTRACTED]--> CRAGHandler
```

> 注：不加 `--undirected` 会返回 `No directed path found`（图默认按有向搜索，而装配关系是 `app/main.py` 单向下发），排查装配链时**一律加 `--undirected`**。

## 6. 局限与风险（必须随图一起说明）

1. **无语义抽取**：本机无 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`，构建用 `--code-only`。**68 个文档（含 `docs/**`、`AGENTS.md`、答辩 PDF）未入图**，图里没有"设计意图"节点，只有代码结构与 docstring（中文 docstring 已进节点 label，所以 `graphify query "CRAG 补充检索"` 仍能命中）。要补文档层需配 API key 后 `graphify extract . --update`。
2. **社区命名用过本机 `claude` CLI**：891 个社区名（如 `Consistency Check Phases`）由 `claude -p` 生成（138,584 in / 6,955 out token）。重跑 `cluster-only` 会再次调用它；无 CLI/无 key 时社区名退化为 `Community N`，不影响结构。
3. **13% 边是 INFERRED**（7,672 条，平均置信度 0.9）。用于"探索"可靠，用于"断言"应先看 `confidence_score`；精确影响面分析请过滤 `relation==EXTRACTED`。
4. **`query_graph.py` 不能直接读 `graphifyy 0.9.97` 的 `graph.json`**（schema 代差，见 §5），必须走 `graph.compat.json`；且该脚本需要 Python ≥3.10。
5. **`graphify-out/` 未进 `.gitignore`**（本次核查：`.gitignore` 里没有 `graphify` 条目；`.graphifyignore` 只影响"抽取时排除"，不影响 git）。**`graphify-out/cache/` 39MB 绝不能提交**；建议后续在 `.gitignore` 补 `graphify-out/cache/` 一行（本轮按分工未改 `.gitignore`，它当前有他人未提交改动）。
6. **规模上限**：24,799 节点已超过 `graph.html` 的 5,000 节点阈值，因此 `graph.html` 是**社区聚合视图**（891 个社区节点 + 3,438 条跨社区边），不是逐符号视图；要逐符号可视化需 `graphify export html --node-limit N` 或 `export obsidian`。
7. **`pyproject.toml` 未产生节点、1 个 `.sql` 因缺 `tree_sitter_sql` 未解析**（抽取期警告）；对架构结论无影响。43 个 `__init__.py` 类空壳文件无符号，属正常。

## 三、问题分析与建议

### 3.1 问题：SafetyGateway自建数据库引擎

**问题位置**：`safety_gateway/checker.py:85-92`

```python
# 当前实现（自建引擎）
self._async_engine = create_async_engine(
    settings.database_url,
    echo=False,
    future=True,
    pool_pre_ping=True,
    pool_size=settings.db_pool_size,
    max_overflow=settings.db_max_overflow,
    pool_timeout=settings.db_pool_timeout,
)
```

**问题影响**：
1. **资源浪费**：创建了独立的数据库连接池，与主应用的连接池重复
2. **配置不一致风险**：如果主配置变更，SafetyGateway可能不会同步更新
3. **代码重复**：数据库连接配置逻辑重复实现
4. **监控盲区**：独立的连接池不在统一监控范围内

### 3.2 代码审查验证

根据测试文件 `tests/unit/test_sec_craft_fixes.py:333-334` 的验证逻辑：

```python
assert "checker._async_engine" in source
assert "create_async_engine" not in source
```

测试期望 `create_async_engine` 不应直接出现在checker.py中，表明这是一个已知的待修复问题。

### 3.3 修复建议

**方案**：SafetyGateway应复用 `app/config/database.py` 提供的统一数据库连接

```python
# 建议修改：复用统一基础设施
from app.config.database import async_engine, get_db_session

class SafetyGatewayChecker:
    def __init__(self):
        # 移除自建引擎逻辑
        self._whitelist_fields = (
            settings.safety_gateway_whitelist_fields
            if settings.safety_gateway_whitelist_fields
            else self.DEFAULT_WHITELIST_FIELDS
        )
        self._query_timeout = settings.db_query_timeout
        self._contraindication_engine = get_contraindication_engine()
        self._threshold_engine = get_threshold_engine()
```

**迁移步骤**：
1. 修改 `safety_gateway/checker.py`，移除 `_ensure_engine()` 方法
2. 将数据库操作改为使用 `get_db_session()`
3. 更新 `close()` 方法，移除引擎dispose逻辑
4. 更新相关测试用例

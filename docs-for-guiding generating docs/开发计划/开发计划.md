### 1.3 模块耦合关系与任务分组

**完全独立模块**（可并行开发）：
- M-INF（基础设施）— 无上游依赖
- M-EDGE（边缘端）— 仅依赖 M-INF
- M-FE（前端）— 仅依赖 M-API 接口契约
- M-OBS（可观测性）— 横切关注点，接口先行
- M-SEC（安全合规）— 横切关注点，接口先行

**集成开发任务组**（存在耦合关系，需协调开发）：

| 任务组 | 包含模块 | 耦合原因 | 集成策略 |
|--------|---------|---------|---------|
| IG-DATA | M-DATA + M-EMB | 知识库数据驱动嵌入模型索引构建 | 数据先行，嵌入模型后行 |
| IG-CORE | M-LLM + M-RAG + M-AGENT + M-FUSION | 推理管线端到端链路紧密耦合 | 接口先行，逐层集成 |
| IG-SAFE | M-SG + M-SEC | SafetyGateway依赖安全合规规则 | 安全规则先行，SafetyGateway后行 |
| IG-API | M-API + M-FE | 前后端接口契约耦合 | 接口契约先行，前后端并行 |

## 二、任务规划与并行策略

### 2.1 任务标识符体系

```
T-{阶段}-{组别}-{序号}
阶段: G0=Gate0 | G1=Gate1 | GA=Gate0A | GB=Gate0B | GR=灰度发布 | GA2=全量发布
组别: INF=基础设施 | DATA=数据 | LLM=推理 | EMB=嵌入 | RAG=检索
      AGT=智能体 | FUS=融合 | SG=安全网关 | API=接口 | EDG=边缘
      FE=前端 | OBS=可观测 | SEC=安全 | INT=集成 | DOC=文档
```

## 三、开发规范与流程

### 3.1 接口先行，契约优先

**执行规则**：

1. **Protocol/ABC先于实现**：每个模块开发前，必须完成Protocol接口定义（Python ABC或TypeScript Interface），包括：
   - 输入/输出数据结构（Pydantic Model / TypeScript Type）
   - 异常定义（自定义异常类+错误码）
   - 性能契约（P99延迟预算）

2. **接口评审检查清单**：
   - [ ] 接口命名遵循项目术语表（00a-术语表.md）
   - [ ] 输入/输出结构符合03-接口规范.md定义
   - [ ] 错误码符合错误码体系（E1xxx/E2xxx/E3xxx/E4xxx）
   - [ ] 性能契约与00-项目总览核心指标对齐
   - [ ] 安全校验需求已明确（A/B/C级安全分级）

3. **接口锁定机制**：接口评审通过后纳入Git版本控制，变更须走接口变更审批流程。

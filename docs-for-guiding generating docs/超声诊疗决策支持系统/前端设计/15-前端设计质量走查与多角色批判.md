# 前端设计质量走查与多角色批判

> 对象：[14-前端设计评审结论](./14-前端设计评审结论.md)（**评审时点为 v2**；该文档已迭代至 **v5**，本文各条现状见下表与 §0.5）

## 0. 证据等级声明（必须先看）

| 项 | 状态 |
|---|---|
| 画布稿（`.ardot`） | **不存在**。全项目 glob `**/*.ardot` 为空；画布通道可用但无文件 |
| 因此本次评审的性质 | **决策层走查（spec-level review）**，不是像素层走查（pixel-level review） |
| 可下结论的维度 | 信息架构、交互状态、内容与文案、标准引用一致性 |
| **不可下结论的维度** | 布局与对齐、色彩对比度比值、字体与排版、控件规格 —— 按双证据硬门（节点声明值 × 渲染像素同时具备）**一律标「低置信度、视觉未验证」** |

这不是免责声明，是纪律：**没有像素就没法说"对比度达标"**。要拿到像素级证据，下一步需把 v2 落成画布稿（画布通道可用，可代建）。本报告 §2 里标注「未验证」的行，就是等画布稿补的那部分。

## 1. 评审概览

**一句话**：v2 在**安全语义**和**减负**两条线上都做对了减法（不确定态从黄色改中性青灰、取消"暗室模式"这个概念本身、一级导航 5→2、把角色的差异收敛到"2–3 个动作"），但它把**"零新增动作"推到了系统的反面**——AI 判读变成无条件自动滑出，却**没有定义去重规则和布局稳定性**。结果是用 v1 的一种"太多"（太多入口）换成了 v2 的一种"太多"（太多自动结论）。

- **最大亮点**：§7 那句认识——"v1 觉得是架构议题，是因为假设了界面要按角色分，**该前提是错的**"。这一句把 5 个议题压成 1 个后端校验点 + 1 个条件渲染。这是真正的架构级简化。
- **最大隐患**：**automation bias 的摩擦被一起减掉了**。v2 只在"严重幻觉"时要求勾选核验；而"结论卡滑出、不打断、医生可以回头再看"的代价，恰是医生**可能一眼不看就签发**。减负减到了安全防线的成本上。

## 2. 质量评分卡（6 维）

| 维度 | 得分 | 核心问题 | 证据等级 |
| :--- | :--- | :--- | :--- |
| **布局与对齐** | 5 / 10 | §2.4 定义了三阶段，但没有定义**任何尺寸与占位**：影像区在三阶段的高度各是多少？结论区是常驻还是生长？现在"影像上缩"与"不打断"直接矛盾（P0-2）。 | 决策层可判；像素未验证 |
| **色彩与对比度** | **7 / 10（v5 重评）** | 原文两条①红/橙不可分②按页面分默认主题 **均已消解**：v5 移除橙、语义色降为两级（停=红 / 看一眼=中性青灰 / 正常不渲染），主题改为设备级。「中性青灰 / 深色底」原先无 hex，**R-03 已补并算出比值**。**仍待**：画布上的实测复核。 | 色值来源可判；对比度**实测**待画布 |
| **字体与排版** | 5 / 10 | **整节缺失**。中文字体族、字号层级、行高、以及一条关键项：**测量数值必须等宽（tabular numerals）**，否则 3.2mm → 3.7mm 的行内跳动会干扰比对。术语未与 `00a-术语表` 对齐。 | 未验证 |
| **控件与一致性** | 5 / 10 | 确认动作区的大按钮、结论卡、部位指示条、部位标签、状态行——**没有任何尺寸 / 圆角 / 描边 / 状态规格**。v1 有 antd 5.x 兜底，v2 反而没接上任何设计系统。 | 未验证 |
| **交互状态** | 4 / 10 | **重灾区**。三阶段的状态机未定义：判读中再冻结怎么办？继续扫查后结论卡去哪？切部位时旧结论保留吗？此外无 loading / empty / error / **AI 不可用**态定义。 | 决策层可判 |
| **内容与文案** | 7 / 10 | `review_reason` 7 种枚举要人话化、禁裸浮点、AI 来源显式标识——方向全部正确。扣分在缺**文案模板库**（"已超基线"那句之外没有别的样板），且未与 `00a-术语表` 建立映射。 | 决策层可判 |

**合计约 32 / 60。** 底子（语义体系 + 架构简化）在 8 分水准，落地定义在 4–5 分水准——**这是一份"想清楚了但没写下来"的设计**。

## 3. 多角色视角批判（核心章节）

v1 的问题是按系统模块划界面；v2 矫枉过正，把界面收敛成**一个医生的一个动作流**。代价是**其余 5 类使用者全部失去了自己的工作面**。下面逐类查。

### 3.1 基层 / 急诊医生（主锚点）

| # | 视角原话 | 问题 | 严重度 |
|---|---|---|---|
| A | "我一例甲状腺要冻十几二十次，你每次冻都给我一张结论卡？" | **判读请求无去重**。全自动 + 每次冻结触发 A 级（完整六阶段链路）→ 一例检查产出数十条结论。这既是后端成本灾难，更是**新形态的告警疲劳**，而且它是系统自动产生的，医生连"拒绝触发"的机会都没有。**这直接抵消了 §5.5"减少告警数量本身就是安全改进"的全部论证。** | **P0-1** |
| B | "我要边扫边看，你把图给我缩小了。" | §2.4 说结论卡从下方滑出、影像上缩；§5.1 说"不打断，医生可以继续扫查"。**这两句不能同时成立**——卡一出现画面就重排了。 | **P0-2** |
| C | "我正在判读，又看见一个结节，再冻一次，现在我在第几阶段？" | **三阶段状态机未定义。** 真实检查是"扫 → 冻 → 读 → 解冻 → 再扫 → 再冻 → 读 → 收尾写报告"，是**循环**，不是单向线。v2 用"阶段 1/2/3 垂直推进"这套词汇描述它，导致回到扫查态时结论卡的去向无人定义。 | **P0-3** |
| D | "我打开系统，怎么直接是某个病人的检查？列表呢？" | §2.3 把"工作列表默认视图 = 当前检查"。**用一个列表页去承载单个对象**，打开时医生无法判断自己在列表还是在详情；且有多个进行中会话时（被打断、多器官）"一键继续"没有定义选谁。 | P1-9 |
| E | "部位条那么细，你还塞了 4 个状态？" | §2.5 说"极细部位指示"，但要求承载 待扫 / 进行中 / 已完成 / **需复核** 四态。**"需复核"是安全信息**，塞进极细条与 §3.1"漏项是安全信息，须可见"自相矛盾。 | P1-10 |

### 3.2 超声科医生（常规 / 三甲）

| # | 视角原话 | 问题 | 严重度 |
|---|---|---|---|
| F | "我们科住院医写完、主治要审、主任终审，你那一个筛选是怎么回事？" | v2 说"审核降为工作列表的一个筛选 + 签发按钮文案差异"。但真实的分级审核需要：**审核队列、审核意见回写、退回修改、双签留痕、工作量统计**。这不是"降级"，是**工作台缺失**。更麻烦的是 v2 同时宣称"三甲需求是其超集，向上扩展是加法"——**这里不是加法，是没有面上**。建议改为**诚实标注"审核工作台不在本轮范围"**，而不是宣称已由筛选解决。 | P1-11 |
| G | "上个月那个结节的片子在哪？我要并排看。" | §3.2 列了 `compared_with_prior` 时间轴并排对比，但 v2 的两项导航 + 单工作区里**没有任何进入既往检查的入口**。随访对比（甲状腺 6 个月复查）是高频刚需，入口不能只写在产物清单里。 | P1-13 |
| H | "测量呢？我要量纵横比和血流。" | **v2 通篇没有测量交互**。§2.7 引用了 Imorgon / ACR TI-RADS 的"零转录"机制——但**零转录的前提是先有测量**：医生量完，数值自动落进结构化报告。v2 把自动测量列为 P2 前瞻，却把**手动测量**（cornerstone.js 现成能力）也一起漏了。冻结态的主要内容就是测量。 | P1-12 |

### 3.3 科主任（DEPARTMENT_HEAD）

| # | 视角原话 | 问题 | 严重度 |
|---|---|---|---|
| I | "我要看科室今天的量、阳性率、AI 采纳率、谁的报告压着没签。" | v2 全篇只为 `ULTRASOUND_DOCTOR` 这一条流设计。`DEPARTMENT_HEAD` 是 `auth.py` 里定义的 5 个角色之一，**在 v2 里没有任何界面差异**，连"范围外"都没标。 | P2-16 |

### 3.4 质控人员（QUALITY_CONTROL）

| # | 视角原话 | 问题 | 严重度 |
|---|---|---|---|
| J | "我天天盯的就是那块看板，你把它放在'设置'里？" | §2.3 把质控看板归入"设置"。**对质控人员，看板是主工作面，不是偏好设置。** 把工作面塞进设置项是 IA 错配；同时 §6 又把质控看板标为"要么接真实接口、要么下线"，两处口径也不一致。 | P1-8 |

### 3.5 系统管理员（SYSTEM_ADMIN）

| # | 视角原话 | 问题 | 严重度 |
|---|---|---|---|
| K | "主链第一步是设备注册，那我可以点哪儿？" | §1.1 把"设备注册(admin)"画成主链第 0 步，但 v2 **没有任何设备管理入口或界面描述**，"按角色出现在设置内"对设备列表 / 在线状态 / 证书 / 注册停用这些内容不成立。 | P1-8（同上） |

### 3.6 患者与陪诊者（v2 完全遗漏的一类人）

> 这一条是 v2 最严重的盲区，也是"多角色视角"最该抓出来的东西：**检查时诊室里不只有医生。**

| # | 场景 | 问题 | 严重度 |
|---|---|---|---|
| L | 医生刚把探头放上，屏幕上滑出「恶性风险：高 · 建议穿刺」，患者和家属就坐在床边看着这块屏。 | **缺"诊室可见性"规则。** ① AI 结论（尤其恶性风险分级、鉴别诊断）**当着患者面裸出**，而医生尚未开口 → 直接制造医患沟通事故与心理伤害；② 切换患者时上一位患者的姓名、影像、结论**零残留规则未定义**（隐私）。这不是"体验问题"，是临床风险。需要：切患者即清屏 + 结论区默认**仅医生可见**（或一键遮蔽）+ 敏感分级值不进入"可见态"。 | **P0-4** |
| M | "这个报告我该跟病人怎么讲？" | 13-文档 M10 明确要求"患者解释话术"，v2 §1.3 也把它列为产物，但**没有任何面向患者的显示态**（大字、无术语、不裸出风险分级裸值）。产物列了，界面没接。 | P2-18 |

## 4. P0–P2 问题清单（带位置与修法）

### P0（致命 · 进画前必须解决）

| 编号 | 位置 | 问题 | 修复建议 |
| :--- | :--- | :--- | :--- |
| **P0-1** | §5.1 冻结即判读 | 无条件逐帧触发 A 级判读，无去重 / 无合并 / 无上限。一例检查可产出数十条结论卡，制造成本灾难 + 新形态告警疲劳。 | 判读请求**以"部位"为去重单位**：同一部位在时间窗内（建议 30–60s）只保留**最新一次**结论，静默替换而非追加；**结论卡全局只有一张**，按部位切换内容，不做竖向堆叠。同时明确"常规存图不触发判读"（Freeze 与 Store 是超声机上的两个键）。 |
| **P0-2** | §2.4 阶段 2 ↔ §5.1 | "影像上缩"与"不打断"自相矛盾。结论卡出现即重排画面，而医生此时正在盯影像。 | **结论区改为常驻预留区**（三态：空态 / 等待态 / 结论态），影像区尺寸在三个阶段**恒定不变**。需要更大影像时用**显式的全屏切换**，而不是被结论卡挤。 |
| **P0-3** | §2.4 整节 | 三阶段状态机缺失：判读中再冻结？继续扫查后结论卡去哪？切部位时旧结论保留吗？ | 把"阶段"重定义为**视图状态**而非单向步骤：`扫查态 ⇄ 判读态`可反复切换，回扫查态时结论卡**收为结论区内的静默状态**（不消失、不弹动）。报告作为**可随时唤起的侧面板**，不是终点站。附一张状态迁移表。 |
| **P0-4** | §2.4 / §3.1 整节 | 诊室有患者与陪诊者在场；AI 结论裸出造成医患沟通风险；切患者零残留未定义。 | 新增"诊室可见性"规则：① 切换患者立即清屏（姓名 / 影像 / 结论）；② 结论区默认**仅医生可见**（首展需一次显式展开，或默认遮蔽敏感分级值）；③ 提供"患者可见态"。 |
| **P0-5** | §4.1 引用 ↔ §5.2 自述 | 引用了 IEC 60601-1-8"报警触发→显示 ≤2s"，但 §5.2 自己写"超过 P99 基线 4.8s"。**引用了一个本系统兑现不了的时限**——本文档将用于 NMPA 可用性工程材料，这属于可被审查抓住的失真。 | 收窄适用范围：≤2s 只约束**本机系统故障 / 连接中断类提示**（本地可兑现）；AI 结论到达**不设时限**，只承诺"真实阶段展示 + 超基线显式声明"。标准引用必须落在能兑现的地方。 |

### P1（重要）

| 编号 | 位置 | 问题 | 修复建议 |
| :--- | :--- | :--- | :--- |
| ~~P1-6~~ **已关闭（v5）** | §4.2 语义色 | **原问题**：红与橙色盲下不可分，却承担最需区分的两级。**v5 已把语义色降为两级**（停=红实心 / 看一眼=中性青灰 / 正常不渲染），**橙被移除 → 红橙配对不复存在，问题消解**。 | 无需动作，保留记录。附带结论：红对深色卡片仅 1.98:1，**故红必须保持实心**、不得改描边。 |
| P1-7 | §4.3 主题规则 | "检查工作区默认深色、工作列表默认浅色"→ 同一台机器在两个页面间来回切主题，**反复破坏暗适应**（阅片室正是暗环境）。 | 主题跟随**设备**一次设置，不按页面分默认。影像渲染区固定深色底这条保持不变。 |
| P1-8 | §2.3 一级导航 | 把**质控看板**（质控人员的主工作面）、**设备运维**（管理员的主工作面）、知识库全塞进"设置"。对这两类角色是 IA 错配。 | 拆开：`设置`只放个人 / 系统偏好；质控与运维按角色出现为**独立工作面入口**（非医生导航位）。若本轮不做，**显式标注"范围外 + 后续工作面名称"**。 |
| P1-9 | §2.3 工作列表 | 列表页以"当前检查"为默认视图；多会话时"一键继续"未定义选谁。 | 工作列表**就是列表**；进行中会话置顶为一行 + 行内"继续"。多会话时按最近活动排序，不用猜。 |
| P1-10 | §2.5 部位指示条 | "极细"却要承载 4 状态；"需复核"是安全信息被压缩到最弱视觉层。 | 指示条只做二值 + 计数（已扫 / 未扫）；**"需复核 / 漏项"升为条上的可点警示点**，点击展开明细。安全信息不得藏在最弱层。 |

| P1-12 | §2.7 / 全文 | 测量交互整体缺失。零转录的前提是先有测量。 | 冻结态以**手动测量为主要交互**（cornerstone.js 已有能力），测量值自动落入结构化报告——这才是 v2 引用 Imorgon 时真正该兑现的机制。 |
| P1-13 | §3.2 产物清单 | `compared_with_prior` 并排对比无入口。 | 影像区 / 结论区提供"与上次对比"一键，载入并排视图。 |
| P1-14 | §5.3 复核门槛 | 只有"严重幻觉"要求勾选核验。**automation bias 的主要风险是医生不假思索接受**，而 v2 的零摩擦设计恰恰强化它。 | 增加一条"依赖度门槛"：当签发内容**未经任何人工修改**且 AI 结论置信度低 / 触发复核标记时，要求一次"已核验"确认。注意与告警疲劳的平衡——只在低置信 + 零修改这个交集触发。 |
| P1-15 | 全文缺节 | 字体 / 字号层级 / 行高 / **测量数值等宽** 全部未定义。 | 新增排版小节；明确测量值与置信度数字使用 tabular numerals。 |

## 7. 总结建议

**先改哪一块**：**P0-1 + P0-2 + P0-3 是一组**，它们共同指向同一件事——v2 把"阶段"当成了不可逆的流程步骤，而真实检查是一个**循环**。把"阶段"改写成"视图状态"，去重规则和布局稳定性就都有地方放了。**这一组不改，画布稿画出来一定是错的。**

**该肯定的地方**：色值来自 ISO / IEC 而不是自创、"取消暗室模式这个概念本身"这类**通过删除概念来消除问题**的手法（§7-C5）、以及把 5 个议题压成 1 个校验点的判断——这三处是这份设计真正的价值，后续版本不要丢掉。

**下一步**：四项分叉已裁定并合入 v3（§6）。但本文所有**像素相关**结论（布局、对比度、字体、控件）都还没验证——**必须先有一份画布稿**。建议把 v3 落成画布稿后再跑一次像素级走查：那时才能说"对比度达标"，也才能核对 §4.7 的字号层级与等宽数字是否真的生效。

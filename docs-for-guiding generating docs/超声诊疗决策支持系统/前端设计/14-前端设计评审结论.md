### 0.1 设计准绳（v4 · 治理原则）

> 用户原则：**医生作为用户群体，系统应当只给他们想要看到的东西。越清晰越简洁越好，越少操作越好。**

三条可观测准绳：

| # | 准绳 | 判定标准 |
|---|---|---|
| **P1** | **默认沉默** | 元素只有在「缺了它医生会做错」时才默认可见；其余**不渲染**（不是折叠、不是灰掉） |
| **P2** | **一次决策** | 任何时刻医生**只需做一个决定**；出现两个并列待选动作即判定设计失败 |
| **P3** | **按打扰总量记账** | 「操作少」= 被打断次数 × 解除成本，**不是元素个数**。为减少打断而增加按键，算减法 |

**凡「某元素显不显示、什么条件下显示」的问题，一律以 [17-医生侧展示契约](./17-医生侧展示契约.md) 为准**——本文解释"为什么"，17-文档裁决"显示什么"。

**本次准绳直接推翻的 v3 条目**（已由 17-文档 §1 裁决）：

| 被削减项 | v3 | v4 |
|---|---|---|
| 常驻条三元素 | 患者/同意/连接**全常显** | 患者常显；**同意与连接仅异常时出现** |
| TTL 倒计时 | 常驻条持续显示 | **删除常驻**，仅 ≤5min 一次性提示 |
| 部位指示条与标签排 | 常驻 | **仅部位数 ≥ 2 时**渲染 |
| 报告状态行 | 常显 | **仅非 `draft` 时**出现 |
| 确认动作区 | 常驻功能区 | **仅存在待确认项时**出现 |
| 进度表达 | **5–6 个内部阶段名** | **「分析中」→「已完成」两个词**（见 §5.2 修订） |
| 路由档位 / 六阶段耗时明细 / 模型版本 | 折叠区可见 | **删除**（医生不想要） |
| 患者可见态 | 独立第二套呈现 | **删除**，改为结论区「遮蔽／临时显示」开关 |
| AI 层标记 | 全局统一标记 | **仅未确认时标记**；确认后消失 |
| 语义色 | **四级**（含绿=正常） | **两级 ＋ 默认无标记**（v5 重判）：「停」红 / 「看一眼」中性青灰 / 正常**不渲染**；**绿搬到质控／管理面**；见 §4.2 修订 |
| 报告生成 | 医生需唤起 | 后台**预生成**，取消该操作（需后端配合） |

**不可削减的三条边界**（17-文档 §4）：禁忌命中的强制勾选 · 签发前的依赖度核验 · 诊室可见性默认遮蔽。三者增加的那一次操作，换来的是"其他所有提示都可以被信任"。

**准绳项裁定（已锁定 · 17-文档 §5）**：进度表达 → **2 个词**（分析中 / 已完成）· AI 层标记 → **确认后消失** · 语义色 → **两级 ＋ 默认无标记**（v5 复盘重判：绿不是颜色档，是另一类问题，故移至质控／管理面）· `/diagnosis` 独立页 → **删除**，其 `LoadingPhase` / `useProgressiveDiagnosis` / `reviewAcknowledged` 三项能力迁入工作区结论区。

## 1. 业务流程与产物现状

### 1.1 端到端主链

```
设备注册(admin) → 建检查会话(同意校验/TTL 7200s)
  → DICOM 进入(REST /imaging/dicom/upload|stream ＋ WS /realtime/dicom)
  → 语音/文本(ASR ＋ POST /voice/confirm)
  → POST /diagnosis/request（幂等、落库 processing）
  → 管线：路由判定 → 专科智能体(RAG) → 融合(冲突/一致性/Self-RAG/CRAG)
          → SafetyGateway 六阶段校验
  → 落库 ＋ WS 推送 → GET /diagnosis/result/{id}
  → 反馈(L2/L3) → 报告(draft → HSM 签名 → PACS 推送) → FHIR 对外
旁路：质控与运维看板 · 审计哈希链 · 多器官并发编排
```

**证据**：路由注册 `app/main.py:535-551`；管线编排 `app/services/diagnosis_pipeline.py:113-238`；worker 池 `app/services/diagnosis_worker.py:160-232`。

### 1.2 角色模型

`app/security/auth.py:139-153` 仅定义 5 个角色：`ULTRASOUND_DOCTOR` / `EMERGENCY_DOCTOR` / `DEPARTMENT_HEAD` / `QUALITY_CONTROL` / `SYSTEM_ADMIN`。

- **不存在"患者"角色**——患者是数据主体（`Patient` 表、FHIR `Patient` 资源、同意对象），非登录用户。**但患者坐在诊室里，是屏幕的被动观看者**——见 §2.8。
- **不存在独立的"报告医师 / 审核医师"**——审核靠权限 `review_l3` ＋ 反馈 L3 级别表达（`app/security/auth.py:150-151`；`app/api/v1/feedback.py:51-55`）。
- **业务主链路普遍只校验"已登录"**：`diagnosis.py:80`、`report.py:86`、`imaging.py:136`、`feedback.py:34` 均为 `Depends(get_current_active_user)`，**报告签发与 PACS 推送不限角色**。

> **v2 修正**：v1 把这条判为"架构议题"，前提是"界面要按角色分"。**该前提是错的**——单一工作区不需要角色专属界面，角色差异只落在 2–3 个动作的可否上。见 §7。

## 2. 模块一：交互模型与信息架构

### 2.1 核心原则：一次检查内部是**循环**，检查之间才是直线

医生跨检查的节奏是一条直线：`看列表 → 叫下一个 → … → 签发 → 下一个`。
但**一次检查内部**是一条**环路**：

```
扫查 ⇄ 冻结判读        （一例检查内重复十几次）
   ↓ 收尾
报告 → 签发
```

**中间任何一次跳页都是打断**，因此采用**单工作区**：影像始终占主，"判读"从影像下方/侧边生长出来，报告随需唤起。**不设多页面导航。**

> **v3 修正**：v2 用"阶段 1 → 2 → 3 垂直推进"描述这个环路，把它写成了**不可逆的线性流程**，于是"回到扫查态后结论卡去哪"无人定义（15-文档 P0-3）。v3 把"阶段"重定义为**视图状态**。

### 2.2 v1 的 9 处习惯违背（自查记录）

| # | v1 设计 | 违背了什么 | v3 修正 |
|---|---|---|---|
| 1 | 建会话时要求**声明检查部位** | 超声是操作者驱动、边扫边定；事前声明是放射科 CT/MRI 的思维 | 默认预选 ＋ 自动补全（§2.5） |
| 2 | **报告**是独立一级导航 | 报告是检查的收尾动作，不是目的地 | 报告侧面板（§2.7） |
| 3 | **审核**是固定一级导航 | 基层多为 1–3 人、多数无审核岗 | 降为工作列表筛选。**审核工作台本轮不交付**——分级审核需要队列 / 意见回写 / 退回 / 双签，**不是"筛选 + 按钮文案差异"能替代的**，v2 那句表述属**失真**，v3 改为诚实标注范围外 |
| 4 | **队列**作为主要入口 | 基层单人单机，队列常年为空；空页面即噪音 | 降为工作列表的默认筛选 |
| 5 | 要医生**主动发起** AI 诊断 | AI 应如导航一样后台常跑 | 导航级全自动；判读由"冻结"自然触发（§5.1） |
| 6 | 一级界面出现**置信度 / 一致性 / Self-RAG** | 不是医生的语言 | 一级只给：一句话结论 · 恶性风险 · 建议动作 |
| 7 | 要求医生**区分告警强度** | 医生不会区分"软警告 vs 被动信息"（即「**看一眼**」档的两类原因），只会全部忽略 | 只有禁忌命中会打断（§5.5） |
| 8 | **三区并置常驻** | 超声基本单屏，扫查时目不转睛盯影像 | 单列为主体，影像恒定占主（§2.4） |
| 9 | 语音"**回读 ＋ 确认词 ＋ 脚踏**"三重 | 基层可能无脚踏硬件；三重机制即三重负担 | 回读 ＋ **一个**确认动作（三选一）（§5.6） |

### 2.3 一级导航：2 项

`工作列表` · `设置`

- **工作列表就是列表**：进行中的会话**置顶为一行** ＋ 行内「继续」；多个进行中会话按最近活动排序。**不把"当前检查"做成列表页的默认视图**——那会让医生打开系统时分不清自己在列表还是在详情（15-文档 P1-9）。
- **检查工作区以"下钻"形式进入**，不占导航位。导航项越少，迷路概率越低。
- **`设置` 只放个人 / 系统偏好**（主题、语音、脚踏、默认部位预设、快捷键）。**质控看板 / 设备运维 / 知识库不进设置**——它们是工作面，按角色出现为独立入口位（本轮不交付界面，见 §0）。

> **候诊队列**（分诊 + 叫号 + 诊室分配）标为**设计前瞻**：后端 `app/api/v1/` 无 worklist/queue/call 任何端点。**不做视觉上的空壳**。
>
> **患者时间轴**（报告 / 既往对比 / 复核）不需要独立导航位：它由**报告侧面板**（§2.7）和**既往对比入口**（§3.2）承载。依据：`sessions` 挂 `patient_id`、consent 以 `patient_id` 为键，而 DICOM/导航/诊断以 `session_id` 为键——实时场景天然是会话轴，档案场景天然是患者轴；**但"轴"是数据组织方式，不必都变成导航项**。

### 2.4 检查工作区：循环 ＋ 恒定布局

```
┌────────────────────────────────────────────────────┐
│ 病人 · 同意状态 · 连接状态            （极窄常驻条） │
├────────────────────────────────────────────────────┤
│                                                    │
│   影像区（尺寸恒定，不因任何面板出现而缩放）          │
│   · 扫查态：全屏 ＋ AI 导航标注自动叠加              │
│   · 冻结态：停帧 ＋ 测量工具就位（§2.4.2）           │
│                                                    │
├────────────────────────────────────────────────────┤
│   结论区（常驻预留，三态：空态 / 等待态 / 结论态）    │
│   · 一句话结论 · 恶性风险分级 · 建议动作             │
│   · 展开：依据 → 鉴别 → AI 过程                     │
│   · **默认仅医生可见**（§2.8）                       │
├────────────────────────────────────────────────────┤
│ 确认动作区（仅待确认时出现）：语音/大按钮/脚踏 三选一  │
└────────────────────────────────────────────────────┘
    报告侧面板：右侧滑出，随时唤起，可钉住
```

**2.4.1 布局稳定性（硬规则）**

- 结论区是**常驻预留区**，影像区尺寸在扫查 / 冻结 / 判读 / 报告四种状态下**恒定不变**；
- 结论卡出现**不得引发画面重排**——v2 的"影像上缩"与"不打断"不能同时成立；
- 需要更大影像时用**显式全屏切换**，而不是被结论卡挤出。

**2.4.2 冻结态 = 测量态**

冻结后的主要内容是**测量**（纵横比、三维径线、血流参数）。测量值**自动落入结构化报告**——这才是"零转录"真正该兑现的机制（§2.7）。自动测量列为前瞻（§6-P2），**手动测量是现有能力**（cornerstone.js）。

**2.4.3 状态迁移表**

| 当前 | 触发 | 转移到 | 结论区表现 |
|---|---|---|---|
| 扫查态 | **冻结**（Freeze） | 判读态 | 空态 → 等待态（显示「分析中」） |
| 扫查态 | **存图**（Store，新增静默键） | 扫查态 | **不变**（不触发判读） |
| 扫查态 | **存图并分析** | 判读态 | 空态 → 等待态 |
| 判读态 | 解冻 / 继续扫查 | 扫查态 | **收为静默状态**（保留、不消失、不弹动） |
| 判读态 | 再次冻结（**同部位**） | 判读态 | 静默**替换**为新结论 |
| 判读态 | 再次冻结（**异部位**） | 判读态 | 切换为该部位结论；旧结论可回看 |
| 判读态 | 唤起报告面板 | 判读态 ＋ 报告面板 | 不变 |
| 报告面板 | 签发 | 报告面板（已签发） | 出现「下一个病人」 |
| 任一 | 切换患者 | 冷启动 | **清屏**（§2.8） |

### 2.5 检查部位：默认预选 ＋ 自动补全

- 建会话时**默认选中上次 / 最常用部位预设**（类比超声机的检查预设），医生通常一键即可，**不增加强制步骤**；
- 系统再把**实际扫描到的部位自动补入**，作为"补全"而非"替代"——保持显式声明为主，避免纯推断带来的不安全因素；
- 表达形式：影像下方一条**极细部位指示条**——**仅 `target_organs` 数 ≥ 2 时渲染**（单部位不出现），见 [17-§1](./17-医生侧展示契约.md)。

> **指示条只承载二值 ＋ 计数**（已扫 n / 未扫 m）。**"需复核 / 漏项"不得压在极细条里**——它是安全信息，升为条上一个**可点的警示点**，点击展开明细（15-文档 P1-10）。
>
> 依据：`POST /diagnosis/multi-organ` 返回 `organ_statuses`（completed/failed/skipped/partial），WS 推 `organ_switching`；13-文档 M1 要求提示"【器官】缺少【切面类型】切面"。可迁移范式：GE Venue 的"解剖示意图按区域存图 ＋ 单键记录"。

### 2.6 多部位场景

进入判读态后，结论卡上方为一排**部位标签**（含各自状态），承担"进度总览"职责；当前部位的结论在下方展开。**仅部位数 ≥ 2 时出现**（单部位不渲染）。**不做独立的进度页面。**

### 2.7 报告与既往：侧面板，不跳页

- 报告以**右侧滑出面板**形式随时唤起（可钉住），**不是流程终点站**；
- AI 草稿已填好所见与印象，走现有 `report.content` JSONB（`app/models/database.py:79-124`；`app/services/report_service.py:136-184`）；
- "改哪句点哪句"＝字段级就地编辑；需要逐项核对时切"结构化校对"模式，借用 ACR TI-RADS 集成 CDS 的成熟机制：**无关段落自动折叠、只显示已填写的项、每选一项即时更新所见与印象、零转录步骤**（Imorgon / ACR TI-RADS 实践；Duke 结构化报告研究：自动化模板下无一名读者犯错，耗时不劣化，医生主观偏好且负担更低）；
- **测量值自动进入草稿**（§2.4.2），这是"零转录"的入口。

### 2.8 诊室可见性（v3 新增）

> 这一节补的是 v2 最严重的盲区：**检查时诊室里不只有医生**，还有患者、家属、陪诊。屏幕上滑出"恶性风险：高 · 建议穿刺"，而医生还没来得及开口——这不是体验问题，是**医患沟通事故与心理伤害**。

## 4. 模块三：视觉风格与语义色体系

### 4.1 颜色服从标准，不自创

临床医生整个职业生涯被医疗安全色约定所训练，偏离即主动制造 use error。

**ISO 3864-4 / 3864-2（安全色与风险等级）**：

| 语义 | 色值 | 含义 |
|---|---|---|
| 高风险 `DANGER` | `#9B2423` 红 / 白字 | 高风险 |
| 中风险 `WARNING` | `#D05D29` 橙 / 黑字 | 警告 |
| 低风险 `CAUTION` | `#F9A900` 黄 / 黑字 | 注意 |
| 强制遵守 | `#005387` 蓝 | 必须执行 |
| 安全状态 | `#237F52` 绿 | 安全 / 正常 |

**IEC 60601-1-8（报警系统）——颜色 ＋ 闪烁频率**：

| 优先级 | 颜色 | 闪烁 |
|---|---|---|
| 高 | 红 | 1.5–3.0 Hz，须覆盖其他非关键界面 |
| 中 | 黄 | 0.5–1.0 Hz |
| 低 | **青或黄** | **常亮，不闪烁** |

配套硬数字：报警触发→显示 **≤ 2s**；触摸操作视觉反馈 **≤ 100ms**；强光下关键参数对比度 **≥ 3:1**；**严禁红/绿配色组合**（色盲兼容）。

> 诚实说明：本软件不是 ME 设备的报警系统，IEC 60601-1-8 严格而言不直接适用。采用其约定是**可用性资产**，不是合规负担。
>
> **适用范围收窄（v3）**：上表"报警触发→显示 **≤ 2s**"**只约束本机系统故障 / 连接中断类提示**（本地可兑现）。**AI 结论到达不设时限**——本系统为 Web ＋ WebSocket ＋ 服务端六阶段推理，§5.2 自述基线已达 4.8s。**引用一个兑现不了的时限，会在可用性工程审查中被抓住**；标准引用必须落在能兑现的地方。

### 4.2 两级语义色 ＋ 默认无标记（v5 修订）

**颜色只回答一个问题：这件事要不要我停下手？** 三档（两色 ＋ 一个默认态）：

| 档 | 含义 | 触发信号 | 表现 |
|---|---|---|---|
| **停** | 必须处理，**挡住动作** | 禁忌命中、`conclusion_suppressed`、同意撤回、严重幻觉 | 红 `#9B2423` 实心 ＋ 白字 ＋ 图标 ＋ 覆盖式提示；一次性声光；**不持续闪烁** |
| **看一眼** | 需要留意，**不挡动作** | `requires_manual_review`、不确定、降级模式、KB 过期、低置信、AI 不可用、Self-RAG 未过 | 中性青灰描边 ＋ 图标 ＋ **文字标签写明原因**；静态，常亮不闪烁 |
| **不用管** | 一切正常 | 校验通过、质控达标 | **不渲染任何颜色** |

**色值定义（v5 补充，R-03）**——原文只给 ISO 五色值，「中性青灰」「深色底」为形容词，不可实现。以下为按 WCAG 相对亮度算法**计算得出**的取值（比值见括号），**最终须在画布上实测复核**：

| Token | 深色主题 | 浅色主题 |
|---|---|---|
| 工作区背景 | `#1B1E23` | `#F7F8FA` |
| 卡片 / 容器（比背景更亮） | `#24282F` | `#FFFFFF` |
| 正文 | `#E6E8EB`（13.6:1） | `#1F2937`（14.7:1） |
| 次要文字 | `#A8AEB6`（8.0:1） | `#5A6673`（5.9:1） |
| **影像渲染区底** | `#15171B`（固定，不参与主题切换；**禁用 `#000000`**——散光光晕） | 同左 |
| **语义·停（红）** | `#9B2423` ＋ 白字 `#FFFFFF`（7.9:1） | 同左 |
| **语义·看一眼（青灰）** | `#8C99A6`（对卡片 5.4:1 / 对背景 5.8:1） | `#5A6673`（对白 5.9:1） |

> ⚠️ **红不得改为描边**：`#9B2423` 对深色卡片仅 **1.98:1**，作描边不达 UI 组件 3:1 门槛；因此「停」档**必须保持实心填充 ＋ 白字**——这条约束同时是可达性结论，不只是视觉偏好。

- **「软警告（橙）」与「不确定（青灰）」合并**：二者在**医生要做什么**上完全一致（看一眼，不挡我）；差别只在**原因**（质量类 / 不确定性），而**原因属于文字、不属于颜色**。详见 [17-文档 §2](./17-医生侧展示契约.md)。
- **绿从医生主链移出（v5 修订）**：绿承载的是"**这一项被确认过了**"——**它不是第四个颜色档，而是另一个问题**。「已确认」改用**图标 ＋ 文字**（`✓ 已核验`）。**质控 / 管理面保留绿 = 达标**（那里"主动宣告达标"是真实需求，且不受 §0.1 P1 约束）。→ **ISO 3864 的绿没有丢，只是搬到了它被需要的地方。**
- **不得只靠颜色承载语义（v3 硬规则，保留）**：红 = 实心填充 ＋ 白字 ＋ 图标 ＋ 覆盖式提示；青灰 = 描边 ＋ 图标 ＋ 文字标签。**颜色永远只是辅助通道。**
- **`08-文档 A6` 红绿配对**：医生主链不再出现绿 → **在医生侧消解**，无需四段冗余编码；**但该约束随绿一起搬到质控 / 管理面**，在那一面内仍需避免绿与红同屏对照。
- **顺带减少的工作量**：17-文档 §1 的 30 个元素若维持四级，每个都要额外定义绿色变体；"正常 = 不渲染"直接归零，并少一类需在可用性工程中说明用途的视觉状态。

### 4.3 主题：跟随设备，不跟随页面（v3 修订）

| 规则 | 内容 |
|---|---|
| **DICOM 影像渲染区** | 固定中对比度深色底，**不参与任何主题切换**（硬规范） |
| **界面外壳** | 跟随**设备级**一次「浅色 / 深色」设置；**检查工作区默认深色** |

> **v3 修订理由**：v2 的"检查台默认深色 / 工作列表默认浅色"是**按页面**分默认——同一台机器在两个页面间来回切主题，会**反复破坏暗适应**（阅片室正是暗环境）。改为设备级一次设置。
>
> - **必须用中对比度，不得用纯黑**：纯黑背景会让散光人群产生**光晕（halation）**；采用 off-white 文字 ＋ dark grey 背景（NHS Digital 乳腺筛查阅片系统设计史）。
> - 卡片 / 容器要比背景**更亮**，不是更暗（Google Material）。
> - **v2 修正保留**：v1 的"暗室模式"概念已取消，因而不再需要额外写一条"禁止作用于影像区"的限制——概念消失，问题消失（§7-C5）。

### 4.4 双度量编码：把"我有多确定"与"病有多危险"从形状上分开

| 度量 | 语义 | 视觉通道 | 层级 |
|---|---|---|---|
| 恶性概率 `malignancy_risk` | 疾病的恶性风险 | **分级标签 ＋ 风险区间** | 一级 |
| AI 置信度 `confidence` | AI 对自身结论的把握度 | **区间带 / 刻度尺** | 二级（折叠） |

- 不使用两个并列的百分比数字（极易被读成同一件事）；
- 不靠颜色单独承载语义；
- 数值必须配人话（"高于典型""需要复核"），而非裸浮点数。

> 依据：医疗 AI 研究中"**必须把严重度与置信度分开，这是最重要的设计选择之一，也最容易做错**"；"72% 的风险值配上『高于典型』『需要复核』比裸浮点数有用得多"；不确定性使用秒级可解析的编码（置信区间带 / 校准徽章 / 百分位区间），而非密集统计图。

### 4.5 AI 视觉身份

「**AI 层**」视觉语言：固定底色 ＋ 左侧竖线 ＋ 统一图标，**只在结论卡上出现**（影像上的标注属导航层，非 AI 结论，不贴同一标识）；人工内容不带任何标记。**v4 修订：仅「未经医生确认」时标记；医生确认或修改后标记消失**——同时满足简洁与防 automation bias。

> 依据：研究要求"AI 生成的结果必须与人工报告视觉上明确可分"；只有可分，审计追溯在界面上才成立。

### 4.6 人体工学约束（可量化）

超声技师是影像科**身体损伤率最高的人群（>90%）**，三大风险为握持捏力、下压力、**肩外展 >30°**。

- 所有高频操作必须落在**身体正前方、单手可达区**，不得要求跨屏伸手；
- 屏幕顶边与视线齐平或略低（俯视 15–20°），距约 60cm；
- 高频调节走物理键 / 脚踏，虚拟键只承接非紧急与复杂设置；
- 命中区与字号按"基层 ＋ 手套 ＋ 深色环境"取值，不小于通用桌面密度。

> 环境照度参考 ACR / AAPM：25–75 lux，**不要全黑**。

### 4.7 排版（v3 新增）

| 项 | 规定 |
|---|---|
| 字体族 | 中文正文用系统无衬线（思源黑体 / HarmonyOS Sans / PingFang SC 按平台回退）；西文与数字用 Inter。**不用衬线 / 装饰字体。** |
| 字号层级 | 一句话结论 20px / `"600"`；分级标签 14px / `"600"`；正文 14px / `"400"`；辅助 12px / `"400"` |

| **数字等宽** | 所有可比较数值——**测量值、置信度、耗时、风险区间端点**——必须使用 **tabular numerals 且右对齐**。否则 `3.2mm ↔ 3.7mm` 的行内跳动会干扰逐次比对 |
| 术语 | 与 `00a-术语表` 对齐；**"判读 / 复核 / 校验"三词不得混用**（分别指冻结触发、AI 建议人工复核、SafetyGateway 校验） |

### 4.8 栅格与间距（v5 新增 · R-15）

原文有 30 个元素的展示条件，却无间距 / 尺寸 token——元件间距无法统一。规定：

| 项 | 值 |
|---|---|
| 基准栅格 | **4px**（最小单位）；布局间距取 **8 的倍数** |
| 间距阶梯 | `4 / 8 / 12 / 16 / 24 / 32 / 48`，不得出现阶梯外的值 |
| 圆角 | 标签 4 · 卡片 8 · 面板 12 · 全屏容器 0 |
| 描边 | 常规 1px；「看一眼」档 1.5px |
| 结论卡内边距 | 16 |
| 常驻条高度 | 40（内容不足时不得压缩低于 32） |
| 命中区 | **≥ 44×44**（§4.6：按"基层 ＋ 手套 ＋ 深色环境"取值，不小于通用桌面密度） |
| 影像区 / 结论区高度比 | 结论区**常驻预留**，影像区尺寸恒定（§2.4.1）；默认 **7 : 3** |

## 5. 模块四：关键交互

### 5.1 判读触发：冻结即判读 ＋ 按部位去重

医生的自然动作是"看到可疑 → 冻结 → 存图"，这是超声医生的肌肉记忆。因此：**医生一冻结当前帧，系统自动对该帧发起判读。**

- **零新增动作**，不需要"发起诊断"这个步骤；
- 冻结帧 = 一张确定的图像，**审计锚点最清晰**（优于对实时流发起判读）；
- 结论卡从影像下方生长出来，**不打断**——医生可以继续扫查，回头再看。

**去重规则（v3 新增，硬规则）**

- **判读请求以"部位"为去重单位**：同一部位在时间窗内（建议 30–60s）只保留**最新一次**结论，静默**替换**而非追加；
- **结论卡全局只有一张**，按部位切换内容，**不做竖向堆叠**；
- 理由：一例检查冻结数十次是常态。若无去重，一例检查会产出数十条结论卡——这既是后端成本灾难（每条都走完整六阶段链路），更是**新形态的告警疲劳**，而且由系统自动产生，医生连"拒绝触发"的机会都没有。**这会直接抵消 §5.5 的全部论证**（15-文档 P0-1）。

**存图与判读分离（v3 新增）**

- `冻结`（Freeze）→ 触发判读；
- `存图`（Store）→ **只留证，静默，不触发**；
- `存图并分析`（Store & Analyze）→ 显式触发；
- 依据：超声机上 Freeze 与 Store 本就是两个键，拆分能一次性削掉大半无效判读请求。

> 保留 A 级显式触发点的必要性：A 级结论须经完整校验链路并逐条审计，不能对实时流无差别触发（13-文档 M2 亦明确快速路径不输出 A 级）。"冻结"是既符合习惯、又天然受医生控制的触发点。

### 5.2 等待体验：无假进度

只显示**两个词：「分析中」→「已完成」**（v4 削减：医生不需要内部阶段名）；**不显示百分比、不显示预计剩余时间**；未完成阶段静态中性灰，不做填充动画；超过 P99 基线时**显式声明**（"本次耗时 6.2s，已超基线 4.8s"）；全程保留"继续扫查 / 先写报告"的出口。

> **依据（v3.1 核定后改写）**：前端 `diagnosisService.ts:26-90` 已把"预计阶段"与真实值显式分开——`resolveStage()` 恒返回 `estimated: true`，注释明确写"不得伪装成真实遥测"；真实值另由 `extractStageTimings()`（`:108-123`）读取。**故风险在于 UI 是否遵守 `estimated` 标志，而非既有实现说谎**——原文"属静默失真"的定性过重，已推翻（见 [16-报告 §X-01](./16-设计依据代码核定报告.md)）。
>
> **但"真实阶段展示"的前提需先修（v3.1）**：`TIMING_KEY_MAP`（`diagnosisService.ts:102-106`）只有 3 项且键名对不上——它映射 `'dispatch'`，而后端实际写的是 `dispatcher.invoke_ms`（`diagnosis_pipeline.py:157`）→ **恒取不到**；`reasoning` 阶段无映射，`db_read_ms` / `db_write_ms` 无人读取。
> **6 个阶段中实际只有 `fusion.fuse_ms` / `sg.check_output_ms` / `pipeline.total_ms` 可用。** 故真实阶段展示须先补映射，或先只展示这 3 项。详见 [16-报告 §X-02](./16-设计依据代码核定报告.md)。

### 5.3 复核门槛：分级，不一刀切

| 触发源 | 是否扣签发 |
|---|---|
| 禁忌命中 / `conclusion_suppressed` / 同意撤回 | ✅ 强制勾选"已人工核验"后方可签发 |
| 严重幻觉 | ⚠️ **当前触发不到**：`hallucination_severity` 后端恒 `None`（[16-报告 N-01](./16-设计依据代码核定报告.md)）。字段接通后启用同一规则 |
| 冲突 / 一致性 / Self-RAG / 低置信度 / KB 过期 | ❌ 仅标注 ＋ 审计记录 |

> 依据：一刀切会让"勾选"退化为无意识动作，反而失去安全价值（告警疲劳研究）。
>
> **待确认（15-文档 P1-14）**：建议增设一条"依赖度门槛"——当签发内容**未经任何人工修改**、且 AI 结论低置信度或带复核标记时，要求一次"已核验"确认。这是 automation bias 的主要暴露点，而零摩擦设计恰恰强化它。触发条件必须收窄在"低置信 **且** 零修改"的交集，否则会变成新的告警疲劳。

### 5.4 路径升级：全自动、无弹窗

- 路由**自动升级**，不设确认弹窗；
- 用状态行一行字非阻断告知（"已升级至深度分析，预计约 5s"）；
- 初步结论先到就先展示；如需更深，结论卡上留**自愿**的「继续深度分析」动作（复用现有 `POST /diagnosis/{id}/confirm-upgrade`）；
- **路由档位信息不出现在一级界面**，仅存于「诊断过程」折叠区。

> 推导：医生冻结图像时，意图已包含"要一个判读"。弹窗实为等待时间通知伪装成决策；且确认动作要求医生放下探头或转身触屏（恰是肩外展超 30° 的动作）。按告警疲劳研究，"几乎 100% 会被点『是』的询问"不产生信息，纯粹消耗「**停**」这一档的信用额度。

### 5.5 告警：只有一件事会打断

- **唯一打断式提示 = 禁忌命中**（**「停」档**，一次性声光 ＋ 覆盖式提示）；
- 高风险导航标记：**一次性声光 ＋ 静态高对比框**，之后不持续闪烁；
- 其余一切（复核、降级、置信度、融合层信号）**全部静态**，就地出现在结论卡内，不弹窗、不发声、不闪烁。

> 依据：IEC 60601-1-8 低优先级报警要求常亮不闪烁；统计显示医生驳回 49–96% 的 CDS 告警，"60% 触发率 ＋ 40% 响应 > 100% ＋ 2%"。**减少告警数量本身就是安全改进。**

### 5.6 确认动作：回读 ＋ 一个确认动作

系统**回读**指令 → 医生给出**一个**确认动作，以下三种**等效、任选其一**（不做多重叠加）：

1. 说确认词（"确认"）
2. 点屏幕大按钮
3. 脚踏开关（如医院配置）

导航控制类指令（放大 / 缩小）免确认。确认面板超时自动关闭且**不触发**任何诊断动作。

> 依据：双手占用（探头 ＋ 耦合剂）；肩外展 >30° 压迫肩袖血流；研究要求"主动确认而非被动接受"以避免 automation bias。**脚踏不得为必需项**——基层可能无此硬件。

### 5.7 会话过期与同意撤回

- 剩余 TTL ≤ 5min：**一次性**提示（**v4 删除常驻倒计时**）；过期后**保留已签发报告的查看权**；
- 同意撤回：立即隐藏 AI 入口，在途请求取消，中间结果不展示；前端信任后端 `consent_status_at_output`，不重复查询。

> 依据：`app/api/v1/session.py:22` TTL 7200s；08-文档 §2.2 / §2.6；`app/api/v1/consent.py:25-104`。

### 5.8 状态矩阵（v3 新增）

| 状态 | 触发场景 | 表现 |
|---|---|---|
| 空态 | 尚未冻结 | 结论区显示"等待冻结取图"，不显示占位骨架动画 |
| 等待态 | 判读中 | 真实阶段名逐项点亮；保留出口 |
| 结论态 | 判读完成 | 结论卡（含复核标记 / 降级说明） |
| **AI 不可用** | 连接中断 / SafetyGateway 不可用 / 模型超时 | **中性青灰** ＋ 一句人话说明为什么；**不伪装成"正常结论"**；保留继续扫查与手工写报告的路径 |
| 错误态 | 请求失败 | 显式失败原因 ＋ 重试；**不静默降级** |

## 7. 五个架构议题的消解

**核心认识**：v1 之所以觉得这些是"架构议题"，是因为假设了"界面要按角色 / 按安全等级 / 按模式分"。**重构后这些假设全部不成立，议题随之消解或降级。**

| 议题 | v1 的处境 | v3 的消解路径 | 剩余工程量 |
|---|---|---|---|
| **C1** 报告签发 / 推送无角色限制 | 安全缺口 | 后端 `sign_report` **补一次 `review_l3` 校验** | 一个校验点 |
| **C2** 权限粒度不匹配 5 角色模型 | 架构议题 | 单一工作区**不存在角色专属界面**；角色差异仅落在 2–3 个动作的可否上，而 `app/security/auth.py:148-153` 的 `PERMISSIONS` 已定义完备。前端按服务端返回的权限位把那两三个按钮改为"提交待审"。**不需要任何权限矩阵界面** | 一个条件渲染 |
| **C3** B 级安全分级扩展（B+） | 与 NMPA 声明的三级框架冲突 | **不引入 B+**。高风险导航标记就是 B 级标注的高亮表现，不新增安全等级。13-文档 M2 绕了一圈又改回 B 级，现在把 B+ 概念**彻底删除**，NMPA 三级框架原封不动 | 0 |
| **C4** 可用性工程交付物 | 关键任务多、风险分析面大 | NMPA 要求"活动深度**与使用风险相称**"。v1 的关键任务有 8–10 个；v3 收敛为 **3 个**：① 发起判读（冻结）② 确认 / 修正结论 ③ 签发。形成性评价轮次与总结性评价样本量随之缩小。**界面越简单，注册材料越轻** | 减少而非增加 |
| **C5** 暗色模式污染影像区 | 需要对模式加限制 | **取消"暗室模式"概念**，拆为两条互不相干的规则：影像渲染区固定深色底不参与主题切换；外壳跟随一次（v3 改：**设备级**）浅/深设置。**概念消失，问题消失** | 0 |

唯一有真实工程量的是 **C4**，但方向是**缩小**而非扩大。

> **C4 待确认（15-文档 P1-14）**：关键任务清单目前不含 **"忽略 / 驳回 AI 结论"**。而 automation bias 的风险恰恰集中在"医生不假思索接受"这一侧。建议补为第 4 项关键任务，随之调整形成性 / 总结性评价的样本量口径。**这是减负与安全之间唯一没被消解的张力**，需显式裁定后再写进注册材料。

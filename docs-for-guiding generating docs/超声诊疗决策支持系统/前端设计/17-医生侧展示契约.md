# 医生侧展示契约

> **定位**：这是**规范性**文档，不是评审意见。凡「某个元素在医生界面上显不显示、什么条件下显示」的问题，**以本文为准**——[14-前端设计评审结论](./14-前端设计评审结论.md) 仍负责解释"为什么这么设计"，本文负责裁决"到底显示什么"。
> **适用对象**：`ULTRASOUND_DOCTOR` / `EMERGENCY_DOCTOR` 的检查工作区。质控、科室概览、设备管理是独立工作面，不受本契约约束（见 14-文档 §0）。
> **v4 · 来源**：用户原则 —— 「**医生作为用户群体，系统应当只给他们想要看到的东西。越清晰越简洁越好，越少操作越好**」。

---

## 0. 三条准绳

| # | 准绳 | 判定标准（可观测） |
|---|---|---|
| **P1** | **默认沉默** | 任何元素，只有当「**缺了它医生会做错**」时才默认可见。其余一律**不渲染**——注意是**不渲染**，不是"折叠起来"或"灰掉" |
| **P2** | **一次决策** | 屏幕上任何时刻，医生**只需要做一个决定**。出现两个并列的待选动作，即判定为设计失败 |
| **P3** | **按打扰总量记账** | 「操作少」的度量 = **医生被打断的次数 × 解除打扰的成本**，**不是**元素个数。为减少打断而增加一个按键，算**减法** |

> **P1 的严格读法**：把"缺了会做错"当门槛，而不是"有了更方便"。举例——患者身份必须常显（缺了会在错误的患者身上工作）；而连接状态**正常时不必显**（缺了不会做错，异常时才缺不了）。**默认沉默不是极简主义审美，是让"异常"重新变成信号。**

> **P3 为什么必须先讲**：否则简化会朝错误方向滑。两个反例——
> ① 「冻结（判读）」与「存图（留证）」拆成两个键，元素**变多**了，但一例检查少发十几次无效判读 → 打扰总量大幅下降，**净减法**。
> ② 禁忌命中前的强制勾选，多了一次操作，但换来"勾选"这个动作**可信** → 唯一保留的「**停**」档才有信用，**净减法**。
> **判断标准**：这个改动是让医生**少做判断**，还是只是让他**少看见东西**？前者才算简化。

## 1. 元素展示契约（全量）

**默认态**列的三档含义：`常显` = 恒可见；`条件` = 满足触发条件才**渲染**（不满足则不存在）；`不显` = 不进医生界面。

| 元素 | 默认态 | 触发条件 / 说明 | 相对 v3 的变动 |
|---|---|---|---|
| 患者身份 | **常显** | 防止在错误的患者上工作 | 保留 |
| 同意状态 | **条件** | **仅非 `granted` 时**出现（`withdrawn` / `denied` / `pending`） | v3 为常驻常显 → **改为条件** |
| 连接状态 | **条件** | **仅异常时**出现（断连、安全网关不可用） | v3 为常驻常显 → **改为条件** |
| TTL 剩余 | **条件** | **删除常驻倒计时**；仅剩余 ≤ 5min 时**一次性**提示 | v3 为常驻条提示 → **改为一次性** |
| 实时影像 | **常显** | 主视区；AI 叠加层一键关闭 | 保留 |
| 导航标注 | **常显** | 校验态用线型＋透明度区分（不靠颜色） | 保留 |
| 部位指示条 | **条件** | **仅 `target_organs` 数 ≥ 2 时**出现 | v3 为常驻 → **改为条件** |
| 部位标签排 | **条件** | **仅部位数 ≥ 2 时**出现 | v3 为常驻 → **改为条件** |
| 部位警示点（需复核 / 漏项） | **条件** | 有事件时出现，点击展开明细 | 保留 |
| 一句话结论 | **常显**（结论态） | 结论区主内容 | 保留 |
| 恶性风险分级 | **常显**（结论态） | 分级标签 ＋ 风险区间 | 保留 |
| 建议动作 | **常显**（结论态） | 结论文本内一句话 | 保留 |
| 需复核 ＋ 原因 | **条件** | 有标记时出现；原因人话化，**须带兜底分支**（见 16-报告 M-02） | 保留 |
| 禁忌命中 | **条件** | 命中时**唯一打断式**提示，挡签发 | 保留（**不可削减**） |
| 降级 / 屏蔽 | **条件** | 屏蔽 = 阻断；降级 = 结论区一行 | 保留（**不可削减**） |
| 严重幻觉 | **条件** | ⚠️ 当前后端恒 `None`（16-报告 N-01）→ 需后端映射 | 保留设计，标后端依赖 |
| 报告状态 | **条件** | **仅非 `draft` 时**出现（signed / pushed / failed） | v3 为常显状态行 → **改为条件** |
| 确认动作区 | **条件** | **仅存在待确认项时出现**（超时自关，已有语义） | v3 为常驻功能区 → **改为条件** |
| 进度表达 | **条件** | **仅分析中时出现**；只用 2 个词（见 §3.1） | v3 为 6 阶段名 → **削减** |
| 患者可见态 | **不显** | **删除独立机制**，改为结论区上的「遮蔽 / 临时显示」开关（复用同一组件） | v3 为第二套呈现 → **删除** |
| 证据溯源 | 折叠 | 点击定位原文条目 | 保留 |
| 鉴别诊断 | 折叠 | 排序卡 ＋ 支持/排除征象 | 保留 |
| 既往对比 | 折叠（含入口） | 一键并排 | 保留 |
| 融合层明细 | **不显** | 已收敛为"为什么建议复核"，明细不直出 | 保留收敛形态 |
| AI 置信度 | 折叠 | 区间带 / 刻度尺，与恶性概率形状不同 | 保留 |
| 路由档位 | **不显** | 医生不想要；归审计 | v3 为折叠区一条记录 → **删除** |
| 六阶段耗时 | **不显** | 医生不想要；**仅超基线时**补一句 | v3 为折叠处 → **删除明细** |
| 模型版本 | **不显** | 归审计 | v3 为折叠区 → **删除** |
| KB 版本 | **不显** | **仅 KB 过期时**出现一行提示 | v3 为折叠区 + 变更提示 → **削减** |
| AI 层视觉标记 | **条件** | **仅"未经医生确认"时标记**；医生确认/修改后标记消失 | v3 为全局统一标记 → **改为条件** |

**净结果**：删除 **5 项**展示元素（患者可见态 / 路由档位 / 六阶段耗时明细 / 模型版本 / 常驻 TTL 倒计时）；**6 项由常显改为条件**。
> 「绿 = 正常」**不再用于医生主链**（v5 修订：绿搬到质控／管理面，见 §2）。因此 `08-文档 A6` 的红/绿配对问题**在医生侧自动消解**，无需额外冗余编码。另：进度表达由 5–6 个词降至 **2 个词**（§3.1）；AI 标记改为**确认后消失**；`/diagnosis` 独立页**删除**。

## 2. 语义色：两级 ＋ 默认无标记（v5 修订）

**裁定（用户，复盘后）**：**两级 ＋ 默认无标记**。
> 上一轮用户选了"保留四级"，判定依据是"标准里有的不该丢"——**根因是当时的选项没把差别讲清**（把"绿"当成第四个颜色档去问，而它其实在回答另一个问题）。判别依据补齐后重判，见下。

**差别只有一个：颜色到底在回答哪个问题？**

| 方案 | 颜色回答的问题 | 同一块屏幕上会发生什么 |
|---|---|---|
| 四级 | **混答两个问题**：「要不要停手」＋「是否达标」 | 结论卡顶部一行绿底「校验通过」、影像区一片青灰、另有一处橙。**三个颜色同时在场，却全都不需要动作** → 医生必须逐个读完才知道"都不用管" |
| **两级（采用）** | 只答「**要不要我停下手**」 | 上述三处**都不出现**。屏幕上 **有颜色 ⇔ 有事**，一眼可判 |

**三档语义（两色 ＋ 一个默认态）**：

| 档 | 含义 | 触发 | 表现 |
|---|---|---|---|
| **停**（红 `#9B2423`） | 必须处理，**挡住动作** | 禁忌命中、`conclusion_suppressed`、同意撤回、严重幻觉 | 实心填充 ＋ 白字 ＋ 图标 ＋ 覆盖式；一次性声光 |
| **看一眼**（中性青灰） | 需要留意，**不挡动作** | `requires_manual_review`、不确定、降级、KB 过期、低置信 | 低饱和描边 ＋ 图标 ＋ **文字标签写明原因**；静态 |
| **不用管**（**无标记**） | 一切正常 | 校验通过、质控达标 | **不渲染任何颜色** |

**关键一：为什么把「软警告（橙）」与「不确定（青灰）」合并。**
二者在**医生要做什么**上完全一致——都是"看一眼、不挡我"。它们的差别是**原因**（质量类 / 不确定性），而**原因属于文字，不属于颜色**。合并后"为什么"由文字标签承担，医生不必再做一次"橙和青灰各代表什么"的翻译。

**关键二：「绿」去哪了——它从"颜色档位"搬到了"另一类信息"。**
绿承载的不是"要不要停"，而是"**这一项被确认过了**"。**它不是第四个档，是另一个问题。** 因此：

| 范围 | 绿的处理 |
|---|---|
| **医生主链（检查工作区）** | 「已确认」用 **图标 ＋ 文字**（`✓ 已核验`），**不用绿色** |
| **质控 / 管理面** | **保留绿 = 达标**——那里"主动宣告达标"是真实需求（主任扫一眼要看达标率），且不受 P1 约束（见 14-文档 §0） |

→ **ISO 3864 的绿没有丢，只是搬到了它真正被需要的地方。**

**连带收益（三项）**：

1. **`08-文档 A6` 的红/绿配对冲突自动消解**——医生主链上不再存在绿，无需为四段做冗余编码，也不必再加"红绿不得同屏对照"这条额外约束。
2. **少设计 30 个"正常态"**：§1 契约表里 30 个元素若维持四级，每一个都要额外定义绿色变体；两级方案下"正常 = 不渲染"，直接归零。
3. **注册材料更轻**：可用性工程里每个视觉状态都要能说明用途，"正常 = 无标记"比"正常 = 绿色"更容易说明，也少一类待验证状态。

**冗余编码（两段即可）**：红 = 实心 ＋ 白字 ＋ 图标 ＋ 覆盖式；青灰 = 描边 ＋ 图标 ＋ 文字标签。**颜色永远只是辅助通道。**

> **承重项**：`16-报告 N-01` 指出现有结果接口把一致性/融合/幻觉字段硬编码。**在那些字段真正接通之前，「看一眼」档里的多数触发条件根本不成立**——必须如实标注，不能画饼。

## 3. 削减后的操作路径

### 3.1 进度表达：6 个词 → 2 个词

| | 内容 |
|---|---|
| v3 | 「检索知识库与证据」「专科模型推理中」「融合与一致性校验」「安全网关校验」「生成结论」——5 个内部阶段名 |
| **v4** | **「分析中」→「已完成」**。仅当超过 P99 基线时补一句真话（"本次耗时 6.2s，已超基线 4.8s"） |

**依据（双向）**：
- **医学上**：医生不关心"知识库检索"还是"融合校验"。这些名字是工程语汇，属 §3.3「不呈现给医生」那一类。
- **工程上**：`16-报告 X-02` 已证 6 个埋点里只有 3 个键能被前端取到（且 `dispatcher.invoke_ms` 键名对不上）。**与其修 6 个映射去展示医生不想看的东西，不如只展示 2 个。** 这让"修映射"从必做项降为可选项。

### 3.2 操作数盘点（一次检查）

| # | 操作 | 是否可再省 |
|---|---|---|
| 1 | 打开系统 → 自动进入进行中会话 | — |
| 2 | 冻结 → 自动判读 | 不可省（也是审计锚点） |
| 3 | 存图 | **静默，不计为操作** |
| 4 | 看结论 | — |
| 5 | 语音确认／修正 | **不可省**（防 automation bias） |
| 6 | 唤起报告面板 | ⬇️ **可省，见下** |
| 7 | 改句（若有） | — |
| 8 | 签发 | **不可省**（法律责任节点） |

**可再省一项**：**取消"生成报告"这个动作**——报告草稿应在结论落地后**后台预生成**，医生永远不必请求生成。这需要后端在结果完成时自动触发草稿（`POST /report` 的生成逻辑已有，缺的是自动触发）→ **列入后端配合项**。

**净结果**：一次检查医生只需 **5 个必要操作**：冻结、看、确认、改、签发。**全程没有"让我先想想该点哪儿"的时刻。**

## 4. 不可削减的三条边界

按 P1"缺了会做错"，以下三项**拒绝以简洁为名删减**。它们不是"多给"，而是 P3 口径下的净减法：

| 项 | 为什么不能删 | 若删掉的后果 |
|---|---|---|
| **禁忌命中的强制勾选** | 医学零容忍；且"勾选"是唯一保留的「**停**」档，它的**信用额度**来自稀缺 | 「停」档变成又一个会被无脑点掉的东西 |
| **签发前的依赖度核验**（低置信 ＋ 零修改时） | automation bias 的主要暴露点，而"零摩擦"设计恰恰在放大它 | 医生一眼不看就签发 |
| **诊室可见性（默认遮蔽）** | 保护的是医生——屏幕上"恶性风险：高"被患者先看到，是医患沟通事故 | 每次检查都是一次敞口 |

> 三项的共同点：**它们增加的那一次操作，换来的是"其他所有提示都可以被信任"。** 这正是 P3 的算法——打扰总量下降。

## 5. 裁定结果（已锁定）

| # | 分叉 | 裁定 | 落点 |
|---|---|---|---|
| 1 | 进度表达 | **2 个词**：「分析中」→「已完成」；仅超基线时补一句真话 | §3.1 |
| 2 | AI 层标记 | **确认后消失**——未经医生确认/修改时标记，确认即撤 | §1 契约表 |
| 3 | 语义色 | ~~保留四级~~ → **两级 ＋ 默认无标记**（v5 复盘重判：绿不是第四个颜色档，它在回答"是否已确认"这个**另一类问题**，故搬到质控／管理面） | §2 |
| 4 | `/diagnosis` 独立页 | **删除**，能力迁入工作区结论区 | §3.2 |

**第 4 项落地要点**：`DiagnosisPage.tsx` 的三项能力**迁移进工作区结论区**——`LoadingPhase`（含 `timeout` / `error`，可直接作为 14-文档 §5.8 状态矩阵的取值来源）、`useProgressiveDiagnosis`（结论先落地、警示/质控/证据链分块补齐）、`reviewAcknowledged`（「已人工核验」勾选）。页面本身删除。这同时关闭 `16-报告 N-02` 记录的功能重叠。

**第 3 项的关联后果（v5 修订后已变为收益）**：医生主链不再出现绿 ⇒ `08-文档 A6` 的红/绿配对冲突**在医生侧消解**，不需追加"红绿不得同屏"约束；但**质控／管理面若使用绿，仍需在该面内避免与红同屏对照**——这一条随绿一起搬走，不要漏。

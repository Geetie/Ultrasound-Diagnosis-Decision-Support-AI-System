## 一、文档集约定

### 1.1 权威次序（冲突时以靠前者为准）

1. **代码与测试**（`app/`、`tests/`）——唯一事实源。
2. **`00-项目总览与核心指标.md`**——**指标口径的唯一来源**（其它文档不得自行改口径）。
3. **`03-接口规范.md` / `04-安全合规.md` / `05-可观测性与运维.md`**——各自领域的唯一来源。
4. **`07-数据标注与模型评估.md` / `14-外部数据源与许可合规清单.md`**——数据与评估的唯一来源。
5. 其余文档为解释与导读。

文档与代码冲突时**以代码为准并立即修正文档**；无法在代码中验证的承诺，一律标注"待验证"，不得写成已完成。

### 1.2 状态标记

| 标记 | 含义 |
|---|---|
| ✅ | 已实现，且有测试覆盖（文档中给测试路径） |
| 🟡 | 部分实现 / 默认关闭 / 仅离线可用 |
| ❌ | 未实现 |
| 🔬 | 需真机或外部系统才能验证（登记于 `docs/合规/覆盖率豁免清单.json`） |

### 1.3 引用与写作规范

- 引用代码必须给 `path:行号`；引用配置项必须给**变量名 + 默认值**；
- 每个文档头部必须写「最后核对日期」与「核对方式」（代码核对 / 实测 / 引用）；
- 禁止使用"已完成""已优化""基本可用"等无证据措辞——**给证据或标待验证**。

## M1：切面标准性评估

### 1.1 需求分析

**现状**：边缘端导航模型仅执行病灶检测/分类推理（输出 bbox + label + confidence），不评估当前超声切面是否标准。流程监控智能体职责为"检查流程质控、漏项提醒"（01-架构 §2），但未定义切面合格性判断能力。

**临床影响**：超声检查中切面标准化是诊断基础。非标准切面可能导致：（1）关键结构未显示而漏诊；（2）测量角度偏差导致大小/比值不准；（3）分级判断依据不充分导致分级偏差。

**需求细化**：

| 需求项 | 说明 |
|--------|------|
| 切面分类 | 识别当前切面类型（如甲状腺横切面/纵切面/非标准切面） |
| 合格性判断 | 判断当前切面是否为标准检查切面 |
| 不合格原因 | 提示具体原因（角度不对、深度不够、未显示关键结构） |
| 前端展示 | 实时提示切面状态，不遮挡图像 |

### 1.2 修改策略

**核心思路**：在边缘端导航模型中增加切面分类/评分头（多任务学习），与现有目标检测头并行输出。切面评估结果作为 B 级输出（导航级），经后端中转推送前端。

**与现有架构的衔接点**：

| 现有组件 | 修改内容 | 衔接方式 |
|----------|----------|----------|
| 边缘端 TensorRT 导航模型 | 增加切面分类/评分输出头 | 共享 backbone，新增分类分支，输出 `plane_type` + `plane_score` + `plane_issues` |
| 导航标注内容规范（01-架构 §1） | 扩展导航标注字段 | 在现有 `bbox + label + confidence` 基础上增加 `plane_assessment` 字段 |
| 导航标签白名单（02-核心流程 §5.1） | 增加切面类型标签 | 白名单增加切面类型枚举值 |
| 流程监控智能体（01-架构 §2） | 增加切面合格性监控 | 接收切面评估结果，触发漏项提醒 |
| 前端检查主界面（08-前端交互 §1） | 增加切面状态指示 | 在图像角落显示切面状态图标 |

### 1.3 实施步骤

**步骤 1：扩展导航标注数据结构**

在 [01-系统架构设计](01-系统架构设计.md) §1 导航标注内容规范中，扩展导航标注结构：

```json
{
  "frame_id": "uuid",
  "annotations": [
    {
      "bbox": [x1, y1, x2, y2],
      "label": "nodule",
      "confidence": 0.88
    }
  ],
  "plane_assessment": {
    "organ_code": "thyroid",
    "plane_type": "transverse | longitudinal | non_standard",
    "is_standard": true,
    "plane_score": 0.92,
    "issues": [],
    "required_structures_visible": ["isthmus", "right_lobe", "left_lobe"]
  }
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `plane_type` | enum | 切面类型，按器官定义。甲状腺：`transverse`/`longitudinal`/`non_standard`；肝脏：`left_lobe_sagittal`/`right_lobe_intercostal`/`non_standard`；心脏：`apical_4ch`/`parasternal_long`/`parasternal_short`/`non_standard` |
| `is_standard` | boolean | 当前切面是否为标准检查切面 |
| `plane_score` | float | 切面质量评分（0.0-1.0），≥ 0.8 为标准切面 |
| `issues` | string[] | 不合格原因列表，枚举值：`angle_incorrect`/`depth_insufficient`/`key_structure_missing`/`probe_position_off` |
| `required_structures_visible` | string[] | 当前切面中可见的关键解剖结构 |

**步骤 2：扩展导航标签白名单**

在 [02-核心流程与知识库](02-核心流程与知识库.md) §5.1 导航标签白名单维护规则中，增加切面类型标签：

| 器官 | 切面类型白名单 |
|------|----------------|
| 甲状腺 | `["transverse", "longitudinal", "non_standard"]` |
| 肝脏 | `["left_lobe_sagittal", "right_lobe_intercostal", "non_standard"]` |
| 心脏 | `["apical_4ch", "parasternal_long", "parasternal_short", "non_standard"]` |

切面类型标签与 UDAF 词汇表同步维护，新增切面类型须走 L2 级反馈流程。

**步骤 3：扩展边缘端导航模型**

在边缘端 TensorRT 导航模型中增加切面分类/评分头：

| 维度 | 规格 |
|------|------|
| 模型架构 | 共享 backbone + 检测头 + 切面分类头（多任务学习） |
| 切面分类头输出 | `plane_type`（3-5 类，按器官）+ `plane_score`（0.0-1.0）+ `issues`（多标签分类） |

| 训练数据需求 | 每器官 ≥ 500 例标注切面类型的超声图像 |

**步骤 4：扩展流程监控智能体**

**步骤 5：扩展前端展示**

在 [08-前端交互与使用指南](08-前端交互与使用指南.md) §2 交互响应规范中，增加切面状态展示：

| 非标准切面 | 黄色警告图标 + "非标准切面" + 具体原因 | 图像右上角 |

## M2：快速路径高危标记与自动升级

### 2.1 需求分析

**现状**：系统安全框架将输出分为 A 级（诊断级，零容忍）和 B 级（导航级，有限容忍）。快速路径（实时导航）仅输出 B 级内容（bbox + label + confidence），不允许输出 A 级内容（风险等级、恶性提示）。医生在实时扫查中最需要高危预警，但安全框架不允许快速路径输出诊断性结论。

**核心矛盾**：安全设计与临床需求的根本张力——A 级安全容忍度要求诊断性结论必须经完整校验链路，但医生在实时扫查中需要即时风险提示。

**需求细化**：

| 需求项 | 说明 |
|--------|------|
| 高危标记 | 在导航标注中标记"需关注"的病灶（非诊断性结论） |
| 自动升级 | 检测到高危标记时自动触发标准/全量路径评估 |
| 风险等级提示 | 经完整校验后输出风险等级 |

### 2.2 修改策略

**核心思路**：引入 B+ 级输出（高危导航标记），介于 B 级（普通导航）和 A 级（诊断结论）之间。B+ 级输出仅标记"需关注"而非诊断性结论，安全容忍度高于 A 级但低于 B 级。同时实现导航→标准路径自动升级机制。

**安全分级框架扩展**（修改 [01-系统架构设计](01-系统架构设计.md) §1 输出安全分级框架）：

| 安全级别 | 适用输出类型 | 安全校验策略 | 安全容忍度 | 降级策略 |
|----------|-------------|-------------|-----------|----------|
| A 级（诊断级） | 诊断结论（含分级、病种编码、治疗建议） | 先校验后输出 | 零容忍 | SafetyGateway 不可用时拒绝输出 |
| **B+ 级（高危导航级）** | **高危标记（risk_flag + 建议升级提示）** | **边缘端标签白名单 + 后端实体校验 + 置信度阈值 × 1.05** | **有限容忍——仅标记"需关注"而非诊断结论** | **后端不可用时标记继续展示，附加"未经深度校验"警告** |
| B 级（导航级） | 导航标注（坐标+标签+置信度） | 先输出后校验 | 有限容忍 | 后端不可用时标注继续展示 |
| C 级（原始级） | 原始超声图像 | 无 AI 校验 | 无 AI 安全风险 | 无降级需求 |

**B+ 级安全容忍度论证**：
1. B+ 级输出仅含 `risk_flag: "high"` + `suggested_action: "start_standard_evaluation"`，不含分级词汇或病种编码，不直接引导临床行动
2. B+ 级触发条件严格：导航标签为高风险标签（如 `malignant_suspected`）且置信度 > 器官级阈值 × 1.05
3. B+ 级输出附加视觉区分：橙色闪烁边框 + "建议启动标准评估"提示，与 B 级的蓝色实线框视觉区分

### 2.3 实施步骤

**步骤 1：扩展导航标注数据结构**

在导航标注中增加 B+ 级字段：

```json
{
  "frame_id": "uuid",
  "annotations": [
    {
      "bbox": [x1, y1, x2, y2],
      "label": "nodule",
      "confidence": 0.88,
      "risk_flag": null,
      "suggested_action": null
    },
    {
      "bbox": [x1, y1, x2, y2],
      "label": "malignant_suspected",
      "confidence": 0.90,
      "risk_flag": "high",
      "suggested_action": "start_standard_evaluation"
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `risk_flag` | enum \| null | 风险标记：`"high"` / `null`。仅当标签为高风险标签且置信度 > 器官级阈值 × 1.05 时设为 `"high"` |
| `suggested_action` | enum \| null | 建议动作：`"start_standard_evaluation"` / `null` |

**高风险标签定义**（纳入导航标签白名单，与 UDAF 词汇表同步）：

| 器官 | 高风险标签 |
|------|-----------|
| 甲状腺 | `malignant_suspected`, `anaplastic_carcinoma` |
| 肝脏 | `hcc_suspected`, `malignant_suspected` |
| 心脏 | `acute_failure_sign`, `tamponade_sign` |

**步骤 2：实现自动升级机制**

在 [02-核心流程与知识库](02-核心流程与知识库.md) §2.1 分层响应路径中，增加快速→标准路径自动升级规则：

| 触发条件 | 升级目标 | 延迟影响 |
|----------|----------|----------|
| 导航标注 `risk_flag="high"` 且置信度 > 器官级阈值 × 1.05 | 自动触发标准路径评估 | 标准路径延迟 < 2s |
| 导航标注 `risk_flag="high"` 且置信度 > 0.90 | 自动触发全量路径评估 | 全量路径延迟 < 5s |

**自动升级流程**：

1. 边缘端导航推理输出含 `risk_flag="high"` 的标注
2. 后端中转校验时检测到 `risk_flag="high"`
3. 后端自动创建标准/全量路径诊断请求（无需医生手动触发）
4. 前端同时展示：B+ 级高危标记（橙色闪烁框）+ "正在启动深度分析..."提示
5. 标准/全量路径评估完成后，A 级诊断结论替换 B+ 级标记

**步骤 3：扩展前端展示**

在 [08-前端交互与使用指南](08-前端交互与使用指南.md) §2.4 导航标注安全状态视觉区分规范中，增加 B+ 级展示：

| 安全校验状态 | 视觉样式 | 说明 |
|-------------|----------|------|
| B+ 级高危标记（已校验） | 橙色闪烁实线边框 + "⚠ 高危标记，建议启动标准评估"提示 | 标记为"需关注"而非诊断结论 |
| B+ 级→A 级升级中 | 橙色闪烁框 + "正在启动深度分析..."加载指示器 | 自动升级进行中 |
| A 级诊断结论（升级完成） | 红色实线框 + 风险等级标签 + 完整诊断结论 | 经完整校验链路的诊断性结论 |

暗室模式下：B+ 级使用高对比度琥珀色/橙色闪烁边框。

**步骤 4：扩展导航校验规则**

后端导航校验链路中增加 B+ 级校验：

| 校验项 | B 级 | B+ 级 | A 级 |
|--------|------|-------|------|
| 标签白名单 | ✅ | ✅ | ✅ |
| 实体校验 | ✅ | ✅ | ✅ |
| 禁忌校验 | ✅ | ✅ | ✅ |
| 置信度阈值 | 器官级阈值 | 器官级阈值 × 1.05 | 器官级阈值 |
| 逻辑校验 | ❌ | ❌ | ✅ |
| Self-RAG 质检 | ❌ | ❌ | ✅ |

### 2.4 预期效果

| 指标 | 目标值 |
|------|--------|
| 高危标记检出率 | ≥ 90%（高风险病灶被标记为 `risk_flag="high"` 的比例） |

| 验证项 | 方法 | 通过标准 |
|--------|------|----------|

## M3：自动测量（三维尺寸/纵横比/距离）

### 3.1 需求分析

**现状**：降级输出白名单包含 `measurement` 字段（float + enum，02-核心流程 §2.3），支持长径/短径/前后径测量值。但导航标注仅输出 bbox 坐标，未定义如何从 bbox 自动计算病灶三维尺寸。UDAF 词汇表无纵横比字段，无距离自动测量功能。

**需求细化**：

| 需求项 | 说明 |
|--------|------|
| 三维尺寸 | 长 × 宽 × 厚（cm），从病灶分割结果自动计算 |
| 纵横比 | 长径/短径比值，甲状腺结节评估关键指标 |
| 距离测量 | 距被膜/距脏器边缘/距皮表距离 |

### 3.2 修改策略

**核心思路**：分两阶段实现——一期基于 bbox 近似计算（精度有限但零额外模型开销），二期基于分割模型精确计算。

**一期方案（bbox 近似）**：

| 测量项 | 计算方法 | 精度 |
|--------|----------|------|
| 长径 | bbox 对角线长度 × 像素-物理比例尺 | ±2mm |
| 短径 | bbox 短边长度 × 像素-物理比例尺 | ±2mm |
| 前后径 | bbox 短边长度 × 像素-物理比例尺（纵切面时） | ±3mm |
| 纵横比 | bbox 宽/高比值 | ±0.1 |
| 体积 | π/6 × 长 × 宽 × 厚（椭球近似） | ±20% |

**像素-物理比例尺来源**：DICOM 帧元数据中的 `PixelSpacing`（0018,0011）和 `ImagerPixelSpacing`（0018,1164）字段。边缘端 DICOM 解码时保留此字段供测量计算使用。

**二期方案（分割模型）**：边缘端导航模型增加分割输出头（实例分割），输出病灶轮廓 mask。基于 mask 计算精确的三维尺寸、纵横比和距离。需训练分割模型，显存增量 ≤ 500MB。

### 3.3 实施步骤

**步骤 1：扩展 UDAF 词汇表**

在 [02-核心流程与知识库](02-核心流程与知识库.md) §5.1 UDAF 统一诊断属性框架中，增加测量相关字段：

| 字段名 | 字段类型 | UDAF 映射 | 说明 |
|--------|----------|-----------|------|
| `aspect_ratio` | float | `aspect_ratio` | 纵横比（宽/高），保留 2 位小数 |
| `distance_to_capsule` | float | `distance_to_capsule` | 距被膜距离（cm），保留 1 位小数 |
| `distance_to_organ_edge` | float | `distance_to_organ_edge` | 距脏器边缘距离（cm），保留 1 位小数 |
| `distance_to_skin` | float | `distance_to_skin` | 距皮表距离（cm），保留 1 位小数 |
| `volume` | float | `volume` | 体积（cm³），保留 1 位小数 |

同步更新降级输出白名单（02-核心流程 §2.3），将以上字段纳入白名单，走白名单变更安全评审流程。

**步骤 2：扩展专科智能体输出**

在 [01-系统架构设计](01-系统架构设计.md) §2.4 专科智能体输出中，增加自动测量字段：

```json
{
  "organ_code": "thyroid",
  "observations": {
    "echogenicity": "hypoechoic",
    "boundary": "ill-defined",
    "morphology": "irregular",
    "calcification": "micro",
    "vascularity": "internal",
    "measurement": {
      "long_diameter": 1.8,
      "short_diameter": 1.2,
      "anteroposterior": 1.3,
      "measurement_type": ["long_diameter", "short_diameter", "anteroposterior"],
      "unit": "cm"
    },
    "aspect_ratio": 0.72,
    "distance_to_capsule": 0.3,
    "volume": 1.47
  }
}
```

**步骤 3：实现 bbox→测量值转换**

在边缘端导航推理后、导航标注上报后端前，增加测量值计算模块：

```
输入：bbox [x1, y1, x2, y2] + PixelSpacing + 切面类型
输出：measurement + aspect_ratio
```

| 计算规则 | 说明 |
|----------|------|
| 长径 | max(bbox_width, bbox_height) × PixelSpacing |
| 短径 | min(bbox_width, bbox_height) × PixelSpacing |
| 纵横比 | bbox_width / bbox_height（横切面）或 bbox_height / bbox_width（纵切面） |
| PixelSpacing 缺失 | 使用默认比例尺（通过 `DEFAULT_PIXEL_SPACING_MM` 配置项，按器官/探头类型配置），输出标记 `pixel_spacing_source: "default"` |

**步骤 4：实现距离测量（一期简化）**

一期距离测量基于解剖知识规则（非分割模型）：

| 距离项 | 一期计算方法 | 精度 |
|--------|-------------|------|
| 距被膜距离 | bbox 边缘到器官轮廓（从导航模型器官分割输出获取）的最短距离 | ±3mm |
| 距脏器边缘距离 | 同上 | ±3mm |
| 距皮表距离 | bbox 上边缘到图像上边缘 × PixelSpacing | ±5mm |

### 3.4 预期效果

| 指标 | 一期目标 | 二期目标 |
|------|----------|----------|
| 长径测量误差 | ±2mm | ±1mm |
| 纵横比误差 | ±0.1 | ±0.05 |
| 距被膜距离误差 | ±3mm | ±1mm |
| 测量延迟增量 | ≤ 2ms | ≤ 10ms |

### 3.5 验证方法

| 验证项 | 方法 | 通过标准 |
|--------|------|----------|
| 长径测量精度 | ≥ 100 例与医生手动测量对比 | 误差 ±2mm 以内 ≥ 90% |
| 纵横比精度 | ≥ 100 例与医生手动计算对比 | 误差 ±0.1 以内 ≥ 90% |
| PixelSpacing 缺失降级 | 模拟 PixelSpacing 缺失场景 | 使用默认比例尺后测量值偏差 < 20% |
| 降级白名单一致性 | CI 检查新增字段与 UDAF 词汇表一致性 | 一致性检查通过 |

## M5：恶性概率字段（malignancy_risk）

### 5.1 需求分析

**现状**：系统输出 `confidence` 字段（0.0-1.0），但这是 AI 对诊断结论的置信度，不是恶性概率。两者语义不同——置信度 0.88 表示"AI 有 88% 把握认为结论正确"，而非"恶性概率 88%"。

**需求细化**：

| 需求项 | 说明 |
|--------|------|
| 恶性概率 | 基于当前征象组合，恶性概率为 XX% |
| 与置信度区分 | 恶性概率是疾病属性，置信度是 AI 属性 |
| 依据列示 | 列出导致该恶性概率的征象组合 |

### 5.2 修改策略

**核心思路**：在专科智能体输出中增加 `malignancy_risk` 字段，基于知识库中征象-概率映射规则计算，与 `confidence` 字段区分。`malignancy_risk` 为 A 级输出，须经完整校验链路。

### 5.3 实施步骤

**步骤 1：增加 malignancy_risk 字段**

在专科智能体输出中增加：

```json
{
  "diagnostic_conclusion": "甲状腺结节，TI-RADS 4b",

  "malignancy_risk": {
    "probability": 0.35,
    "level": "medium",
    "basis": [
      {"feature": "低回声", "contribution": "+5%"},
      {"feature": "边界不清", "contribution": "+10%"},
      {"feature": "微钙化", "contribution": "+15%"},
```

## M9：后方回声特征（UDAF 扩展）

### 9.1 需求分析

**现状**：UDAF 词汇表定义了 `echogenicity`、`boundary`、`morphology`、`calcification`、`vascularity` 枚举，但未定义后方回声特征字段。后方回声是甲状腺/乳腺结节评估的重要指标。

### 9.2 修改策略

**核心思路**：在 UDAF 词汇表中增加 `posterior_acoustic` 枚举，同步更新降级输出白名单和导航标签白名单。

### 9.3 实施步骤

**步骤 1：扩展 UDAF 词汇表**

在 [02-核心流程与知识库](02-核心流程与知识库.md) §5.1 UDAF 统一诊断属性框架中，增加：

| 字段名 | 枚举值 | 中文含义 |
|--------|--------|----------|
| `posterior_acoustic` | `enhancement` | 后方回声增强 |
| | `attenuation` | 后方回声衰减 |
| | `shadowing` | 后方声影 |
| | `none` | 后方回声无变化 |
| | `mixed` | 混合表现 |

**步骤 2：同步更新降级输出白名单**

在 [02-核心流程与知识库](02-核心流程与知识库.md) §2.3 降级输出白名单中增加 `posterior_acoustic` 字段，走白名单变更安全评审流程。

**步骤 3：更新专科智能体 TI-RADS 规则**

在甲状腺超声智能体专属规则中，将 `posterior_acoustic` 纳入 TI-RADS 分级判断依据：

| posterior_acoustic 值 | TI-RADS 影响 |
|----------------------|-------------|
| `attenuation` | 可疑征象（+1 分） |
| `shadowing` | 良性征象（可能为粗大钙化） |
| `enhancement` | 囊性变提示（良性倾向） |
| `none` | 不影响分级 |

### 9.4 预期效果

| 指标 | 目标值 |
|------|--------|
| 后方回声识别准确率 | ≥ 85% |
| TI-RADS 分级准确性提升 | 加入后方回声后分级准确率提升 ≥ 3% |

### 9.5 验证方法

| 验证项 | 方法 | 通过标准 |
|--------|------|----------|
| 识别准确率 | ≥ 100 例专家标注后方回声的测试集 | 准确率 ≥ 85% |
| 分级影响 | 对比加入前后 TI-RADS 分级准确率 | 提升 ≥ 3% |

## 架构一致性修订说明

> 以下问题在实施前须先修订 01-系统架构设计和 02-核心流程与知识库的架构基线，使基线与实施目标对齐后再推进开发。

### 问题 1：输出安全分级框架扩展（B+ 级）

**发现**：01-系统架构设计 §1 明确定义"三级"安全分级框架（A/B/C），并规定"安全分级框架须在 NMPA 注册材料中明确声明"。B+ 级的引入将三级变为四级，与现有声明直接矛盾。同时，现有判定规则仅有三条路径，B+ 级的 `risk_flag: "high"` 按现有规则应判为 B 级，但按"就高不就低"原则应升级为 A 级，与 B+ 级的设计意图矛盾。

**解决方案**：不引入新的 B+ 级别。改为在现有 B 级框架内实现高危标记功能——将 `risk_flag` 和 `suggested_action` 纳入 B 级导航标注的合法字段范围，但附加更严格的校验规则：

1. **修订 01-架构 §1 导航标注内容规范**：将"仅包含坐标和标签（bbox + label + confidence）"修订为"包含坐标、标签、置信度及辅助评估字段（risk_flag、suggested_action、plane_assessment、image_quality）"，同时明确所有辅助评估字段不含分级词汇或病种编码
2. **修订安全分级判定规则**：增加第 (2a) 条——"输出包含 risk_flag 等风险提示字段但不含分级词汇或病种编码 → 仍为 B 级，但须执行增强校验（置信度阈值 × 1.05）"
3. **NMPA 注册更新**：安全分级框架仍为三级（A/B/C），B 级内部增加"普通导航"和"高危导航"两种校验策略，不改变分级框架层级数

### 问题 2：导航标注数据结构扩展

**发现**：01-架构 §1 规定导航标注"仅包含坐标和标签（bbox + label + confidence）"，此为排他性约束。M1（plane_assessment）、M2（risk_flag/suggested_action）、M6（image_quality）新增字段均超出此范围。

**解决方案**：修订 01-架构 §1 导航标注内容规范，将导航标注结构从"仅包含 bbox + label + confidence"扩展为包含帧级辅助评估字段的结构化对象。扩展后的导航标注分为两个层级：

1. **标注级字段**（annotations 数组内）：`bbox` + `label` + `confidence` + `risk_flag` + `suggested_action`——保持不变，仅增加两个可选字段
2. **帧级字段**（annotations 数组外）：`plane_assessment` + `image_quality`——新增帧级评估

同时扩展边缘端轻量级校验规则，增加 `risk_flag` 枚举值校验（仅允许 `"high"` / `null`）、`plane_assessment.plane_type` 白名单校验、`image_quality` 评分范围校验。

### 问题 3：UDAF 词汇表类型体系扩展

**发现**：现有 UDAF 属性全部为枚举/分类类型，M3 新增的 `aspect_ratio`、`distance_to_capsule` 等为 float 连续值类型，改变了 UDAF 的类型体系性质。

**解决方案**：将 UDAF 从"纯分类属性框架"正式扩展为"分类+连续混合属性框架"，明确定义两类属性的维护规则差异：

1. **分类属性（enum）**：维护规则不变，新增枚举值走 L2 级反馈流程
2. **连续属性（float）**：新增属性走 L2 级反馈流程，额外要求定义正常范围、测量单位、精度要求。降级输出白名单中 float 字段的 UDAF 映射规则为"字段名即映射名"（自映射），安全评审关注点为"测量值组合是否可能关联患者身份"（风险极低，但须显式评估并记录）

### 问题 4：专科智能体输出格式扩展与 SafetyGateway 降级逻辑

**发现**：01-架构要求专科智能体输出仅包含 `observations` 和 `diagnostic_conclusion` 两个独立字段，SafetyGateway 降级时过滤 `diagnostic_conclusion` 仅保留 `observations`。M4（differential_diagnoses）、M5（malignancy_risk）、M7（clinical_actions）等新增 A 级顶层字段在降级时未被覆盖，可能导致降级输出中包含未经校验的诊断性信息。

**解决方案**：修订专科智能体输出结构，将所有 A 级字段统一归入 `diagnostic_conclusion` 对象内：

```json
{
  "observations": {
    "echogenicity": "hypoechoic",
    "boundary": "ill-defined",
    "aspect_ratio": 0.72,
    "posterior_acoustic": "attenuation"
  },
  "diagnostic_conclusion": {
    "conclusion": "甲状腺结节，TI-RADS 4b",
    "confidence": 0.85,
    "grading": "TI-RADS 4b",
    "malignancy_risk": {"probability": 0.35, "level": "medium"},
    "differential_diagnoses": [...],
    "clinical_actions": [...]
  }
}
```

SafetyGateway 降级时过滤整个 `diagnostic_conclusion` 对象，仅保留 `observations` 字段——此逻辑与现有设计完全一致，无需修改 SafetyGateway 降级策略。所有 A 级字段（conclusion、grading、malignancy_risk、differential_diagnoses、clinical_actions）均在 `diagnostic_conclusion` 对象内，降级时统一被过滤。

### 问题 5：流程监控智能体职责扩展与"智能体结构不可修改原则"

**发现**：01-架构规定"模块接口定义（Protocol/ABC）一期二期完全相同"为架构红线。M1（切面合格性监控）和 M8（报告完整性校验）新增职责可能需要新增 Protocol/ABC 方法签名。

**解决方案**：通过扩展现有接口方法的内部逻辑实现职责扩展，不新增 Protocol/ABC 方法签名：

1. **M1 切面合格性监控**：扩展现有 `check_quality()` 方法的内部逻辑，增加切面评估结果的处理分支。切面评估结果作为导航标注的一部分传入，`check_quality()` 内部根据 `plane_assessment` 字段触发漏项提醒
2. **M8 报告完整性校验**：扩展现有 `check_completeness()` 方法的内部逻辑，增加基于报告模板必填项的校验规则。报告模板配置作为知识库条目加载，`check_completeness()` 内部根据模板定义校验报告字段完整性

此方案保持 Protocol/ABC 签名不变，仅扩展方法内部逻辑，不违反"智能体结构不可修改原则"。

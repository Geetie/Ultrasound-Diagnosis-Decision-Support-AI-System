### 1.3 ⚠️ 向量化：**默认走的是假向量**

| 项 | 事实 |
|---|---|
| 构建器默认 | 未注入 `embedding_service` 时 → **`MockEmbeddingService()`**（`builder.py:250-254`） |
| Mock 实现 | `sha256(text)` 展开成 768 维，`model="mock-bge-m3-medical"`，**无任何语义**，仅确定性可测（`:168-223`） |
| 真实 embedding | `embedding/bge_m3.py BgeM3MedicalService` —— **只用于 RAG 检索侧**（装配 `main.py:178`） |
| `--embedding-model` | 仅作入参透传，**不用于选服务** |

**后果**：用默认 CLI 建出的知识库**不具备语义检索能力**（向量是 hash），
必须显式注入 `BgeM3MedicalService` 才能得到可用的库。**这是评估与验收前必须先确认的前提。**

### 1.4 索引双轨与 BM25 兜底

| 项 | 事实 |
|---|---|
| 工厂 | `embedding/index_factory.py:33 create_index_client`；后端解析 `:75-85`（默认 `settings.vector_index_backend`） |
| 回退 | Qdrant 健康检查 3s 超时/异常 + `auto_fallback=True` → `_create_pgvector`（`:88-156,159`） |
| BM25 兜底 | `rag/bm25_fallback.py`（装配 `main.py:215-219`），阈值 `rag_bm25_min_top1_score/min_results` |

⚠️ **两条链路的"索引"不是同一套**：**建库只写 pgvector**（`knowledge_chunks`）；
Qdrant 双轨属**在线检索侧**（`rag/retriever.py` + `index_factory`）。文档不得混为一谈。

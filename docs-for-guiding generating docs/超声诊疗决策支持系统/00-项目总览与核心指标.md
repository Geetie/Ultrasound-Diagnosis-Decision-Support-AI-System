# 项目总览与核心指标

## 1. 项目定位

本项目旨在构建一套**医疗专科定制化的多模态智能体增强 RAG 系统**，定位为**辅助诊断工具**，所有输出均需医生确认后方可纳入临床决策。系统不替代医生诊断，而是通过提供结构化知识依据与推理辅助，降低漏诊率、提升诊断效率。

针对超声诊疗场景，解决基层医生诊断能力不足、术语表述异构、AI 幻觉风险、数据隐私合规等行业痛点，实现从检查前准备、检查中实时导航、检查后报告生成到长期随访的全流程临床闭环。

通过整合权威诊疗指南、专家共识、典型病例与标注影像数据，构建标准化医疗知识底座，结合专属多模态对齐、医疗级抗幻觉机制与 1+N 多智能体协作架构，最终实现：

- 基层医院超声诊断准确率从 78% 提升至 89%（定义：AI 模型独立诊断结论与金标准一致的比例；基线 78% 为基层医生无 AI 辅助时的诊断准确率**此基线值须在项目立项前实测验证（≥ 200 例），而非 Gate 0A 前——若立项后发现目标设定不合理，项目方向调整成本极高。Gate 0A-Tech 通过后可启动技术框架开发（不依赖基线数据），但依赖临床数据的功能开发须等待 Gate 0A 基线验证结果通过后方可启动**；三甲医院因病例复杂度更高，目标值单独设定为 ≥ 92%）
- 漏诊率从 15% 降低至 5% 以下（定义：AI 辅助下医生最终诊断的漏诊率；此指标为人机协同指标，与 [07-数据标注与模型评估](07-数据标注与模型评估.md) 1.1 节敏感性指标为模型级别指标不同，两者不可简单等同）
- AI 生成报告草稿时间：单器官 ≤ 2 分钟、多器官联合诊断 ≤ 3 分钟（端到端，从图像输入到报告草稿输出）；AI 纯处理时间：单器官 ≤ 100s、多器官联合诊断 ≤ 120s（从诊断请求触发到报告草稿输出，不含人类等待）；医生完成报告总时间（含审核修改）≤ 8 分钟
- AI 幻觉率按风险等级差异化控制（高风险病种 ≤ 1%，整体 ≤ 5%）
- 同时满足三甲医院复杂病例支持与基层医院轻量化部署的双重需求

> **报告生成时间说明**：≤ 2 分钟的分解——图像预处理（≤ 10s）+ 诊断推理（≤ 15s/器官，多器官串行，三器官合计 ≤ 45s）+ 报告模板填充与格式化（≤ 5s）+ 质控校验（≤ 10s）+ 等待 DICOM 帧缓冲与医生确认触发（≤ 60s）≈ 130s，预留余量至 120s 时须依赖导航帧预缓冲与医生确认并行操作。与单次诊断延迟 P99 < 5s 的区别：诊断延迟仅指单次推理耗时，报告生成需等待所有器官诊断完成、汇总融合输出、填充报告模板。

## 2. 核心量化指标

> 以下指标在本文档集中仅定义一次，其他文档引用时标注"详见核心指标"。

| 指标 | 一期目标值 | 校准方法 | 校准周期 |
|---|---|---|---|
| 诊断准确率 | ≥ 89%（基层）/ ≥ 92%（三甲） | AI 模型独立诊断结论与金标准（病理/手术结果）对比 | 每季度 |
| 阳性预测值（PPV） | ≥ 85%（基层）/ ≥ 90%（三甲） | AI 提示阳性结果中与金标准一致的比例。PPV 比准确率更能反映 AI 辅助的临床价值——高 PPV 意味着 AI 提示的阳性结果更可靠，医生更愿意参考；低 PPV 导致频繁误诊，医生可能降低对 AI 的信任度反而增加漏诊风险 | 每季度 |
| 漏诊率 | 15% → 5%（人机协同） | AI 辅助下医生最终诊断的回顾性病例审计 | 每季度 |
| AI 报告草稿生成时间 | ≤ 2 分钟 | 端到端计时（从图像输入到报告草稿输出） | 每月 |
| 医生完成报告总时间 | ≤ 8 分钟 | 端到端计时（从图像输入到医生确认报告） | 每月 |
| 实时导航端到端延迟 | P99 < 200ms | 生产环境 P99 监控 | 实时 |
| 辅助评估延迟 | P99 < 2s | 生产环境 P99 监控 | 实时 |
| 完整诊断延迟 | P99 < 5s（不含 Self-RAG 重试）；含重试 < 8s | 生产环境 P99 监控 | 实时 |
| 多器官联合诊断延迟（三器官串行） | compact 模式 P99 < 25s（不含 Self-RAG 重试，含 CRAG 补充检索余量）；含重试 < 35s；full 模式 P99 < 15s（不含 Self-RAG 重试）；含重试 < 24s | 生产环境 P99 监控 | 实时 |
| 严重幻觉率（全病种） | ≤ 0.5% | 专家盲评 + 依据溯源校验 | 每周 |
| 整体幻觉率 | ≤ 5% | 专家盲评 + 依据溯源校验 | 每月 |
| 高风险病种幻觉率 | ≤ 1% | 专家盲评 + 依据溯源校验 | 每周 |

> **纯文本检索模式下的核心指标调整**：若 Ultrasound-CLIP 商业授权谈判失败（详见 [07-数据标注与模型评估](07-数据标注与模型评估.md) §5.5），系统降级为 bge-m3-medical 纯文本检索模式，以下指标须相应调整：混合检索召回率目标从 ≥ 90% 下调至 ≥ 85%；多模态检索 I2T@10 指标取消；端到端诊断准确率目标维持不变（≥ 89% 基层 / ≥ 92% 三甲），但须基于纯文本检索路径重新验证。

> **⚠️ Ultrasound-CLIP 商业许可问题处理声明**：Ultrasound-CLIP 非商业许可与 NMPA 注册的潜在冲突已识别。一期为学术研究验证阶段可合法使用 Ultrasound-CLIP，但**Gate 0 启动后 30 个自然日内须获得商业授权意向书面确认**（详见 [01-系统架构设计](01-系统架构设计.md) §5.5），逾期未确认则自动切换为 bge-m3-medical 主方案。商业过渡路径（协商商业授权或切换 bge-m3-medical）详见 [01-系统架构设计](01-系统架构设计.md) §5.5 与 [07-数据标注与模型评估](07-数据标注与模型评估.md) §5.5。

### 2.1 延迟分层设计

系统按临床场景分为三条响应路径，各自独立优化延迟：

| 响应路径 | 延迟目标 | 延迟分解 |
|---|---|---|
| 快速路径（实时导航） | P99 < 200ms（极简 compact Profile `EDGE_GPU_ENABLED=false` 时 P99 < 500ms） | **一期后端中转模式延迟分解**：边缘端处理 < 30ms + 边缘端→后端传输 < 20ms + 后端校验处理 < 30ms + 后端→前端传输 < 20ms + 结果返回渲染 < 80ms ≈ 180ms，P99 < 200ms 可达成。**二期直推模式延迟分解**（设计参考，一期不启用）：边缘端处理 < 30ms + 网络传输 < 40ms + 后端处理 < 50ms + 结果返回渲染 < 80ms；**极简 compact Profile 延迟分解**（P99 < 500ms）：导航推理在后端 RTX 3060 串行执行，延迟 = 边缘端帧传输 < 20ms + 后端排队等待（诊断推理间隙）< 200ms + 后端导航推理 < 100ms + 结果返回渲染 < 80ms + 余量 ≈ 400ms，预留至 500ms |
| 标准路径（辅助评估） | P99 < 5s（2026-10-30 按实测重新定口径：管线 dispatch+fusion 常态已达 ~4.7s（settings.py 并发审查 P0-1 注释实测记录），原 2s 与现状差 2.4 倍、结构性不可达——经拍板改口径，不立项做性能优化；分档端到端预算见 `settings.pipeline_total_budget_standard_s=10.0s`） | — |

> **档位语义口径（2026-10-31 登记，01-2 收口）**：低置信度/跨器官 → **直接升 FULL 档**（`app/agents/routing.py` assess 的 elif 既有规则，`_build` 对 FULL 给 full 检索档含 bge 精排）；不存在"仅升检索档不改档位"的第二套语义（A.99 曾设想该分支，经代码复核为死代码已回退，见 16 号 A.97.4/A.99.3）。`_assess_routing` 当前**不传** `retrieval_confidence`，故该升档路径生产未触发——是否接线属行为变更，需先做 02-3 延迟回归再议。
| 全量路径（完整诊断） | P99 < 5s（不含重试） | — |

> 其他文档引用延迟指标时须以本节为准，不得重复定义分项数值。监控告警阈值须与目标值对齐：Warning 阈值 = 目标值，Critical 阈值 = 目标值的 1.25~1.5 倍，详见 [05-可观测性与运维](05-可观测性与运维.md) §2。

### 2.2 幻觉率一期监控方案

一期采用**二维指标**监控：严重幻觉率 + 整体幻觉率，分别统计与告警：

| 监控维度 | 阈值 | 告警级别 | 统计周期 |
|---|---|---|---|
| 严重幻觉率（全病种） | ≤ 0.5%（> 0.5% 即 Critical） | Critical，立即暂停 AI 辅助 | full：每周统计；compact：**周统计 + CUSUM**（compact 日检查量 ≤ 50 例，周统计约 350 例，与 full Profile 统计粒度一致，确保熔断规则可直接执行。compact 周统计辅助判断规则：（1）周度严重幻觉率 > 0.5% 即触发暂停；（2）连续 3 周出现 ≥ 1 例严重幻觉即触发暂停；（3）单周出现 ≥ 3 例严重幻觉即触发暂停。此外 compact 模式须实现 CUSUM 累积和控制图——以 0.5% 为目标值，当累积偏差超过决策阈值 h=3 时触发告警，CUSUM 可在样本量不足时更早检测到异常偏移，弥补周统计的响应延迟） |
| 整体幻觉率 | ≤ 5%（> 5% 即 Critical） | Critical，暂停 AI 辅助直至排查 | 每月 |
| 高风险病种幻觉率 | ≤ 1%（> 1% 即 Critical） | Critical，立即暂停该病种 AI 辅助 | 每周（full）；**双周 + CUSUM**（compact——compact 日检查量 ≤ 50 例，高风险病种占比约 5-10%，每周仅约 17-35 例统计功效不足；双周统计约 35-70 例统计功效显著提升。compact 双周统计辅助判断规则：（1）双周高风险病种幻觉率 > 1% 即触发暂停；（2）双周内任一周出现 ≥ 1 例高风险病种幻觉即触发暂停。CUSUM 累积和控制图以 1% 为目标值，累积偏差超过 h=3 时触发告警） |

**严重幻觉定义**：改变诊断结论方向的幻觉（如良性误判为恶性）。中度/轻微幻觉的分级监控在样本量充足后引入，详见 [09-二期规划](09-二期规划与远期增强.md)。

> **开发规范**：一期监控仪表盘仅展示上述三个指标。`HALLUCINATION_MONITORING_MODE` 配置项一期固定为 `simple`。

### 2.3 高风险病种定义

指误诊可能直接危及患者生命或导致不可逆损害的病种：

| 阶段 | 覆盖器官 | 高风险病种示例 |
|---|---|---|
| 一期（当前） | 甲状腺、肝脏、心脏 | 未分化癌（甲状腺）、肝细胞癌（肝脏）、急性心衰（心脏） |
| 二期 | 待接入器官 | 详见 [09-二期规划](09-二期规划与远期增强.md) |

一期高风险病种清单由科室主任审定，每半年复审一次。二期新增器官的高风险病种须在该器官专科智能体接入时同步审定。

### 2.4 知识来源权威性评分

本表为全系统唯一权威的知识来源置信度评分标准：

| 来源类型 | 初始评分 | 下限阈值 | 低于下限处理 |
|---|---|---|---|
| 权威指南（中华医学会/ACR/AIUM 等） | 0.95 | ≥ 0.90 | 不参与推理 |
| 专家共识 | 0.80 | ≥ 0.75 | 不参与推理 |
| 典型病例报告 | 0.60 | ≥ 0.50 | 不参与推理 |
| 医生个人经验 | 0.40 | — | 仅作参考提示，不参与推理 |

> 任何模块不得自行定义知识来源评分标准。精简输出必含字段中的"置信度"字段与检索结果可信度评分均引用本表。衰减后评分低于下限阈值的条目不参与在线推理。

### 2.5 置信度阈值乘数

一期仅两种乘数场景：

| 场景 | 乘数 | 示例（甲状腺器官级阈值 0.85） | 适用条件 |
|---|---|---|---|
| 快速路径 | 器官级阈值 × 1.05 | 0.89 | 后端可达，导航结果经后端最小安全校验；快速路径跳过逻辑校验与 Self-RAG 质检，安全防线少于标准/全量路径，阈值乘数 1.05 补偿跳过校验带来的安全防线削弱（与 [09-二期规划](09-二期规划与远期增强.md) §3 边缘端自治模式乘数 `EDGE_AUTONOMY_MULTIPLIER` 1.15-1.25 的安全逻辑一致——安全校验越少，阈值门槛越高）。乘数 1.05 为保守取值（低于边缘端自治的 1.15-1.25），因快速路径仍保留实体校验+禁忌校验+置信度阈值校验，仅跳过逻辑校验与 Self-RAG 质检 |
| 标准/全量路径 | 器官级阈值 × 1.0（即原始阈值） | 0.85 | 辅助评估、完整诊断 |

> Neo4j 故障降级等场景通过临时调高器官级阈值配置值实现，不引入专门乘数机制。远期乘数场景详见 [09-二期规划](09-二期规划与远期增强.md)。快速路径乘数 1.05 与 [06-开发环境与进度规划](06-开发环境与进度规划.md) §5 配置项 `EDGE_FAST_PATH_THRESHOLD_MULTIPLIER=1.05` 保持一致。

## 1. 项目定位

面向超声科医生的**诊疗决策支持系统**：从 DICOM 影像与临床文本出发，经三类专科智能体
（甲状腺/肝脏/心脏）推理，由融合层（冲突检测 + 一致性校验 + Self-RAG + CRAG）产出
分级结论与证据链，并强制人工复核机制；全程满足数据脱敏、审计可追溯与患者知情同意要求。

**部署形态**：`compact`（边缘/单机，llama.cpp + CPU 语音）与 `full`（服务器，vLLM + GPU）两档，
差异覆盖项见 `06-开发环境与进度规划.md` §4。

## 5. 口径说明（避免误读）

1. **"文档说完成"不等于"运行期生效"**：本项目已多次出现"能力已实现但未接线"
   （指标导出、告警回调、前端双通道 WS，见 `05` §2.4/§4.4 与 `08` §2.4）。
   因此本文档的"实测状态"列只接受**可复现的证据**（测试数字、报告文件、代码位置）。
2. **样本量决定结论有效性**：`phase0a_report.json` 的 `passed=false` 是真实未达标，
   但 6 例本身也不足以证明"不达标"——两项都不能作为验收结论，必须重测。
3. **指标口径的权威性**：若临床/产品方给出新的目标值，请直接修改本文档第 2 节并在
   `10-架构优化与修订记录.md` 登记变更理由与影响面。

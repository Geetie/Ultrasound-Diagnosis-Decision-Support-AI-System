## 2. 实时双通道（nav + dicom）

### 2.1 契约（与后端一致）

| 项 | 前端行为 | 后端要求（见 `03-接口规范.md` §3） |
|---|---|---|
| 握手 Query | `session_id` + `device_id`（**必填**） | `Query(...)` 必填，缺失在握手阶段即被拒 |
| 鉴权 | 连接后发 `{type:'auth', session_id, token}` | 5s 内首条必须是 `AuthMessage`；走 `token + session_id` 路径 |
| 建立顺序 | nav `auth_ok` → 才建 dicom 通道 | — |
| 心跳 | 每 **5s** 发 `ping`；**连续丢 3 次**触发重连；收到服务端 `ping` **回 `pong`** | 后端连续 3 次未收 pong → 关闭 `WS_1001_GOING_AWAY` |
| 重连 | 指数退避 `1s × 2^n`，上限 30s，最多 20 次；关闭码非 1000 才重连 | 鉴权失败码 `4001`、超时 `4002` |

### 2.2 连接条件与生命周期

`hooks/useRealtimeConnection.ts` 是 `wsManager.connect()` 的**唯一调用点**（挂在 `AppLayout`，
覆盖所有需登录页面）：**必须同时具备 `sessionId` + `deviceId` + token 才连接**，
会话切换或组件卸载时 `disconnect()`（避免旧连接继续往新会话推送）。

> 要求 `deviceId` 是刻意的：会话创建接口 `SessionCreateRequest` 里 `device_id` 必填，
> 因此正常流程一定具备；缺参时**直接不连**，而不是连上后无限重连。

### 2.3 消息分发

`wsManager` 只维护 handler 列表；实际派发在 `hooks/useNavigationAnnotations.ts:11-29`
→ `websocket/navChannel.ts` → `useNavigationStore` / `useSessionStore`（`navChannel.ts:6-65`）；
DICOM 二进制帧经 `onDicomFrame`（`:105`）。

### 2.4 本次修复（2026-09-28）

| 缺陷 | 修复前 | 修复后 |
|---|---|---|
| 调用点 | `wsManager.connect()` **无任何调用点**，`websocketStore.setUrls` 亦无 → **双通道从未建立** | 新增 `useRealtimeConnection`，`AppLayout` 调用 |
| Query 参数 | `buildWsUrl` 不带 query → 后端必填校验**握手即拒** | 新增 `wsParams()`，nav/dicom 均带 `session_id`/`device_id` |
| 心跳应答 | switch **无 `ping` 分支**，不回 pong → 十几秒后被判死并反复重连 | nav/dicom 均补 `ping → pong` |

守卫：`frontend/src/hooks/__tests__/useRealtimeConnection.test.ts`（6 项）。

## 4. 核心交互流程

### 4.1 诊断主流程

`ExaminationPage.requestDiagnosis`（`:53`）→ `navigate('/diagnosis?request_id=…')`（`:63`）
→ `DiagnosisPage` 读 `request_id`（`:39`）→ `startPolling`（`:66-82`）
→ `pollDiagnosisResult`（`diagnosisService.ts:137`）：首延迟 **800ms**、间隔 **1500ms**、
**总等待上限 60000ms**、瞬时失败退避 ×1.5（上限 8000ms）
→ 阶段先"预计"（`resolveStage`）后"真实"（`extractStageTimings`）
→ 结果**分段揭示**：结论 → 安全警示 → 质控 → 证据链（延迟 0/120/280/440ms，`useProgressiveDiagnosis.ts:17-29`）
→ 完成后 `navigate('/report?request_id=…')`（`DiagnosisPage.tsx:501-503`）。

### 4.2 报告与签名（`ReportPage.tsx`）

生成草稿（`:99-117`）→ **签发** `signReport`（`:119-132`，按钮 `disabled={signed}`）
→ **推送** `pushReport`（`:134-146`，`disabled={!signed}`，未签发时提示 `:344-347`）
→ **验签** `verifyReportSignature`（`:148-166`）。
失败统一 `getApiErrorMessage` + `message.error`，**无自动重试**，靠医生再点；
完整性面板列出缺失段落（`:270-296`）。

### 4.3 DICOM 阅片（cornerstone）

- 工具集**仅** 窗宽窗位 / 缩放 / 平移（`DicomToolbar.tsx:23-27` → `WwwcTool`/`ZoomTool`/`PanTool`，`DicomViewer.tsx:169-181`）；
- 窗宽滑块 1–4096、窗位 −2000~4000（`:78-94`），可重置（`:59`）；
- 帧切换 prev/next（`:97-125`）、overlay 开关（`:63-71`）；
- ⚠️ **没有任何测量工具**。

### 4.4 语音交互

`VoiceControl.tsx`（常驻）→ `useVoiceRecorder` 录音 → `POST /speech/recognize`
（16k 单声道 PCM base64，`useVoiceRecorder.ts:280`）→ `parseVoiceCommand` **保守关键词解析**（`voiceCommand.ts:110`）
→ `VoiceConfirmDialog` **必须人工确认** → `POST /voice/confirm`（含 `confirmed=false` 的拒绝上报）。

降级路径（5 类：权限拒绝/无设备/过短/不支持/转写失败，`useVoiceRecorder.ts:19-21,103-112`）：
右键或长按可"手工输入"（`:161-165`）、"重新解析"（`VoiceConfirmDialog.tsx:71-81`）。
反馈页用 `VoiceDictationButton`（**只转写不执行**，`:21-34`）。

> **设计意图**：语音**不能直接触发诊断**——必须经确认弹窗，这是防止误识导致误诊的关键约束，勿简化掉。

# 前端交互与使用指南

## 1. 关键页面

| 页面 | 核心功能 | 交互要求 |
|---|---|---|
| 检查主界面 | DICOM 图像 + 实时导航标注 + 语音/点击输入 | 暗室环境适配，高对比度 |
| 诊断结果页 | 诊断结论 + 依据溯源 + 置信度 + 质控状态 | 渐进式展示：先结论后依据；AI 失败时显示警告横幅 |
| 反馈提交页 | 修正/纠错/补充表单 | 最少操作步骤，支持语音输入 |
| 质控报告页 | 科室统计 + 趋势图 + AI修正率告警 | 主任角色可见 |
| 知识库管理页 | 版本列表 + 变更记录 + 复审通知 | 管理员角色可见 |
| 患者知情同意页 | 同意书签署 + 状态管理 + 降级模式切换 | 检查前必经 |

## 2. 交互响应规范

**暗室模式定义与切换机制**：超声检查室通常为暗室环境，系统提供"暗室模式"以优化暗室环境下的视觉体验。暗室模式为**手动切换**——设置页面提供"暗室模式"开关（默认关闭），与深色主题独立控制。医生在检查开始前手动开启即可。暗室模式不采用自动检测环境光方案（需额外光线传感器硬件，一期不必要）。暗室模式下的视觉规范：高对比度琥珀色/橙色边框替代黄色背景（避免暗室中黄色背景过亮刺眼）、深色主题、最小亮度、闪烁边框确保安全关键事件不被忽视。正常模式与暗室模式的视觉差异在各交互场景中分别标注。

| 场景 | 反馈方式 | 延迟要求 |
|---|---|---|
| 实时导航 | 图像叠加标注框 + 状态指示灯；**帧状态区分处理**：（1）**低置信度标注帧**（导航推理已覆盖该帧，但置信度低于器官级阈值）——隐藏标注，显示虚线框黄色提示"AI置信度不足，建议人工评估"；（2）**无标注帧**（导航推理未覆盖该帧，因导航推理帧率 15fps < DICOM 帧显示帧率 30fps，约 50% 帧无标注）——静默处理，不显示任何 AI 标注，原始超声图像正常展示，无额外提示，避免干扰医生对未处理帧的判断。**未经安全校验的标注附加黄色警告标记"未经安全校验"** | P99 < 200ms（极简 compact Profile 时 P99 < 500ms） |
| 辅助评估 | 进度条 + 预估时间 | < 2s |
| 完整诊断 | 渐进式加载：先结论后依据 | < 5s（不含 Self-RAG 重试）；含重试 < 8s |
| 标准路径自动升级 | 检测到复杂推理需求时，前端先展示标准路径的初步结论（标注"初步结论，建议深度分析"），同时弹出确认对话框"检测到复杂情况，是否切换至深度分析模式？预计等待 3-5 秒"。医生确认后切换至全量路径；医生拒绝则保留标准路径初步结论。此设计将升级决策权交给医生，避免自动升级打断临床工作流 | 自动升级时延迟从 < 2s 变为 < 5s |
| AI 诊断失败 | 禁用诊断 UI，警告提示条"AI 辅助诊断失败，请完全依赖人工判断"（暗室模式：高对比度琥珀色/橙色闪烁边框 + 文字提示 + 3 次蜂鸣音频提示（间隔 1 秒），琥珀色/橙色在暗室中既醒目又传达警示含义，闪烁确保安全关键事件不被忽视；正常模式：红色警告横幅） | 即时 |
| 调度不可达 | 黄色提示"调度服务不可达，导航结果未经中央校验"（暗室模式：高对比度琥珀色/橙色边框 + 文字提示 + 单次蜂鸣；正常模式：黄色横幅） | 即时 |
| 缓存依据输出 | 诊断结果含"缓存依据，基于旧版本知识库"标记时，该结论区域**始终以黄色背景高亮显示**，附加醒目警告标记"⚠ 此结论基于缓存知识，可能非最新，建议重新评估"（暗室模式：高对比度琥珀色/橙色边框替代黄色背景，避免暗室中黄色背景过亮刺眼；正常模式：黄色背景高亮）。不自动折叠——超声检查中医生双手操作探头，自动折叠可能打断阅读且触摸事件检测不可靠。医生可通过点击"重新评估"按钮触发新诊断（限 1 次重试），新诊断使用最新知识库版本 | 即时 |
| 语音指令 | 转写文本实时显示 + 确认按钮 | 转写 < 500ms |
| 患者未同意 | 系统进入**纯报告模式**：AI 诊断入口灰色禁用，保留基础报告编辑功能 | 即时 |

**纯报告模式功能清单**：

| 功能 | 可用性 | 说明 |
|---|---|---|
| 基础报告编辑 | ✅ 可用 | 手动填写超声所见、诊断意见、建议等 |
| DICOM 影像查看 | ✅ 可用 | 原始超声图像浏览，无 AI 标注 |
| 报告模板选择 | ✅ 可用 | 选择标准超声报告模板 |
| 报告签发 | ✅ 可用 | 手动填写后签发 |
| 患者信息管理 | ✅ 可用 | 查看/编辑患者基本信息 |
| AI 诊断请求 | ❌ 禁用 | 入口灰色禁用，不可点击 |
| AI 导航标注 | ❌ 禁用 | 边缘端停止 AI 标注，仅显示原始图像 |
| 语音指令（诊断类） | ❌ 禁用 | 诊断触发、分级变更类指令不可用 |
| 语音指令（导航类） | ✅ 可用 | "放大""缩小"等导航控制指令仍可用 |
| 反馈提交 | ❌ 禁用 | 无 AI 诊断结果则无反馈对象 |

### 2.1 语音指令确认交互规范

涉及诊断触发、分级变更等关键语音指令，转写结果需医生确认后方可执行：

| 交互步骤 | 前端行为 |
|---|---|
| 语音输入 | 实时显示转写文本（< 500ms，GPU 模式）；降级模式（CPU 推理）端到端延迟 < 4s，前端提示"语音转写降级模式，响应可能延迟" |
| 确认提示 | 转写完成后弹出确认面板，显示转写文本 + "确认执行"/"取消"按钮 |
| 医生确认 | 调用 `POST /api/v1/voice/confirm`，触发对应诊断操作 |
| 医生取消 | 不触发任何诊断操作，转写文本保留在交互历史中供参考 |
| 超时处理 | 确认面板 30 秒无操作自动关闭，不触发诊断操作；关闭后可通过语音重新触发。30 秒超时与超声检查快节奏操作匹配——超声检查中医生通常在数秒内完成确认决策，30 秒已留有充足余量 |

> 导航控制类语音指令（"放大""缩小"）无需确认，直接执行。仅诊断触发和分级变更类指令需确认。确认方式支持点击按钮、语音指令"确认执行"、脚踏开关（如医院配置），适应超声检查中医生双手操作探头的场景。

**语音指令容错机制**：

| 容错场景 | 处理策略 | 前端反馈 |
|---|---|---|
| 语音识别失败 | 提示"未识别到语音指令，请重试" | 黄色提示条 |
| 指令歧义 | 列出可能的指令选项供选择 | 选择面板 |
| 网络超时 | 自动重试 2 次，间隔 1 秒 | 加载动画 + 重试提示 |
| 指令不支持 | 提示"当前不支持此指令" | 红色提示条 |
| 重复指令 | 检测到重复指令（30秒内相同指令），跳过执行并提示 | 灰色提示条 |

### 2.1.1 幂等性要求

前端发起的所有诊断请求必须满足幂等性要求：

| 请求类型 | 幂等性保障 | 说明 |
|---|---|---|
| 诊断请求 | 使用 `request_id` 作为幂等键 | 相同 `request_id` 在 5 分钟内重复提交仅执行一次 |
| 反馈提交 | 使用 `feedback_id` 作为幂等键 | 相同 `feedback_id` 在 24 小时内重复提交仅执行一次 |
| 报告签发 | 使用 `report_id` 作为幂等键 | 相同 `report_id` 重复提交不重复签发 |

> 前端须自动生成唯一的 `request_id`/`feedback_id`/`report_id`，确保请求的幂等性。后端根据这些 ID 进行去重处理，避免重复执行。

### 2.1.2 DICOM 索引转换说明

前端处理 DICOM 帧时须进行索引转换：

| 索引类型 | 说明 | 转换规则 |
|---|---|---|
| 边缘端帧索引 | 边缘端内部帧编号（从 0 开始） | 用于边缘端内部追踪 |
| 会话帧索引 | 会话内帧编号（从 0 开始） | 前端显示给医生的帧序号 |
| DICOM Instance UID | DICOM 文件唯一标识 | 用于 PACS 系统交互 |

**索引转换流程**：
1. 边缘端推送帧时携带 `frame_index`（边缘端帧索引）和 `instance_uid`（DICOM Instance UID）
2. 前端维护会话帧索引映射表：`session_frame_index = len(received_frames) - 1`
3. 前端显示时使用会话帧索引，与 PACS 交互时使用 DICOM Instance UID

### 2.2 患者知情同意状态显示

| 交互步骤 | 前端行为 |
|---|---|
| 会话创建前 | 调用 `GET /api/v1/consent/{patient_id}` 查询同意状态 |
| 已同意 | 正常进入 AI 辅助诊断模式，所有 AI 入口可用 |
| 未同意/已撤回 | 进入纯报告模式：AI 诊断入口灰色禁用，页面顶部显示蓝色提示"患者未签署/已撤回 AI 辅助诊断知情同意，系统运行于纯报告模式" |
| 检查中撤回 | 已生成结论标记"患者已撤回 AI 辅助同意"，前端立即隐藏 AI 入口，边缘端停止 AI 标注；在途诊断请求自动取消，中间结果不展示。**前端展示层同意状态检查**：诊断结果到达前端后，前端根据后端响应中的 `consent_status_at_output` 字段（SafetyGateway 输出前直查 PostgreSQL 获取的同意状态快照）决定是否展示诊断结论区域，无需额外调用 `GET /api/v1/consent/{patient_id}`。后端 SafetyGateway 已确认同意状态为 granted 方输出结果，前端信任后端判断即可。撤回事件通过 WebSocket `session_terminated` 推送处理（详见 [03-接口规范](03-接口规范.md) §1.4），前端收到撤回事件后立即隐藏诊断结论区域并显示提示"患者已撤回 AI 辅助同意，诊断结果不可用"。此设计减少不必要的 API 调用和 PostgreSQL 查询负载——安全防线完全由后端 SafetyGateway 保障（详见 [01-系统架构设计](01-系统架构设计.md) §3.4 输出前同步同意状态校验），前端无需重复校验 |

### 2.3 AI 诊断失败降级状态机

| 状态 | 触发条件 | 前端行为 | 可执行操作 |
|---|---|---|---|
| 正常 | AI 诊断成功 | 展示完整结论 + 依据 + 置信度 | 确认/修正/反馈 |
| AI 失败-可重试 | 首次失败（`ai_diagnosis_failed=true`） | 禁用诊断 UI，警告提示条（暗室模式：高对比度黄色边框 + 文字提示；正常模式：红色横幅），仅展示 `observations` 字段（白名单内单属性列表），`diagnostic_conclusion` 字段不展示。**重试期间 UI 状态**：显示"AI 诊断重试中..."加载指示器，同时保留手动报告编辑功能可用（医生可在等待重试结果的同时手动填写报告）。重试结果到达后，若成功则更新诊断区域；若失败则隐藏重试按钮，标记永久降级 | 点击"重试 AI 诊断"（限 1 次） |
| AI 失败-永久降级 | 重试仍失败或医生放弃 | 警告提示条（暗室模式：高对比度黄色边框 + 文字提示；正常模式：红色横幅），仅展示 `observations` 字段，`diagnostic_conclusion` 字段不展示 | 该会话后续不再调用 AI 诊断 |

> 重试按钮仅在首次失败时显示，点击后调用 `POST /api/v1/diagnosis/request`（`retry_strategy` 根据失败原因设置：检索相关失败 E2001/E2006 设置 `full_retrieval`，生成相关失败 E3003 设置 `generation_only`，质检失败设置 `quality_check_only`）。重试请求一律跳过 Self-RAG 重试（仅执行 1 次生成+质检），将前端重试延迟控制在 3s 以内。重试失败后隐藏按钮，会话标记 `ai_permanently_degraded`。

**脱敏降级状态前端展示规范**（与 [01-系统架构设计](01-系统架构设计.md) §3.4 SafetyGateway 降级策略对齐）：诊断结果响应中包含 `desensitization_status` 字段（`full` / `degraded`），前端须根据该字段区分展示：
- `desensitization_status=full`（正常模式）：不额外提示，按标准 UI 展示诊断结果
- `desensitization_status=degraded`（SafetyGateway 降级模式）：在诊断结果区域的脱敏标记旁附加橙色提示标签"降级模式，身份信息保护等级降低，请人工核验脱敏结果"（暗室模式：高对比度琥珀色/橙色边框 + 文字提示；正常模式：橙色横幅），确保医生知悉当前脱敏策略与正常模式不同（正常模式使用 ML NER + 规则增强 NER 严格脱敏，降级模式使用"类型化脱敏"策略——`[REDACTED:{类型}]` 替换，与 [01-系统架构设计](01-系统架构设计.md) §3.4 降级策略总表及 [04-安全合规](04-安全合规.md) §2 降级模式脱敏策略对齐）

### 2.4 导航标注安全状态视觉区分规范

导航标注按安全校验状态采用差异化视觉渲染，与 [01-系统架构设计](01-系统架构设计.md) §1 输出安全分级框架 B 级（导航级）安全容忍度对齐：

| 安全校验状态 | 视觉样式 | 说明 |
|---|---|---|
| 已校验（后端校验通过） | 实线边框 + 高亮填充 + 实色标签 | 标注已通过完整安全校验链路，可信度高 |
| 待校验（后端异步校验中） | 虚线边框 + 半透明填充 + 闪烁提示"待校验" | 后端校验进行中，约 50ms 内完成校验或移除 |
| 校验超时/后端不可达（一期后端中转模式） | 导航标注区域替换为"导航服务中断"提示 + 红色连接状态指示灯 | **一期后端中转模式下后端不可达时导航标注不可用**——边缘端与前端无直推路径，后端不可达则导航功能中断。前端显示"导航服务中断"提示，与 [01-系统架构设计](01-系统架构设计.md) §2.2 一期降级策略一致 |
| 校验超时/后端不可达（二期直推模式，规划中） | 虚线边框 + 半透明填充 + 黄色警告标记"未经安全校验" | 二期直推模式下后端不可达时边缘端导航标注继续直推前端展示，附加警告 |
| 后端校验移除 | 标注消失 + 短暂红色闪烁提示"导航标注经安全校验已移除：[原因]" | 后端校验不通过，标注被移除 |
| 器官切换中（二期直推模式） | 灰色虚线边框 + 半透明灰色填充 + "[旧器官]模型标注，切换中"提示文字 | 器官模型切换期间边缘端使用旧器官模型产出的导航标注，前端须明确标识避免误判 |
| 器官切换中（一期后端中转模式） | 导航标注区域替换为"器官模型切换中，导航暂停"提示 | 一期后端中转模式下器官切换期间后端暂停导航标注推送，前端显示切换中提示。5-10 秒的导航中断在超声检查中可接受（医生仍在操作探头）。新器官模型加载完成后前端收到 `organ_switching: false` 事件后恢复正常导航标注渲染。与 [01-系统架构设计](01-系统架构设计.md) §4 一期后端中转模式器官切换期间导航标注处理规则一致 |

> **视觉区分设计原则**：未校验标注（虚线+半透明）与已校验标注（实线+高亮）的视觉差异须足以在超声检查的快速操作中区分——医生在 1 秒内应能识别标注的校验状态。虚线边框间距 ≥ 4px、半透明度 ≤ 60%，确保视觉区分度。此规范与 [01-系统架构设计](01-系统架构设计.md) §1 B 级安全容忍度"有限容忍——~50ms 安全窗口内可展示未校验标注，但须附加视觉区分"一致。**器官切换中标注的视觉区分**：灰色虚线框与正常蓝色实线框的色相差异须 ≥ 30°（色相环），确保在超声图像的灰度背景上可快速区分。器官切换完成后，前端收到 `organ_switching: false` 事件后立即清除所有灰色虚线框标注，恢复正常蓝色实线框渲染，详见 [01-系统架构设计](01-系统架构设计.md) §4 器官切换期间边缘端导航标注处理规则。

### 2.5 严重幻觉与路径结论差异前端处理规范

**严重幻觉前端处理**（与 [01-系统架构设计](01-系统架构设计.md) §3.5 严重幻觉输出处理规则一致）：诊断结果响应中 `hallucination_severity="severe"` 时，前端须执行以下处理：

1. **红色警告横幅**：在诊断结果区域顶部显示不可关闭的红色警告横幅"⚠️ AI 检测到生成内容可能存在严重幻觉，请务必人工核验诊断结论"，横幅须持续显示直至医生点击"已知晓"确认按钮
2. **诊断结论高亮标记**：`diagnostic_conclusion` 字段附加红色边框 + "严重幻觉检测"标签，与正常结论的蓝色边框区分
3. **强制人工复核提示**：`requires_manual_review=true` 且 `review_reason="severe_hallucination_detected"` 时，诊断结论区域禁止直接签发，须医生手动确认"已人工核验"后方可签发报告

**标准/全量路径结论差异前端处理**（与 [01-系统架构设计](01-系统架构设计.md) §5.3 Adaptive RAG 动态路由规则一致）：标准路径初步结论与全量路径深度分析结论不一致时，前端须同时展示两者并标注差异：

| 展示元素 | 样式 | 说明 |
|---|---|---|
| 标准路径初步结论 | 蓝色边框 + "初步结论"标签 | 标注"初步结论，基于标准路径分析" |
| 全量路径深度分析结论 | 绿色边框 + "深度分析"标签 | 标注"深度分析结论，基于完整校验链路" |
| 差异说明 | 黄色高亮差异部分 + 差异原因 | 如"初步结论：TI-RADS 3 → 深度分析：TI-RADS 4b，差异原因：多特征组合推理需完整校验" |

> **结论差异展示原则**：不直接替换初步结论，而是同时展示两个结论供医生对比参考——医生可能已基于初步结论形成初步判断，突然替换可能导致认知混乱。全量路径结论为更可靠的参考依据（经过完整校验链路），但初步结论仍保留供对比。

| 图表 | ECharts | 质控报告页趋势图 |
| 部署形态 | 浏览器 Web 应用（Chrome 110+） | 无需安装，医院内网访问；暗室环境通过深色主题适配 |

> **二期规划参考——直推模式设计**：前端与边缘端之间**仅建立导航标注直推的 WebSocket 连接**，不直接调用边缘端的诊断/管理接口（诊断请求由前端发起至后端，后端调度边缘端）。边缘端导航标注直推前端（边缘端通过本地 WebSocket 服务器直接推送导航标注至前端，前端接收后立即渲染，无需等待后端校验）；后端异步校验不通过时通过后端实时通信通道发送 `navigation_revocation` 消息通知前端移除对应标注。诊断结果优先通过后端实时通信通道推送通知，前端收到通知后通过 HTTP REST 获取完整结果；WebSocket 不可用时降级为 HTTP 轮询。实时导航延迟预算已计入直推模式下的网络传输（边缘端→前端一段传输），详见 [00-项目总览](00-项目总览与核心指标.md) 2.1 节。直推模式需实现 `TripleWebSocketManager`（三连接：后端实时通信通道 + 后端 DICOM 帧通道 + 边缘端导航直推通道），边缘端 WebSocket 认证、直连降级方案等详见 [09-二期规划](09-二期规划与远期增强.md)。

## 5. 使用指南

### 5.1 超声科医生

1. **登录**：通过医院统一认证登录
2. **患者知情同意**：确认患者已签署知情同意书；拒绝则系统进入**纯报告模式**（隐藏 AI 诊断入口，保留基础报告编辑功能）
3. **创建检查会话**：选择检查部位，系统自动关联患者信息并预加载器官知识
4. **检查中交互**：
   - 系统自动接收 DICOM 图像并实时分析（快速路径）
   - 语音输入："帮我评估这个结节" → 触发标准路径
   - 点击操作：选择病灶区域 → 触发全量路径
5. **查看结果**：诊断结果含结论、依据、置信度、质控状态、知识库版本
6. **确认或修正**：确认纳入报告，或提交修正反馈

### 5.2 科室主任

1. **审核 L3 反馈**：知识纠错类反馈交叉审核
2. **查看质控报告**：准确率、漏诊率、幻觉率、AI修正率告警
3. **调整阈值**：根据临床实际调整置信度阈值（记录审计日志）
4. **审批高风险病种清单**：每半年复审

### 5.3 系统管理员

1. **模型版本管理**：灰度发布、回滚
2. **日志查询**：按时间、用户、操作类型查询
3. **系统监控**：实时性能指标、GPU 健康、告警
4. **知识库版本管理**：查看版本、触发复审
5. **一键式运维操作**（compact 模式专用）：API Key 轮换（单按钮触发，自动完成旧 Key 失效→新 Key 生成→边缘端同步→验证连接）、设备隔离与恢复（单按钮触发，自动完成设备状态检查→隔离/恢复操作→验证设备连接）、模型热重载（单按钮触发，自动完成等待空闲→卸载旧模型→加载新模型→预热推理→恢复服务）。所有一键操作须二次确认（模态对话框展示操作影响范围），操作结果实时反馈（进度条+成功/失败状态），操作记录审计日志。一键式运维界面将底层复杂操作封装为单个按钮操作，降低基层 IT 人员的理解门槛，与 [01-系统架构设计](01-系统架构设计.md) §5.8 compact 模式运维策略对齐

## 2. 实时双通道（nav + dicom）

### 2.1 契约（与后端一致）

| 项 | 前端行为 | 后端要求（见 `03-接口规范.md` §3） |
|---|---|---|
| 握手 Query | `session_id` + `device_id`（**必填**） | `Query(...)` 必填，缺失在握手阶段即被拒 |
| 鉴权 | 连接后发 `{type:'auth', session_id, token}` | 5s 内首条必须是 `AuthMessage`；走 `token + session_id` 路径 |
| 建立顺序 | nav `auth_ok` → 才建 dicom 通道 | — |
| 心跳 | 每 **5s** 发 `ping`；**连续丢 3 次**触发重连；收到服务端 `ping` **回 `pong`** | 后端连续 3 次未收 pong → 关闭 `WS_1001_GOING_AWAY` |
| 重连 | 指数退避 `1s × 2^n`，上限 30s，最多 20 次；关闭码非 1000 才重连 | 鉴权失败码 `4001`、超时 `4002` |

### 2.2 连接条件与生命周期

`hooks/useRealtimeConnection.ts` 是 `wsManager.connect()` 的**唯一调用点**（挂在 `AppLayout`，
覆盖所有需登录页面）：**必须同时具备 `sessionId` + `deviceId` + token 才连接**，
会话切换或组件卸载时 `disconnect()`（避免旧连接继续往新会话推送）。

> 要求 `deviceId` 是刻意的：会话创建接口 `SessionCreateRequest` 里 `device_id` 必填，
> 因此正常流程一定具备；缺参时**直接不连**，而不是连上后无限重连。

### 2.3 消息分发

`wsManager` 只维护 handler 列表；实际派发在 `hooks/useNavigationAnnotations.ts:11-29`
→ `websocket/navChannel.ts` → `useNavigationStore` / `useSessionStore`（`navChannel.ts:6-65`）；
DICOM 二进制帧经 `onDicomFrame`（`:105`）。

### 2.4 本次修复（2026-09-28）

| 缺陷 | 修复前 | 修复后 |
|---|---|---|
| 调用点 | `wsManager.connect()` **无任何调用点**，`websocketStore.setUrls` 亦无 → **双通道从未建立** | 新增 `useRealtimeConnection`，`AppLayout` 调用 |
| Query 参数 | `buildWsUrl` 不带 query → 后端必填校验**握手即拒** | 新增 `wsParams()`，nav/dicom 均带 `session_id`/`device_id` |
| 心跳应答 | switch **无 `ping` 分支**，不回 pong → 十几秒后被判死并反复重连 | nav/dicom 均补 `ping → pong` |

守卫：`frontend/src/hooks/__tests__/useRealtimeConnection.test.ts`（6 项）。

## 4. 核心交互流程

### 4.1 诊断主流程

`ExaminationPage.requestDiagnosis`（`:53`）→ `navigate('/diagnosis?request_id=…')`（`:63`）
→ `DiagnosisPage` 读 `request_id`（`:39`）→ `startPolling`（`:66-82`）
→ `pollDiagnosisResult`（`diagnosisService.ts:137`）：首延迟 **800ms**、间隔 **1500ms**、
**总等待上限 60000ms**、瞬时失败退避 ×1.5（上限 8000ms）
→ 阶段先"预计"（`resolveStage`）后"真实"（`extractStageTimings`）
→ 结果**分段揭示**：结论 → 安全警示 → 质控 → 证据链（延迟 0/120/280/440ms，`useProgressiveDiagnosis.ts:17-29`）
→ 完成后 `navigate('/report?request_id=…')`（`DiagnosisPage.tsx:501-503`）。

### 4.2 报告与签名（`ReportPage.tsx`）

生成草稿（`:99-117`）→ **签发** `signReport`（`:119-132`，按钮 `disabled={signed}`）
→ **推送** `pushReport`（`:134-146`，`disabled={!signed}`，未签发时提示 `:344-347`）
→ **验签** `verifyReportSignature`（`:148-166`）。
失败统一 `getApiErrorMessage` + `message.error`，**无自动重试**，靠医生再点；
完整性面板列出缺失段落（`:270-296`）。

### 4.3 DICOM 阅片（cornerstone）

- 工具集**仅** 窗宽窗位 / 缩放 / 平移（`DicomToolbar.tsx:23-27` → `WwwcTool`/`ZoomTool`/`PanTool`，`DicomViewer.tsx:169-181`）；

- 帧切换 prev/next（`:97-125`）、overlay 开关（`:63-71`）；
- ⚠️ **没有任何测量工具**。

### 4.4 语音交互

`VoiceControl.tsx`（常驻）→ `useVoiceRecorder` 录音 → `POST /speech/recognize`
（16k 单声道 PCM base64，`useVoiceRecorder.ts:280`）→ `parseVoiceCommand` **保守关键词解析**（`voiceCommand.ts:110`）
→ `VoiceConfirmDialog` **必须人工确认** → `POST /voice/confirm`（含 `confirmed=false` 的拒绝上报）。

降级路径（5 类：权限拒绝/无设备/过短/不支持/转写失败，`useVoiceRecorder.ts:19-21,103-112`）：
右键或长按可"手工输入"（`:161-165`）、"重新解析"（`VoiceConfirmDialog.tsx:71-81`）。
反馈页用 `VoiceDictationButton`（**只转写不执行**，`:21-34`）。

> **设计意图**：语音**不能直接触发诊断**——必须经确认弹窗，这是防止误识导致误诊的关键约束，勿简化掉。

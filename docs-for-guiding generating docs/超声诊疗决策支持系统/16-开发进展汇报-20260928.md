**失败模式分析**（报告 failure_analysis，587 例分级失败）：
1. **两个 1.5B 引擎的独立采样方差是主因**：llama.cpp Q4_K_M 量化输出含重复/幻觉段落

2. **心脏最差（8.2%）**：LVEF→分级的映射在两引擎间系统性分歧（84.9% 边界跨越），

   （"轻度降低"vs"mildly_reduced"vs 直接复述 LVEF）。
3. **61 例分级提取失败**：正则 `TI-RADS/LI-RADS/LVEF` 覆盖不了引擎的自由表述
   （如"TR4a"、"3 级（TI-RADS）"），提取失败被计为不一致——需扩展抽取口径或
   约束输出格式（如强制 JSON 字段）。

**过程中拔出三颗"实现了但从未接线/从未跑通"的钉子**：
1. `knowledge_chunks.embedding` ORM 硬编码 `Vector(768)`（Ultrasound-CLIP 时代），

   正式迁移文件待补）；
2. `hybrid_indexer.py` upsert 的 `on_conflict_do_update(set_=…)` 用了 ORM **属性名**
   `"meta"` 当键——`set_` 字符串键是**数据库列名**（物理列 `metadata`）→ 首次建库
   即 `column "meta" does not exist`（该路径此前从未真机跑通）。已修复并抽
   `build_upsert_statement()` 加编译级回归守卫（`test_hybrid_indexer_upsert.py`）；
3. **接线缺口**：`init_knowledge_base.py` 只写 `knowledge_chunks`，而生产检索器
   （`app/rag/retriever.py`）读的是 `vector_index_knowledge_chunks`——建库后向量
   索引表为空，dense 检索什么都查不到。新增 `scripts/server_populate_vector_index.py`
   （经生产客户端灌数，幂等）补上该步。

**Gate 1 检索准确率（KB 级 golden set：语料=433 chunks，查询=200 条 chunk 首句截断）**：

| dense（bge-m3） | 0.945 | 0.965 | 0.876 | 0.898 |

反超单腿（RRF 融合在 KB 语料上生效）。报告：`tests/reports/t1_kb_retrieval_eval.json`。

**端到端打通**：生产 `PgvectorVectorIndex.search(filter={'organ':'thyroid'})` 实测
命中 5/5 全 thyroid；主服务冒烟 `completed + requires_manual_review=False +
desensitization_status=full`。**带知识注入的完整 RAG 链路首次真实工作**。

**知识注入暴露并修复的上线级问题**：诊断 prompt（含真实 KB 检索内容）达 5943

（Q8_0 7B 显存可行）。期间发现 **vLLM V1 的 `VLLM::EngineCore` 是独立子进程，

### A.6 T1c：第一轮检索调优 + faithfulness 生成评测基线（2026-09-29）

**方法论全部对齐权威源（不自造）**：QA 型 golden set 构造对标 BEIR/MS MARCO
查询-文档相关性构造；加权 RRF 用 Elastic 官方公式
`fused(d)=Σ w_i/(rank_i+rank_constant)`（2025-09 官方博客）；两阶段 rerank 按
业界惯例"召回 Top-N → Cross-Encoder 精排 → Top-k"；chunk 区间取主流
512~1500 tokens 口径；faithfulness 照抄 RAGAS 官方实现与 prompt
（vibrantlabsai/ragas，Apache-2.0，`scripts/prompts/ragas_faithfulness.py`）。

**评测集升级**：QA 型 golden set——136 条**真实患者问题**（医疗对话数据的患者
提问，肿瘤/外科/内科分层），gold=来源文档全部 chunk（source_doc 级相关性，
chunk 变体跨版本可复用）。构造：`scripts/t1b_build_qa_golden.py`。

**① 检索调优网格（报告 `tests/reports/t1_tuning_*.json`）**：

| 配置 | R@5 | R@10 | MRR@10 | nDCG@10 |
|---|---|---|---|---|
| **基线：等权 RRF k=60（现状）** | 0.993 | 0.993 | 0.984 | **0.985** |
| 加权 RRF 12 格（w×k_const） | 0.993 | 0.993 | — | 0.980~0.985 |
| + rerank top_n=20/50/100 | — | **1.000** | — | 0.982 |

- **结论：等权 RRF(k=60) 已是最优**——加权网格无增益（向 dense 偏移反而降
  nDCG）；bge-reranker 精排可将 R@10 提到 100%（top_n=20 即满，约 22ms/例）
  但 nDCG 略降（-0.3pp），排序质量无增益。
- **chunk 策略不敏感**：kb_v1.0.1（大块 450-900 tok，420 chunks）/
  kb_v1.0.2（小块 ~300 tok，459 chunks）与基线（256-512 tok，433 chunks）
  三版本 R@10 全部 99.26%，nDCG 差 ≤0.2pp——对话语料一问一答天然成块，
  chunk 边界无影响。**维持默认 sentence_boundary**。

**② faithfulness 生成评测基线（`tests/reports/t1_faithfulness_report.json`）**：

- 流程：真实患者问题 → 等权 RRF Top-5 上下文 → llama.cpp 7B 生成 →
  vLLM 7B 判官（RAGAS 断言分解 + NLI 逐条判定）+ 数值一致性启发式交叉校验
- **实测：mean faithfulness = 56.3%（97/100 成功解析），门控 ≥95%（对应整体
  幻觉率 ≤5%）❌ 系统性未达标**；拒答 9 例（正确拒答记 1.0，官方空断言
  口径）；数值一致性 78%
- **归因（抽样确认）**：①**判官过严是主因**——7B 判官 NLI 能力有限，
  常识性改写（如"甲状腺肿大=颈部肿胀"）一律判 0（RAGAS 官方明确判官应为
  GPT-4 级强模型，同规模 7B 是已知局限）；②生成腿存在上下文外扩写（超出
  检索片段但医学上常见的事实补充），按"依据溯源校验"口径不可溯源；
  ③解析噪声已在 v2 修复（首轮 84/100 判官 JSON 解析失败 → 引入
  json_repair 修复库 + 拒答/元语句处理）。
- **改进路径（后续轮次）**：升级判官（更强模型或 RAGAS 官方支持的
  HHEM-2.1-Open 专用 NLI 分类器）；生成 prompt 强化溯源约束（仅复述检索
  片段内信息）；抽样人工标注校准判官。

**本轮新增钉子**：chunk_id 生成不含 kb_version——多版本共存时 resume 的
exists() 跨版本误判（变体建库 0 chunks）且 upsert 会**静默覆盖其他版本**
同 id 行（PK 级隐患）→ chunk_id 改为 `{kb_version}:{source_doc_id}#{index}`，
三版本重建验证通过（守卫：`test_build_chunk_id_format`）；灌数脚本加
`--purge` 防陈旧残留。

#### A.2.2 双引擎定位修订：部署档位等价性 + 口径决策项（2026-09-30，详见 10 号 v1.3）

1. **定位修订**：双引擎 = compact（llama.cpp）/ full（vLLM）**部署档位
   等价性验证**，非热备冗余。A2/A3 数据支持该修订：格式统一后两引擎
   同源模型一致率 80%+，剩余分歧为边界模糊用例设计内行为。
2. **口径决策项（管理决策，待项目组确认）**：780 例门控 ≥95% 应分层——
   常规+高风险（340 例）与边界模糊（440 例，刻意 ±1.5 抖动构造）分开
   统计；边界用例采用语义等价/边界容差口径。决策后重算门控。
3. **达标主路径更新**：约束解码（guided decoding/GBNF）+ 统一解码参数，
   而非更换基座（A3 已证 7B 无净收益）。
4. **前置缺口（T2c 实测，A.7）**：端到端响应无结论文本（契约缺装载）、
   管线单例 26s（fusion 19.6s）——两者修复前，部署档位等价性在用户
   可感知层面无法验证。

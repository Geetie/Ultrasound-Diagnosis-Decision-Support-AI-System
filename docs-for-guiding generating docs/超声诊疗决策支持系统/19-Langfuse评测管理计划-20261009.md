# 19-Langfuse 评测管理计划（2026-10-09）

## 一、目标
把"双引擎评测集 ≥700 例"从口号变成可持续运营的评测资产：每次判读自动产生
trace（问/答/检索依据/耗时/SG 结论），坏例沉淀进评测集，指标门控进 CI。

## 二、分期
**P1 采集（1 周）**：判读管线出结果时同步写 trace（Langfuse SDK，self-host
部署在服务器 8003 旁）；字段=输入(clinical_text/imaging_metadata/organ)、
输出(结论/ malignant_risk/actions)、中间态(retrieval chunks+分数、SG allowed、
timings_ms)。已有 timings_ms 落库可复用为 trace 元数据。
**P2 数据集管理（1 周）**：医生/质控在反馈页标记"结论有误" → 坏例自动快照
（输入+输出+正确口径）入评测集；去重（同患者同影像 hash）；≥700 例进度条。
**P3 门控（3 天）**：faithfulness/答案相关性离线批跑（RAGAS 口径脚本已有），
阈值 95%/90% 不达标即阻断 feature 合入 —— 与 quality 门禁同层。

## 三、验收判据
①任意一次真机判读可在 Langfuse 界面看到完整 trace；②评测集条目 ≥700 且
含 ≥50 例医生标注坏例；③门控脚本入 Makefile。

## 四、风险
自托管 Langfuse 需 Postgres+Clickhouse 资源（服务器紧张 → 先用 Postgres 后端
小规模跑）；数据外发禁止 → 仅 self-host，禁 SaaS。

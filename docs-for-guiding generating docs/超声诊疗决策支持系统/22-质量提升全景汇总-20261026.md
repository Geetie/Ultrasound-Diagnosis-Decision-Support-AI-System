### Q2. `r17-rrag-metric-caliber` 两项 RAG 指标口径拍板

**情景**：faithfulness 实测 **0.0906**，门限 **0.95** —— 差 **10 倍**。
但低分不是"模型在胡说"：结论 = 影像所见 + 知识建议，
而**影像所见永远不在知识库里**（"右叶低回声结节、边界清"是我看到的，不是书上抄的）。
所以即使知识部分 100% 有据，总分也上不去。三个候选口径只差 ~0.03（A 判全文 0.0906 /
B 只判理由后 0.1258 / C 剔除派生字段 0.0836），说明**换口径救不了这个指标**。

**提升后的效果**：
* 若拍板切成「引用正确率」（逐句查引用段落是否支持），指标**从语义上变得可达成** ——
  它衡量"引的知识对不对"，而不是"影像所见能不能在书上找到"；
* 若保留 faithfulness 但降为诊断指标（不进 gate），则**不再有 7 倍差距阻塞交付**；
* 无论哪种，「替代监控四量」（周滑动中位数/未测到率/口径覆盖率/改检索后重跑同切片）
  上屏后**趋势可见** —— 现在改了检索没有任何方式判断好坏。

**怎么算做完**：口径拍板 + 四量看板上屏 + `--judge-mode gate` 的四条判据写入脚本 help。
**卡在谁**：**项目组拍板**。

### Q3b. 分级无法判断的真根因：**76% 是"没给影像特征"**（新测得，非立项项）

> 这一条不在 `feature_list` 里 —— 是本次汇总时**新测出来的**，所以登记为观察结论。

**实测**（thyroid 59 条「分级: 无法判断」样本）：

| 特征 | 命中 | 占比 |
|---|---|---|
| 正文明确说**缺影像特征** | 45/59 | **76%** |
| 说"信息不足/不足以" | 40/59 | 68% |
| 建议人工判读 | 16/59 | 27% |

典型原文：
> 甲状腺 · TR3 — … 理由: 由于**缺乏具体的影像特征描述**和临床信息，现有知识
> 无法给出确切的 TI-RADS 分级。建议结合图像与病史进行人工判读。

**结论：不是解析 bug，是"输入侧没把影像特征喂给模型"。**
所以修法应该在 **prompt / 影像腿**，而不该继续改解析逻辑
（A.93 已经修掉了 `_extract_reason` 吞整段这个真 bug，但那只解决"展示矛盾"，
不解决"确实判不出来"）。

**情景**：现在医生看到 TR3 但理由是"判不出来"—— 系统等于说
"我给它分了个级，但我其实没依据"。这种输出**对临床是负价值的**（比不给更糟）。

**提升后的效果**（若把影像特征真正送进 prompt）：
* 19.3% 的"无法判断"大部分可变成有依据的分级 → **甲状腺可用率从 80.7% 提到 90%+**；
* 医生不再需要"看到 TRx 但又不敢信"；
* A.93 加的那句"分级来自结构化重试、依据仍不充分"提示会**大幅减少触发**
  （因为首次输出就能给出分级，不必重试）。

**根因已定位（本次核对）**：不是模板缺位置，是**开关没开**。

| 核对项 | 实际 |
|---|---|
| `app/agents/prompts/thyroid.md` | **要求**影像特征（成分/回声/形态/边缘/钙化），并规定"未提到的特征记 0 分" |
| `rag_use_multimodal` | **`False`**（默认关）→ 影像腿不参与检索 |
| 影像腿本身 | **可用**：A.90 实测裁决 `GAIN`（36 例跨 3 器官，新增 54 块）；584/584 影像已假名化 |

即：**模板在要特征，但影像腿没开，模型只能看到文本 —— 拿不到特征，只能写"缺影像特征"**。

**怎么修（待立项，两小步）**：
1. **打开 `rag_use_multimodal` 做 A/B**：同一批真实影像，开关 on/off 各跑 N 例，
   对比"无法判断率"与"分级分布"；A.90 的 `p62` 三臂脚本可直接复用；
2. 若确认有效，再定默认值（涉及性能：影像腿每例多一次 CLIP 嵌入 + 一次 Qdrant 检索，
   A.90 实测 `image_leg.attach_ms ≈ 17~18ms`，可接受）。

**卡在谁**：自己能做（**纯 A/B，不动数据**）。

**⚠️ 前提**：这条与 A.90 的结论一致 —— 影像腿"接线已通、贡献已量化（GAIN）"，
但**从未在完整的诊断链路里以 `on` 状态跑过**（A.90 是检索层 A/B，不是判读质量 A/B）。
这正是"打通 ≠ 真实实现"的又一个例子：腿通了，但没接到实际产出上。

**情景**：**无任何可商用公开数据集** —— TN3K/TG3K 是 NC（非商业）、TNSCUI 是 ND（禁止分发）、
HF ThyroidDataSet 是 gated 且含 NC 子集。这意味着**当前所有对外数字都不能作为注册证据**。
**提升后**：自有/合作医院或授权采购数据到位后，Q5（独立验证）、Q6（NMPA）、
Q23（faithfulness 语料）**三项同时解锁**。
**卡在谁**：**数据方/商务**。

### Q26. `e5-speech-medical-verify` 语音医疗术语实效验证

**情景**：ASR 链路已通（模型自带真实语音 **3/3**），但"医生口述 + 医疗术语"**缺真实样本**。
公开的"医生口述超声报告"中文数据集**不存在**。
**提升后**：真实验证后，医生可以**口述生成报告草稿** —— 这是最直接的效率提升
（一条报告打字 3~5 分钟 → 口述 1 分钟）。当前数字 3/3 不能证明医疗术语准确率。
**卡在谁**：**真实医生语音样本**（用户 2026-10-12 已决策：暂不可得，挂起）。

### Q27. `r3-hard-set-expand` 难集造不出来（与 Q8 同一条目，此处记「为什么它算阻塞」）

**情景**：golden 集已饱和（136 条 top-1 命中 129、累计 hit@10 **0.9853**）——
任何检索改进在它上面都显示"没变化"。而 A.68 已实测：现有语料上**造不出**
gold 唯一的难集（放宽分组 `prefix2`≡exact、`prefix1` 更糟；指南 `section_path`
只有 8 个取值、组内 2~5 篇的小组 = 0）。

**提升后的效果**：难集成立后，**R2（邻居选择器）/ R4（嵌入换代）两项才有判定依据** ——
现在它们卡的不是技术，是**没有能分辨好坏的尺子**。这一项同时决定了
"图谱扩边那 +15pp 召回到底能不能用上"。

**卡在谁**：**新语料**（细粒度章节的长文档，或人工标注「问题→依据段落」对）。
不是我们能凭空造的 —— 所以它列在 blocked 而非 planned。

**与 Q8 的关系**：Q8 描述"要做什么"，本条记录"为什么它现在是阻塞而不是待办"。
### Q28. `a70-prompt-echo-defect` 结论输出泄漏提示词示例

**情景**：A.70 发现评测集 **98.7%（155/169）的结论是提示词示例整段照抄** ——
里面含 `chunk_a1b2`/`chunk_c3d4`/`患者PATIENT_001` 占位符与重复 4 份 `# 输出` 块。
**真实引用率 0**。所有基于这些样本的指标（faithfulness 0.0906 等）**只反映"抄示例"**。
**提升后**：提示词示例脱敏 + 生产侧拒收后（已修），**评测集重新变得可信**；
该项是 Q2/Q23 的**前置**——不清掉，重测也没意义。

## 第四部分 · 技术债与升级（15 号 P0/P1，尚未全清）

### Q29. `P0-2` 双引擎一致率改「约束解码」路线
**情景**：原 llama.cpp 已弃用（CPU-only 构建，7B 实际跑 8 线程 CPU），
双引擎一致率口径随之失效；`N_CTX=512` 与诊断 prompt 5943 tokens 的矛盾真机已暴露。
**提升后**：vLLM `response_format: json_schema` 约束解码后，**780 例重测分级一致率 ≥95%**，
结构化输出不再靠 prompt 祈祷。

### Q30. `P0-3` faithfulness 判官升级（HHEM-2.1-Open 替代 7B LLM 判官）
**情景**：现用 7B LLM 当判官，**判官自身的判断力就是上限**。
**提升后**：专用 NLI 判官与人工标注子集相关性达标后，**指标可信度提升一个档**；
也是 Q23 口径拍板的技术前提之一。

### Q31. `P0-4` 依赖安全清理
**情景**：`python-jose`（已不维护）、`passlib`（2022 停更 + bcrypt 4.x 兼容问题）、
锁定漂移（`prometheus_client` 锁 0.20 vs 实装 0.25 —— **这就是直方图 p99=None 的诱因**）。
**提升后**：`pip-audit --strict` 通过 + "锁定 vs 实装"守卫测试后，
**p99 这类指标不再因为依赖漂移而静默失效**（这正是 A.90/A.91 反复踩的坑）。

### Q32. `P0-5` P0 安全项
**情景**：`/api/v1/internal/obs/*` **四端点无认证**（含写操作 cold-archive/run）；
DICOM 去标识化非 fail-closed；vLLM V1 EngineCore 孤儿进程真机曾占 **33GB 显存**。
**提升后**：安全域回归通过后，**内部端点不再是后门**；去标识化失败即拒存
（不是"失败也存"）；GPU 不再被孤儿进程占死。

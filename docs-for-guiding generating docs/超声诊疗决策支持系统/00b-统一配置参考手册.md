## 二、架构配置项

### 2.1 部署模式配置

| 配置项 | 默认值 | compact | full | 说明 |
|--------|--------|---------|------|------|
| `DEPLOYMENT_PROFILE` | `compact` | ✅ | ✅ | 部署模式：`compact`（基层）或 `full`（三甲） |
| `EDGE_DIRECT_WS_ENABLED` | `false` | ❌ | ❌ | 边缘端直推通道开关（一期强制关闭） |
| `REDIS_SINGLE_INSTANCE` | `true` | ✅ | ❌ | Redis单实例模式（full模式使用主从） |
| `PG_POOL_MAX_SIZE` | 10 (compact) / 20 (full) | 10 | 20 | PostgreSQL连接池最大大小 |

### 2.2 边缘端配置

| 配置项 | 默认值 | 说明 | 约束条件 |
|--------|--------|------|----------|
| `EDGE_DEVICE_ID` | 必填 | 边缘设备唯一标识 | 64位UUID格式 |
| `EDGE_MODEL_PATH` | `/models/trt/` | TensorRT模型路径 | 必须包含预编译引擎文件 |
| `EDGE_HEARTBEAT_INTERVAL` | `30s` | 设备注册心跳间隔（导航活跃期间） | 最小10s，最大300s |
| `EDGE_MAX_RETRY_COUNT` | 3 | 最大重试次数 | 0-10 |
| `DICOM_SCP_PORT` | `10400` | DICOM SCP服务监听端口 | ≥1024避免特权端口 |
| `DICOM_MAX_CONNECTIONS` | 1 | 一期最大支持超声设备连接数 | 固定为1 |
| `NAV_ANNOTATION_MAX_PER_FRAME` | 20 | 单帧导航标注数量上限 | 5-50 |
| `EDGE_NAV_WS_PORT` | `9100` | 边缘端导航WebSocket服务端口 | - |

### 2.3 端口分配表

| 服务组件 | 配置项 | 默认端口 | 说明 |
|----------|--------|----------|------|
| 主应用服务 | `APP_PORT` | `8000` | FastAPI 主服务端口 |
| llama.cpp | `LLAMA_CPP_PORT` | `8001` | llama.cpp HTTP server 端口（独立进程） |
| vLLM | `VLLM_PORT` | `8002` | vLLM HTTP server 端口（full模式） |
| SafetyGateway | `SAFETY_GATEWAY_PORT` | `9001` | SafetyGateway 独立进程端口 |
| 边缘端导航WS | `EDGE_NAV_WS_PORT` | `9100` | 边缘端 WebSocket 导航服务端口 |
| 边缘端管理界面 | `EDGE_MGMT_PORT` | `8443` | 边缘端本地管理界面端口（HTTPS） |
| DICOM SCP | `DICOM_SCP_PORT` | `10400` | DICOM 服务端口 |

> **端口冲突防护**：启动时自动检测端口占用，冲突时拒绝启动并输出明确错误信息。

## 五、安全配置项

### 5.1 脱敏配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `DESENSITIZATION_ENABLED` | `true` | 脱敏功能开关 |
| `DESENSITIZATION_MODE` | `standard` | 脱敏模式：`standard`（标准）/`strict`（严格）/`emergency`（紧急） |
| `PATIENT_ID_MASK_LENGTH` | 6 | 患者ID脱敏长度 |

**脱敏模式说明**：

| 模式 | 说明 | 对应脱敏防线 |
|------|------|--------------|
| `standard` | 标准脱敏（默认） | 标准化层预脱敏 + 融合层 ML NER + 规则增强 + SafetyGateway 规则增强 |
| `strict` | 严格脱敏 | 标准脱敏 + 额外的人工可识别信息过滤 |
| `emergency` | 紧急模式 | 仅保留 observations 白名单字段，禁用诊断结论输出 |

### 5.2 HSM配置

| 配置项 | 默认值 | 说明 | 约束条件 |
|--------|--------|------|----------|
| `HSM_TYPE` | `SoftHSM` | HSM类型：`SoftHSM`/`USBHSM`/`CloudHSM` | 生产环境推荐USBHSM |
| `HSM_RETRY_COUNT` | 3 | HSM操作重试次数 | 0-5 |
| `HSM_TIMEOUT` | `5000ms` | HSM操作超时时间 | 最小1000ms |

### 5.3 同意状态配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `CONSENT_CACHE_TTL` | `500ms` | 调度层入口快速拒绝缓存TTL |
| `CONSENT_CACHE_TTL_SECONDS` | 60 | 同意状态Redis只读缓存TTL（仅用于入口快速拒绝） |
| `CONSENT_REQUIRED` | `true` | 是否强制要求知情同意 |

> **重要**：同意状态权威校验始终直查PostgreSQL，不使用任何缓存。Redis缓存仅用于调度层入口快速拒绝优化。

### 6.2 缓存TTL配置

| `CACHE_TTL_HOURS` | 24 | 会话状态缓存TTL（小时） |
| `CACHE_KB_ENTRY_TTL_HOURS` | 168 | 知识条目缓存TTL（小时，7天） |
| `CACHE_NULL_TTL_MINUTES` | 5 | 空值缓存TTL（分钟，用于缓存穿透防护） |

### 6.3 缓存防护配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `CACHE_PENETRATION_ENABLED` | `true` | 缓存穿透防护开关（布隆过滤器+空值缓存） |
| `CACHE_BLOOM_FILTER_SIZE` | `1000000` | 布隆过滤器预计元素数量 |
| `CACHE_BLOOM_FILTER_ERROR_RATE` | `0.01` | 布隆过滤器误判率 |
| `CACHE_BREAKDOWN_PROTECTION_ENABLED` | `true` | 缓存击穿防护开关（热点key保护） |
| `CACHE_AVALANCHE_PROTECTION_ENABLED` | `true` | 缓存雪崩防护开关（TTL随机化+预热） |
| `CACHE_TTL_RANDOMIZATION_PERCENT` | 10 | TTL随机化百分比（±10%） |
| `CACHE_WARMUP_TOP_N` | 100 | 启动时预热Top-N热点知识条目 |

### 6.4 Redis定位与降级策略

| 维度 | compact模式 | full模式 |
|------|------------|---------|
| Redis定位 | 性能加速器，非核心依赖 | 性能加速器+高可用 |
| 调度租约 | PG Advisory Lock | Redis SET NX EX + PG降级 |
| 消息队列 | PG轮询 | Redis Streams + PG降级 |
| 会话状态 | 顺序双写PG+Redis | 顺序双写PG+Redis |
| 同意状态 | 直写PG，Redis只读缓存 | 直写PG，Redis只读缓存 |
| 降级触发条件 | Redis不可用时，系统继续运行，仅失去缓存加速 | Redis不可用时，系统继续运行，仅失去缓存加速 |
| 用户感知 | 诊断响应可能变慢，但功能完整 | 诊断响应可能变慢，但功能完整 |

## 九、配置自动调整规则

### 9.1 基于部署模式的自动调整

| 触发条件 | 调整动作 | 调整参数 |
|----------|----------|----------|
| `DEPLOYMENT_PROFILE=full` | 自动切换推理引擎 | `INFERENCE_ENGINE=vLLM` |
| `DEPLOYMENT_PROFILE=full` | 增加连接池大小 | `PG_POOL_MAX_SIZE=20` |
| `DEPLOYMENT_PROFILE=compact` | 启用单实例模式 | `REDIS_SINGLE_INSTANCE=true` |

### 9.2 基于系统负载的自动调整

| 触发条件 | 调整动作 | 调整参数 |
|----------|----------|----------|
| CPU使用率>80%持续5分钟 | 启用请求限流 | `MAX_CONCURRENT_REQUESTS`降低30% |
| GPU显存占用>90%持续5分钟 | 触发模型热重载 | 清理碎片化显存 |
| Redis响应延迟>500ms | 切换PostgreSQL写入 | `REDIS_FALLBACK_ENABLED=true` |

### 9.3 基于业务指标的自动调整

| 触发条件 | 调整动作 | 调整参数 |
|----------|----------|----------|
| 幻觉率>2%持续1小时 | 提高置信度阈值 | `ORGAN_CONFIDENCE_THRESHOLD`+0.05 |
| 响应延迟>3s持续10分钟 | 切换快速路径 | 自动应用`EDGE_FAST_PATH_THRESHOLD_MULTIPLIER` |
| 检索失败率>5% | 触发CRAG补充检索 | `CRAG_ENABLED=true` |

## 十、配置校验规则

### 10.1 静态校验规则

| 配置项 | 校验规则 | 错误级别 |
|--------|----------|----------|
| `EDGE_DEVICE_ID` | 必须为64位UUID格式 | 致命 |
| `DEPLOYMENT_PROFILE` | 必须为`compact`或`full` | 致命 |
| `EDGE_DIRECT_WS_ENABLED` | 一期必须为`false` | 警告 |
| `HSM_TYPE` | 生产环境不能为`SoftHSM` | 警告 |

### 10.2 动态校验规则

| 校验项 | 校验方法 | 失败处理 |
|--------|----------|----------|
| HSM可用性 | 启动时连接测试 | 告警并降级为软件签名 |
| PostgreSQL连接 | 定期健康检查 | 切换只读模式 |
| Redis连接 | 定期健康检查 | 继续运行，仅失去缓存加速 |
| 知识库版本兼容性 | 会话创建时校验 | 拒绝创建新会话（E4004） |

### 10.3 配置项约束关系

| 约束关系 | 涉及配置项 | 约束条件 | 违反处理 |
|----------|-----------|----------|----------|
| 边缘端直推开关与安全窗口 | `EDGE_DIRECT_WS_ENABLED`, `EDGE_NAV_SECURITY_WINDOW_MS` | `EDGE_DIRECT_WS_ENABLED=false` 时 `EDGE_NAV_SECURITY_WINDOW_MS` 应为 0 | 警告提示 |
| 部署模式与推理框架 | `DEPLOYMENT_PROFILE`, `INFERENCE_ENGINE` | compact → `llama.cpp`，full → `vLLM` | 启动时自动覆盖 |
| 部署模式与Redis模式 | `DEPLOYMENT_PROFILE`, `REDIS_SINGLE_INSTANCE` | compact → `true`，full → `false` | 启动时自动覆盖 |
| 幻觉率阈值层级 | `HALLUCINATION_ALERT_THRESHOLD`, `HALLUCINATION_CRITICAL_THRESHOLD` | Alert < Critical（0.02 < 0.05） | 拒绝启动 |
| 端口无冲突 | `LLAMA_CPP_PORT`, `VLLM_PORT`, `SAFETY_GATEWAY_PORT`, `APP_PORT` | 所有端口值互不相同 | 拒绝启动 |
| 一期直推禁用 | `EDGE_DIRECT_WS_ENABLED` | 一期必须为 `false` | 警告提示 |
| compact禁用组件 | `DEPLOYMENT_PROFILE`, `NEO4J_ENABLED`, `ELASTICSEARCH_ENABLED`, `AB_TEST_ENABLED` | compact模式下须为false | 拒绝启动 |
| 脱敏规则缓冲期与Pub/Sub延迟 | `DESENSITIZATION_RULE_PROPAGATION_GRACE_PERIOD_MS` | 缓冲期须 > Redis Pub/Sub P99 传播延迟（默认 100ms）+ 实例处理延迟（P99 < 50ms），2000ms 为推荐值 | 警告提示（< 200ms 时拒绝启动） |
| SafetyGateway健康检查与降级判定 | `SAFETY_GATEWAY_HEALTH_CHECK_INTERVAL`, `SAFETY_GATEWAY_HEALTH_CHECK_TIMEOUT` | 连续 3 次失败判定不可用（3 × (interval + timeout) = 15s），与降级策略总表"持续不可用 > 15s"阈值一致 | 警告提示 |
| SafetyGateway排队超时与重启时间 | `SAFETY_GATEWAY_QUEUE_TIMEOUT_SECONDS` | 须 > SafetyGateway看门狗重启时间（5s）且 < 持续不可用判定阈值（15s），推荐 10s | 超出范围时拒绝启动 |
| SafetyGateway readiness探针与Redis依赖 | `DEPLOYMENT_PROFILE` | compact 模式下 readiness 探针不检查 Redis 连接（Redis 为性能加速层，宕机不影响 SafetyGateway 核心职责）；full 模式下可选检查 Redis 连接 | 警告提示 |
| 降级会话缓存TTL与正常缓存TTL | `DEGRADED_SESSION_CACHE_TTL_SECONDS`, `EDGE_SESSION_CACHE_TTL_SECONDS` | 降级 TTL（默认 1800s）须 > 正常 TTL（默认 300s），且降级 TTL 须覆盖典型后端故障恢复时间 | 警告提示 |
| vLLM GPU显存利用率与compact模式 | `VLLM_GPU_MEMORY_UTILIZATION`, `DEPLOYMENT_PROFILE` | compact 模式下须 ≤ 0.80（RTX 3060 12GB 约束），full 模式推荐 0.90 | compact 下 > 0.80 时拒绝启动 |

## 十一、配置管理流程

### 11.1 配置变更流程

```
配置变更申请 → 配置校验 → 安全评审（安全配置） → 灰度发布（10%流量24h） → 全量生效 → 监控观察（24h） → 变更确认/回滚
```

**详细流程说明**：
1. **配置变更申请**：由运维工程师或开发负责人提交配置变更申请，包含变更内容、变更原因、影响范围评估、回滚方案
2. **配置校验**：系统自动校验配置项格式、约束关系、依赖关系
3. **安全评审**：安全配置须经安全工程师双人评审
4. **灰度发布**：先在测试环境验证，再在少量生产实例上灰度验证（建议10%流量24h）
5. **全量生效**：灰度验证通过后逐步全量推广
6. **监控观察**：全量后持续观察24h，监控相关指标是否正常
7. **变更确认/回滚**：24h后无异常则确认变更；有异常则立即回滚

**自动回滚触发条件**：
- 关键指标偏离基线超过50%
- 错误率上升超过1%
- 用户反馈负面反馈率超过5%

### 11.2 配置变更审批权限

| 配置类别 | 变更权限 | 审批流程 | 说明 |
|----------|----------|----------|------|
| 架构配置 | 高级运维/技术负责人 | 单人审批 | 部署模式、端口配置等 |
| 推理配置 | 算法工程师/技术负责人 | 双人审批（算法+运维） | 置信度阈值、模型参数等 |
| 知识库配置 | 知识工程师/技术负责人 | 双人审批（知识+运维） | 版本锁定、反馈衰减等 |
| 安全配置（安全关键） | 安全工程师/技术负责人 | 双人审批（安全+运维） | 脱敏规则、HSM配置、禁忌条件等 |
| 安全配置（非安全关键） | 安全工程师 | 单人审批 | 日志级别等 |
| 运维配置 | 运维工程师 | 单人审批 | 监控、告警配置等 |
| 开发配置 | 开发工程师 | 单人审批 | 测试模式、Mock数据等 |

**紧急变更流程**：生产环境出现紧急问题时，可跳过灰度发布，经技术负责人审批后直接变更，但变更后须24h内补全变更记录和审计日志。

### 11.3 配置优先级

1. 命令行参数（最高优先级）
2. 环境变量
3. 配置文件（`config.yaml`）
4. 默认值（最低优先级）

### 11.4 配置变更审计

所有配置变更须记录审计日志，包含：
- 变更时间
- 变更人
- 变更前值
- 变更后值
- 变更原因
- 审批人
- 变更结果（成功/失败/回滚）

### 11.5 敏感配置项管理

| 敏感配置项 | 保护措施 |
|------------|----------|
| API Key | 环境变量注入，不在配置文件中存储 |
| 数据库密码 | 环境变量注入，使用密钥管理服务 |
| HSM密钥 | 硬件安全模块保护 |
| 加密密钥 | 密钥管理服务存储 |

### 11.6 配置项影响评估模板

配置变更申请须包含以下评估内容：

| 评估项 | 说明 |
|--------|------|
| 变更内容 | 具体修改哪些配置项 |
| 变更原因 | 为什么需要变更 |
| 影响范围 | 影响哪些模块、哪些功能 |
| 风险评估 | 变更可能带来的风险 |
| 回滚方案 | 出现问题时如何回滚 |
| 验证计划 | 如何验证变更是否成功 |
| 监控指标 | 变更后需要重点监控哪些指标 |

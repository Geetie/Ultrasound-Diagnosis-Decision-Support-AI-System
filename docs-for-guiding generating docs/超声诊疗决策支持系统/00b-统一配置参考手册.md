|------|------|--------------|

## 九、配置自动调整规则

### 9.1 基于部署模式的自动调整

| 触发条件 | 调整动作 | 调整参数 |
|----------|----------|----------|
| `DEPLOYMENT_PROFILE=full` | 自动切换推理引擎 | `INFERENCE_ENGINE=vLLM` |
| `DEPLOYMENT_PROFILE=full` | 增加连接池大小 | `PG_POOL_MAX_SIZE=20` |
| `DEPLOYMENT_PROFILE=compact` | 启用单实例模式 | `REDIS_SINGLE_INSTANCE=true` |

### 9.2 基于系统负载的自动调整

| 触发条件 | 调整动作 | 调整参数 |
|----------|----------|----------|
| CPU使用率>80%持续5分钟 | 启用请求限流 | `MAX_CONCURRENT_REQUESTS`降低30% |
| GPU显存占用>90%持续5分钟 | 触发模型热重载 | 清理碎片化显存 |
| Redis响应延迟>500ms | 切换PostgreSQL写入 | `REDIS_FALLBACK_ENABLED=true` |

### 9.3 基于业务指标的自动调整

## 十一、配置管理流程

### 11.1 配置变更流程

```
配置变更申请 → 配置校验 → 安全评审（安全配置） → 灰度发布（10%流量24h） → 全量生效 → 监控观察（24h） → 变更确认/回滚
```

**详细流程说明**：
1. **配置变更申请**：由运维工程师或开发负责人提交配置变更申请，包含变更内容、变更原因、影响范围评估、回滚方案
2. **配置校验**：系统自动校验配置项格式、约束关系、依赖关系
3. **安全评审**：安全配置须经安全工程师双人评审
4. **灰度发布**：先在测试环境验证，再在少量生产实例上灰度验证（建议10%流量24h）
5. **全量生效**：灰度验证通过后逐步全量推广
6. **监控观察**：全量后持续观察24h，监控相关指标是否正常
7. **变更确认/回滚**：24h后无异常则确认变更；有异常则立即回滚

**自动回滚触发条件**：
- 关键指标偏离基线超过50%
- 错误率上升超过1%
- 用户反馈负面反馈率超过5%

### 11.2 配置变更审批权限

| 配置类别 | 变更权限 | 审批流程 | 说明 |
|----------|----------|----------|------|
| 架构配置 | 高级运维/技术负责人 | 单人审批 | 部署模式、端口配置等 |
| 推理配置 | 算法工程师/技术负责人 | 双人审批（算法+运维） | 置信度阈值、模型参数等 |
| 知识库配置 | 知识工程师/技术负责人 | 双人审批（知识+运维） | 版本锁定、反馈衰减等 |
| 安全配置（安全关键） | 安全工程师/技术负责人 | 双人审批（安全+运维） | 脱敏规则、HSM配置、禁忌条件等 |
| 安全配置（非安全关键） | 安全工程师 | 单人审批 | 日志级别等 |
| 运维配置 | 运维工程师 | 单人审批 | 监控、告警配置等 |
| 开发配置 | 开发工程师 | 单人审批 | 测试模式、Mock数据等 |

**紧急变更流程**：生产环境出现紧急问题时，可跳过灰度发布，经技术负责人审批后直接变更，但变更后须24h内补全变更记录和审计日志。

### 11.3 配置优先级

1. 命令行参数（最高优先级）
2. 环境变量
3. 配置文件（`config.yaml`）
4. 默认值（最低优先级）

### 11.4 配置变更审计

所有配置变更须记录审计日志，包含：
- 变更时间
- 变更人
- 变更前值
- 变更后值
- 变更原因
- 审批人
- 变更结果（成功/失败/回滚）

| HSM密钥加密密钥 | 环境变量注入，Fernet格式校验，生产环境必填 |
| 加密密钥 | 密钥管理服务存储 |

### 11.6 配置项影响评估模板

配置变更申请须包含以下评估内容：

| 评估项 | 说明 |
|--------|------|

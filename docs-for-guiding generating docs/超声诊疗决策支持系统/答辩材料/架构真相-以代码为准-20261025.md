## 0. 一句话

**设计的骨架没变，但"多智能体并行融合"这一层在实现里塌了。**

- 真实链路是 **单请求 → 单专科 → 条件触发的浅校验 → 安全门 → 医生确认**，不是"1 个调度 + N 个专科并行 + 四层融合"。
- 这不是 bug，是**前提不成立**：融合层的冲突检测要求 ≥2 份独立结论，而生产每次只产 1 份。

## 2. 融合层：设计 4 层，实跑 1.3 层（`A`，这是最关键的一处）

| 层 | 设计声称 | 代码实况 | 证据 |
|---|---|---|---|
| 冲突检测 | 多专科结论互检 | **恒空**：4 类规则全部要求 `len(responses) >= 2`，单专科永不满足 | `app/fusion/conflict.py:287,313,335,384` |
| 一致性·与既往比 | 和上次检查对比 | **不可达**：pipeline 从不传 `prior_diagnosis` | `pipeline.py:678-686`；`consistency.py:604` |
| 一致性·与指南比 | RAG 检索指南比对 | **默认恒空**：请求 `min_score_threshold=0.5`，而 RRF 分数区间仅 0.016~0.033 → 全被剔除 → 记 `no_guideline_chunks` | `rag/protocols.py:119`；`retriever.py:589`；`rag/service.py:290`；`consistency.py:837-863` |
| 一致性·跨器官 | 多器官互检 | **不可达**：要求 ≥2 响应 | `consistency.py:656,915` |
| Self-RAG | 三维打分 + 重试 | **真跑，但只在 FULL 档，且 `max_retries=0`（仅评估 1 次）** | `layered_validator.py:118`；`settings.py:291`；`main.py:583` |
| CRAG | 检索不足则补检重生成 | **真跑**，单次、有界、有真实"重跑专科"接线；但 `recovered=True` 只要求检索非空，不校验质量 | `crag.py:244-291`；`main.py:602-613` |

**净结论**：一次判读里真正起作用的校验 = **Self-RAG（FULL 档 1 次） + CRAG（条件触发 1 次）**。冲突检测与两条一致性分支没有输入。

**为什么重要**：这决定了答辩能不能讲"四层校验"。讲 = 一问即穿；不讲 = 少一个卖点但站得住。

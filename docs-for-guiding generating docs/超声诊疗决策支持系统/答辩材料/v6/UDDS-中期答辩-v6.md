## 三、排版系统（改版必读）

### 3.1 版式原语

| 函数 | 用途 |
|---|---|
| `two_col_slots()` | **左右两栏 + 栏内等分槽位**。最稳的版式：每项高度严格相等，从结构上不可能溢出 |
| `arch_chain()` | 纵向链路（序号轨 + 内容），带 `brk` 断点样式 |
| `num_block()` | 大数字块（数值 + 标签 + 口径），高度自适应 |
| `fit_list()` | 自适应纵向列表，超限等比压缩 |
| `fit_size()` | **动态字号**：给定宽度挑能放下的最大字号 |
| `auto_tb()` | 按真实断行数给足高度的文本框 |
| `table()` | 表格，支持 `accents={行: [列]}` 标暗红 |

### 3.2 尺寸纪律（血的教训）

1. **绝不手写固定框高**。所有高度必须走 `lines_needed()` / `block_height()`，它们用 PingFang SC 的**真实字宽**做贪心断行。
2. **槽位优于内容高**。内容多的页用 `two_col_slots` 均分，而不是"每项各算各的再堆"——后者必然累积误差。
3. **20pt 是物理约束**。实测：13.333×7.5 画布在 20pt 下满页约 **655 个 CJK 字**（零留白）。原 v10 的 P6 把三档 + 指标表放一页，实测需 >4.9in 而可用仅 4.86in，**物理上装不下**，所以拆成 P6/P7 两页。
4. 改字号后必须重跑 `check_deck.py`——检查器会重新按新字号算断行。

### 3.3 校验方法

```bash
# 1. 生成
python build_deck.py

# 2. 静态校验（边界 / 真实断行 / 重叠 / 术语）
python check_deck.py UDDS-中期答辩-v6.pptx

# 3. 渲染 + 像素与字体校验
node <libreoffice-kit>/cli.js render --input UDDS-中期答辩-v6.pptx \
     --output-dir <tmp>/render --pages "1,2,3,4,5,6,7,8,9" > <tmp>/manifest.json
python check_deck.py UDDS-中期答辩-v6.pptx --render-dir <tmp>/render --manifest <tmp>/manifest.json
```

### 3.4 七把尺子（`check_deck.py`）

| 尺子 | 抓什么 | 原理 |
|---|---|---|
| A 真实字体度量 | 文字超出框高、单行超宽 | PIL 加载 PingFang SC，按**实际字宽**贪心断行 |
| B 渲染像素墨迹 | 越界、裁切、空白页 | 统计边缘墨迹，区分「有意出血」与「意外裁切」 |
| C 文本区墨迹 | 字体掉字、白字 | 每个文本形状的渲染区域必须有墨迹 |
| D missingFonts | 中文掉字 | 渲染清单的 `missingFonts` 字段（LibreOffice 会静默回退，像素审计抓不到） |
| E 术语可读性 | 行话未解释 | 缩写首次出现必须带白话（跨专业评委约束） |
| F 框外墨迹（受限） | 孤立文本溢出到画布空白 | 只对周围无邻近形状的文本框生效；密集版面会误报，故受限 |
| G 孤字检测 | ① 末行只有 1 个 CJK 字；② **前一行为满行（>88% 可用宽）且末行 < 前行 35%** | 抓「医生不敢用」的"用"、「依据不可核查」的"查"单独成行。**必须用 `wrap_runs` 分段测量**——混合 bold/常规时按单一字体估宽会低估，漏报（P4 实例） |
| H 页脚保留区 | 形状侵入页面底部 0.55in | 抓「安全层压住页脚」这类几何不重叠但视觉压叠的问题 |

**负测试已验证有牙齿**：故意造溢出（9.60in 需 vs 0.50in 框）、越界（15.50×8.00）、重叠（4.00×0.70in）、假字体（`NoSuchFontXYZ`），全部被尺子分别命中。

**F/G/H 的由来（重要教训）**：前四把尺子全部通过后，人工看图仍发现 9 处视觉问题——说明程序化校验有盲区。G（孤字）与 H（页脚区）补上后**立刻复现了人工发现的问题**，F 因密集版面误报率高而受限。

**G 尺子自身也迭代过两轮**：
1. 初版只报「末行 1 个 CJK 字」——**漏掉了 P4 总问题条的「用」**。根因：该段前半 bold、后半常规，而度量按单一非粗体估宽，低估约 6%，算出"单行放得下"，于是不进入多行判定。修复：改用 `wrap_runs` 按 run 分段测量。
2. 加宽为「末行 < 均行 1.5×」后**误报 4 条**（多段拼接的条目末段天然短）。收紧为「前一行为满行 **且** 末行 < 前行 35%」，误报归零。

**结论：尺子能兜住"会不会崩"，兜不住"好不好看"；而且尺子本身也会漏，需要人眼反证来迭代。交付前必须有人看图。**

## 六、已知限制（诚实声明）

1. **视觉审美未经本项目作者确认**。制作 AI 无法读图（`read_image` 报 `does not declare image input`），已用七把客观尺子 + 负测试替代。**经 Lead 人工读图发现并修复 9 处视觉问题**（P1 卡片文字溢出、P4 尾字孤行、P5 压页脚等），说明程序化校验 ≠ 视觉验收。**最终外观须由人看 `render-png/` 的 9 张图确认。**
2. **LibreOffice 渲染 ≠ PowerPoint 渲染**。字体度量基于 PingFang SC，若在 Windows 上打开会自动回退到其他中文字体，行宽可能变化（但框高已留余量，不会崩版）。
3. **P6/P7 拆分是我的判断**，若坚持 8 页需进一步删减 P6 条目（每档降到 2 条）或把指标表压成 3 行。
4. **口播稿不在本文件范围**——逐字稿需按 9 页版重排（原 v10 是按 8 页设计的）。

## 0. 先明确一件事：这四个成因不是并列的

答辩时如果四个成因并列讲，评委会觉得"问题很多但都很散"。实际上它们有依赖关系：

```
④ 数据不可信  ──→  ①③ 的所有指标都测不准（先决条件）
                          │
② 依据不可核查 ──→  医生不敢用（临床效用的必要条件）
                          │
③ 判断不稳定   ──→  ②的产物没法稳定复现
                          │
        ↓ 全部指向
        临床效用无法证明（总问题）
```

**所以路线图必须是「先修④ → 再补②③ → 最后①在真实病例上量」**，不能四条并行。
这一点直接决定了第六部分的周排期。

# 一、成因①：没有衡量效用的指标

## 1.1 可选方案对比

| # | 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|---|
| **A** | **DCA / net benefit 移植到 RAG** | 把"结论是否被采纳"当作二分类预测，用 DCA 公式算净获益；阈值概率 p_t 由临床代价比决定 | 公式成熟（2006 年起被引 5800+）、有 Python 实现、直接对应"临床效用"这个词 | RAG 输出是文本不是概率，需要先定义"阳性"（如"判为需穿刺"）；需要真实转归 |
| **B** | **改 RAGAS 的 faithfulness 为"分方向"** | 不改造 RAGAS 内核，而是**把评测集按误判方向切片**，分别算 faithfulness / 引用正确率 | 改造成本最低（只改数据组织，不改库） | 只能"分方向看"，不能合成单一效用数 |
| **C** | **自定义 RubricsScore（ragas 0.4.3 原生支持）** | 用 `RubricsScore` 把"把恶性判成良性"设成一条**高权重负向准则**，把"把良性判成恶性"设成低权重准则 | 工具原生支持，无需自研；可解释 | rubric 由谁定要有依据（需临床专家） |
| **D** | **cost-sensitive 阈值搜索** | 用代价矩阵搜索最优决策阈值，报告"在不同代价比下的表现" | 直接回答"这台机器在什么代价假设下可用" | 只解决阈值，不解决生成质量 |

**推荐：A + C 组合。**
- **A 解决"对外怎么讲临床效用"**（答辩时"净获益"是一个临床专家听得懂的词）；
- **C 解决"对内怎么算分"**（rubric 里显式区分两个方向）。

**为什么不用 B 单干**：B 只是"分方向看指标"，最终还是两个数，没有合成成"这台机器值不值得用"。
DCA 的核心价值恰恰是**把两个方向压缩成一个可比较的净获益数**。

## 1.2 具体做法：DCA 怎么算（公式已从原文核实）

Vickers & Elkin 2006 的原文（PMC 全文 PMC2577036）给的公式是：

```
Net Benefit = (真阳性数 / n) − (假阳性数 / n) × [ p_t / (1 − p_t) ]
```

原文例句（可用来校验我们的实现对不对）：
> "where p_t is 10%, the true-positive count is 65, the false-positive count is 225 and the total number of patients (n) is 902.
> The net benefit is therefore (65/902) – (225/902) × (0.1/0.9) = **0.0443**."

**关键洞察（这条要写进答辩稿）**：
`p_t/(1−p_t)` 就是**代价比**。p_t = 10% 意味着"漏诊的代价是过度治疗的 9 倍"。
→ **医学里两个方向代价不对称这件事，DCA 用一行公式就表达完了**，而 RAGAS 的 faithfulness 没有这个维度。
这正是成因①的解法核心。

**移植到 RAG 的关键改造（这一步没有现成论文，属于本项目要做的）**：

| RAG 输出 | DCA 里的对应物 | 怎么定义 |
|---|---|---|
| "这个结节建议 FNA（穿刺）" | 阳性（predict positive） | 结论里出现处置建议 = 阳性 |
| 真实转归（良性/恶性） | 金标准 | 需要病理或随访 |
| 真阳性 | 判为需穿刺 + 实际恶性 | — |
| 假阳性 | 判为需穿刺 + 实际良性 | **过度医疗成本** |
| 假阴性 | 判为随访 + 实际恶性 | **漏诊成本** |

→ 于是 `NB(阈值)` 这条曲线可以直接画，横轴是 p_t（0.01~0.5），纵轴是净获益。
**"AI 辅助"与"全穿刺"、"全随访"两条极端策略比，看曲线在哪个 p_t 区间高于两条极端线**——这就是"临床效用区间"。

**实现**：`pip install dcurves`（v1.1.7，MSKCC-Epi-Bio 维护，PyPI 官方包，文档 `decisioncurveanalysis.org`）。
API 是 `dca(data=df, outcome='cancer', modelnames=[...], thresholds=np.arange(0,0.36,0.01))` + `plot_graphs()`。

> ⚠️ **R 的 `rmda` 包已于 2026-05-04 从 CRAN 下架**（原因：维护者邮箱不可达），**不要用 R 路线**。
> 必须走 Python 的 `dcurves`。

**参考来源**
- Vickers AJ, Elkin EB. *Decision curve analysis: a novel method for evaluating prediction models.* Med Decis Making. 2006;26(6):565-74. DOI 10.1177/0272989X06295361，PMID **17099194**，PMCID **PMC2577036**（全文已抓，公式与算例见上）`A`
- *Decision curve analysis explained.* Diagnosis (Berl). 2026. DOI 10.1515/dx-2025-0113，PMID **41493769** `A`（最新教程）
- `dcurves` Python 包 v1.1.7：https://pypi.org/project/dcurves/ （requires Python >=3.9,<3.14）`A`

## 1.3 ragas 侧的配合改造（基于 0.4.3 源码实读）

`ragas 0.4.3`（源码 `src/ragas/metrics/__init__.py`）里有三个可直接用的扩展点：

1. **`RubricsScore`（domain-specific rubrics）** → 写一份"超声分级-rubric"：
   ```
   - 把恶性判成良性（漏诊）：-5 分（每条）
   - 把良性判成恶性（过度）：-1 分
   - 分级正确且给出正确处置：+2 分
   ```
   这是**唯一能在现有工具链里表达"方向不对称"的原生接口**。
2. **`FaithfulnesswithHHEM`** → 项目 `15号` P0-3 想做的"HHEM 判官替代 7B 判官"，**ragas 0.4.3 已内置**，
   不用自己接模型。
3. **`MultiModalFaithfulness` / `MultiModalRelevance`** → 针对"图文混合结论"，比纯文本 faithfulness 语义更匹配。

> ⚠️ **API 变更预警**：`AnswerRelevancy` 在 0.4.3 里已标 `deprecated`（走 `_DEPRECATED_METRICS` 映射），
> 新代码要 import `ragas.metrics.collections`。本项目 `scripts/prompts/ragas_answer_relevancy.py` 抄的官方 prompt
> 可以继续用，但**升级 ragas 时 import 路径必然要改**。

# 二、成因②：依据不可核查

## 2.1 根因复述（一句话）

`KnowledgeChunk`（`app/knowledge/protocols.py:95-103`）的字段里**没有 `evidence_level`、没有 `recommendation_id`**；
真机体检（`16号:6004-6005`）**88.5% 的文档只有 1 个 chunk、块中位 146 token** →
**不是切分算法不好，是语料在结构上就没有"层级"可切**。

## 2.2 可选方案对比

| # | 方案 | 做法 | 优点 | 缺点 | 适配本项目？ |
|---|---|---|---|---|---|
| **A** | **LlamaIndex `HierarchicalNodeParser` + `AutoMergingRetriever`** | 三层切分（如 2048 / 512 / 128），检索命中叶子节点后**自动向上合并到父节点**返回 | **现成实现**（源码已核实 `llama-index-core 0.14.25` 里有 `node_parser/relational/hierarchical.py` 与 `retrievers/auto_merging_retriever.py`）；父节点携带上下文，正好解决"推荐条目丢了证据等级" | 需要多存一份父节点；AutoMerging 的 `simple_ratio_thresh=0.5` 需调；对单块文档无效 | ⚠️ 部分——**对 88.5% 单块文档无效** |
| **B** | **RAGFlow DeepDoc 做结构解析** | 用 DeepDoc 的 layout analysis / OCR / table recognition 把 PDF 指南解析成带层级的结构化文档 | 官方在维护（README 明确写 "DeepDoc uses CPU inference for layout analysis, OCR, and table recognition"）；能处理扫描件 | 是独立服务，要部署；只解决"解析"，不解决"检索时怎么用层级" | ✅ 解决语料入口问题 |
| **C** | **CPG-on-FHIR / EBMonFHIR 信息模型** | 按 HL7 CPG-on-FHIR 规范表示"推荐条目 + 推荐强度 + 证据确定性 + 证据链接" | **国际标准**，字段定义现成；Lichtner 2023 论文给了完整信息模型 | 需要人工/半自动把中文指南映射到 FHIR profile，工作量最大 | ✅ 作为**数据模型参考**，不必全量实现 |
| **D** | **自建 `evidence_level` 字段 + 规则抽取** | 在 `KnowledgeChunk` 加 `evidence_level` / `recommendation_id` / `grade_certainty`，用正则从指南原文抽（"推荐等级：A"、"强推荐"） | 改动最小（加字段 + 一个抽取器）；不动检索链路 | 中文指南的证据标注格式不统一，抽取召回率未知 | ✅ **第一步就该做这个** |

**推荐：D（先）→ C（定字段口径）→ B（补语料解析）→ A（有长文档后再上）。**

**为什么这个顺序**：
1. **D 是所有方案的前提**——不管用 A/B/C，字段总得先存在。而且 D 一天就能做完，可以马上验证"中文指南里到底有多少条能抽出证据等级"。
2. **C 用来防止字段设计跑偏**。CPG-on-FHIR 的信息模型（Lichtner 2023）已经把该有的字段列全了：
   > "the ratings for the recommendations (e.g., **strength of recommendation**, **certainty of overall evidence**), the ratings of certainty of evidence for individual outcomes (e.g., risk of bias) and **links to the underlying evidence**"
   → 这正好是我们要的四个字段。
3. **B 解决"语料从哪来"**：本项目现在建库只吃 `manifest.json + <organ>/*.json`（`15号` §4.3 已记录），真实 PDF 指南进不来。DeepDoc 是补这一环。
4. **A 最后上**：因为 AutoMerging 对单块文档无效，**必须等 B 把长文档弄进来**才有意义。

## 2.3 具体做法（D 的字段设计）

给 `KnowledgeChunk` 加三个字段（从 CPG-on-FHIR 抄口径）：

```python
# app/knowledge/protocols.py:95-103 追加
evidence_level: str | None = None        # GRADE: high / moderate / low / very_low
recommendation_strength: str | None = None  # strong / weak / conditional
recommendation_id: str | None = None     # 指南内条目号，如 "ACR TI-RADS 2017 §4.2-1"
```

抽取器（`app/knowledge/chunker.py` 旁边新增）：
- 正则抓中文指南常见标注：`推荐等级[:：]\s*([A-D])`、`(强|弱)推荐`、`证据(质量|等级)[:：]\s*(高|中|低|极低)`
- 抓不到 → `None`，**不猜**（沿用项目 `grading_floor.py` 的"不猜"原则）
- 每条抽取动作留 `extraction_basis`（原始匹配串 + 偏移），可审计

**验收判据**：在现有 8 份中文指南 PDF 上跑一遍，统计
`有 evidence_level 的 chunk 数 / 总 chunk 数`。**这个数字就是答辩后第一步的产出**（先行实验，1 天）。

# 三、成因③：关键判断不稳定

## 3.1 根因复述（一句话）

约束解码只保证**格式合法**，不保证**内容确定**。`16号` §A.95 ③ 的原话：
> "根因：约束解码只保证'格式合法'，不保证'内容确定'；**TI-RADS 在边界病例本身就有判读分歧**。"

实测：常规档 **79.56%** / 高风险档 **40.88%**（同引擎两次生成一致率，门控 95%）。

## 3.2 先修一个技术错误：vLLM 的 API 我们用对了，但文档已经变了

项目 `AGENTS.md` 硬规则 #5 写"禁止用 `extra_body.guided_json`（新版 vLLM 静默失效）"——**这条是对的，且现在有官方依据**：

> vLLM 官方文档原文：`guided_json` → `{"structured_outputs": {"json": ...}}` 或 `StructuredOutputsParams(json=...)`，
> 且这些字段 **"were removed in v0.12.0"**。

所以正确的三条路（按推荐顺序）：

| 做法 | 写法 | 说明 |
|---|---|---|
| **① OpenAI 兼容（推荐）** | `response_format={"type":"json_schema","json_schema":{"name":...,"schema":...}}` | 项目 `app/inference/vllm.py:176-182` 已实现，**保持** |
| ② vLLM 新参数 | `extra_body={"structured_outputs": {"json": <schema>}}` | 可用，但绑死 vLLM |
| ③ `choice`（最省） | `extra_body={"structured_outputs": {"choice": ["2","3","4a","4b","5"]}}` | **分级任务最合适**——输出就是一个枚举值，不需要 object 包装 |

**后端选择**：vLLM 默认 `--structured-outputs-config.backend auto`（自动在 xgrammar / guidance 里选）。
项目若要固定，显式设 `xgrammar`（注意：**xgrammar 与 guidance 用 Rust 风格正则，lm-format-enforcer 用 Python 风格**，换后端会改变允许的 token）。

> ⚠️ `lm-format-enforcer` 后端从 v0.33.0 起 deprecated，v0.34 需显式 opt-in，**v0.35 移除**。项目若还在用，必须迁。

## 3.3 可选方案对比（针对"分级不稳定"）

| # | 方案 | 做法 | 优点 | 缺点 | 实测/文献支撑 |
|---|---|---|---|---|---|
| **A** | **`choice` 约束 + 枚举派生** | 把 `structured_outputs.choice` 设为该器官的合法分级列表，模型只能吐那 5 个值之一 | 输出空间最小，格式错误率≈0；比 JSON Schema 少一层包装 | 仍不解决"选哪个" | vLLM 官方支持 `choice` `A` |
| **B** | **多次采样 + 投票（self-consistency）** | temp>0 采样 k 次，对分级码取多数；k=5~9 | 直接降低方差；论文级方法 | k 倍推理成本；**若模型系统性偏向某一档，投票放大偏差** | Wang et al., *Self-Consistency Improves Chain of Thought Reasoning*, arXiv:**2203.11171** `A` |
| **C** | **规则后校验（deterministic post-check）** | 输出分级后，用 TI-RADS 计分规则**重算一遍**（成分/回声/形态/边缘/钙化各计分），与模型输出比对，不一致就降级/转人工 | **不增加推理成本**；可解释；能把"模型瞎猜"挡住 | 需要规则表准确；对"特征没提取到"无能为力 | 项目已有 `app/knowledge/risk_rules.py`（M5 恶性概率 + M9 后方回声规则表），**可直接复用** |
| **D** | **分级专用小模型（分类头）** | 不用生成式 LLM，改成"结构化特征 → 分类器 → 分级" | 确定性最高；可复现 | 需要标注数据；丢掉 LLM 的解释能力 | 未检索到"超声分级专用小模型 + 公开权重" |
| **E** | **自验证链（CoVe）** | 生成后让模型逐条核对自己的结论与依据是否一致 | 不依赖多次采样 | **Huang 2023 证明无外部反馈时自我纠错不可靠，甚至会改坏** | Huang et al., arXiv:**2310.01798** `A`（明确否掉） |

**推荐：A + C 为主线，B 作为"高风险档"的加强项。明确不用 E。**

**为什么这么选（这是答辩要说的关键判断）**：
1. **A 是必做的基础**（成本几乎为零，且能消掉"格式错误"这一类失败）；
2. **C 是真正解决"内容确定"的那一步**——因为 TI-RADS 本身就是**可计算的规则体系**（5 个特征各计分，加总定档）。
   模型输出分级 → 用规则重算 → 不一致就降级，**这一步不依赖模型**，是确定性的。
   而且项目里已经有 `risk_rules.py` 的计分项，**改造成本低**。
3. **B 只在"高风险档"用**（高风险档只有 40.88%，必须加强），因为 k 倍成本在常规档不划算。
4. **E 明确排除**：有直接反证（arXiv:2310.01798），答辩时如果被问"为什么不做 self-refine"，这条就是答案。

**预期收益（可算）**：
- A 消掉"格式错"（当前 `grade_unparseable` 已接近 0，收益小但必要）；
- C 能挡住"分级与特征自相矛盾"的那部分——`22号` §Q3b 实测 **76% 的"无法判断"是因为没给影像特征**，
  这属于**输入侧**问题，C 挡不住；但 C 能挡住"给了特征、模型仍算错"的那部分。
  → **诚实结论：C 的收益上界 = 1 − 76% = 24% 的那部分样本。** 不要吹。

# 四、成因④：底层数据不可信

## 4.1 根因复述（一句话）

`16号` A.70 实测：全库 1071 条判读里 **608 条（真结论的 98.1%）是提示词示例照抄**（`chunk_a1b2` / `患者PATIENT_001`），
451 条**根本没有结论**。→ **所有基于该集的 RAG 指标（0.0906 / 0.3788 / 0.1993 / 0.1645）已判定作废。**

## 4.2 可选方案对比

| # | 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|---|
| **A** | **生产侧拒收（已上线）** | `output_guard.detect_prompt_echo` 三规则，解析前拒收 | 已落地、已真机验证（回放 169 条 → 158 条被拒收，93.5%） | **只防新数据，不产生干净数据** |
| **B** | **提示词示例脱敏** | 把 prompt 里的 `chunk_a1b2` / `患者PATIENT_001` 换成 `[1]` / `[2]` | 从源头消除回显 | 已在做；但历史数据仍脏 |
| **C** | **从零重建干净评测集** | 按 STARD/CLAIM 规范重新构造：患者级切分 + 双人标注 + 一致性检验 + 功效分析定样本量 | **唯一能产出可信数字的路** | 需要医生时间；需要真实病例 |
| **D** | **合成数据补量** | 用 LLM 生成"影像所见 + 分级"样本 | 快 | **绝对不能用于验证**（自证循环），只能用于开发 |

**推荐：A（继续）+ B（继续）+ C（新建，这是重点）。D 明确不用。**

## 4.3 具体做法：干净评测集的构建 SOP

### 步骤 1｜参考标准（reference standard）怎么定

| 场景 | 标准 |
|---|---|
| 有病理 | **病理报告为金标准**（最优） |
| 无病理 | **两名独立超声医师双盲判读 + 第三人仲裁**（共识） |
| 随访可用 | 随访 ≥6 个月的最终诊断 |

**关键要求**：**判读者必须看不到 AI 输出，也看不到彼此的结果**（单盲 + 独立）。

### 步骤 2｜标注一致性怎么保证

| 项 | 具体做法 |
|---|---|
| 双人独立标注 | 两人各标一遍，互不可见 |
| 一致性统计量 | **Cohen's κ**（两人）/ **Fleiss' κ**（≥3 人） |
| 判定阈值 | 沿用 Landis & Koch 1977 的经验刻度：κ>0.81 几乎完全一致 / 0.61–0.80 高度 / 0.41–0.60 中等 |
| **本项目建议门槛** | **TI-RADS 分级 κ ≥ 0.61**（达到"高度一致"）；若 < 0.61，说明**分级标准本身在你们科室就没对齐**，要先对齐标准再谈 AI |
| 不一致怎么办 | **不取平均、不妥协**：全部进"第三人仲裁"队列，仲裁结果单独记一档 |
| 报告什么 | κ + 95%CI + 混淆矩阵，**三个都要报** |

> **为什么 κ 门槛这么定**：这是本项目最有价值的一条"先行实验"——如果两位医生对同一批结节的 TI-RADS 分级
> κ 只有 0.4，那"AI 分级准确率 91%"这个指标**根本没意义**（人类自己都不一致）。
> 这个数字必须先测出来，答辩时说出来会非常有说服力。

### 步骤 3｜样本量怎么定（三种口径，取最大）

| 口径 | 公式/工具 | 本项目估算 |
|---|---|---|
| **诊断准确率精度** | `n = Z²·p(1−p) / d²`；p=预期准确率 0.85，d=半宽 0.05，Z=1.96 → **n ≈ 196** | 约 200 例 |
| **敏感性/特异性亚组** | 若要单独报敏感性（目标 0.90±0.05），`n ≈ 139 / 患病率`；按恶性率 30% 折算 → **n ≈ 463** | 约 460 例 |
| **双人一致性** | κ 的精度依赖"阳性/阴性例数平衡"；经验上**每档分级 ≥30 例**。按代码里的**真实档数**算：甲状腺 TR1–TR5 = **5 档**、肝脏 LR-1~LR-5 + LR-M + LR-TIV = **7 档**、心脏 LVEF 4 档 = **4 档**，合计 **16 档** → **n = 480** | 约 480 例 |

→ **建议目标 n = 480 例**（16 档 × 30 例；档数来自 `app/agents/specialist/{thyroid,liver,cardiac}.py` 的 `TI_RADS_LEVELS`(5) / `LI_RADS_LEVELS`(7) / `LVEF_SEVERITY_LEVELS`(4)）。
若资源不够，**退到 n = 200** 只报总体准确率，
**不报分档指标**（分档指标在 <30 例/档 时不可靠，会被评委追问）。

> 统计工具：Python `statsmodels`（PyPI 可用）或 R `pmsampsize`；诊断准确性专用可参考 Obuchowski 的
> binormal ROC 样本量方法（DOI 10.1002/(sici)1097-0258(19970715)16:13<1529::aid-sim565>3.0.co;2-h）`A`

### 步骤 4｜数据表结构（直接可落库）

```
eval_case
  case_id            主键
  patient_id         ← 患者级切分的最小单位
  organ              thyroid / liver / cardiac
  image_ids[]        一个 case 可含多张图
  split              dev / test        （按 patient_id 切，不按 image_id）
  gold_grade         TR1..TR5 / LR-1..LR-5 / normal..severe
  gold_action        follow_up / fna / surgery / refer
  gold_source        pathology / consensus / follow_up
  reader_a_grade     ← 标注者 A（盲）
  reader_b_grade     ← 标注者 B（盲）
  adjudicated_grade  ← 仲裁结果（若 A≠B）
  kappa_pair         该 case 所属批次的一致性
```

**患者级切分的硬要求**：`split` 必须按 `patient_id` group split（`sklearn.model_selection.GroupShuffleSplit`），
**禁止**按 `image_id` 随机切——这正是本项目现在的问题（584 张来自 11 个患者）。

### 步骤 5｜验收判据

- [ ] `patient_id` 在 dev / test 之间**零重叠**（写个断言测试）
- [ ] 双人 κ ≥ 0.61，且 κ 的 95%CI 下界 ≥ 0.5
- [ ] 每档分级 ≥ 30 例（或明确声明"不报分档指标"）
- [ ] "无法判断"样本占比 < 20%（当前是 13.5%~19.3%，可作基线）
- [ ] 全库 `prompt_echo` 命中率 = 0（用生产同一把尺子 `app.inference.output_guard` 跑）

## 5.1 可选路径对比

| # | 路径 | 做法 | 优点 | 缺点 | 时间 |
|---|---|---|---|---|---|
| **P1** | **回顾性（retrospective）** | 拿医院历史病例（已有病理），离线跑系统，比对 | 快（1~2 月）；不需要伦理大改；样本易凑 | 不能证明"临床效用"（只证明准确率）；有选择偏倚 | 1~2 月 |
| **P2** | **前瞻性 silent / shadow mode** | 系统在线跑但**不输出给医生**，只记录；事后比对医生结论 | 能拿到真实分布；无医疗风险；伦理门槛低 | 仍不证明"改变行为" | +2 月 |

## 5.2 具体设计（P1 + P2 合并为"阶段一"）

### 阶段一（第 1–3 月）：回顾性 + shadow mode

| 项 | 设计 |

|---|---|

### 三个必须卡住的"门"（否则整条路线白跑）

| 门 | 时间点 | 判据 | 不达标怎么办 |
|---|---|---|---|
| **门 1：κ 门** | W7 | 双人 TI-RADS κ ≥ 0.61 | κ < 0.61 → **先对齐科室分级标准**，AI 评测暂停（否则测的是噪声） |
| **门 2：规则重算门** | W12 | "模型分级 vs 规则重算"不一致率 < 15% | 不达标 → 说明特征提取不可靠，回到成因②（影特征没进 prompt） |
| **门 3：shadow 安全带门** | W11 | 恶性→良性的严重误判率 < 5% | 不达标 → **不进前瞻性**，先修 SafetyGateway 规则 |

# 七、答辩版的一句话方案（每个成因一句话）

| 成因 | 一句话方案（口播可用） | 支撑数字 |
|---|---|---|
| **① 没有衡量效用的指标** | 「把临床的**净获益曲线（DCA）**搬到我们的评测上——同一个评测集，横轴是医生愿意接受的风险阈值，纵轴是净获益，这样"良性判成恶性"和"恶性判成良性"的代价差异第一次被算进指标里。」 | 公式来自 Vickers 2006（被引 5800+）；Python 有现成 `dcurves` 包 |
| **② 依据不可核查** | 「给每个知识块加上**证据等级和推荐条目号**三个字段，用 CPG-on-FHIR 的国际口径定字段，再用 RAGFlow 的 DeepDoc 把 PDF 指南真正解析成有层级的结构——现在我们库里 88.5% 的文档只有一个块，不是切分算法的问题，是语料根本没有层级。」 | 88.5% 单块 / 中位 146 token |
| **③ 关键判断不稳定** | 「约束解码只能保证格式合法、保证不了内容对——所以分级不能只靠模型：**输出后用 TI-RADS 计分规则独立重算一遍**，算不出来或对不上就转人工。高风险档再叠 5 次采样投票。」 | 高风险档 40.88%；规则表已有 |
| **④ 底层数据不可信** | 「按 STARD 和 CLAIM 的规范重建一套 **480 例、患者级切分、双人盲标注** 的评测集，先测医生之间的一致性 κ——如果两位医生自己对同一批结节的分级 κ 只有 0.4，那谈 AI 准确率就没意义。」 | 608/1071 条照抄示例；584 张影像来自 11 个患者 |
| **落地验证** | 「和复旦合作医院走**回顾性 → shadow → 前瞻性读片**三级，不直接上 RCT：先拿 480 例历史病例算净获益，再让系统在线跑但不输出、只比对，最后做 50~100 例的读片研究看医生会不会采纳。伦理批件这周就递，因为它是唯一压不缩的环节。」 | JAMA 2023 的 vignette RCT 证明"偏差 AI 会让医生准确率掉 11.3pp" |

**如果只有 25 秒（P5 页）**，只讲这三句：
> 「下一步我做三件具体的事：第一，按 STARD 规范重建 480 例患者级切分的评测集，先测医生之间的一致性；
> 第二，给知识块加证据等级字段，让每条结论能追到指南第几条；
> 第三，跟复旦合作医院走回顾性 + shadow + 读片研究三级验证，伦理批件这周递。
> 我们不直接上 RCT——因为前两级就能证伪，不用等到花两年。」

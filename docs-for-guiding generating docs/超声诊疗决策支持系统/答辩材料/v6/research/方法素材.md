## 第一部分 · 先把「研究内容」这个词的边界钉死

### 1.1 一条可直接引用的官方定义

华中农业大学研究生院《研究生学位论文研究开题报告写作规范》（2019-08-29 发布）把开题报告正文拆成七节，
**研究内容、研究方法、技术路线、工作基础和已有进展是四个并列的独立小节**，并逐节给了撰写要求：

> **6.2 研究内容**：对拟开展的研究工作**分层次进行详尽的描述**。
>
> **6.3 试验材料（研究对象）、研究方法和技术路线**
> ……**研究方法**：描述应详尽，以能将试验材料（研究对象）与试验结果（研究结果）贯通为准。**描述的详尽程度应能使必要时他人能重复出这一试验为准。**
> ……**技术路线**：对材料（对象）、方法、研究内容和目标的关系有时用一个示意图往往更容易描述清楚，**鼓励用路线图的方式描述这种关系**。
>
> **6.4 工作基础和已有进展**：课题研究的**起点**，课题组内外已有的工作基础、材料和方法。本人的预研情况，**目前已经取得的进展**等。

来源：https://yjs.hzau.edu.cn/info/1202/3772.htm 等级 `A`（校级研究生院正式发布）

这一段信息量很大，四个词的分工在这份规范里是**显式写死**的：

- **研究内容** = 「拟开展的研究工作」分层次描述 → 说的是**要做什么工作**，而且是"分层次"（= 拆成若干子项/子问题），不是罗列技术；
- **研究方法** = 详尽到「他人能重复出这一试验」→ 说的是**怎么做才可信**，落点是可复现性；
- **技术路线** = **图**，画的是「材料/对象 ↔ 方法 ↔ 研究内容 ↔ 目标」的**关系**→ 它是内容的可视化，不是内容的重复；
- **工作基础和已有进展** = 「起点」+「已经取得的进展」→ 说的是**已经发生了什么**（过去时）。

### 1.2 第二份可交叉验证的规范：研究内容挂在「选题」下，技术路线挂在「研究方案」下

常州大学研究生院《研究生开题报告会程序及内容要求》（2024-09-25 修订）的层级是：

> 二、研究生学位论文开题报告应包括以下内容：
> **1．论文选题的目的、意义和研究动态**：①课题来源…②本选题的理论意义或应用价值；③**本选题的主要研究内容、重点与难点、关键技术或主要创新**。
> **2．研究方案**：①**技术方案（技术路线、技术措施）**；②实施方案所需的条件…⑦研究计划进度。

来源：https://gs.cczu.edu.cn/2024/0925/c1824a371327/page.htm 等级 `A`（校级研究生院）

对照 1.1 可以看出稳定性：**「研究内容」和「选题/意义」是同一层（回答"研究什么"），「技术路线」和「进度/条件」是同一层（回答"怎么落地"）**。
两份不同学校、相差五年的规范，把同一个词放在同一个位置——这不是某一家的习惯。

### 1.3 基金口径：研究内容是一个独立的一级标题，和"研究基础/可行性"分开

国家自然科学基金 2026 版面上项目申请书正文提纲：

> （一）**立项依据**：（为什么要开展此项研究，研究的科学技术价值如何）
> （二）**研究内容**：（提纲不做限制，请按照研究工作的自身逻辑撰写。应提炼出特色与创新点、年度研究计划）
> （三）**研究基础**：1．研究基础与可行性分析（与本项目相关的研究工作积累和已取得的研究工作成绩，研究风险的应对措施等）…

来源：2026 版面上项目申请书撰写提纲（经搜狐转载全文，逐条比对与公开模板一致）
https://news.sohu.com/a/975272458_121124372 等级 `B`（转载，非 nsfc.gov.cn 原始页；原始页本轮未取到）

这里有一条很关键的信号：**2026 版把「研究内容」的写法彻底放开了**——"提纲不做限制，请按照研究工作的自身逻辑撰写"。
意思是评审不再要求你按「分几个子问题」的模板写，但你仍然必须自己**立起一个逻辑骨架**。
这恰恰反证了：研究内容不是格式填空，是**你要论证的东西**。

> ⚠️ **待核实项**：更早年份（约 2013–2024）的面上项目提纲里，研究内容下面还挂着一条
> 「拟采取的研究方案及可行性分析（**包括研究方法、技术路线、实验手段、关键技术等说明**）」。
> 这句话在多个文库/问答页面被反复引用，但**本轮没有取到 nsfc.gov.cn 或 edu.cn 的原始页**，
> 只能标 `C`。**结论可以用（研究方案里要写方法+技术路线），但对外引用时不要写"基金委原话"。**

### 1.4 四者辨析对照表

| 维度 | **研究内容** | **研究方法** | **技术路线** | **已完成工作** |
|---|---|---|---|---|
| **回答什么问题** | 我要研究**什么**（拆成哪几个子问题） | 凭什么**可信**（方法是否被领域承认、是否可复现） | 这些东西**怎么串起来**（先后、依赖、数据流） | 我**已经**做到哪一步了 |
| **时态** | 将来/应然（拟开展） | 将来/应然 | 将来/应然（但画成图） | **过去**（已发生） |
| **该写什么** | 子问题清单，每条是一个**未被解决的困难**；子问题之间有依赖或并列关系 | 领域内成熟方法的**名称 + 出处 + 选用理由**；必要的方法改造点 | 一张**图**：数据 → 处理 → 方法 → 输出，标出关键节点与判据 | 数字 + 证据：实测指标、交付物、通过的门禁 |
| **不该写什么** | ❌ 技术名（"我用 bge-m3"）<br>❌ 步骤（"先切块再入库"）<br>❌ 已经做完的事 | ❌ 自己的实现细节（那是工程文档）<br>❌ 空泛的"采用了深度学习方法" | ❌ 另一份文字版研究内容（图应压缩信息，不是复述）<br>❌ 甘特图（那是进度） | ❌ 计划（"下一步将…"）<br>❌ 没有分母的数字 |
| **判断写错的口诀** | 出现**动词+技术名词** → 大概率写成了方法 | 出现**文件名/函数名/接口名** → 大概率写成了实现 | 图里出现**时间刻度** → 写成了进度 | 出现**"将/拟/计划"** → 写成了计划 |

### 1.5 本项目上次到底错在哪（对照着看）

| 上次写的 | 属于哪一类 | 为什么错 |
|---|---|---|
| 「知识怎么组织」 | 研究方法（chunking 策略） | 通用 RAG 共有，不是医学问题；且它是**手段**不是**待解决的困难** |
| 「检索怎么保相关」 | 研究方法（hybrid retrieval） | 同上。BM25（Robertson & Zaragoza, 2009，被引 3288）+ 向量 + RRF（Cormack et al., SIGIR 2009，被引 790）都是十几年前的成熟件 |
| 「结论怎么保依据」 | 研究方法（Self-RAG / 冲突检测） | 同上。且本项目这两个组件本身还没调通 |
| 「把成熟方法组合成一条可核查链路」 | 已完成工作（而且只是工作量） | 组合不产生新知识，评委会直接问"那你的贡献是什么" |

**一句话结论**：研究内容必须写到**"这里有一个别人没解决的困难"**这一层，而不是"我用了什么工具"这一层。

### 1.6 中期答辩 PPT 里怎么分开呈现

曦源中期的官方门槛是三条：**完成文献综述 / 明确课题进展思路 / 已取得初步成果**（2012、2017 两版《中期报告须知》措辞一致，`03-曦源中期要求调研.md` §1.3 有原文）。
注意中间那条是**「思路」**——这正好对应"研究内容与方法"页要证明的东西：你有思路，不是有一堆工具。

实操上四者在一页里这样落位（3 分钟版只有一页，装不下四块）：

| 页 | 承载 | 对应四者中的 |
|---|---|---|
| P3「研究内容与方法」 | 2~3 个子问题 + 每个子问题下方一行"用什么方法/凭什么" | 研究内容（主）+ 研究方法（从，一行一个方法名） |
| P3 或 P4 的小图 | 数据流/模块关系图 | 技术路线 |
| P4「已完成工作与阶段成果」 | 数字 + 证据 | 已完成工作 |

**关键取舍**：一页里研究内容是**主语**，研究方法是**谓语**（"用什么手段解决它"），绝不能反过来把方法当主语。
反过来写就会出现"我有 bge-m3、有 CRAG、有 Self-RAG"这种念工具清单的效果——评委听到的是一份技术选型报告，不是一份研究计划。

## 第二部分 · 医学 RAG 到底特殊在哪（8 条结构性差异）

这一节是全稿的核心。判断标准只有一条：**这条差异如果不成立，通用 RAG 方案就该直接能用；它成立，通用方案就必须改造。**

先给总表，后面逐条展开证据。

| # | 差异 | 通用 RAG 的做法 | 医学里为什么直接套会失效 | 本项目碰没碰 |
|---|---|---|---|---|
| **D1** | 错误代价**不对称** | faithfulness / answer relevancy 是**无方向标量** | 良性→恶性 与 恶性→良性 代价差一个量级；同一个分数背后可能是漏诊也可能是过度治疗 | 碰了：代码区分"活检 vs 随访"强冲突，**指标没跟上** |
| **D2** | 知识是**层级结构** | 按 token 长度切块 | 指南的语义单元是「推荐条目 + 证据等级 + 适用人群」，证据等级挂在章节上，切碎就丢 | 碰了但**主动放弃**：库里 88.5% 单块文档，结构上不存在层级 |
| **D3** | 要求**逐条可追溯** | 答案相似即可，引用是加分项 | 要能说"这句来自 ACR TI-RADS 2017 第 X 条"，且要能被人复核 | 碰了：只有 chunk 级 ID，**无条目级/证据等级**；且证据链在 CRAG 路径断 |
| **D4** | **跨来源断崖** | 换测试集掉几个点算正常 | 医学是物理层面的 shift（设备/探头/采集协议/人群），本项目实测 0.895 → 0.4929 | 碰了，**有硬数字** |
| **D5** | **患者级泄漏** | 按样本随机切分 | 同一患者多张图跨集 → 指标虚高；规范要求患者级切分 | 碰了：库里 584 张影像只来自 **11 个患者** |
| **D6** | **术语体系**（UMLS/SNOMED/分级术语） | 通用 embedding 处理同义词 | 上下位关系（"低回声" ⊂ "回声异常"）、分级术语（TR4/LR-5）不是语义相似度能表达的 | 碰了：自建 UDAF 词表，**UHAT 四级层级未实现**，未接 UMLS |
| **D7** | **触发/判定器是通用训练的** | Self-RAG 用反思 token、CRAG 用轻量评估器 + **网页搜索** | 医学语料封闭，网页搜索是风险源；通用判官不懂分级体系 | 碰了：Self-RAG 是**提示词版的 7B 判官**，不是训练出来的反思模型；CRAG 的 web 扩展在本项目里不存在 |
| **D8** | **融合架构假设 ≥2 份独立结论** | 多智能体投票/辩论天然成立 | 临床推理通常是**单专科单结论**，没有第二份可投票 | **架构性不成立**：`len(responses) < 2` 时冲突检测直接 return |

## 第三部分 · 逐条展开（问题描述 / 为什么通用方案解决不了 / 有没有人在做 / 本项目碰没碰）

### D1 · 错误代价不对称，但评测指标是无方向标量

**问题描述。** 医学里"答错"不是一个标量：把良性判成恶性 → 过度穿刺、过度治疗、患者恐慌；
把恶性判成良性 → 漏诊、延误、可能致命。这两个方向的代价差一个量级，而且**方向不同、纠错手段也不同**。
但主流 RAG 评测的所有核心指标——faithfulness、answer relevancy、context precision/recall——**都是无方向的标量**。
一个 0.9 的 faithfulness 背后，可能是 9 次良性误判，也可能是 9 次恶性漏诊，**指标看不出来**。

**为什么通用方案解决不了。** 通用 RAG 的评测问题定义里根本没有"错误方向"这一维，它假设所有错误等价。
要加这一维，指标就从"一个数"变成"一个带权矩阵"，而这套东西通用 benchmark 里没有。

**有没有人在做。** 有，但是**在别的圈子里，没有搬到 RAG**：

| 工作 | 干了什么 | 与本问题的距离 |
|---|---|---|
| Vickers & Elkin, *Decision Curve Analysis: A Novel Method for Evaluating Prediction Models*, Medical Decision Making 2006（DOI 10.1177/0272989X06295361，被引 5813）`A` | 用**净获益（net benefit）**给临床预测模型做评价，显式引入"假阳性/假阴性代价比" | 这是医学里解决不对称代价的标准工具，但它评的是**预测模型**，不是 RAG |
| Elkan, *The Foundations of Cost-Sensitive Learning*, IJCAI 2001 `C`（经典文献，本轮未取到原文页，标待核实） | 给出代价敏感学习的理论基础（代价矩阵如何影响最优决策） | 同上：分类器层面，不是生成/检索层面 |
| Pal & Sankarasubbu, *Med-HALT: Medical Domain Hallucination Test for LLMs*, CoNLL 2023（DOI 10.18653/v1/2023.conll-1.21，被引 151）`A` | 第一个医学幻觉基准，分 reasoning / memory 两类 | 分了**类型**，没分**方向**，也没分**代价** |
| Han et al., *MedSafetyBench*, NeurIPS 2024（DOI 10.52202/079017-1054）`A` | 测医学安全，判"回答是否违反医学伦理/安全" | 二元安全判定，不是风险分层评分 |
| Rana, *Beyond RAGAS: A Compliance-Aware Evaluation Framework for RAG in Regulated Sectors*, 2026（DOI 10.70917/ijcisim-2026-4739）`A`（新，被引 0） | 明确提出 RAGAS 在**受监管行业**不够用，要加合规维度 | **最接近的一条**，但它做的是"合规"（可审计、可追溯），不是"临床代价不对称" |
| Arora et al., *HealthBench*, arXiv:2505.08775（2025）`A` | 5,000 段多轮对话，由 **262 位医生**编写对话专属 rubric，共 **48,562 条评分准则**（覆盖准确性、指令遵循、沟通等维度） | 说明"按准则逐条打分"在医学里已被接受；但它评的是**对话**，不是 RAG 检索链。⚠️ 每条准则的分值是否加权，摘要未写明，**待核实** |

**结论：这个 gap 是真的。** 医学有自己的代价工具（DCA），RAG 有自己的评测工具（RAGAS），**两者没有接上**。

**本项目碰没碰。碰了，而且碰到了痛点。**
- 代码里已经**承认了方向不对称**：`app/fusion/protocols.py:44` 把 `RECOMMENDATION_CONFLICT`（"活检 vs 随访"）定义为一种独立冲突类型；

### D2 · 医学知识是层级结构（指南→章节→推荐条目→证据等级），扁平分块会切碎语义单元

**问题描述。** 临床指南的组织方式是：**指南 → 章节 → 推荐条目 → 证据等级/推荐强度**。
一条推荐意见常常只有一两句话（"对于 TI-RADS 4 类结节，建议 FNA"），但它的**证据等级**（A/B/C、强/弱推荐）
附着在章节级别上。按 token 长度切块，会把推荐条目和它的证据等级切开——检索到条目时，系统不知道这条推荐有多硬。

**为什么通用方案解决不了。** 通用 chunking 的优化目标是"块长适中、语义连贯"，它对"文档内部有没有权威层级"
是**无感**的。同理通用 embedding 也不区分"这段是正文还是证据标注"。

**有没有人在做。** 有，但分成两条互不相关的线：

| 工作 | 干了什么 | 缺什么 |
|---|---|---|
| Peleg et al., *GLIF3: a representation format for sharable computer-interpretable clinical practice guidelines*, J Biomed Inform 2004（PMID 15196480）`A`；GLIF 系列综述见 *Computer-Interpretable Guideline formalisms*, Stud Health Technol Inform 2008（PMID 18806319）`A`；*Comparing computer-interpretable guideline models: a case-study approach*, JAMIA 2003（PMID 12509357）`A` | 把指南形式化成**可执行流程**（决策节点、条件、动作） | 目标是把指南变成**工作流引擎**，不是"让检索找到推荐条目"。而且要**人工形式化**，成本极高 |
| Guyatt et al., *GRADE: an emerging consensus on rating quality of evidence and strength of recommendations*, BMJ 2008（DOI 10.1136/bmj.39489.470347.ad，被引 20723）`A` | 证据质量与推荐强度的**国际通用分级体系** | 定义了**怎么标**证据等级，没说**怎么检索**它 |
| Buonocore & Marino, *Ontology-Enriched Guidelines Retrieval for Complex Rheumatological Cases*, Stud Health Technol Inform 2026（DOI 10.3233/shti260345）`A` | **本体增强的指南检索**，正好打这个点 | 2026 年新工作，被引 0；做法是加 ontology 层，不是改 chunk 语义单元 |
| Schwietering & Lichtner, *Benchmarking LLMs for question answering on German clinical practice guidelines*, BMJ Health Care Inform 2026（DOI 10.1136/bmjhci-2026-102207，PMID 42580812）`A` | 拿真指南做 QA 基准 | 只做评测，不做检索结构改造 |

**结论：指南"怎么表示"有人做（CIG），指南"怎么分级"有人做（GRADE），指南"怎么检索"刚有人起步（2026 那两篇，
被引都是 0）——但"把证据等级做成检索的一等公民"这件事，没有成熟方案。**

**本项目碰没碰。碰了，而且做过量化体检，然后主动放弃。**
- 代码**有**层级概念：`app/knowledge/protocols.py:75-100` 的 `KnowledgeChunk` 带 `section_path`
  （注释举例就是 `"TI-RADS/Category 4/Subcategory 4A"`）；`app/knowledge/chunker.py:304` 的 `SemanticChunker`
  会按 TI-RADS / LI-RADS / Category 标题切。
- **但默认不用它**：`app/knowledge/builder.py:269` 的默认策略是 `strategy: str = "sentence_boundary"`。
- **体检结果更狠**（`16-开发进展汇报-20260928.md:6004-6005`，A.64 WP2 真机 SQL）：
  文档粒度 **单块文档 936 个（88.5%）**、2-3 块 116、4+ 块 5；块粒度中位 **146 token**、`<256` 占 **68.8%**。
  结论写得很直白：「**88.5% 的文档结构上不可能有图边**」，overlap 类切分改造对 936 个单块文档**零影响**。

- 结论：这不是"没做"，是"发现了但没有可用的结构去承载"。**这个 gap 是可以写进研究内容的。**

### D3 · 要求逐条可追溯，但引用粒度只到 chunk

**问题描述。** 医学场景的要求不是"答案和原文相似"，而是"这句话来自哪份指南的第几条推荐、证据等级多少"，
且这个溯源链要能让**另一位医生独立复核**。通用 RAG 的引用是加分项（ALCE 里 citation precision 是可选指标），
医学里引用是**必要条件**——没有出处的结论医生不敢用。

**为什么通用方案解决不了。** 通用评测的归因粒度是"这句话是否被某个 passage 支持"（claim-level entailment），
**passage 边界就是引用边界**。医学要的是"条目级"，而条目往往只有一两句话、和周围文字混在同一个 chunk 里。

**有没有人在做。**

| 工作 | 干了什么 | 与本问题的距离 |
|---|---|---|
| Gao et al., *Enabling Large Language Models to Generate Text with Citations*（ALCE），EMNLP 2023（DOI 10.18653/v1/2023.emnlp-main.398，被引 213）`A` | 定义 citation recall / citation precision 两个自动指标 | 通用文本，passage 级；不涉及"证据等级" |
| Rashkin et al., *Measuring Attribution in Natural Language Generation Models*, arXiv:2112.12870（2021）`A` | AIS 框架：归因要可分解、可核验 | 通用框架，不解决医学条目粒度 |
| Bohnet et al., *Attributed Question Answering: Evaluation and Modeling for Attributed LLMs*, arXiv:2212.08037（2022）`A` | 把"答案+出处"作为联合建模目标 | 同上 |
| Ülkir & Paslı, *Reference Hallucination, Citation Reliability, and Readability of LLMs in Anatomy-Related Questions*, Clinical Anatomy 2026（DOI 10.1002/ca.70187，被引 5）`A` | 测医学问答里的**参考文献幻觉** | 只评测"引用是否真实存在"，不解决"引用是否支持该结论 + 证据等级" |

**结论：通用归因指标体系成熟（citation recall/precision、AIS），医学特有的两种需求——**
**「条目级粒度」和「证据等级入引用」——没有被解决。**

**本项目碰没碰。碰了，而且出了一条很难看的实测。**
- 数据结构只有 chunk 级：`evidence_chunk_ids` 是 chunk 列表，没有条目级子结构。
- 真机实测（`22-质量提升全景汇总-20261026.md` §Q11）：**心脏腿 2/2** 出现"数据库 `knowledge_ids` 里有块，
  但不在任何 `_build_prompt` 留痕中"（例：`dialogue_cardiac_外科_0028#0000`），甲状腺腿 5/5 正常。
  **后果是一条结论无法回答"这条结论到底看了哪些材料"**——这正好是可信度的根基。
- 定位到具体位置：`app/fusion/crag.py::_merge_evidence_three` 第①步（有意合并非 bug），
  `progress.md` A 类「Q11 证据链」条已记录，并加了 `evidence_sources` trace + 专用日志。

### D4 · 跨来源断崖：医学影像的 domain shift 是物理层面的

**问题描述。** 同一模型在同一任务上，换数据来源后性能可能从"可用"掉到"接近随机"。
这不是过拟合，来源是**设备厂商、探头型号、采集参数（增益/深度/频率）、操作者手法、人群分布**——
这些差异在自然图像里没有对应物。

**为什么通用方案解决不了。** 通用 NLP/视觉的 domain shift 主要是**语义/风格**层面（换领域语料、换画风），
主流做法是继续预训练或少量适配。医学的 shift 是**成像物理**层面的，继续预训练需要目标域标注数据——
而目标医院恰恰没有。

**有没有人在做。** 有，而且是医学影像 AI 的公认痛点：

| 工作 | 干了什么 | 与本问题的关系 |
|---|---|---|
| Zech et al., *Variable generalization performance of a deep learning model to detect pneumonia in chest radiographs: A cross-sectional study*, PLoS Medicine 2018（DOI 10.1371/journal.pmed.1002683，被引 1693）`A` | 证明同一模型换医院后性能大幅变化，且**不同医院变化方向不同** | 这是这个痛点的经典证据 |
| Yoon et al., *Domain Generalization for Medical Image Analysis: A Review*, Proceedings of the IEEE 2024（DOI 10.1109/jproc.2024.3507831，被引 107）`A` | 医学影像域泛化综述 | 说明"方法很多但没有通解" |
| *The impact of scanner domain shift on deep learning performance in medical imaging: an experimental study*（PMID 42062639，2026）`A` | 专门量化**扫描仪**造成的性能损失 | 2026 年还在做，说明没解决 |
| *The reliability of a deep learning model in clinical out-of-distribution MRI data: A multicohort study*, Medical Image Analysis 2020（PMID 33007638）`A` | 多队列 OOD 可靠性 | 同上 |

**结论：公认痛点，方法很多，没有通解。** 但注意——**这一条偏"影像模型"，不是 RAG 问题**（见第四部分，我建议它降级）。

**本项目碰没碰。碰了，拿到了本项目最硬的一个负结果。**
- 三口径分列（`progress.md:154`、`:751`，A.63 WP3 + A.64.1 判定）：
  **开发集 0.8751 / AUL 公开集 0.8950 / TN3K 跨来源 0.4929**（n=614，AUC 0.4929，95%CI [0.4438, 0.5402]）。

  → 排除"映射写反""阈值不当"两种解释，判定为真实的跨来源失效。

  `tests/reports/t2a_tn3k_generalization.json` 已加 `_status: VOIDED`。唯一可复现口径 = `reports/t2a_tn3k_cross_source.json`。

### D5 · 患者级数据泄漏：指标准则层面的规范问题

**问题描述。** 同一患者的多张图像（同一结节的不同切面/不同时间）如果被随机分到训练集和测试集，
模型会"见过这个人"，指标虚高。医学影像的标准要求是**患者级（patient-level）切分**，不是样本级。

**为什么通用方案解决不了。** 通用 ML 的切分规范只要求"训练/测试独立同分布"，没有"患者"这个实体概念。
自然图像里一张图就是一个独立个体，医学里一个患者对应几十上百张图。

**有没有人在做。** 有，而且已经写进**报告规范**：

| 工作 | 干了什么 | 等级 |
|---|---|---|
| Kapoor & Narayanan, *Leakage and the reproducibility crisis in machine-learning-based science*, Patterns 2023（DOI 10.1016/j.patter.2023.100804，被引 1313）`A` | 系统梳理 ML 研究中的数据泄漏类型，患者级泄漏是其中一类 | 通用方法论，不专医学 |
| Mongan et al., *Checklist for Artificial Intelligence in Medical Imaging (CLAIM): A Guide for Authors and Reviewers*, Radiology: AI 2020（DOI 10.1148/ryai.2020200029，被引 1437）`A`；2024 更新版 DOI 10.1148/ryai.240300（被引 616）`A` | 医学影像 AI 论文的**强制检查清单**，含切分方式、外部验证 | 规范层面已解决（"该怎么写"），执行层面没解决 |
| Collins et al., *TRIPOD+AI statement*, BMJ 2024（DOI 10.1136/bmj.q902，被引 203）`A` | 临床预测模型的报告规范更新 | 同上 |

### D6 · 医学术语体系：上下位、同义词、分级术语，通用 embedding 处理不了

**问题描述。** 医学概念有三层结构通用 embedding 表达不了：
①**同义词**（"低回声"/"hypoechoic"/"回声减低"）；②**上下位**（"微钙化" ⊂ "钙化" ⊂ "回声异常"）；
③**分级术语**（TR4a / LR-5 / LVEF 40% 这些是**离散有序标签**，不是自由文本）。
语义相似度会把"TR3"和"TR4"算得很像（一个字之差），但它们临床上处置完全不同（随访 vs 穿刺）。

**为什么通用方案解决不了。** 通用 embedding 训练目标是"语义相近的文本向量相近"。
分级术语恰恰是"文本极像但语义上有序且不相邻"的反例。同理，"低回声"和"高回声"字面相似度极高，
临床上却是相反的征象。

**有没有人在做。** 术语资源与实体链接很成熟，但**接到 RAG 检索上**没成熟：

| 工作 | 干了什么 | 等级 |
|---|---|---|
| Bodenreider, *The Unified Medical Language System (UMLS): integrating biomedical terminology*, Nucleic Acids Research 2003（DOI 10.1093/nar/gkh061，被引 4326）`A` | UMLS 把 100+ 术语体系（含 SNOMED CT、ICD）整合成统一超词表，带同义词与上下位关系 | 元数据层面成熟 |
| Donnelly, *SNOMED-CT: The advanced terminology and coding system for eHealth*, Stud Health Technol Inform 2006（被引 549）`A` | SNOMED CT 的概念模型（is-a 层级 + 属性关系） | 同上 |

**结论：术语资源（UMLS/SNOMED/CMeKG）和实体表示（SapBERT）都成熟，但"中文 + 超声 + 分级术语"**
**这一层没有现成件。分级术语的有序性更是完全没人处理。**

### D7 · Self-RAG / CRAG 的触发与判定机制，在医学场景前提不成立

**问题描述。** 这两套方法是目前 RAG 纠错的两条主线，但它们的**前提在医学场景不成立**：

- **Self-RAG** 的核心是「训练一个会用**反思 token**（retrieve / ISREL / ISSUP / ISUSE）的模型」，
  让模型自己决定"要不要检索、这段支持不支持、这段有没有用"。
  → **前提：你要能训练这个 critique 模型，且有大量标注。**
- **CRAG** 的核心是「一个轻量**检索评估器**判检索质量，差就走**大规模网络搜索**补」。
  → **前提：有公开网络可搜，且网上有正确答案。**

**为什么通用方案解决不了。** 医学场景两条前提都塌：
① 训练 critique 模型需要医学标注数据（本项目只有 11 个患者）；
② 医学的"正确答案"在**封闭指南语料**里，网络搜索会引入无来源内容——**在医疗里这是风险源不是补救**。

**有没有人在做。**

| 工作 | 干了什么 | 对本问题的意义 |
|---|---|---|
| Asai et al., *Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection*, arXiv:2310.11511（2023）`A` | 训练带反思 token 的 LM（7B/13B），自适应检索 | 原始方法**必须训练**，不是提示词能复现的 |
| Yan et al., *Corrective Retrieval Augmented Generation*, arXiv:2401.15884（2024）`A` | 轻量检索评估器 + **大规模 web 搜索**扩展 + decompose-then-recompose | web 扩展这条在医学封闭语料里**不可用** |
| Huang et al., *Large Language Models Cannot Self-Correct Reasoning Yet*, arXiv:2310.01798（2023）`A` | 证明 LLM **无外部反馈时自我纠错不可靠**，甚至会改坏 | 直接否掉"让模型自己判自己对不对"这条路 |
| Xiong et al., *Can LLMs Express Their Uncertainty? An Empirical Evaluation of Confidence Elicitation in LLMs*, arXiv:2306.13063（2023）`A` | LLM 自报置信度**系统性过度自信** | 同上：判定器本身不可靠 |
| Geifman & El-Yaniv, *Selective Classification for Deep Neural Networks*, arXiv:1705.08500（2017）`A` | 选择性预测：允许模型"拒答"，用 coverage-risk 曲线评价 | **这才是医学该用的思路**——不是自纠，是"不知道就说不知道" |

**结论：这是本稿里"最被高估"的一块。** Self-RAG/CRAG 的论文很热，但**在医学封闭语料 + 低标注量 +
不可自纠**三个约束下，它们的适用性是**存疑**的。这本身就是一个值得研究的问题。

**本项目碰没碰。碰了，而且实现与论文名同实异——这一点必须自己先说清楚，否则被评委问穿。**
- `app/fusion/self_rag.py`：是**提示词驱动的 7B LLM 判官**（`DEFAULT_PASS_THRESHOLD = 3.0`，`:82`；
  有 `InferenceEngine=None` 时的启发式兜底，`DEFAULT_HEURISTIC_THRESHOLD = 0.7`，`:85`），
  **没有**训练反思 token，**没有** retriever 决策 token。**叫 Self-RAG，但机制不是 Self-RAG。**
- `app/fusion/crag.py`：有检索质量评估（`_chunk_score`，`:112`；失败原因含 `score_below_threshold`，`:102`），
  但**没有 web 搜索腿**——这个项目的语料是封闭指南库，"补检索"只能回到同一个库。
- 判官实测：Qwen3-8B（GGUF Q4_K_M，独立 8006 实例，`16-开发进展汇报-20260928.md:396`）。
  faithfulness 100 例重跑见 `tests/reports/t1_faithfulness_qwen3_report.json`。
- 还有一条更细的坑值得写：`progress.md:144` 记录判官**把中文结论拆成英文断言再对中文资料做 NLI**，
  跨语言错配使分数**约减半**（auto 英文断言原口径 0.1021 → 强制中文 0.1993）。
  → **这不是模型问题，是判定器与语种不匹配的建模问题。**

### D8 · 多智能体融合的前提（≥2 份独立结论）在单专科场景下不成立

**问题描述。** 融合层 / 冲突检测 / 投票 / 辩论这一整套多智能体机制，**共同前提是有 ≥2 份独立结论可比**。
但临床推理的常态是：**一个器官、一个专科、一份结论**。没有第二份可比，融合层就空转。

**为什么通用方案解决不了。** 多智能体框架（AutoGen / LangGraph / 辩论 / 投票）都是在"多份输出"的设定下设计的，
它们不处理"只有一份输出时怎么办"。而"只有一份"恰恰是医学的常态。

**有没有人在做。**

| 工作 | 干了什么 | 对本问题的意义 |
|---|---|---|
| Wu et al., *AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation*, arXiv:2308.08155（2023）`A` | 多智能体对话编排框架 | 框架，不回答"单结论时怎么校验" |
| Du et al., *Improving Factuality and Reasoning in Language Models through Multiagent Debate*, arXiv:2305.14325（2023）`A` | 多智能体辩论提升事实性 | **前提就是多份**独立回答 |
| Cemri et al., *Why Do Multi-Agent LLM Systems Fail?*, arXiv:2503.13657（2025）`A` | 1600+ 条标注轨迹 / 7 个主流 MAS 框架，归纳出 **14 种失败模式、3 大类**（系统设计 / 智能体间不一致 / 任务验证），判官与人工一致性 κ=0.88 | **最有价值的一篇**：核心结论是「**MAS 在主流基准上的性能增益常常很小**」——多智能体不是净收益，它自带新的失败面 |
| Dhuliawala et al., *Chain-of-Verification Reduces Hallucination in LLMs*, Findings of ACL 2024（DOI 10.18653/v1/2024.findings-acl.212，被引 273）`A` | 单模型自我验证链（不依赖多份结论） | **医学更该走这条路**：用外部证据验证，而不是用第二份模型输出投票 |

**结论：多智能体在「多结论」设定下成熟；在「单结论」设定下，没有成熟的替代方案。**
（按 Dhuliawala 那条 CoVe 的思路，答案大概率是「用外部证据逐条验证」，而不是「多模型投票」。）

**本项目碰没碰。碰了，而且代码里能直接看出这个空洞。**
- `app/fusion/conflict.py` 四个检测器都是同一个模式：
  - `_detect_grading_conflicts`（`:287`）：`if organ_value == "__none__" or len(group) < 2: continue`
  - `_detect_confidence_conflict`（`:313`）：`if len(responses) < 2: return []`
  - `_detect_recommendation_conflict`（`:335`）：`if len(responses) < 2: return []`
  - `_detect_evidence_conflict`（`:384`）：`if len(responses) < 2: return []`

  → **单器官单结论请求进来，四个检测器全部直接返回空**，融合层不产生任何校验。
- 而实际请求的主路径恰恰是单器官：`app/models/schemas.py:240` 的 `target_organ: Organ`（单数，必填），
  多器官走的是另一条 `target_organs` 路径（`:712`、`:720`）。
- 所以本项目"融合层"的真实收益场景是**跨器官请求**，而这是少数场景。
  这一点必须自己想清楚：**不能把"多智能体融合"当成通用贡献讲。**

## 第四部分 · 模型性能层：两条"通用榜单强 ≠ 垂域强"的实测

这一节单独拎出来，因为它是"模型性能"层面的、和上面的架构/评测层面不重叠。

### C1 · 通用 embedding 在医学垂域的退化（本项目有一手 A/B）

- **背景工作**：MTEB（Muennighoff et al., EACL 2023，DOI 10.18653/v1/2023.eacl-main.148，被引 544）`A`
  是通用嵌入基准，医学任务只占其中很小一块；M3-Embedding / bge-m3（Chen et al., Findings of ACL 2024，
  DOI 10.18653/v1/2024.findings-acl.137，被引 749）`A` 是多语言多粒度检索嵌入；
  MedCPT（Jin et al., Bioinformatics 2023，DOI 10.1093/bioinformatics/btad651，被引 174）`A` 用 PubMed 搜索日志
  做对比预训练——**是英文 + PubMed 文献域**，不是中文 + 超声指南。
- **有人在做**：*Clinical Context Variables Collectively Rival Model Choice in Embedding-Based Retrieval:
  Multi-Corpus Benchmark Study*, JMIR Medical Informatics 2026（PMID 42097608）`A`——结论是"临床上下文变量
  的影响与选哪个模型相当"，说明**榜单排名在真实临床语料上不可靠**。
- **本项目实测（一手）**：Qwen3-Embedding-0.6B 换代 A/B，**显著退化**：hit@5 **-18.38pp**、MRR **-29.19pp**
  （`progress.md:12`、§Q10）。项目组的结论一句话：「**通用榜单强 ≠ 垂域强，必须自己 A/B**」。
  → 这是本项目**可以直接讲的一条方法论结论**，而且是负结果，含金量比正结果高。

### 推荐的三个（+ 为什么不选另外几个）

**S1｜错误代价不对称条件下，RAG 系统该怎么评测？**
- 通用 RAG 没有任何"误判方向"的概念，指标是标量；
- 医学有成熟工具（DCA / net benefit，Vickers 2006），但**从没接到 RAG 上**；
- 本项目一手证据：**干净样本**（n=17）faithfulness 原口径 **0.1767** / A 口径 **0.1331**，门限 0.95；
  三种口径在同一（脏）切片上只差 0.03（0.0906/0.1258/0.0836）→ **换口径救不了，说明指标本身问错了问题**；
  更硬的证据是断言构成：干净样本里 **knowledge 占 54.6%、知识断言支持率仅 15.5%**（`progress.md:140`）；
- 可行落点：把"方向 + 风险等级"做成评测矩阵（良性→恶性 / 恶性→良性 / 处置层 / 分级层）。
  ⚠️ 前提：这需要**带真实转归的病例**，现有 780 例是模板生成、没有"良恶性真值方向"，**不能直接用**。
  现实做法是先用 157 条真实判读 + 扩采后的人工标注子集做口径验证，把矩阵定义钉死，再谈全面重算。

**S2｜指南的层级结构与证据等级，能不能成为检索的一等公民？**
- 这是**最"RAG 医学特异"**的一条：通用 chunking 对文档权威层级完全无感；
- 有人做指南"表示"（GLIF 系列，2003-2008 的三篇已核实；PROforma/Asbru 同类形式化体系**本轮未取原文，标待核实**）、
  有人做指南"分级"（GRADE，2008）、2026 才有两篇碰"指南检索"（被引都 0）→ **真正的空白**；
- 本项目一手证据最狠：库结构体检查出 **88.5% 单块文档、中位 146 token**，
  且 `KnowledgeChunk` **根本没有 evidence_level 字段** → "不是没做，是没有承载结构"；
- 可行落点：给 chunk 加 `evidence_level` + `recommendation_id`，在语义切分策略下做 A/B。

**S3｜结构化分级（TI-RADS/LI-RADS）能不能作为生成与评测的对齐目标？**
- 通用 RAG 的优化与评测都在**文本空间**（相似度、faithfulness）；分级是**离散有序标签**，
  "文本很像"和"分级正确"是两件事（TR3 vs TR4 一字之差，临床上随访 vs 穿刺）；
- 本项目一手证据最完整：`app/inference/grading_definitions.py` 396 行在做分级解析。
  三条实测**必须分开讲，别混**（口径、样本、时点都不同）：
  - **A2 口径**（结构化输出 + 双引擎 Qwen2.5-7B，**780 例脚本生成的分层用例**，2026-09-30）：
    常规+高风险 **91.47%**（340 例），距 95% 差 3.5pt（`16号` §A.2.2，`tests/reports/consistency_780_a2_layered_report.json`）。
    ⚠️ **这 780 例不是真实病例**——由 `scripts/server_build_eval_cases.py` 从模板生成
    （常规 3 器官×80 + 边界 440 刻意 ±1.5 抖动 + 高风险 100），测的是**两台引擎对模板的一致性**，
    **不是临床准确率**。答辩时要说"双引擎一致性"，不能说"准确率 91.47%"。
  - **Q29 约束解码重测**（`response_format: json_schema`，同引擎两次生成）：常规 **79.56%** / 高风险 **40.88%**，
    **远未达标**；根因写得很清楚——"约束解码只保证**格式合法**，不保证**内容确定**；TI-RADS 在边界病例
    本身就有判读分歧"（`16号` §A.95 第③条，`progress.md:13`；原始表在 `16号:8230-8231`）。这条是**否掉"约束解码能救一致率"**的关键负结果。
  - **样本量现状**：真实判读记录经 A.70 清理后**当前最大只有 157 条**（`16号` §A.95 ③ 原话："**780 例已不存在**（当前最大 157 条，A.70 清理 608 条后）"）；
    780 例那套可以重新生成，但**不能拿来说"我评了 780 个真实病例"**。
- 另一条根因证据：**甲状腺** 306 条里有 **59 条（19.3%）"分级无法判断"**（全库是 67/497=13.5%），
  这 59 条里 **76%（45 条）正文明确说"缺影像特征"**（`22号` §Q3b 及 §0 基线表）——
  即分级失败的**一半原因是输入侧没把影像特征喂进去**（`rag_use_multimodal` 默认 `False`，
  `app/config/settings.py:416`），不是模型不会分级；
- 可行落点：把"分级正确率"作为一级指标，做"文本相似 → 分级正确"的口径切换 + 双引擎一致性验证。

**为什么 S4（跨来源泛化）不推荐作研究内容**：它本质是**影像模型**问题不是 RAG 问题，
而且中期后做不完（需要新的外部数据集 + 重训）。建议把它放 P4「已完成工作」作为**一条发现**讲
（"我们发现模型换来源后 AUC 从 0.895 掉到 0.4929，所以我们不敢声称它的临床可用性"），
比塞进研究内容更诚实、更有说服力。

**为什么 S7（患者级泄漏）不作研究内容**：规范层面已经解决（CLAIM 2020/2024、TRIPOD+AI 2024），
它不构成"未解决的研究问题"。但它是本项目**最重要的现状约束**（584 影像/11 患者），必须在 P5 说。

## 第六部分 · 这一页建议怎么组织（3 种版式）

前提：P3 只有 50 秒、口播约 200 字。一页装不下三个子问题的完整论证，**只能装"三个标题 + 每个标题下一行证据"**。

### 版式 A｜三栏并列（推荐）

```
┌──────────────────────────────────────────────────────────────┐
│  研究内容：医学 RAG 里三个没解决的问题                       │
├───────────────┬───────────────┬──────────────────────────────┤

│               │               │                              │
│ 同一句"答错"，│ 指南的语义单元│ 分级是离散有序标签，         │
│ 良性→恶性 与  │ 是"推荐条目+  │ 文本相似 ≠ 分级正确          │
│ 恶性→良性     │ 证据等级"，按 │                              │
│ 代价差一个量级│ token 切就碎  │                              │
│               │               │                              │
│ 现有指标：    │ 本库实测：    │ 本库实测：396 行分级定义     │

│ 仅 0.03       │ level 字段    │                              │
├───────────────┴───────────────┴──────────────────────────────┤
│ 方法（一行一个）：代价敏感评价｜层级感知检索｜结构化约束     │
└──────────────────────────────────────────────────────────────┘
```

**优点**：三块等权，视觉上一眼看出"三个问题"；每块下面都有一个**自己实测的数字**，这是最强的说服力。
**缺点**：每块只能留一句论证，讲不深。
**⚠️ 数字口径注意（三条，务必分清）**：
① ③ 栏的 **91.47%** 是「**双引擎一致性**」，A2 口径，780 例**脚本生成的分层用例**（不是真实病例）；
② **79.56% / 40.88%** 是 Q29 约束解码重测（同引擎两次生成），**不能和 91.47% 混着说**；
③ ① 栏的 **0.1767** 是 A.70.4 **干净样本 n=17** 的 faithfulness（**不是** 0.0906，那个已作废）。
页面上最稳的三种写法：「一致率 91.47%，门限 95%」「忠实度 0.18，门限 0.95」「88.5% 文档只剩一块」。
**口播建议**（约 200 字）：
「我的研究内容不是'做一个 RAG'，而是医学把 RAG 逼出来的三个问题。第一，误判方向不对称——
良性判成恶性和恶性判成良性，代价差一个量级，可现在所有 RAG 指标都是一个不分方向的数；
我们测的忠实度只有 0.18，门限 0.95；换三种口径只差 0.03，说明问题在指标本身，不在模型。
第二，指南是'推荐条目+证据等级'的层级结构，按 token 切就碎了，我们库里 88.5% 的文档只剩一块。
第三，分级是离散的临床标签，文本像不等于分级对。这三条都不是通用 RAG 会遇到的。」

### 版式 C｜一条主线（问题 → 通用方案的失效点 → 我的落点）

```
┌──────────────── 通用 RAG 的三条隐含假设 ─────────────────┐
│  ① 错误等价   ② passage 即语义单元                       │
│  ③ 文本相似 = 正确                                       │
└───────────────────┬──────────────────────────────────────┘
                   │
                   │ 医学里三条全塌
                   ▼
┌───────────────── 换到医学，三条都不成立 ─────────────────┐
│① 良性→恶性 ≠ 恶性→良性（代价差一个量级）                 │
│② 指南=指南→章节→推荐条目→证据等级                        │
│   （按 token 切就碎）                                    │
│③ TR3 ≠ TR4 但字面只差一个字                              │
│   （分级是离散有序标签）                                 │
└───────────────────┬──────────────────────────────────────┘
                   │
                   ▼
┌──────────────────────── 我的落点 ────────────────────────┐
│风险分层评测｜层级感知检索｜分级一致性口径                │
└──────────────────────────────────────────────────────────┘
```

**优点**：**逻辑最完整**，把"通用假设 → 医学反驳 → 我的落点"三段论画出来了，最像"研究思路"而不是"技术清单"。
**缺点**：信息密度低，只有观点没有数字；且画起来最费时间。
**适合**：想强调"我有一套研究思路"而不是"我做了多少活"的场合——但中期答辩评委更想看你做到哪了，
所以我**不推荐单用这一版**，可以把它当成版式 A 的页眉（三行小字）。

---

### 我的建议

**版式 A 为主 + 版式 C 的页眉一句**。理由：
1. 中期答辩的核心不是"思路多漂亮"，是"**这个学生知道问题在哪，而且已经摸到了边**"——A 的每块下面都有自己实测的数字，这一点无可辩驳；
2. 版式 C 的"通用假设 → 医学反驳"结构放在页眉做成一行小字，一句话就把"这不是通用 RAG 问题"讲完了，成本极低；
3. 三个方法名放在底部一行，满足"研究方法"这个栏目标题的要求，但不占版面——因为**这一页的主角是研究内容，不是方法**。

**绝对不要做的两件事：**
- ❌ 不要在 P3 放四层架构图（那是技术路线，属于 P4 或单独一页）。架构图一放，评委的注意力就从"问题"转到"模块"，这一页就废了。
- ❌ 不要在 P3 出现任何技术产品名（bge-m3 / CRAG / Self-RAG / vLLM）。一出现，"研究内容"立刻退化成"技术选型报告"。

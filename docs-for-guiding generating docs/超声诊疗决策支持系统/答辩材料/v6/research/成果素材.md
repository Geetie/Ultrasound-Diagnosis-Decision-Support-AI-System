### 2.2 这套流程里"医生做的决定"有 5 个

① 先看哪位病人（S2）→ ② 看谁、看哪个部位（S3）→ ③ 描述临床情况 + 勾禁忌 + 挑片子（S4）→
④ 信不信这个结论（S6）→ ⑤ 改哪一句、签不签（S7）

**答辩论述用这个**：系统的价值不是"自动出诊断"，是**把医生这 5 个决定的成本降下来**——
第 ②③ 步给结构化入口、第 ④ 步给依据和置信度、第 ⑤ 步给可直接改的草稿。

## 七、给 P4 的两块图（可直接用的骨架）

### 7.1 P4a-① 业务流程图（8 个动作，横向）

```
① 登录         ② 看工作列表      ③ 开一次检查        ④ 传影像 + 填信息
   账号/角色       待处理会话数       患者+设备+部位         DICOM + 临床描述 + 禁忌
   ↓              ↓                ↓                   ↓ 上传即自动发起
                                                      ⑤ 等结果（秒数+字数走动）
                                                       ↓
⑧ 离开/反馈    ⑦ 出报告 + 签发   ⑥ 看结论 + 确认
   回工作列表      草稿→补录→签名      结论/建议/是否复核
```

**每一步标"医生的决定"**（这是这页的魂）：

| 步 | 医生的决定 |
|---|---|
| ① 登录 | 我是谁（角色决定能看到什么） |
| ② 工作列表 | 先看哪位病人 |
| ③ 开检查 | 看谁、看哪个部位 |
| ④ 传影像 | 描述临床情况、勾禁忌、挑片子 |
| ⑤ 等结果 | 继续扫查 or 先写别的（界面明确说"不用等它跑完"） |
| ⑥ 看结论 | 信不信这个结论 |
| ⑦ 出报告 | 改哪一句、签不签 |
| ⑧ 离开/反馈 | 这套系统的结论准不准（唯一的结构化回流通道，但主流程里目前没有入口） |

### 7.2 P4a-② 系统架构图（5 层，纵向）

```

        ↓                          ↓                      ↓
```

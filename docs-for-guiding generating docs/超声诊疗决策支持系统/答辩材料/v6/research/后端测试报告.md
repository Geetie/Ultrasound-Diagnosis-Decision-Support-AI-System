## 3. ⚠️ 测试文件自身的 1 个 bug（你的代码没问题）

### 3.1 现象

原始测试文件（未改动前）在服务器上是 **6 passed / 1 failed**：

```
FAILED tests/unit/api/test_doctor_confirm.py::TestDoctorConfirmBoundaries::test_does_not_sign_or_generate_report

tests/unit/api/test_doctor_confirm.py:146: in test_does_not_sign_or_generate_report
    assert not hasattr(repo, "sign_report")
E   AssertionError: assert not True
E    +  where True = hasattr(<Mock id='133481287079008'>, 'sign_report')
```

### 3.2 根因：不是端点做了什么，是 `Mock()` 的默认行为

`_deps()` 里 `repo = Mock()`（裸 Mock，无 spec）。`unittest.mock.Mock` 的契约是**对任意属性名都返回子 Mock**：

```python
>>> hasattr(Mock(), "sign_report")
True          # ← 哪怕 DiagnosisRepository 根本没有这个方法
>>> hasattr(Mock(), "create_report")
True
```

所以 `assert not hasattr(repo, "sign_report")` **无论 `doctor_confirm_result` 做了什么都会失败**——
这条断言测的是 "Mock 的默认行为"，不是在测"端点有没有偷偷签名"。

**验证（我在本机独立复现过，不是猜的）**：
```
hasattr(repo,'sign_report') = True
assert not hasattr(...) 会: FAIL ← 测试自身 bug
```

同理 `test_does_not_touch_status_or_confidence` 里的
`assert not hasattr(repo, "update_result") or not repo.update_result.called`
也是**靠 `or` 右边才碰巧通过**（左边恒 False）——同样脆弱。

### 3.3 修法：给 Mock 加 `spec`

```python
# 改前
repo = Mock()
# 改后
from app.repositories import DiagnosisRepository
repo = Mock(spec=DiagnosisRepository)
```

加 `spec` 后 Mock 只响应该类**真实存在**的属性：

| 断言 | `spec` 前 | `spec` 后 | 语义 |
|---|---|---|---|
| `hasattr(repo, "sign_report")` | `True`（假） | **`False`** ✅ | 该类确实没有 sign_report |
| `hasattr(repo, "create_report")` | `True`（假） | **`False`** ✅ | 该类确实没有 create_report |
| `hasattr(repo, "update_result")` | `True` | `True` | 该类**有**，但本文不该调用 → 靠 `.called` 判 |
| `hasattr(repo, "mark_doctor_confirmed")` | `True` | `True` | 正常 |

**修完后这条断言才真正有守卫价值**：如果将来有人在这个端点里偷偷调了 report service，
`spec` 会直接 choke（`AttributeError: Mock object has no attribute 'sign_report'`）——
比原来"恒失败"的断言强得多。

> 这条正是 AGENTS.md 记录的「自证腿」纪律：**测试自己也要能证明它能红**。
> 原断言的"红"是永久的，等于没有守卫。

### 3.4 修改落在哪里

- 本机 `tests/unit/api/test_doctor_confirm.py` 已改（`_deps` 加 `spec=` + 补 `from app.repositories import DiagnosisRepository`，并在 docstring 里写清为什么）；

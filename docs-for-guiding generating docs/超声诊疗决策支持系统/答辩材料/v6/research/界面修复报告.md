## 4. P0-4（未做）：确认结论落库 —— 需要你拍板

**位置**：`frontend/src/hooks/useWorkspaceFlow.ts:221-224`

**原问题**：`confirm()` 只 `setAcknowledged(true)`；全仓无消费者、后端无端点。

**为什么本轮没做**：这不是"接线"，是**从零设计一个临床动作的落库形态**。
后端 `diagnosis_results` 表**没有**任何"已核验"字段（`app/models/database.py:82-110` 全量字段已核），
也没有对应端点（`grep doctor_confirm|review_ack|acknowledged app/` 只有 1 处误命中）。

**三个可选方案（都能最小改动落地，但选哪个是产品/合规决策）**：

| 方案 | 做法 | 代价 | 适合谁 |
|---|---|---|---|
| **A（推荐）** | `diagnosis_results` 加 `review_acknowledged_at` + `review_acknowledged_by` 两列，新增 `POST /diagnosis/{id}/acknowledge` | 1 个 alembic 迁移 + 2 列 | 需要"这条结论被谁在何时核验"可查（报告页/质控/审计都要） |
| B | 只写审计链 `AuditLog`，`action="diagnosis_acknowledged"` | 零迁移 | 只要合规留痕，不需要状态字段 |
| C | A + B | 最大 | 临床可查 + 合规留痕 |

**还有一条语义必须先定**：**「确认结论」是否等同「签发授权」**？
我的理解是**不等同**：确认 = 医生表示"我看过这条结论"；签发 = 对报告正文负法律责任（RSA 签名）。
若两者混同，等于把"看了一眼"和"签字负责"变成一个动作 —— 这在 NMPA 体系下是危险的。
**但这是临床流程决策，需要你和导师确认，我不替你定。**

**在拍板前的过渡处理（本轮已做）**：`WorkspaceActionBar` 的按钮仍然只 setState（行为未变），
但回读文案已改用真实结论（P0-5）—— 至少医生不会对着错误的分级按确认。
**当前状态：点了仍然不落库，答辩不能说"医生确认有记录"。**

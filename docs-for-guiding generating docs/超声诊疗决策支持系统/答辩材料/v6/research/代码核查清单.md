```python
def _severest_in(text, organ):
    patterns = _GRADING_PATTERNS.get(organ, [])      # 各器官的正则组
    hierarchy = _GRADE_HIERARCHY.get(organ, {})      # 主级序
    best = None
    for pattern in patterns:
        for match in pattern.finditer(text):
            raw = match.group(1)
            if organ == "cardiac":
                grading = (_CN_CARDIAC_TO_GRADING.get(raw)
                           or _EN_CARDIAC_TO_GRADING.get(raw.lower())
                           or _CN_CARDIAC_CLASS_TO_GRADING.get(raw)
                           or _map_lvef_to_grading(raw))
            else:
                grading = raw.lower()
            level = hierarchy.get(grading)
            if level is None: continue
            if best is None or level > best[0]:       # 元组比较：(major, sub) 字典序
                best = (level, grading)
    return best[1] if best else None
```

**⚠️ 两处必须知道的限定**：
1. **`_severest_in` 是"取最严重"，但它是被 `extract_grading_severest` 包起来的** ——
   后者**先切出 `分级:` 段**再取最严，避免"把理由里的范围说明当结论"（docstring :371-390 记录了
   真机教训：模型写 `分级: TR3 … 6 分 → TR4`，全文取最严会给出 TR4，比模型自己写的高一级）。
   → 对外用 `extract_grading_severest`，不要直接用 `_severest_in`。
2. **`liver` 的层级表只到 5**（`"0".."5"` + `"lr-tr"`），**没有 LR-M / LR-TIV**。
   而 `liver.py:37` 的 `LI_RADS_LEVELS` **有 7 个**（含 `LR-M` / `LR-TIV`）。
   → `grade_major_level("liver", "LR-M")` 会返回 **`None`**（`hierarchy.get("lr-m")` 未命中）。
   → 后果：凡是按主级排序/去重的路径（含一致性比对），遇到 LR-M / LR-TIV 会**落到"未知"分支**。
   **这是分级对齐里真实存在的一处不一致**，答辩若被追问"li-rads 之类都对齐了吗"，必须承认这条。

**P4-S3-① 小计：✅ 成立（分级序 + `_severest_in`）；⚠️ 一处 liver 层级缺 LR-M/LR-TIV**

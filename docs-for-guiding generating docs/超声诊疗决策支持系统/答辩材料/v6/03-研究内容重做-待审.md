## 一、先承认：我上一版的研究内容错在哪

我写的是「知识怎么组织 / 检索怎么保相关 / 结论怎么保依据」。

**这三个问题，任何领域的 RAG 都有。** 电商客服 RAG 一样要解决 chunking、一样要解决召回、一样要防乱答。把它们当研究内容，等于说「我要研究怎么做一个 RAG」——这不是研究问题，是工程实现。

更要命的是那句「本研究的贡献在于把成熟方法组合成一条可核查的链路」。**组合不是贡献。** 把 bge-m3 + CRAG + Self-RAG 拼起来，谁都会拼。评委会问：那你的贡献是什么？

## 二、医学 RAG 到底特殊在哪（这是研究内容的来源）

我从代码里挖，加上对领域的判断，找到几条**通用 RAG 里不存在、医学里绕不开**的结构性差异：

### 差异 1：错误代价不对称，但指标是统一口径

通用 RAG 里「答错」就是答错，损失一样。医学里不是：

- 把良性判成恶性 → 过度治疗、穿刺、患者恐慌
- 把恶性判成良性 → 漏诊、延误

这两个方向的代价完全不同。但 RAGAS 的 faithfulness、answer relevancy **是不区分方向的标量**，一个 0.9 的分数背后可能是 9 次良性误判，也可能是 9 次恶性漏诊，指标看不出来。

**项目里的证据**：`app/fusion/protocols.py:44` 有 `RECOMMENDATION_CONFLICT` 冲突类型，`app/fusion/consistency.py:1450` 的 `_is_strong_recommendation_mismatch` 把「活检 vs 随访」定义为强冲突——系统已经在代码里承认了这种不对称，但**评测指标没有对应上**。这是真实存在的空白。

### 差异 2：输出不是文本，是「分级 + 处置」，且分级直接决定临床动作

通用 RAG 输出一段话，用户自己判断。医学里输出的是 TI-RADS / LI-RADS / ASE 分级，**分级直接映射到做不做穿刺、多久随访、转不转诊**。

`app/knowledge/grading_floor.py` 的注释把这件事说得很清楚：

> 「分级直接决定处置建议（FNA / 随访间隔 / 转诊科室）。给它加一个『自动抬级』的副作用，等于让一个**没有临床验证的规则**改医生的结论」

这意味着医学 RAG 的评测**不能只看"答案对不对"，要看"分级对不对 + 处置对不对"**。现有 RAG 评测体系没有这一层。

### 差异 3：知识的层级结构 vs 扁平 chunk

临床指南是「指南 → 章节 → 推荐条目 → 证据等级」的层级，一条推荐意见可能只有一句话，但它的**证据等级**（A/B/C 级推荐）附着在整个章节上。

通用 RAG 的 chunking 按 token 长度切，会把推荐条目和它的证据等级切开。检索到推荐条目时，系统不知道这条推荐是什么级别的证据。

**项目里的证据**：`app/inference/grading_definitions.py` 396 行专门处理 TI-RADS/LI-RADS 的分级解析，包括 `_severest_in`（取最严重分级）、`grade_major_level`（分级序）。这说明分级体系本身就是一套复杂的规则结构，不是文本。

### 差异 4：跨来源性能断崖

医学影像模型在一个数据集上 AUC 0.89，换个来源掉到 0.49。这不是过拟合，是医学影像的**设备、采集协议、人群分布**差异导致的。

**项目里的证据**：本项目实测——公开集 AUC 0.895，换 TN3K 数据源后 AUC 0.4929（n=614），接近随机。这个现象在通用 NLP 里没那么极端。

## 三、提炼成 3 个研究子问题（这次是医学特异的）

| # | 研究子问题 | 为什么通用 RAG 解决不了 | 项目里碰到没有 |
|---|---|---|---|
| **Q1** | **错误代价不对称条件下，检索增强系统该怎么评测？** 现有 faithfulness 是标量，不区分误判方向；医学需要「按风险等级分层」的评测口径 | 通用 RAG 没有"误判方向"概念，指标设计里没有这一维 | 有。系统代码里已区分强冲突（活检 vs 随访），但评测指标没跟上 |
| **Q2** | **结构化分级（TI-RADS/LI-RADS）能否作为检索与生成的对齐目标？** 分级是规则体系不是自由文本，RAG 能否以"分级正确"而非"文本相似"为优化目标 | 通用 RAG 的 loss 和评测都在文本层面，没有结构化标签层 | 有。`grading_definitions.py` 396 行在做分级解析，但没接进 RAG 优化 |
| **Q3** | **跨来源泛化失效时，单源训练的医学模型还有没有使用价值？** 0.89→0.49 的断崖是普遍现象，如何界定"什么条件下可迁移" | 通用领域的 domain shift 没这么剧烈，也没有大规模 benchmark 暴露这个问题 | 有。TN3K 实测 0.4929（n=614） |

**这三个问题都不是"怎么做 RAG"，而是"医学场景下 RAG 的评测与优化目标该怎么定"。**

## 五、P2 拆不拆：我给你算一下

你问「P2 一页塞四个点，你真的确定吗」——**我不确定，我算给你看**。

3 分钟 180 秒，7 页的话平均每页 26 秒。P2 要放四块：

| 内容块 | 最少需要 | 为什么 |
|---|---|---|
| 同类项目现状 | 3~4 行（开源 2 + 商用 2） | 少于此说不清"别人做到哪" |
| 现实问题数据 | 2~3 个数字 + 出处 | 少于此不足以证明问题真实 |
| 国家政策 | 2 条原文 | 少于此说明不了"时机" |
| 研究问题 | 1 行大字 | 必须有 |

四块加起来，**一页 16:9 的画面能放下（信息密度够），但口播 35 秒讲不完**——每块平均不到 9 秒。

**所以真正的矛盾不是"页面放不下"，是"口播讲不完"。**

三种解法：
1. **拆成 2 页**：P2a 背景现状（同类项目 + 问题数据）、P2b 政策 + 研究问题。各 20 秒。**代价：多一页翻页，多 5 秒**
2. **一页但口播只讲两块**：页面写满四块（评委可以自己看），口播只讲「问题有多严重」和「我的研究问题」，同类项目和政策一句话带过。**代价：政策这块的铺垫没了**
3. **砍掉政策**：只留同类项目 + 问题数据 + 研究问题。**代价：失去"为什么是现在"的论证**

**我倾向方案 2。** 因为页面可以密（评委有眼睛），口播必须疏（评委只有耳朵）。政策原文放在页面上够醒目，口播只需要说「政策已经明确 AI 辅助诊断不单独收费，理由是效用难以确定，这就是我要解决的」。

## 一、整体结构判断（先说结论）

**6 段 = 6 页**，这是 3 分钟的合理上限。但按你的要求提高信息密度后，有两页可能装不下：

| 页 | 名称 | 信息密度 | 是否可能拆页 |
|---|---|---|---|
| P1 | 封面 | 低 | 否 |
| P2 | 研究背景与意义 | **高**（同类项目 + 问题数据 + 政策） | 可能会拆成 2 页 |
| P3 | 研究内容与方法 | **高**（领域技术栈 + 研究内容分层） | 可能会拆成 2 页 |
| P4 | 已完成工作与成果 | **极高**（功能清单 + 流程图 + 架构图 + 指标） | **一定要拆成 2 页** |
| P5 | 存在问题与后续计划 | 中（阻塞点 + 计划 + 实践落地） | 否 |
| P6 | 总结与展望 | 低 | 否 |

**我的建议：7 页**。P4 拆成「P4a 业务流程图 + 系统架构图」和「P4b 核心功能交付情况 + 效果指标」——因为这一页要装的两类内容性质完全不同（一张是图，一张是数据），硬塞一页会两边都讲不清。

### P2 · 研究背景与意义（35 秒）🔍

**这一页要回答**：这个领域现在是什么状况？为什么这个问题值得研究？

**放什么（四块，按"从大到小"漏斗排列）**

**① 同类项目现状**（国内外开源 / 闭源都在做什么）
> 🔍 调研中，回填以下结构：
> - 开源阵营：____（项目名 + 能力 + 是否含超声 + 是否含 RAG）
> - 商用阵营：____（产品 + 器官 + 认证情况）
> - **共同缺口**：多数做"图像分类"或"通用医疗问答"，**面向基层、结论带可核查依据的超声辅助诊断**这个交叉点基本空着

**② 现实问题的数据佐证**（证明不是臆造）
> 🔍 调研中，回填 2~3 个权威数字：
> - 基层超声医生配置/缺口（必须有权威出处）
> - 医生间诊断一致性（kappa 值类研究）
> - 基层 vs 三甲 准确率差距

**③ 国家政策**（说明时机）
> 已知可引用（需复核原文）：
> - 卫健委《卫生健康行业人工智能应用场景参考指引》2024-11，84 个场景，明确列出超声
> - 医保局《放射检查类医疗服务价格项目立项指南》2024-11-20：AI 辅助诊断不单独收费，理由原文「辅助诊断质量效用难以确定」

**④ 研究问题**（本页落点，一行大字）
> **怎么让 AI 给出的超声辅助结论，基层医生敢参考、能核对、说得清依据？**

**逻辑串法（这是本页的骨架）**
```
同类项目都在做 → 但都缺失"可核查依据 + 面向基层"
        ↓
现实数据证明问题真实存在（不是我想当然）
        ↓
国家政策已经铺路（时机到了）
        ↓
但政策同时指出门槛："效用难以确定"
        ↓
所以我的研究问题 = 解决"可核查"这件事
```
**关键**：四块不是并列，是**层层收窄**。从"别人做到哪"收到"现实多严重"，再收到"政策怎么说"，最后收到"所以我要解决什么"。这样落点才立得住。

**口播（约 155 字 / 34 秒）**——待素材回填后重写。

### P3 · 研究内容与方法（50 秒）🔍

**这一页要回答**：我要研究的问题拆成哪几个子问题？解决它们要借助哪些成熟方法？

**⚠️ 这一页最容易写错的地方**（你纠正过我）：**研究内容 ≠ 我具体做了什么**。
- 研究内容 = 把"让结论可核查"这个总问题，**拆成几个可研究的子问题**
- 研究方法 = 解决每个子问题**要借助哪些成熟技术**，以及为什么选它

**放什么（左右分栏）**

**左栏：研究内容（拆成 3 个子问题）**
| 子问题 | 要解决什么 |
|---|---|
| ① 知识怎么组织，才能被检索到？ | 超声指南/共识是长文档、术语多，要变成可检索的结构化知识 |
| ② 检索到的依据，怎么保证真的相关？ | 单一路径检索会漏，要解决召回与相关性的平衡 |
| ③ 给出的结论，怎么保证有依据、不出格？ | 要能追溯到原文，且高风险内容能被拦住 |

**右栏：研究方法（对应每个子问题，借用领域成熟技术）**
> 🔍 调研中，回填技术栈。预期结构：
>
> | 子问题 | 借用方法 | 代表工作 |
> |---|---|---|
> | ① | 医学文本嵌入 + 知识图谱 | bge-m3 / 医学知识图谱 |
> | ② | 混合检索 + 检索增强的纠错机制 | BM25+向量混合 / CRAG |
> | ③ | 生成约束 + 独立安全校验 | Self-RAG / 结构化输出约束 / 独立安全网关 |

**底部一行**：明确写「**上述方法均为领域已有工作，本研究的贡献在于把它们组合成一条面向超声、可核查的完整链路**」——这句话直接回应"站在前人肩膀上"。

**逻辑串法**
```
总问题：让结论可核查
   ↓ 拆
三个子问题（知识组织 / 检索质量 / 结论约束）
   ↓ 每个子问题
借用领域已有的成熟方法（点名 + 代表工作）
   ↓ 合起来
形成一条完整技术路线（不是堆砌，是各有其位）
```

**口播（约 225 字 / 50 秒）**——待素材回填后重写。

### P4a · 已完成工作（一）：业务流程 + 系统架构（30 秒）🔍

**这一页要回答**：这套系统医生怎么用？它是怎么造出来的？

**放什么（上下两块）**

**① 业务流程图（医生视角，横向 5 步）**
> 🔍 从 `frontend/src/pages/` 和 `app/api/` 还原真实流程，回填：
```
登录 → 选择检查/上传影像 → 系统给出结论与分级
   → 查看依据（引用的指南原文） → 医生确认/修改 → 生成报告
```
每一步标注：**医生在这里做什么决定**

**② 系统架构图（与上面流程对应）**
> 🔍 从代码还原真实架构，回填分层：
```
前端（React + TS）
    ↓
后端 API（FastAPI，91 个接口）
    ↓
业务层（检索 → 专科判读 → 融合校验 → 安全网关）
    ↓
数据层（PostgreSQL / Redis / Qdrant 向量库）
    ↓
模型层（vLLM 推理 / 嵌入服务 / 判官）
```

**逻辑串法（本页核心）**
```
上半：医生看到的是什么（业务视角，一条动线）
   ↕ 严格对应
下半：背后支撑它的是什么（技术视角，一套分层）
```
**关键**：两张图**必须上下对齐**——流程图的每一步，架构图上都要能找到对应的模块。这样评委才能建立"看到的功能 ↔ 背后的实现"的映射。

### P5 · 存在问题与后续计划（25 秒）🔍

**这一页要回答**：哪些核心功能没打通？卡在哪？接下来怎么打？在哪落地？

**放什么（三块，纵向）**

**① 没交付的核心功能 + 阻塞点**（要说清"卡在哪"，不能只说"还没做"）
> 🔍 已知的阻塞（从 feature_list.json 的 blocked 项）：
> - **RAG 核心指标未达标**：faithfulness 实测 0.0906，门槛 0.95。阻塞原因不是模型能力，而是**评测数据本身失效**——620 条历史判读里 608 条是照抄提示词示例，真引用率为 0。指标要重算，前提是先有干净数据。
> - **评测集规模不足**：现有 169 条，其中 152 条来自同一演练患者，独立病例仅 12 个。这个量算出来的任何指标统计上都站不住。
> - **甲状腺注册数据方案未定**：卡在真实病例来源与伦理批件。
> - **语音医疗术语未验证**：语音链路的医学术语识别准确率还没实测。

**② 下一步计划**（对应上面的阻塞，逐条给动作）
> - 评测集从 169 扩到 700，补足独立病例
> - 重建干净评测数据，重算 RAG 指标
> - 补齐定量测量功能

**③ 实践交付与实地验证计划**（你特别强调的，必须有）
> 🔍 待你提供：打算在哪个医院/科室落地？有没有对接人？预计什么时间？
> 这一条我编不出来，需要你告诉我实际情况。

**逻辑串法**
```
没交付什么（功能层）
   ↓ 为什么
卡在哪（技术层 / 数据层，要具体到"是哪一环断了"）
   ↓ 所以
下一步怎么办（对应动作）
   ↓ 在哪验证
落地场景 + 时间（不能停在"继续优化"）
```
**关键**：三块是**因果链**，不是三个清单。评委顺着"没交付 → 卡在哪 → 怎么解 → 去哪验"读下来，才会觉得这个学生想清楚了。

**口播（约 115 字 / 26 秒）**——待落地信息回填后重写。

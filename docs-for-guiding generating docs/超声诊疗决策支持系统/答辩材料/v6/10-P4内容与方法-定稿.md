## 二、左栏：研究内容（四项"设计"）

| 编号 | 研究内容 | 针对哪个成因 | 为什么这是研究内容而非工程任务 |
|---|---|---|---|
| **D1** | **设计一套临床效用的衡量标准** | 没法量 | 学界现有 RAG 指标是无方向标量；`asymmetric cost misdiagnosis` 全库 0 条 → 这是要**新建一套标准**，不是套用现成的 |
| **D2** | **设计一套从结论回溯到证据原文的链** | 依据不可核查 | `hierarchical chunking clinical guidelines` 全库 0 条；最接近的 Q(t) 用 EvidScore 而非 GRADE → 要**新建一套可追溯的链** |
| **D3** | **设计一套让结构化输出可重复的约束机制** | 关键判断不稳定 | 现有约束解码在高风险档 40.88%；ProbeGuard 证明一致性是错误代理 → 要**设计新的约束机制**并给出稳定性判据 |
| **D4** | **设计一套数据可信度的审计与溯源规范** | 底层数据不可信 | 620 条里 608 条照抄示例；deceptive grounding 证明 faithfulness 满分也可能错 87% → 要**建立数据可信度的判定规范** |

**页面呈现的关键**：每一项都写「设计一套……」，动词是**设计**，不是「分析/评测/优化」。这是研究内容与工程任务的分界线。

## 三、右栏：研究方法（五项科研方法）

**注意**：这里必须写**科研方法论意义上的方法**，不是技术栈。

| 方法 | 具体怎么做 | 回答哪个研究问题 | 产出什么证据 |
|---|---|---|---|
| **定量评估** | 同一批数据跑多种指标口径，做对照，看差异来源 | D1：现有口径差多少、差在哪 | 多口径对比表（同一批 n=157） |
| **代价敏感分析** | 借 DCA / net benefit（Vickers 2006）框架，改造为分方向的 RAG 评测 | D1：误判方向该怎么计权 | net benefit 曲线 / 决策阈值表 |
| **结构审计** | 对知识库做结构体检（文档粒度、块粒度、字段完备性），而非只看检索结果 | D2：结构缺什么 | 结构体检报告（现状 88.5% 单块 / 中位 146 token） |
| **消融实验** | 逐因子消融：改一个变量（层级切分 / 约束解码策略 / 重试次数），看指标变化 | D2/D3：哪个因子影响最大 | 单因子变化曲线 |
| **数据审计** | 建立三元口径标注（样本量 / 划分来源 / 脚本路径），对历史数据做可信度判定 | D4：哪些数据能用 | 口径标注规范 + 审计结论 |
| **案例研究** | 在复旦合作医院做回顾性验证，看真实病例下的表现 | 全部：真实场景能不能用 | 落地验证结果 |

## 五、为什么这个写法是对的

### 反例（我之前的写法，错的）
> "全量复现评测 / 外部验证集 / 口径三元标注"

问题：
- 「全量复现评测」是**技术动作**，不是研究方法
- 「外部验证集」是**数据划分方式**，不是方法
- 「口径三元标注」是**规范**，勉强算方法但没说清回答什么问题

### 正例（现在的写法）
> "定量评估 / 代价敏感分析 / 结构审计 / 消融实验 / 数据审计 / 案例研究"

每一项都是**科研方法论**里的标准方法，各自回答不同的研究问题，产出不同类型证据。评委会看到的是"这个学生知道怎么用研究方法回答研究问题"，而不是"这个学生会调库"。

### 关键区别
| | 技术动作 | 科研方法 |
|---|---|---|
| 例子 | 跑一遍评测脚本 | 定量评估（设计对照组、控制变量、分析差异来源） |
| 回答 | "结果是多少" | "为什么是这个结果、可信吗" |
| 产出 | 一个数字 | 一套有论证的证据 |

## 0. 脊柱：一条能串起四问的线

四个根命题如果各讲各的，就是四段互不相干的介绍。**它们必须回答同一个问题。**

我用的是这条：

> **政策已经把 AI 辅助诊断放进价格体系，却明确"暂不单独付费"，理由原话是"辅助诊断质量效用难以确定"。
> 所以这个领域真正的门槛不是"做得更准"，而是"**让效用可被确定**"。
> 我做的是后者：一套**可被验证**的辅助诊断系统。**

四个根命题由此各就各位，不再是并列的四个介绍：

| 根命题 | 在脊柱上的位置 | 一句话答案 |
|---|---|---|
| ① 是什么 | **产品定义**：既然门槛是"可被验证"，产品就不能只是"给结论" | 一款在诊室内工作、只给一个决策、每句结论都带出处的辅助系统 |
| ② 意义 | **为什么现在做**：政策开了入口，把定价权留给效用证明 | 政策的空白处，正是研究该站的位置 |
| ③ 怎么完成 | **怎么把"可验证"做进产品**：每个减法都有工程装置兜底 | 产品决策与技术约束是同一件事 |
| ④ 进展 | **验证到了第几层**：能证明的给数，不能证明的说清缺什么 | 四层可验证 / 一层必须等数据 |

**这条线的好处**：四个答案互为因果，删掉任何一个，其余三个都会显得没根据。

## 1. ① 我做的是什么（产品经理视角）

### 1.1 产品定义卡（P2 的全部内容）

| 维度 | 答案 |
|---|---|
| **品类** | 诊室内**决策支持**系统（in-workflow decision support），不是 AI 阅片平台，不是独立 App，不是报告代写工具 |
| **主用户** | 基层 / 急诊超声医生：**单人单机、多数无审核岗、边扫边定**（依据：`14 号 §2.2` 第 3 条——基层多为 1–3 人、多数无审核岗） |
| **次用户** | 三甲复核医师、质控人员（不同工作面，不受本产品契约约束） |
| **使用场景** | **一次检查内部是循环**：扫查 ⇄ 冻结判读，一例重复十几次；报告与签发是收尾（`14 号 §2.1`） |
| **价值主张** | 把"AI 给一个结论"变成"**结论带出处、带边界、带签字责任**" |
| **形态约束** | 单工作区、不跳页、影像恒定占主（超声基本单屏，扫查时目不转睛盯影像，`14 号 §2.2` 第 8 条） |
| **不是什么** | 不替代医生 · 不出最终诊断 · 不是医疗器械（科研验证阶段，`00 号 §3` NMPA 申报"待启动"） |

> **为什么"是什么"要这么答**：如果一开口讲"六步流程"，评委会把它归类成"一个功能很多的软件"。讲品类、用户、形态约束，才会被归类成"一个**有产品判断**的系统"。

### 1.2 三条产品准绳（P3）

这三条是自定的，不是抄的，而且每条都能在文档里找到裁决记录（`17 号 §0`、`14 号 §0.1`）：

| 准绳 | 判定标准（可观测） | 它否掉了什么 |
|---|---|---|
| **P1 默认沉默** | 元素只在"缺了它医生会做错"时才默认可见；其余**不渲染**（不是折叠、不是灰掉） | 否掉常驻的同意状态、连接状态、TTL 倒计时、六阶段耗时、路由档位、模型版本 |
| **P2 一次决策** | 任何时刻医生**只需做一个决定**；出现两个并列待选动作即判定设计失败 | 否掉三区并置常驻、否掉"语音回读+确认词+脚踏"三重机制 |
| **P3 按打扰总量记账** | "操作少" = 被打断次数 × 解除成本，**不是元素个数** | 允许"元素变多但打扰变少"（冻结/存图拆分、禁忌强制勾选） |

> **P3 是这三条里最值钱的**，因为它防住了"简化"最容易走歪的方向：把简化理解成"少放东西"。判定标准只有一句——**这个改动是让医生少做判断，还是只是少看见东西？**

### 1.3 与替代方案的差别（P3 下半页）

| 替代方案 | 它解决什么 | 它不解决什么 |
|---|---|---|
| PACS 自带 CAD 标注 | 标出病灶框 | 不给依据、不给边界、不参与责任链 |
| 通用大模型（直接问） | 能写一段像样的话 | 无法追溯、不可复现、不进医院系统 |
| 双人双签复核 | 提高准确率 | 成本翻倍，基层根本没有第二个人 |

→ **本产品的差异位**：不是"更准"，是"**把可追溯与责任链做进流程**"。这一句话要和 §0 的脊柱对齐。

## 2. ② 意义（三层，每层都有出处）

### 2.1 政策层：入口已开，但定价权留给了"效用证明"（P4）

三条官方事实，按"从远到近"排：

| # | 文件（`A`） | 与本项目的关系 |
|---|---|---|
| 1 | **2024-11**，国家卫健委、国家中医药局、国家疾控局《卫生健康行业人工智能应用场景参考指引》：4 大类 13 小类共 **84 个场景**，其中"医学影像智能辅助诊断"明确列举 **X 射线、CT、MRI、PET-CT、超声**、病理切片… | 方向在国家点名清单里，**超声被单独列出** |
| 2 | **2023-02**，中办、国办《关于进一步深化改革促进乡村医疗卫生体系健康发展的意见》：要求"**加快推动人工智能辅助诊断在乡村医疗卫生机构的配置应用**" | 需求侧是政策要求，不是我的猜测 |
| 3 | **2024-11-20**，国家医保局《放射检查类医疗服务价格项目立项指南（试行）》：在主项目下统一安排"人工智能辅助诊断"**扩展项**，执行与主项目相同价格、**不与主项目重复收费** | 见下方原文 |

医保局给出的理由，原文（`A`，nhsa.gov.cn）：

> "目前，人工智能技术在临床实践中一定程度上起到辅助诊断或提高效率的作用，但**还无法替代医师诊断**，在尚无独立的医疗服务产出、**辅助诊断质量效用难以确定**的情况下，在已收取诊断相应项目检查费用后，不宜单就人工智能辅助诊断再向患者额外收费。"

**这一句就是全场的支点**：
- 它证明"辅助、不可替代"是政策定的位，不是我们谦虚；
- 它把"不能单独收费"的原因归到"**质量效用难以确定**"——也就是说，**谁能把效用确定下来，谁才真正进得了临床**；
- 而"确定效用"正是本项目在做的事（口径、分母、可复跑、拒收脏数据）。

> 3 分钟里这一页只念一句：**"医保局说 AI 辅助诊断暂时不能单独收费，原因是'质量效用难以确定'。我做的事，就是把这句话里的六个字变成可以量出来的东西。"**

### 2.2 立项层：当初承诺了什么（P5 上半）

`00 号 §1` 与 `06 号 §6.2` 写的是量化目标（`C` 立项规划值，非实测）：

| 立项时的目标 | 值 | 中期状态 |
|---|---|---|
| 诊断准确率 | ≥89%（基层）/ ≥92%（三甲） | **给不出**——需患者级金标准（见 §4.3） |
| 漏诊率 | 15% → 5%（人机协同） | 给不出——需回顾性病例审计 |
| AI 纯处理时间（单器官） | ≤100s | 可给（时延已测） |
| 完整诊断延迟 | P99 < 5s | 可给 |
| 幻觉率 | 严重 ≤0.5% / 整体 ≤5% | 部分可给（需专家盲评样本） |
| 灰度发布数据 | 每器官 ≥667 例（验证集 ≥100） | **未达**——卡在合作医院 |

> **这一页的作用**：**主动把"给不出的数"摆出来**。评委最反感的是"避而不谈"；一旦你自己先说"89% 我给不出，因为需要金标准"，后面所有数字的可信度都会上调。

### 2.3 设计层：承诺被翻译成了界面裁决（P5 下半）

意义不能停在"有用"。它必须落到"因此界面长什么样"。`17 号` 把 30 个元素逐条裁决成三档（常显 / 条件 / 不显），并锁定**三条不可削减的边界**：

> 禁忌命中的强制勾选 · 签发前的依赖度核验 · 诊室可见性默认遮蔽

这三条的共同点：**每一条都增加了一次操作**，但换来"其他所有提示都可以被信任"（`17 号 §0` P3 的原文逻辑）。

## 3. ③ 我怎么完成（先产品，后技术）

> v4 的错误是把流程条放在第二页。流程是"怎么用"，属于这一问，不属于"是什么"。本问的展开顺序：**信息架构 → 约束设计 → 技术支撑**，三层逐级下沉。

### 3.1 信息架构（P6）

| 决策 | 内容 | 依据 |
|---|---|---|
| 一级导航只有 **2 项** | 工作列表 / 设置 | `14 号 §2.3` |
| 检查内部是**循环**不是阶段 | 扫查 ⇄ 冻结判读（十几次）→ 报告 → 签发 | `14 号 §2.1`（v3 修正：把"阶段"重定义为视图状态） |
| 报告是**侧面板**，不是目的地 | 报告是检查的收尾动作 | `14 号 §2.2` 第 2 条 |
| **审核不设固定入口** | 基层 1–3 人、多数无审核岗；降为工作列表筛选，审核工作台**显式声明范围外** | `14 号 §2.2` 第 3 条 |
| 建会话**不要求事先声明部位** | 超声是边扫边定；事前声明是 CT/MRI 思维 | `14 号 §2.2` 第 1 条 |

> 这一页有一个隐藏加分项：**"审核工作台本轮不交付"是主动声明的范围外**，而不是用"降为筛选"掩盖缺失。评委问"审核怎么办"时，这个答案比"我们做了"更可信。

### 3.2 约束设计：30 个元素逐条裁决（P7）

`17 号` 的契约把 30 个元素分三档，这里只讲最反直觉的四条（都是"该没有就没有"）：

| 元素 | 默认态 | 为什么 |
|---|---|---|
| 同意状态 | **条件**（仅非 granted 出现） | 正常时缺了不会做错 → 常显就是噪音 |
| 连接状态 | **条件**（仅异常出现） | 同上 |
| 六阶段耗时 / 路由档位 / 模型版本 | **不显** | 医生不想要，归审计 |
| 进度表达 | **只有两个词**（分析中 / 已完成） | 5–6 个内部阶段名对医生无意义 |
| 严重幻觉 | 条件，**但当前后端恒 `None`** | 已在文档标注"不可用"，不假装有 |

**两条必须一起讲的边界**（因为它们都"增加操作"）：
- 禁忌命中 → **唯一打断式**提示，挡签发；
- 签发前依赖度核验 → 多一次确认。

> 台词：**"这三处我故意让医生多做一次动作。因为只有它们值得打断，其他所有提示才敢保持沉默。"**

### 3.3 技术支撑：每个减法背后都有一个装置（P8）

这是"产品决策与技术决策是同一件事"的证据页：

| 产品决策 | 对应工程装置 | 证据 |
|---|---|---|
| 默认沉默（不渲染） | 条件渲染真的不进 DOM（不是 `display:none`） | `17 号 §1` + 前端代码 |
| 一次决策 | 融合层只输出一个建议动作；7 种复核原因翻译成一句中文 | `17 号 §1`；`14 号 §5.3` |
| 结论要带出处 | 证据编号 `[1]..[n]` + 回表取原文 | `specialist/base.py:776-790` |
| 不许瞎编 | 生成侧示例脱敏 → 解析前回显拒收 → 采集端过滤 → 输出守卫 | `output_guard.py` + A.70 |
| 不许跨病人 | 影像归属校验（跨会话 400）+ 影像向量检索强制 session | A.78/A.79 |
| 多智能体要能互检 | **真 N 并行**（甲状腺/肝脏/心脏三路汇入融合层） | 本轮改造（`A` 架构变更） |
| 三个器官不是套壳 | 三套分级 / 三套置信度公式 / 三套冲突裁决 | `specialist/{thyroid,liver,cardiac}.py` |

> 这一页是"怎么完成"的落点：**先有产品判断，再有工程装置，不是反过来。** 顺序反了就会做出"功能很多但医生不用"的系统。

### 4.3 能证明到第几层（P9）

这是"进展"最诚实也最有说服力的报法——**按可验证层级报，不按功能数报**：

| 层级 | 能证明什么 | 数 | 需不需要临床金标准 |
|---|---|---|---|
| 检索 | 能不能找到对的依据 | hit@10 0.9853（dense 同构，134/136） | 否 |
| 时延 | 能不能进诊室节奏 | P50 1.34s（**真 N 后重测**）/ validate P99 884.6ms | 否 |
| 流程 | 医生能不能走完 | 9 步 + 2 反证腿，11/11 | 否 |
| 病灶 | 边界找得准不准 | DSC 0.7961（公开集 614 张，256 输入） | 公开集即可 |
| **疗效** | **准确率 89%、漏诊率 5%** | **给不出** | **是（患者级金标准）** |

> 收口台词：**"前四层我能给数，第五层给不出——它需要患者级金标准，而我没有。所以我不报这个数，我报的是它还缺什么。"**

### 4.4 三次证伪（P10，研究性角度）

| 层面 | 原以为 | 实测 | 改了什么 |
|---|---|---|---|
| 模型（外部效度） | 公开集 AUC 0.895 可用 | 换来源（TN3K, n=614）**0.4929** | 公开集分数不作临床证据 |
| 数据（指标效度） | 输出差 = 模型能力不足 | **608/620 条照抄示例（98.1%）**；忠实度三口径只差 0.03 | 三道防线 + 指标降级 |
| 系统（架构效度） | 多智能体并行 → 融合能互检 | 融合要 ≥2 份结论，单路时恒空 | **改为真 N 并行** |

> 三条正好覆盖"模型 / 数据 / 系统"，**这是曦源中期最该展示的东西**——因为曦源的中期要求是"完成综述 + 有一定研究结果"（见 §8 第 4 条），研究结果不等于功能数量。

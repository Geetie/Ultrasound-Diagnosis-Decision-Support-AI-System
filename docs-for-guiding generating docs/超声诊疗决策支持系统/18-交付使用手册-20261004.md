## 一、医生的日常使用（三步）

### 步骤 0：访问入口（每天第一件事）

主服务**只监听服务器本机回环地址**（`127.0.0.1:18000`），这是安全硬规则——临床 API
与真实患者检查链路**不允许暴露在校园网**。因此从办公电脑访问必须走一条 SSH 隧道：

```
# 在你自己的电脑上执行一次，然后把窗口留着
ssh -N -L 8000:127.0.0.1:18000 student03@10.20.28.21
```

然后浏览器打开：

```
http://127.0.0.1:8000/ui/
```

| 现象 | 含义 | 处理 |
|---|---|---|
| 页面正常 | 隧道通 | 正常使用 |
| 打不开 / `ERR_CONNECTION_REFUSED` | 隧道断了 | 重新执行上面那条命令 |
| 一直转圈 | 隧道通但后端慢或挂 | 找管理员，先看 `/api/v1/health` |

> 隧道只是"把你本机的 8000 端口接到服务器的 18000"。不装任何客户端、不开放端口、
> 断开后本机不留痕迹。**不要**把 `10.20.28.21:18000` 填进任何浏览器或工具——
> 那样连不上（这是设计如此，不是故障）。

### 步骤 1：登录

在 `/ui/` 登录页用分配的个人账号密码登录。账号由管理员发放，**不要共用账号**
（审计日志按人记录，共用账号会让追溯失效）。

- 连续输错会触发限流：同一账号 5 次/分钟、同一 IP 30 次/分钟。这是暴力破解防护，
  等一分钟再试即可，不要反复重试。
- 登录态由 refresh token 维持。**同一账号在多个浏览器标签页同时刷新会互相踢下线**
  （检测到 token 重放即撤销整个会话族，这是防窃取的设计取舍，见第七节限制 ⑦）。

> **当前版本状态（2026-10-05 下午更新）**：登录、9 条页面路由、知情同意签署、工作列表、
> 报告草稿、**影像装载入口**、**工作区导航出口**均已实测可用（A.28 真机走查 20/20 PASS，
> 含真传一个 DICOM 后自动进入「分析中」）。若你看到登录页白屏或登录后跳出一串 JSON，
> 说明拿到的是 2026-10-05 之前的旧构建，请找管理员按 `start_main.sh` + 门禁流程重新部署。

### 步骤 2：检查 → 诊断 → 报告

1. **从工作列表进入检查**：在 `/ui/worklist` 点「继续」（进行中的检查）或
   「查看」（今日待处理），系统会带着这次检查的编号回到工作区 `/ui/`。
   也可以用顶栏「新建会话」先建一次检查，再从列表点进去。

2. **装载影像**：在下方结论区点「选择 DICOM 影像」，挑一个 `.dcm` / `.dicom` 文件。
   **装载完成后系统自动发起判读，不需要再点任何按钮。**
   - 装载后结论区显示「分析中」，影像区显示你刚选的那份片子；
   - **若提示缺少必需标签 / 模态不是 US / 文件超过 500MB**，那是后端按规范拒绝，
     界面会原样显示原因—— 这类文件本就不能进系统，请换合规文件，**不会**伪造结果；
   - 进度只出现「分析中」与「已完成」两个词，看不到百分比属正常。

3. **查看结论**：结论区给出「一句话结论 + 恶性风险 + 建议动作」，可展开依据 / 鉴别诊断。
   甲状腺会额外输出**结节轮廓与面积**。
   若结论区出现红色停档条，说明安全网关要求转人工诊断，按提示完全依赖人工判断即可，
   写报告与签发不受影响。

4. **书写与签名归档**：报告分节呈现，含证据来源（可溯源到知识库条目）、一致性与
   安全网关结论。医生确认后签名，报告锁定；此后任何改动会被签名校验拦下并留痕。

5. **下一个病人**：签发后点「下一个病人」回到工作列表。顶栏右侧三个入口
   （工作列表 / 新建会话 / 设置）在任何页面都能随时切换。

> 分割旁路与属性提示的开关由**管理员**在启动时设定（`start_main.sh`），医生侧无感知。
> 关闭时报告里会写明「该能力未启用」及原因，**不会伪造空白结果**。

> **影像显示（2026-10-06 起）**：影像区显示的是与判读**同源**的服务端字节
> （已做 PHI 剥离）。回到工作区或刷新页面后，系统会按检查会话自动恢复最近一份
> 影像，不再需要重选文件。

## 二、管理员运维

### 2.1 服务拓扑（全部只绑 127.0.0.1，无一例外）

| 端口 | 组件 | 作用 | 备注 |
|---|---|---|---|
| 18000 | 主服务（FastAPI/uvicorn） | 全部业务 API + 临床前端 `/ui` | 唯一对外入口，只走隧道 |
| 9001 | SafetyGateway（独立进程） | 输出安全网关，对抗提示注入/越权 | 停掉则诊断**拒绝输出**，这是设计 |
| 8002 | vLLM + Qwen2.5-7B-Instruct | 主生成引擎 | `--gpu-memory-utilization 0.46` |
| 8003 | 嵌入服务（BiomedCLIP 等） | 图像/文本嵌入、良恶性分类、属性提示 | 报告属性提示的来源 |
| 8006 | 判官（llama.cpp + Qwen3-8B GGUF） | 忠实度/幻觉评测，**离线用** | 与 8002 **必须串行**启动 |
| 16379 | Redis（容器 `uai-redis`） | 令牌、限流、DLQ、检索缓存 | **不是** 6379 |
| 15432 | Postgres（容器 `uai-postgres`） | 业务库，已迁移到 `0017` | |
| 30100 | Langfuse v3 | 可观测 | |
| 9090 | metrics | Prometheus 抓取 | 默认绑回环，需跨机抓才显式设 `OBS_METRICS_HOST` |

> **共享服务器铁律**：`6379` 上的 `redis-server` 是**别人的**，本项目一律用容器
> `uai-redis`（16379）。曾因未加载 `.env` 误连 6379，本项目脚本必须显式加载环境文件。

### 2.2 一键动作（都用这个，别手写命令）

| 目的 | 命令 |
|---|---|
| 启动/重启主服务（**唯一权威入口**） | `bash ~/uai/src/scripts/start_main.sh` |
| 只探活不重启 | `bash ~/uai/src/scripts/start_main.sh --no-restart` |
| 重启 + 跑交付门禁 | `bash ~/uai/src/scripts/deploy_restart_and_gate.sh` |
| 交付验收门禁（23 项） | `bash ~/uai/src/scripts/deploy_acceptance_gate.sh` |
| 全量恢复 GPU 服务（**严格串行**） | `bash ~/uai/src/scripts/restore_all_gpu_services.sh` |
| 端到端演练 | `bash ~/uai/src/scripts/deploy_drill_e2e.sh` |
| 清理 `/tmp` 探针 | `bash ~/uai/src/scripts/clean_tmp_probes.sh` |
| 从本机同步代码到服务器 | `bash ~/uai/src/scripts/sync_from_tar.sh`（先 `git archive` 再传） |

**为什么必须有唯一入口**：2026-10-05 实测发现主服务绑在 `0.0.0.0:18000`（对校园网裸奔）。
根因不是有人写错，而是当时**没有权威启动入口**——仓库里一个脚本写 `--host 127.0.0.1`，
另有 7 个 `deploy_*.sh` 写死 `0.0.0.0`，谁最后跑谁说了算，改绑必然漂回。
`start_main.sh` 把"裸机 = 回环"固化为唯一默认，并由测试 `tests/unit/config/test_api_host_binding.py`
双向锁定（裸机必须回环 / 容器内必须 `0.0.0.0`，否则容器端口映射不通）。

### 2.3 启动顺序与两个不能省的检查

```bash
bash ~/uai/src/scripts/restore_all_gpu_services.sh   # 8002 与 8006 串行，勿并发
bash ~/uai/src/scripts/start_main.sh                 # 内含绑定合规 + 假活校验
bash ~/uai/src/scripts/deploy_acceptance_gate.sh     # 期望 PASS=23 FAIL=0
```

`start_main.sh` 启动后会自动打印并校验三件事，任何一项不过就 `exit 1`：

1. `api-ready` —— 健康探测通过；
2. `绑定合规（loopback）` —— 监听地址必须是 `127.0.0.1:*`，否则判 FATAL；
3. `age=…s (本次脚本已跑 …s)` —— 进程确实是本次拉起的。**探活 200 可能是旧进程假活**，
   所以要比对进程已运行秒数与脚本自身运行时长。

### 2.4 部署与回滚

```bash
# 部署（本机）
git push origin main
git archive --format=tar HEAD -o uai.tar
scp uai.tar student03@10.20.28.21:/tmp/u.tar
ssh student03@10.20.28.21 "cd ~/uai/src && tar xf /tmp/u.tar && rm -f /tmp/u.tar"
ssh student03@10.20.28.21 "bash ~/uai/src/scripts/deploy_restart_and_gate.sh"

# 回滚：把上面的 tar 换成上一个 commit 的 archive，然后重跑同一套重启 + 门禁
git archive --format=tar <上一个commit> -o uai_rollback.tar
# 之后同上
```

回滚判据同样以门禁为准：**PASS=23 FAIL=0 才算回滚成功**，不要只看服务起没起。
数据库迁移回滚需单独处理（`alembic downgrade`），本项目迁移到 `0017` 为止。

### 2.5 部署窗口内的两个必守约束

1. **8002（主生成）与 8006（判官）必须串行启动**。两者都做显存/CPU 探测，并发启动会互踩
   memory probe，出现"服务假活但推理失败"。
2. **分割旁路与属性提示的开关必须在重启主服务前 export**。这两个开关是**进程启动时读取**的
   （`NODULE_CONTOUR_IN_PIPELINE_ENABLED` / `ATTRIBUTE_HINTS_ENABLED`），事后改环境变量无效，
   必须重启才生效——`start_main.sh` 已把它们默认设为 `1`。

## 四、排障速查

| 症状 | 先查 | 常见原因与处理 |
|---|---|---|
| 浏览器打不开 `/ui/` | 本机 `curl http://127.0.0.1:8000/api/v1/health` | 返回 000 → 隧道断，重连；返回 200 → 浏览器缓存/代理问题 |
| 页面白屏但接口通 | 浏览器 F12 Console | `/ui/assets/*` 404 → 静态产物未部署，重建前端（见钉子 ④） |
| 登录 429 | 等 60 秒 | 限流生效：账号 5 次/分、IP 30 次/分。**别反复重试** |
| 登录 500 且日志报 SoftHSM 过期 | `~/uai/logs/api.log` | `soft_hsm_enabled_at.txt` 被提交进仓库、`git archive` 把**已过期**时间戳带回去。删除该文件并重新初始化（脚本 `server_fix_soft_hsm.sh`） |
| 诊断一直 `processing` | `~/uai/logs/api.log` + DB 会话 | DB 会话跨 LLM 调用会被 `idle_in_transaction_session_timeout` 掐断。已治理，若复现请记录 request_id |
| 报告结论为空 | 报告 JSON 的 `error` 字段 | 历史上出现过结论抽取异常被吞。**必须抽查结论非空**，不要只看 `completed` 数 |
| 分割段缺失/写着未启用 | 启动环境变量 | `NODULE_CONTOUR_IN_PIPELINE_ENABLED` 是启动时读取，需 `export` 后重启主服务 |
| 属性提示 400/E4005 | 输入语言 | 英文文本塔只吃英文；中文是**预期拒绝**，不是故障 |
| 门禁 FAIL≠0 | 逐项看 `[FAIL]` 行 | 不要跳过门禁继续交付 |

## 五、关键钉子（踩过的坑，别重复踩）

1. **服务只绑 127.0.0.1**。改绑前先确认容器例外：`Dockerfile.dev` 必须 `0.0.0.0`，
   否则 `ports: 8000:8000` 映射不通。用 `start_main.sh`，别手写 `--host`。
2. **6379 的 Redis 是别人的**。本项目只用 `uai-redis`（16379）；脚本必须加载 `~/uai/.env`，
   否则会静默连到 6379（本项目已实测踩到：`Error 111 connecting to localhost:6379`）。
3. **8002 与 8006 串行启动**。并发会互踩 memory probe。
4. **前端产物需带 base 重建**：产物挂 `/ui`，`mount("/ui")` 会在注册顺序上吃掉全部
   `/ui/*`，导致 SPA 刷新 404；正确做法是只挂 `/ui/assets` + 回落路由。
   重建命令：`cd frontend && VITE_BASE=/ui/ npm run build`，产物复制到 `app/static/ui/`。
5. **仓库用 LF**。`.gitattributes` 已强制；上传到服务器的 `.sh` 若被改成 CRLF，bash 会直接炸。
6. **报告 id 有长度上限**，客户端不要截断或改写服务端返回的 id。
7. **refresh token 重放即撤销会话族**（限制 ⑦）。若产品侧认为"误伤正常用户"不可接受，
   正确解法是加**旋转宽限期**（旧 token 在短窗口内可再换一次、返回同一个新 token），
   而不是放松 reuse 检测——后者等于把 7 天令牌变成无限续期。
8. **`.gitignore` 不要用整目录规则管文档/资产**。本项目已因此发生过两次：一次吞掉
   `tests/unit/data`（3 个测试文件从未进仓库、CI 从未运行），一次吞掉本手册
   （提交成功但文件从未入库、却被记账为"已交付"）。正确做法：删掉目录级规则，
   改用内容级 `**` + 逐级反白名单，并由 `tests/unit/quality/test_doc_files_are_tracked.py` 守卫。

     界面会原样显示原因 —— 这类文件本就不能进系统，请换合规文件，**不会**伪造结果；
   - 进度条里只会出现「分析中」和「已完成」两个词，看不到百分比属正常。
3. **查看结论**：结论区给出「一句话结论 + 恶性风险 + 建议动作」，
   展开可看依据 / 鉴别诊断。甲状腺会额外输出**结节轮廓与面积**。
   若结论区出现红色停档条，说明安全网关要求转人工诊断，按提示完全依赖人工判断即可，
   其余流程（写报告、签发）不受影响。
4. **书写与签名归档**：报告分节呈现，含证据来源（可溯源到知识库条目）、一致性与安全网关结论。
   医生确认后签名，报告锁定；此后任何改动会被签名校验拦下并留痕。
5. **下一个病人**：签发后点「下一个病人」回到工作列表。顶栏右侧三个入口
   （工作列表 / 新建会话 / 设置）在任何页面都能随时切换。

> 关闭时报告里会写明「该能力未启用」及原因，**不会伪造空白结果**。

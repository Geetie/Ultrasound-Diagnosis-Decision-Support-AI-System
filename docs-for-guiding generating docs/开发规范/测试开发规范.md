# 测试开发规范

## 1 测试构建流程

### 1.1 需求分析阶段

| 步骤 | 输入 | 输出 |
|---|---|---|
| 识别测试范围 | 设计文档(接口规范/架构设计) | 测试覆盖清单 |
| 确定测试层级 | 单元/集成/端到端 | 测试文件归属目录 |
| 标记测试轨道 | API/SEC/SG/OBS/LLM | pytestmark标记 |

**测试层级划分**：

| 层级 | 目录 | 依赖 | 速度目标 |
|---|---|---|---|
| 单元测试 | `tests/unit/` | Mock所有外部服务 | <100ms/用例 |
| 集成测试 | `tests/integration/` | Mock部分外部服务 | <5s/用例 |
| 基准测试 | `tests/benchmark/` | 真实服务或完整Mock | 按需 |

### 1.2 用例设计阶段

**必须覆盖的场景**：

1. 正常路径（Happy Path）
2. 边界条件（空值/极值/负值）
3. 异常路径（权限拒绝/资源不存在/服务不可用）
4. 并发安全（多协程/多线程竞争）
5. 幂等性（重复请求返回相同结果）

**用例设计模板**：

```
测试方法名: test_{功能}_{场景}_{预期结果}
示例: test_submit_diagnosis_no_consent_returns_403
```

### 1.3 编码阶段

1. 先写测试骨架（类+方法名+断言占位）
2. 实现fixture和mock
3. 填充测试逻辑
4. 本地验证通过

### 1.4 执行阶段

```bash
# 按轨道运行
python -m pytest tests/unit/api/ -v --tb=short

# 按标记运行
python -m pytest -m track_api -v

# 显示最慢测试
python -m pytest --durations=10
```

### 1.5 维护阶段

- 新增接口时同步补充测试
- 修改接口时更新受影响的测试
- 定期清理废弃测试

## 2 测试编码规范

### 2.1 命名约定

| 对象 | 规范 | 示例 |
|---|---|---|
| 测试文件 | `test_{模块名}.py` | `test_diagnosis.py` |
| 测试类 | `Test{业务域}{功能}` | `TestDiagnosisConsentFlow` |
| 测试方法 | `test_{功能}_{场景}_{预期}` | `test_consent_withdrawn_raises_403` |
| Fixture | 小写snake_case | `mock_db_session` |
| Mock工厂 | `_mock_{依赖名}` | `_mock_feedback_repo` |
| Payload工厂 | `_base_payload` | `_base_payload(**overrides)` |

### 2.2 代码结构

```python
# 1. 导入区
import pytest
from unittest.mock import AsyncMock, patch

# 2. 模块级标记
pytestmark = [pytest.mark.track_api, pytest.mark.track_sec]

# 3. 辅助函数/工厂函数
def _base_payload(**overrides):
    payload = {"session_id": "sess_001", "target_organ": "thyroid"}
    payload.update(overrides)
    return payload

# 4. 测试类
class TestDiagnosisConsentFlow:
    @pytest.fixture(autouse=True)
    def mock_deps(self):
        # 依赖注入
        yield

    async def test_consent_not_granted_raises(self):
        # 测试逻辑
        pass
```

### 2.3 pytest标记规范

| 标记 | 用途 | 示例 |
|---|---|---|
| `track_api` | API接口轨道 | `pytestmark = pytest.mark.track_api` |
| `track_sec` | 安全合规轨道 | `pytestmark = pytest.mark.track_sec` |
| `track_sg` | 安全网关轨道 | `pytestmark = pytest.mark.track_sg` |
| `sec_domain_consent` | 同意域 | 细粒度安全域标记 |
| `asyncio` | 异步测试 | `@pytest.mark.asyncio` |

**多维度标记**：`pytestmark = [pytest.mark.track_api, pytest.mark.track_sec]`

### 2.4 断言规范

- 使用明确断言，避免 `assert True`
- 错误码断言：`assert exc.error_code == "E1008"`
- 状态码断言：`assert response.status_code == 403`
- 异常断言：`with pytest.raises(PatientNotConsentedException)`

## 3 Mock对象使用规范

### 3.1 适用场景

| 场景 | 推荐方式 | 说明 |
|---|---|---|
| FastAPI依赖注入 | `app.dependency_overrides` | 首选，最贴近框架设计 |
| 外部服务(Redis/PG) | `unittest.mock.patch` | 在conftest.py中集中管理 |
| 数据库会话 | `AsyncMock(spec=AsyncSession)` | Mock SQL操作 |
| WebSocket连接 | `AsyncMock()` | Mock send_json/accept |
| 配置对象 | `patch("module.settings")` | 覆盖配置值 |

### 3.2 实现方式

**FastAPI依赖注入覆盖**（首选）：

```python
@pytest.fixture(autouse=True)
def mock_deps(self, app):
    mock_repo = AsyncMock()
    app.dependency_overrides[get_diagnosis_repo] = lambda: mock_repo
    yield
    app.dependency_overrides.clear()
```

**patch方式**（用于非DI场景）：

```python
with patch("app.api.v1.consent.ConsentRepository") as MockRepo:
    MockRepo.return_value.get_latest_consent = AsyncMock(return_value=mock_record)
    result = await get_consent(...)
```

**Redis Mock统一创建**：

```python
def _make_redis_mock():
    redis_mock = AsyncMock()
    redis_mock.get = AsyncMock(return_value=None)
    redis_mock.setex = AsyncMock(return_value=True)
    redis_mock.delete = AsyncMock(return_value=1)
    redis_mock.exists = AsyncMock(return_value=0)
    redis_mock.expire = AsyncMock(return_value=True)
    redis_mock.incr = AsyncMock(return_value=1)
    redis_mock.pipeline = MagicMock(return_value=AsyncMock())
    return redis_mock
```

### 3.3 验证方法

```python
# 验证方法被调用
mock_ws.send_json.assert_called_once_with({"type": "test"})

# 验证调用参数
call_args = mock_ws.send_json.call_args[0][0]
assert call_args["type"] == "diagnosis_result"

# 验证方法未被调用
mock_ws.send_json.assert_not_called()
```

## 4 测试编码实践经验

### 4.1 性能优化

#### 4.1.1 autouse fixture使用原则

| 原则 | 说明 |
|---|---|
| **禁止全局autouse做状态重置** | `reset_desensitization_engine`等应改为显式fixture |
| **autouse仅用于环境设置** | 如`os.environ.setdefault`等无副作用操作 |
| **按目录分层autouse** | 全局conftest只放环境变量；状态重置放子目录conftest |

**反面案例**（当前conftest.py）：

```python
@pytest.fixture(autouse=True)  # 每个测试都执行，即使不需要
def reset_desensitization_engine():
    from app.security.desensitization import DesensitizationEngine
    DesensitizationEngine._instance = None
    yield
    DesensitizationEngine._instance = None
```

**正面案例**（改为显式fixture）：

```python
@pytest.fixture  # 只在需要时请求
def reset_desensitization_engine():
    from app.security.desensitization import DesensitizationEngine
    DesensitizationEngine._instance = None
    yield
    DesensitizationEngine._instance = None
```

#### 4.1.2 TestClient生命周期

| 规则 | 说明 |
|---|---|
| session-scoped TestClient | 整个测试会话只创建一次 |
| lifespan依赖必须全量mock | 任何lifespan中创建的组件都应mock |
| 新增lifespan依赖时同步更新mock | main.py变更时同步更新_patch_lifespan_deps() |

#### 4.1.3 外部服务连接

| 规则 | 说明 |
|---|---|
| 单元测试禁止真实外部连接 | Redis/PG/SG必须mock |
| 需要真实连接的测试用mark标记 | `@pytest.mark.requires_redis` |
| 连接超时上限5秒 | `asyncio.wait_for(timeout=5.0)` |

#### 4.1.4 fixture作用域选择

| 场景 | 推荐scope |
|---|---|
| TestClient | session |
| 无状态工具对象 | function |
| Mock依赖注入 | class或function |
| 全局状态重置 | function(显式请求) |

### 4.2 可维护性提升

#### 4.2.1 Payload工厂模式

```python
def _base_payload(**overrides):
    payload = {
        "session_id": "sess_001",
        "target_organ": "thyroid",
        "response_tier": "compact",
    }
    payload.update(overrides)
    return payload
```

#### 4.2.2 Mock工厂模式

```python
def _mock_feedback_repo(found=True):
    repo = AsyncMock()
    if found:
        repo.create_feedback = AsyncMock(return_value=MagicMock(feedback_id="fb_001"))
    else:
        repo.create_feedback = AsyncMock(side_effect=NotFoundException())
    return repo
```

#### 4.2.3 纯逻辑测试与集成测试分离

- **纯逻辑测试**：直接import被测模块，不启动HTTP服务（如test_errors.py、test_rate_limit.py）
- **集成测试**：使用TestClient测试完整请求链路（如test_api_integration.py）

### 4.3 常见问题与解决方案

| 问题 | 解决方案 |
|---|---|
| 测试间状态泄漏 | 使用function-scoped fixture，每个测试独立实例 |
| Mock未生效 | 检查patch路径是否为被测模块的导入路径 |
| 异步测试报错 | 确保使用`@pytest.mark.asyncio`装饰器 |
| Redis连接超时 | 使用_make_redis_mock()替代真实连接 |
| TestClient初始化慢 | 扩展_patch_lifespan_deps()覆盖所有重量级组件 |

## 5 test_websocket.py性能优化方案

### 5.1 问题诊断

test_websocket.py执行速度慢的三层叠加根因：

1. **全局autouse fixture过度执行**：4个autouse fixture × 30个测试 = 120次无意义调用
2. **TestClient初始化链路过重**：lifespan中6+个重量级组件未被mock
3. **fixture重复创建**：6个类各自定义manager fixture

### 5.2 优化措施

#### P0-1: 扩展_patch_lifespan_deps()

在`tests/unit/api/conftest.py`的`_patch_lifespan_deps()`中增加：

```python
patch("app.inference.factory.create_inference_engine_from_settings", return_value=AsyncMock()),
patch("app.speech.funasr.FunASROnnxEngine.__init__", return_value=None),
patch("app.inference.gpu_monitor.GPUScheduleStrategy.__init__", return_value=None),
patch("app.observability.cusum.CUSUMMonitor.register_alert_escalation_callback", new_callable=AsyncMock),
patch("app.observability.cusum.AISafetyCircuitBreaker.get_instance", return_value=MagicMock()),
patch("app.observability.cusum.HallucinationCUSUMBridge.get_instance", return_value=MagicMock()),
```

#### P0-2: autouse改为显式fixture

将`tests/conftest.py`中的`reset_desensitization_engine`和`reset_verification_config`从`autouse=True`改为显式fixture。

#### P1: redis_client超时保护

```python
@pytest.fixture(scope="session")
async def redis_client():
    try:
        client = await asyncio.wait_for(RedisPool.get_client(), timeout=5.0)
    except Exception:
        pytest.skip("Redis not available")
        return
    yield client
    await client.flushdb()
    await RedisPool.close()
```

#### P2: 消除重复manager fixture

删除test_websocket.py中6个类内重复的manager fixture定义，使用conftest.py中已有的manager fixture。

### 5.3 预期效果

| 指标 | 优化前 | 优化后目标 |
|---|---|---|
| 单个测试fixture开销 | 50-100ms | 5-10ms |
| test_websocket.py总耗时 | 1.5-3s | 0.15-0.3s |
| TestClient初始化 | 数秒 | 毫秒级 |

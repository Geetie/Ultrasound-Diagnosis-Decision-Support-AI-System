## 二、我做了什么：引文候选生成工具

新增 `scripts/audit/p116_quote_candidates.py`。

### 解决的具体痛点

B2 的 `gold[].evidence_quote` 必须**逐字**来自 KB（现有 152/152 命中）。
手写新条目时若先写问题、再去 KB 找逐字匹配的句子，会反复试错——
这是扩充到 487 条时最大的时间浪费。

**本工具反过来**：先从 KB 筛出「值得作为引文的句子」，让人拿着候选写问题。
这样每写一条必然命中。

### 候选产出量（实测）

```
thyroid: 402 条
liver:   187 条
cardiac: 194 条
合计:    783 条
```

**足够支撑扩到 487 条**（缺口 367）。

### 判据（8 类，每类带 why，可直接写进 notes）

| 类 | 正则要点 | 可考什么 |
|---|---|---|
| 阈值 | `[>＞≥≤<] 数字 mm/cm/%/分` | 这个数是多少 |
| 区间 | `数字 ~ 百分号` | 恶性率范围 |
| 分档 | `[1-6] 类/级` | 积几分归几类 |
| 计分 | `计N分 / 积N分 / +1分` | 这项计几分 |
| 分级系统 | `C-TIRADS / LI-RADS / TR1-5 / LR-1-5M` | 属哪一档 |
| 结节大小 | `直径/大小/最大径 数字mm` | 多大要穿 |
| 随访 | `随访/复查/间隔` | 多久复查 |
| 穿刺 | `穿刺/FNA/活检` | 要不要穿 |

### 两个已被排除的噪声源

1. **泛化的 `\d+ (mm|cm|%)`**：会把「术后切口感染率 1%~2%」这类
   **不是影像检索该考的内容**收进来 → 改成只收 `直径/大小/最大径 + 数字mm`
2. **非散文行**：Markdown 标题（`# xxx`）、表格分隔行（`|---|`）、纯编号行
   → 加了 `_NON_PROSE_RE` 过滤 + 必须含中文

## 三、仍需人工完成的部分（367 条）

**工具只提供候选，条目必须逐条手写。** 每条要写：

```
query_id, query（15-40 字临床真实提问）, organ, query_type,
imaging_terms（3-5 个，供 p79 门禁检查 ≥50%）, 
gold: [doc_id, chunk_index, evidence_quote（用工具给的候选）],
answerable, notes（为什么这样问）
```

**三条硬约束**：
1. `evidence_quote` 必须逐字命中（工具已保证）
2. 过 p79 四道闸：重复率 0 / 模板 ≤10% / 影像术语 ≥50% / 自相矛盾 0
3. **不得用脚本批量生成**（用户明确要求「一条一条深思熟虑地撰写」）

## 四、为什么本轮不自动生成

我可以用脚本拼 367 条 `query = "{organ} {术语} {问法}"` 的模板化条目，
**但那正好会撞上 p79 的「模板 ≤10%」闸，且违背用户明确要求。**

**与其产出 367 条不能用的假数据，不如如实说明这一步需要专门轮次。**

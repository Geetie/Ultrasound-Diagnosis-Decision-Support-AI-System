# T2b 诊断结论更正：20.99% 是代码 bug，不是"微调训坏了特征"

> 更正日期：2026-11-08｜原结论见 `reports/_archived_20261108/p87_cactus_video_disjoint.json`

## 一、原结论（**已推翻**）

> 「任务可分（冻结特征 86.28%），是 T2b 微调配方把 BiomedCLIP 特征训坏了（86.3%→21.0%）」

## 二、推翻它的证据（四处独立缺陷，我独立复现了第 3 条）

### 缺陷 ③ 标签-特征错位（最致命）—— **我独立复现，错位率 79.77%**

`p87` 抽特征时用 `DataLoader(..., shuffle=train)`（训练集 `shuffle=True`），
但 `extract()` 只是 `torch.cat(feats)` **不记录样本下标**，随后按 `rows` 原序配标签。

复现脚本（最小构造，`__getitem__` 返回下标+标签）：

| loader | 顺序与前 N 个下标一致 | 标签错位率 |
|---|---|---|
| `shuffle=True`（p87 用的） | **False** | **79.77%（16120/20207）** |
| `shuffle=False`（p89 用的） | True | **0.00%** |

**79.77% 的样本标签与特征不匹配 → 5 类 LR 退化成多数类 → 恰好解释 20.99%。
同时解释了「为什么冻结比微调好 4 倍」——p89 用 `shuffle=False`，没有这个 bug。**

**所以：`0.8628` 是真的，`0.2099` 是假的。**

### 缺陷 ② 训练用了验证集变换（零增强）

```python
model, _, preprocess = open_clip.create_model_and_transforms(uri, device=device)
#       ↑ 这里是 preprocess_train，被丢弃了
```
返回三元组是 `(model, preprocess_train, preprocess_val)`，写成 `model, _, preprocess`
意味着 `preprocess` 拿到的是 **preprocess_val**（纯 resize+center crop）→ 训练**零增强**。

### 缺陷 ① 样本内打分

`t2b_cactus_train.py::eval_split` 拿同一份特征 `fit` 再 `predict` 同一份特征 = 训练集自评。

### 缺陷 ④ 损失函数正样本口径错

`open_clip.ClipLoss` 用批内对角线作正样本，但 batch=256 只有 **5 条唯一 caption**，
同 caption 批内出现约 51 次 → 对角线把同类另一张图当负样本。
理论下界 `log(256/5)=3.94`，p87 实测 loss 4.21→4.06→4.03 **贴着下界走不动**。

## 三、修法与当前状态

新脚本 `scripts/audit/p92_t2b_retrain.py`（**不覆盖 p87**，保留可追溯）：

| 缺陷 | 修法 |
|---|---|
| ③ 标签错位 | Dataset 返回样本下标 → 抽完按下标重排 + `assert sorted(idx)==range(n)` 硬校验（**结构上不可能沉默通过**） |
| ② 零增强 | 用 `preprocess_train` |
| ① 样本内打分 | LR 探针只在 train 视频特征上拟合；val 仅选 epoch；**test 定稿后评一次** |
| ④ 损失口径 | 改**类别锚点交叉熵**（5 类 softmax，无重复正样本问题） |

**正式重训进行中**：4 个配方网格（lr 3e-6 / 1e-5 / 3e-5 + 只训最后 block lr 5e-5），早停。
结果出来后填进 `评测总表-待填模板` 的 1.11 行。

## 四、对评测总表的影响

模板里这三行的关系需要重新理解：

| 行 | 值 | 含义 |
|---|---|---|
| 1.11 心脏切面（视频不交集重训） | ⏳ 待测 | **即将有真数** |
| 1.13 冻结特征基线 | **0.8628** | ✅ **这个是真的，是必须超越的基线** |
| 1.15 多数类参照 | **0.2099** | ✅ 参照值（p87 的 0.2099 与之巧合相同，因为退化成了多数类） |

**注意**：p87 的 0.2099 与 p89 的多数类 0.2099 数值相同不是巧合——
错标 79% 的 LR 退化后就是"永远猜最多那一类"。

## 五、教训

**这个 bug 属于"代码缺陷伪装成模型缺陷"**——如果不查代码、只读数字，
会得出"任务不可分/微调方法有毒"的错误结论，进而放弃一条本来可行的路线。

`p87` 的报告里我写了 `scope_note` 详细描述泄漏，却**没有校验特征与标签的对应关系**。
教训：**任何"抽特征→配标签→拟合"的流水线，必须显式断言顺序一致**，
不能依赖"我知道 loader 是有序的"这种隐含假设。

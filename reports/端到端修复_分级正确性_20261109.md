# 端到端修复：从「无法分级」到「4A 类正确计分」

> 日期：2026-11-09｜本轮把提示词与检索的错配全部修通

## 一、症状演变（三个连续缺陷）

| 阶段 | 输出 | 原因 |
|---|---|---|
| 修复前 | `TR4 — 实性(3)+低回声(2)=5 分 → TR4` | 用 ACR 加权法，与知识库 C-TIRADS 混用 |
| 改提示词后 | `TR1 — 现有知识未涉及足够的影像特征` | 提示词塞了两套体系，模型不知用哪个 → 拒答 |
| **最终** | **`4A类`，`实性 +1 = 1 分 → 4A 类`** | 计分规则 + 查表警示 + 双来源标注 |

## 二、本轮修的五个真实缺陷

### 缺陷 1：`needs_backfill` 只看来源个数（我上一轮写的 bug）
```
原判据：len(present) >= 2 → 不补捞
实测问题：召回了 norm_2018 + guideline_2022 两个来源 → 判"已覆盖"
         但两个来源都不含 C-TIRADS 分档表 → 模型无法分级
修法：改成看「**是否覆盖分级体系**」(_GRADING_SOURCE_SETS)
```

### 缺陷 2：`_source_sets_of` 永远返回空集
```
原因：检索返回的 KnowledgeChunk.metadata 常是 None
     （source_set 在 PG 的 metadata 列里，不一定带进对象）
修法：改用权威规则表 source_set_of(source_doc_id=...) 推导
```

### 缺陷 3：`context.clinical_text` 字段不存在
```
trace 显示：witness_backfill -> error:AttributeError
真因：AgentContext 的字段是 `user_query`，不是 clinical_text/query_text
影响：补捞**全程静默失效**，查了三轮才定位
改进：异常日志从 `type(exc).__name__` 改成带完整堆栈（截 800 字）
```

### 缺陷 4：模型把「各计 1 分」理解成「每项 ±0.5 分」
```
实测输出：实性(+0.5) + 极低回声(+0.5) + 边界清(-0.5) + … = 0 分 → 3类
修法：加明确示例 + 禁令「分数只能是整数，不许出现 0.5」
```

### 缺陷 5：分档表映射被模型自行推算
```
实测：2 分 → 报成 4A（表里是 4B）
修法：表里加粗关键档 + 警示「3 分不是 4B；4 分属于 4C 不是 5 类；5 分才是 5 类」
```

## 四、一个关键方法论收获

**「改提示词」不能靠读代码判断效果，必须跑真模型。**

我这轮改了 4 次提示词：
1. 加 C-TIRADS 分档 → 模型仍用 ACR
2. 要求同时给两套 → 模型拒答（"知识未涉及"）
3. 加计分示例 → 模型用 0.5 分
4. 加整数禁令 + 查表警示 → **正确**

**每次都是"看起来对、跑起来错"。**

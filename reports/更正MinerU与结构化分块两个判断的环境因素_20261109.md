# 更正：我的「MinerU 不如 pypdf」「结构化分块负增益」两个判断都受环境限制

> 日期：2026-11-09｜用户质疑后重新核查，确认两个判断都不可靠

## 一、MinerU：我说「打平」，实际是**没跑到能发挥的档位**

### 我实际跑的命令
```bash
mineru parse <pdf> --tier flash --pages all -f markdown -o out.md
```

### 各档位的能力与实测状态

| 档位 | 表格识别 | 本机状态 |
|---|---|---|
| **flash**（我用的） | ❌ 输出「空格对齐等宽文本」，**非** Markdown 管道表 | ✅ 可运行 |
| **standard** | ✅ 有表格识别 | ❌ **崩溃**：`failed to allocate Vulkan0 buffer of size 709379584` |
| **advanced** | ✅ 最强 | ❌ 需要 parse-server（`managed_tier` 只接受 basic/standard，**不接受 advanced**） |

### 崩溃原因（实测）
```
GPU 总 49140 MiB，已用 47272 MiB，空闲 1231 MiB
  vLLM (II-Medical-8B)  38926 MiB   ← 占 79%
  bge-m3                 3546 MiB
  reranker               2410 MiB
  UltraSoundCLIP         2326 MiB
```

**MinerU 的表格识别模型需要 709 MB 连续 Vulkan 缓冲，而 II-Medical-8B 的 vLLM 已占 38.9/48 GB。**

### 所以正确的结论是
> **MinerU 的优势档位（表格结构化）在本机跑不起来，因为显存被 II-Medical-8B 占满。**
> 这不是「MinerU 不如 pypdf」，是**显存不够**。

**要验证 MinerU 真实能力，必须先停 vLLM（或换机器），再跑 standard/advanced 档。**

## 二、结构化分块：A/B 负增益的结论**不成立**，因为输入数据不对

### 我的分块器怎么识别表格
`app/knowledge/md_chunker.py` 依赖三类信号：
1. **围栏代码块**（```` ``` ````）
2. **管道行**（`|...|`）
3. **题注**（`表N` / `Table N` 行首独立成行）

### 但 flash 档的输出是
```
TIRADS分类
无结节 无分值*      0     1 无结节
有结节    -1     0     2 良性
       0      <2    3 良性可能
       1     2~10   4A 低度可疑恶性
       ...
```
**没有 `|`、没有 `表1` 题注、没有围栏** —— 三类信号**一个都不匹配**。

### 所以我的 A/B 做了什么
> 用「结构化信号全缺」的数据，去测「结构化分块器」vs「纯文本分块器」
> → 结构化分块器拿不到任何结构 → 必然等价于或劣于纯文本切分

**A/B 测的不是「结构化分块好不好」，而是「在无结构输入上强行做结构分块会不会变差」——答案显然是会。**

### 这解释了当时的消融数字
| 臂 | hit@10 | 我的解释 | 真实原因 |
|---|---|---|---|
| 旧 sentence_boundary | 0.8348 | 基线 | 基线 |
| 仅表格保护 | 0.8061 (−5.1pt) | 表格保护有害 | **表格根本识别不到**，等于没做，只增加了块边界扰动 |
| 结构化+管道化 | 0.7449 | 结构有害 | **无结构可感知**，白增块数 |

## 三、正确的做法（两步，缺一不可）

### 第 1 步：先拿到**带结构的** MinerU 输出

前提是腾出 GPU。可选：
- (a) 临时停 vLLM → 跑 MinerU standard 全量 → 重启 vLLM（**推荐，一次性**）
- (b) 用 MinerU 的 `--remote`（mineru.net 官方服务，需 API key）
- (c) 换一台有独立显存的机器跑解析

### 第 2 步：**在有结构的输入上重做 A/B**

只有当 markdown 里真的有 `|...|` 管道表与 `表N` 题注时，
「结构化分块」与「纯文本分块」的对比才有意义。

## 四、我要认的错

**我在没跑通 MinerU 有效档位的情况下，就下了「MinerU 不如 pypdf」的结论；
又在无结构输入上做 A/B，就下了「结构化分块负增益」的结论。**

两个判断都**把环境限制误当成方案优劣**。

这与我这个项目里反复出现的错误同源：**看到 A 和 B 不一样，就归因到最显眼的变量，
而不是先确认实验条件是否成立。**

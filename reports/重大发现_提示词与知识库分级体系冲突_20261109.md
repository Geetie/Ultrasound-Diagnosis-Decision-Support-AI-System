# 重大发现：提示词用 ACR TI-RADS，知识库补的是 C-TIRADS —— 两套体系混用

> 日期：2026-11-09｜来源：真实端到端查询暴露

## 一、端到端的那个"错误结论"，其实是体系冲突

真实查询「4A 类 12mm 要不要穿刺」返回：
```
甲状腺 · TR4 — 实性(3) + 低回声(2) = 5 分 → TR4
```

**我当时以为这是"模型算错了"。查明后不是。**

## 二、真相：两套计分体系混用

| | **C-TIRADS 2021**（中华医学会） | **ACR TI-RADS**（美国） |
|---|---|---|
| 计分法 | **计数法**：每个可疑征象计 **1 分** | **加权法**：各征象 0-3 分 |
| 征象 | 实性、微钙化、极低回声、边缘模糊、边缘不规则/外侵、垂直位（6 项） | 成分/回声/形态/边缘/钙化（5 维 × 0-3） |
| 特殊情况 | 彗星尾伪像 **总分 -1** | — |
| **分档** | **-1→2类 / 0→3类 / 1→4A / 2→4B / 3~4→4C / 5→5类** | **0→TR1 / 2→TR2 / 3→TR3 / 4-6→TR4 / ≥7→TR5** |
| 满分 | **5 分** | **15 分** |

### 系统里实际是什么

**`app/agents/prompts/thyroid.md` 第 55-65 行**（提示词）：
```
| 成分 | 囊性/几乎全囊 | 海绵状 | 囊实混合 | 实性/几乎全实 |
| 回声 | 无回声 | 高回声/等回声 | 低回声 | 极低回声 |
...
- TR1（0 分）
- TR2（2 分）
- TR3（3 分）
- **TR4（4-6 分）**
- **TR5（≥7 分）**
```
→ **这是 ACR TI-RADS 的加权计分法与分档。**

**知识库里**（我 2026-11-08 补的 `ctirads_2021_counting_table`）：
```
| 1 | 2~10 | 4A 低度可疑恶性 |
| 2 | 10~50 | 4B 中度可疑恶性 |
| 3~4 | 50~90 | 4C 高度可疑恶性 |
| 5 | >90 | 5 高度提示恶性 |
```
→ **这是 C-TIRADS 的计数法。**

## 三、所以 5 分到底是 TR4 还是 5 类？

**取决于用哪套体系，两套都对，但混用就错：**
- 按 ACR：5 分 ∈ [4,6] → **TR4** ✅（提示词的逻辑自洽）
- 按 C-TIRADS：5 分 = 5 → **5 类** ✅（知识库的逻辑自洽）

**端到端返回 `5 分 → TR4`，说明模型用了 ACR 分档；
但它同时引用了《甲状腺癌诊疗规范 2018》的 4a 定义 —— 那是第三套口径。**

**结果是三段拼起来：ACR 计分 + C-TIRADS 知识库 + 诊疗规范引用。**
在医生看来就是"算了个 5 分，判成 TR4，引了个不相干的规范"。

## 四、这正是本项目 RAG 改造要解决的核心问题

用户的原话：
> "某些医院以 A 语料为权威，某些医院以 B 语料为权威…里面的口径不一样，以什么为准？"

**我们做了知识库之间的冲突并列（阶段 3），但漏了「提示词 vs 知识库」这一层。**

提示词里的分档表**本身也是一份"权威语料"**，它没有 source_set、不参与冲突检测、
也不会被 `rag_enabled_source_sets` 过滤。

## 五、修复方案（两条路，我建议 A）

### 方案 A：让提示词的分档表也带上 source_set 语义（推荐）

1. **提示词分档表标注体系**：明确写「以下为 ACR TI-RADS 加权计分」
2. **同时给出 C-TIRADS 计数法**（从知识库检索到的那份）
3. **让模型显式选择**：在结论里写「依据 ACR TI-RADS」或「依据 C-TIRADS 2021」
4. **`rag_enabled_source_sets` 同时控制提示词里的分档表**：
   医院只启用 C-TIRADS 时，提示词就只给 C-TIRADS 的分档

### 方案 B：只保留一套（不推荐）
选定 C-TIRADS（中国场景），删掉 ACR 那套。
**问题**：ACR TI-RADS 在国际上更通用，且我们的知识库里有 ACR LI-RADS。
一刀切会让系统丧失国际兼容性。

## 六、这个发现的元意义

**阶段 3 做的"知识库之间冲突并列"是必要的，但不充分。**

因为**权威口径不仅存在于知识库文档里，也存在于提示词里**。

系统里目前有 **3 处**可能含临床口径：
1. 知识库 chunk（✅ 已有 source_set + 冲突检测）
2. **提示词模板（❌ 没有标注、不参与冲突检测）**
3. 代码里的硬编码规则（如 `detect_self_made_grading_rule` 的判定表）

**第 2 处是本轮漏掉的。**

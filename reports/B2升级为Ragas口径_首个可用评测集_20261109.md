# B2 升级为 Ragas 口径：第一个真正可用的评测集

> 日期：2026-11-09｜目标第 16 轮：放弃合成，改用 B2 升级

## 一、15 轮合成失败的根本原因

| 问题 | 根因 |
|---|---|
| 「APHE 分 6 级」 | II-Medical-8B **不知道** LI-RADS 的 APHE 是二值 |
| 「4 类以上恶性可能逐渐减小」 | 不知道分级方向 |
| 摘录真实但与问题无关 | 选段能力不足 |
| few-shot 反而更差 | 区分不了「示范格式」与「示范内容」 |

**三条都是模型能力问题，不是工程问题。** 所以我停下了合成。

## 二、但我漏看了一个关键事实

**B2 里的 `evidence_quote` 本身就是人工逐字摘录的原文。**

```
gold[0].evidence_quote: "实性、 微钙化、 极低回声、 边缘模糊…是可疑恶性超声特征"
gold[1].evidence_quote: "|1|2~10|4A<sup>低度可疑恶性</sup>|"
```

**这正是「抽取式」要的东西，而且是人工写的、已过 p117 三判据（487 条 0 问题）。**

**所以 `reference_answer` 不需要生成，只需要把已有的 evidence_quote 拼起来。**

## 三、实现（`p128_b2_upgrade.py`）

### 3.1 reference_answer = 拼接 evidence_quote

```
原文提到：实性、微钙化、极低回声…是可疑恶性超声特征。
原文提到：|1|2~10|4A（低度可疑恶性）|。
原文提到：当结节内出现点状强回声时，按可疑特征优先的原则优先记录微钙化。
```

**每段都是人写进 gold 的逐字原文，只做了排版清理（去 `<sup>` 标签），不改内容。**

### 3.2 四维 metadata —— **诚实标注，能算的算、算不出的标 unassigned**

| 维度 | 填充方式 | 依据 |
|---|---|---|
| `organ` | 直接继承 | 客观 |
| `length` | 按 query 字数 | 客观可算 |
| `hop` | gold 条数 ≥2 → multi | **代理指标**（已在 `hop_note` 注明非真实跳数） |
| `specificity` | query 含数值/分级码 → specific | 客观可算 |
| **`persona`** | **`unassigned`** | **原数据无此信息，不伪造** |
| `source` | `manual_b2` | 真实来源 |
| `dataset_version` | `rag-eval-v2.0.0-b2upgrade` | — |

**`persona=unassigned` 是这一版的硬限制。** Ragas 要求这个维度，
但 B2 没有，编一个会让「按 persona 切片」变成假分析。

## 四、第一次真正跑通 context_recall

**修正了两个兼容性问题**（都是我的脚本只认合成集布局）：
1. 过滤条件：原按 `gate_passed`，改按 `reference_answer` 非空
2. `organ` 位置：合成集在顶层，v3 在 `metadata` 里

### 实测结果（100 条，top_k=10）

| 指标 | 值 |
|---|---|
| **context_recall** | **0.2600**（median 0.0） |
| **context_precision** | **0.1040**（median 0.0） |

### 按格子

| 格子 | recall | n |
|---|---|---|
| single/specific/medium | **0.500** | 8 |
| multi/specific/medium | 0.375 | 12 |
| single/abstract/medium | 0.216 | 51 |
| multi/abstract/medium | 0.204 | 22 |
| single/abstract/short | 0.200 | 5 |

**具体性高的 query 检索效果更好**（specific 0.375-0.5 vs abstract 0.2）。

## 五、这两个数字说明什么

### `context_recall = 0.26`

**检索到的 10 个块，只覆盖了参考答案的 26%。**

对照：`hit@10 = 0.7872`（B2 原始指标）
→ **找到了答案所在的块（78.7%），但内容只覆盖 26%。**

**这正是目标要求的「覆盖检索质量的完整两面」** ——
只测 hit@k 会以为检索还行，测了 context_recall 才发现内容严重不足。

### `context_precision = 0.10`

**10 个块里只有 1 个含答案要素。** 噪声率 90%。

# 跨语言检索诊断：英文语料对中文提问为什么检索不到

> 日期：2026-11-08｜触发：语料 Agent 报「补了 15 份英文指南但 3 条 answerable:false 一条没变成可答」

## 一、先纠正一个误判

Agent 报「bge-m3 在这个部署下没做跨语言对齐」。**我实测：对齐是有的，但不充分。**

### 测试 1：同义句对（语义完全对齐）

| 中文 | 英文 | 余弦 |
|---|---|---|
| 甲状腺结节消融后的体积缩小率 | volume reduction rate of thyroid nodule after ablation | **0.6228** |
| 主动脉瓣狭窄的峰值流速 | peak velocity of aortic stenosis | **0.6364** |
| 左心室射血分数正常范围 | normal range of left ventricular ejection fraction | **0.7029** |
| 肝细胞癌的动脉期高增强 | arterial phase hyperenhancement of hepatocellular carcinoma | **0.6376** |
| **对照：不相关** | 消融(中) ↔ LVEF(英) | **0.4609** |

**同义 0.62–0.70 vs 不相关 0.46，区分度明确 → bge-m3 确实做跨语言对齐。**

### 测试 2：真实检索排序

中文 query「甲状腺结节消融后体积缩小率多少算治疗成功」：
```
#1  pdf_thyroid_ctirads_2021_0012   sim 0.6515   ← 中文 C-TIRADS
#2  pdf_thyroid_thyroid_cancer_...  sim 0.6492   ← 中文
#3  pdf_thyroid_ctirads_2021_0027   sim 0.6439   ← 中文
```
英文 query「thyroid nodule ablation volume reduction rate...」：
```
#1  ata_ablation_2023_focus        sim 0.6682   ← 英文 ATA 消融指南
```
**英文语料不是检索不到，而是被中文语料赢了。**

## 二、根因定量化

| 中文 query 对… | 均值 sim | 最高 sim |
|---|---|---|
| 中文 chunk（40 个） | 0.4853 | **0.6515** |
| 英文 chunk（ata_ablation，40 个） | 0.4446 | **0.5422** |
| **差距** | **+0.0407** | **+0.1093** |

**同一个中文 query，对中文 chunk 的最高相似度比英文 chunk 高 0.11。**
这个差距足够让相关的中文 chunk 稳定压过更对题的英文 chunk。

**结论**：不是"跨语言完全失效"，而是"跨语言相似度系统性偏低 0.11，被中文 chunk 抢先"。

## 三、为什么这解释了 B2 掉分

语料从 1297 → 3745（+189%），其中 **1924 片是英文/中英混排**。

- 旧语料（v1.4）：1297 块，几乎全中文 → 中文 query 的竞争只在中文之间
- 新语料（v1.5）：3745 块，一半英文 → 英文块进入候选池，但因为相似度低 0.11，
  **它们既抢不到 Top-1，又把原本的中文 chunk 名额稀释了**

**所以 B2 hit@1 从 0.5641 掉到 0.5556，不是语料质量差，是语料语言分布变了。**

## 四、三个可选方案（按性价比）

### 方案 A：查询翻译扩展（推荐，改动最小）
检索前把中文 query 用 LLM 译成英文，**同时用中英两个 query 各检索一次，合并结果**。

- 优点：不动索引，不动语料，只改检索链一处
- 缺点：多一次 LLM 调用（延迟 +200~500ms）
- 已有基础设施：`QueryEnhancer` / `llm_enhancer` 已在链路上，可复用

### 方案 B：给每个 chunk 生成中英双语摘要再嵌入
- 优点：一次建索引，永久生效，无查询延迟
- 缺点：要重跑 3745 次 LLM（~1 小时）+ 重建索引；摘要会引入 LLM 幻觉风险

### 方案 C：混合检索权重调优
既然 BM25 对字面 token 更敏感，可以让 BM25 权重更高（已落 1:2）。
但中文 query 里没有英文 token，BM25 也救不了英文 chunk。**这个方案无效。**

## 五、我的建议

**同时做 A 的长版：**
1. **短期（本轮）**：`rag_latest_version_only` 默认开启，先解决 56.5% Top-10 被重复副本占据的问题
   （这个比跨语言更严重——真实可用召回位只剩 4 个）
2. **中期（下一轮）**：方案 A —— query 双语检索合并

## 四、合成质量（这轮最重要的发现）

### 4.1 纯提示词约束不住 8B 模型

即使提示词明确写「禁止编造文献名称与年份」，实测输出仍是：

| 编造内容 | 真相 |
|---|---|
| `依据《C-TIRADS 2018》` | 真实是 **2021** |
| `根据《LI-RADS 2017》` | **用在了甲状腺问题上** |
| `根据《Hürthle 细胞肿瘤》` | **编的** |

### 4.2 五道闸（p121）抓出的问题分布

10 条样本上：
```
闸1 引文真实: 4 条  ← 编造文献名
闸2 体系一致: 3 条  ← 甲状腺问题出现 LI-RADS
闸3 问句形态: 2 条  ← 把原文复述当 query（129 字）
闸4 答案信息量: 0
闸5 gold 一致: 0
总不合规 5/10 = 50%
```

### 4.3 闭环重试（p122）

把「具体哪里不合格」写回提示词再试，最多 3 次：

```
过闸 9 / 被拒 9 / 去重丢 2  → 过闸率 45%
尝试次数：1 次过 5 条、2 次过 1 条、3 次过 3 条
```

**45% 的过闸率意味着：要凑 500 条合格数据，需要生成 ~1100 次。**

## 五、诚实评估：这条路能走通，但成本比预期高

### 5.1 好消息
- Ragas 方法**确实能保证覆盖矩阵**（48 格全填，人手写做不到）
- 质量门**确实能抓住问题**（50% 不合格率被抓出）
- 闭环**确实有效**（重试能救回一部分）

### 5.2 坏消息
- **过闸率 45%** → 成本是预期的 2.2 倍
- **被拒的 9 条里 3 条是 3 次都没过** → 说明有些场景 LLM 就是生成不好
- II-Medical-8B 是 8B 模型，**约束遵循能力弱于 GPT-4o**（Ragas 默认用 gpt-4o-mini）

### 5.3 可能的改进方向（需实测）

| 方向 | 预期收益 | 代价 |
|---|---|---|
| 换更强的生成模型（如调 GPT-4o-mini API） | 过闸率可能到 70-80% | 需 API key |
| 放宽闸 1（允许「原文提到」但不写书名） | 立刻消除 4/9 不合格 | 降低可审计性 |
| 把 prompt 里的「不要写文献名」改成 few-shot 示例 | 可能比否定指令有效 | 需构造示例 |
| 人工修 rejected 条目而非丢弃 | 保留更多数据 | 回到"手工昂贵" |

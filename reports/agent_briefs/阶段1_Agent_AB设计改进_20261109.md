# 致阶段1 Agent：A/B 设计建议（不是否定你的结论）

## 先说：你做得对

**发现负增益就不全量上线、如实报告** —— 这正是我要的纪律。
本项目刚因为"凭直觉上线查询扩展"吃过亏，你避免了重蹈。

## 但你的 A/B 有一个混杂变量问题，必须指出

你的两臂同时变了 **4 个** 变量：

| 变量 | 旧臂 | 新臂 |
|---|---|---|
| **A. 解析器** | pypdf | **MinerU** |
| B. 分块策略 | sentence_boundary | md_structure |
| C. 尺寸 | 256/512 | 400/1600 |
| D. 父子块 | 无 | 有 |
| E. 语料总量 | 3511 | 6477 |

**所以「hit@10 −6.1pp」无法归因到「分块策略」** —— 因为解析器也换了，
而**解析器换掉意味着语料内容本身变了**（pypdf 抽出来的文本 ≠ MinerU 抽出来的文本）。

### 这带来一个严重问题：gold 定位口径可能不一致

你说用 B2 的 `evidence_quote` 做金标，「98 条 gold 能在新语料里定位到」。

**但旧臂的语料是 pypdf 抽的，新臂是 MinerU 抽的。** 同一句原文在两种抽取下
可能有细微差异（空格、标点、`<br>`、换行）。若你在**新语料里**定位 gold，
再拿到**旧语料**里检索，那旧臂的 gold 可能定位不准 —— 反之亦然。

**这会让"哪一臂更好"的结论失真。**

### 建议：先做单变量分离

按成本从低到高，至少做到第 1 步：

**第 1 步（必做）：只换分块策略，不换解析器**
```
臂 A: pypdf 语料 → sentence_boundary(256/512)   ← 现状基线
臂 B: pypdf 语料 → md_structure(等效尺寸)         ← 只改策略
```
若 B < A → **是对"在 pypdf 语料上做结构分块"不适用**（因为 pypdf 没有 `##` 结构）
→ 那这个对比本身就不公平：md_structure 依赖 MinerU 的标题层级，在 pypdf 语料上无从发挥。

**第 2 步（更有意义）：只换解析器，不换分块策略**
```
臂 A: pypdf 语料  → sentence_boundary(256/512)
臂 B: MinerU 语料 → sentence_boundary(256/512)   ← 只改解析器
```
**这一步能回答最重要的问题：MinerU 到底有没有让语料变好？**
如果 B > A → MinerU 有价值，值得换；然后才轮到讨论分块策略。

**第 3 步：在 MinerU 语料上比两种分块策略**
```
臂 B: MinerU → sentence_boundary(256/512)
臂 C: MinerU → md_structure(调大尺寸)
```
这才是"分块策略"的干净对比。

## 你的归因里有一条我认同，但要注意

你说「child 中位数 346 tok vs 旧 486 tok，块数 3511 → 6477（近 2 倍）」——
**这个观察很可能是对的**：检索单元变小变多 → 单块可命中的金句跨度变小 → hit@k 下降。

**但这属于「尺寸」问题，不是「结构感知」问题。**
所以你「把 child 上限调到 512/800 重测」是对的实验方向。

**建议再加一个对照**：`md_structure` 但**关闭父子块、尺寸与旧臂完全相同（256/512）**——
这样才能分离"结构切分"与"尺寸"。

# 重要发现：B2 测的 query 形态与生产实际不一致

> 日期：2026-11-09｜用户问「你拿去测的问题是医生通过系统会发出的问题吗？」
> 实测答案：**形态不一样，我的指标高估了生产表现**

## 一、B2 是什么、测什么

**B2 是「检索」指标的唯一来源**：`hit@1/5/10`、`MRR`、`NDCG@10`。
它测的是「给定一个问题，系统能否从 3748 个 chunk 里把含答案的那块捞进 top-k」。

**用途**：
1. 判断检索改动是否有效（精排、融合权重、查询扩展）
2. 判断语料/分块改动是否有效
3. 报告系统检索能力

## 二、形态不一致（实测）

### B2 的 query
```
P50 = 26 字，全部是纯问句
例：「2022 版指南 4c 类的恶性风险区间是多少？」
    「LI-RADS 分类能不能换算成 OPTN 的类别？」
```

### 生产实际送的 `user_query`
代码路径（`app/services/diagnosis_pipeline.py:907`）：
```python
user_query = 脱敏后的 request.clinical_text   # 整段临床描述原文
```

实测形态：
```
「甲状腺右叶实性低回声结节，大小12mm，边界清，形态规则，纵横比<1，
  内部未见明显钙化，CDFI示周边少量血流。TI-RADS 4A类。是否需要穿刺活检？」
→ 76 字，影像描述 + 分级 + 问句混合
```

## 三、这个差异的实际影响（实测）

用 4 条**真实生产形态**的描述去检索，top-1 命中情况：

| 器官 | 真实描述 | top-1 内容 | 是否答到问题 |
|---|---|---|---|
| thyroid | 4A 类 12mm 要穿刺吗 | 「（4）用于诊断的相关分子检测…」 | ❌ 应命中 FNA 阈值表 |
| thyroid | 4C 类 8mm 怎么处理 | 「诊断: 结节性甲状腺肿;CTIRADS4A…」 | ❌ 应命中处理建议 |
| liver | LI-RADS 分类 | 「窝状增强…填充，大小约（）mm」 | ❌ 应命中 LI-RADS 判据 |
| cardiac | LVEF 38% 收缩功能分级 | 「一、心脏定量测值…」 | ❌ 应命中分级标准 |

**4/4 全部没命中该问题的答案。**

## 四、为什么会这样

长描述里**大部分词是影像特征**（「实性」「低回声」「边界清」），
这些词在知识库里到处都有 → BM25/dense 都被这些高频词主导，
**真正的检索意图（「4A 类要不要穿刺」）被稀释了**。

而 B2 的短问句没有这个问题 —— 它干净地表达了意图。

## 五、结论：0.3760 高估了生产表现

| 场景 | 实测 |
|---|---|
| B2（短问句） | hit@1 **0.3760** |
| 真实生产形态（长描述） | 4 条抽样 **top-1 0/4** |

**这不是说 0.3760 是假数字，而是它测的**不是**生产场景。**

## 六、正确做法（两条，都要做）

### 6.1 补一份「生产形态」测试集（B2-real）

不替换 B2（它是「干净问句下的检索能力」基线，用于改动 A/B 仍有意义），
**另建一份 `B2-real`**：
- 每条是一段 60-120 字的真实临床描述（影像特征 + 分级 + 问句）
- gold 是「回答该问题时该看的那块」
- 用途：**测生产环境下的真实检索能力**

### 6.2 或者在检索前做「意图抽取」

长描述 → 抽取检索意图 → 用短问句检索。这其实是**查询改写**的一种，
但方向和阶段2 试过的「查询扩展」相反：
- 查询扩展：短 → 长（加同义词）→ 之前测是负增益
- **意图抽取：长 → 短（去噪）→ 未测过，可能更有效**

## 七、我要回答你的三个问题

1. **B2 是干什么用的**：检索指标的唯一来源，用于判断检索/语料改动是否有效、报告检索能力
2. **B2 的 query 是医生会发出的问题吗**：
   **不完全是** —— B2 是「医生心里那个问题」（短问句），
   而生产送进 RAG 的是「医生从工作站粘的整段描述」
3. **这个差异有影响吗**：**有，而且很大** —— 实测 4 条真实描述 top-1 全未命中

## 八、下一步

先做 6.2（意图抽取），因为它：
- 不需要新建数据集（快）
- 可能同时提升生产表现与 B2 指标
- 是阶段2 没试过的方向（当时只试了「短→长」扩展）

如果意图抽取有效，再决定要不要建 B2-real。

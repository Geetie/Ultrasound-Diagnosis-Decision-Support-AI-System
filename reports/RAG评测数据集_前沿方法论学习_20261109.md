## 一、理想测试数据集的四个特征（Ragas 原文）

> - Contains high quality data samples
> - **Covers wide variety of scenarios as observed in real world**
> - **Contains enough number of samples to derive statistically significant conclusions**
> - **Continually updated to prevent data drift**

## 二、最关键的认知冲击：Ragas 明确推荐**合成生成**

Ragas 原文：

> "Curating such a dataset **manually can be time-consuming and expensive**.
> Ragas provides a set of tools to **generate synthetic test datasets**"

### 我把方向搞反了

我一直把 `authored_by: "manual"` 当质量保证，并逐条手写。
**Ragas 认为手工整理是「耗时且昂贵」的问题，出路是合成。**

但注意：Ragas 的「合成」不是随便生成，而是**知识图谱驱动的受控合成**：

```
文档 → 分块成层级节点 → 提取器抽实体/关键短语
     → 关系构建器（如 Jaccard 实体相似度）连边
     → 遍历图生成不同场景的 query
```

**核心价值**：能系统性地覆盖「单跳/多跳 × 具体/抽象」四象限，
而人手写很难保证这个覆盖矩阵。

### 但我不该直接照搬合成

理由：**Ragas 的合成需要 LLM 生成 query**，而本项目：
- 有 II-Medical-8B（可以调）
- 但 synthetic query 会引入「LLM 自己造的问题 LLM 自己答得好」的偏差
- 且医疗场景的 query 必须临床合理，LLM 编的可能不真实

**正确做法**：合成负责**覆盖矩阵**，人工负责**临床合理性审核**。
（Ragas 也提到 `generate_personas_from_kg` 是 LLM 生成后人工调整）

## 三、Query 分类体系：我漏了两个维度

### Ragas 的四象限（单跳/多跳 × 具体/抽象）

| | 具体（Specific） | 抽象（Abstract） |
|---|---|---|
| **单跳** | `4A 类 FNA 阈值是多少？` | `C-TIRADS 为什么用计数法而不是权重法？` |
| **多跳** | `ACR 和 C-TIRADS 对同 4 分结节分别归什么类？` | `两份指南体系差异的临床影响是什么？` |

**我现在的 B2 主要在「单跳×具体」，多跳和抽象几乎没有。**

### Ragas 的 Scenario 三要素

```
Scenario = Nodes（知识图节点）+ Query Length（short/medium/long）+ Query Style（web search/chat/...）
          + Persona（用户角色）
```

**Persona 是本项目最该补的维度**：

| Persona | 会问什么 |
|---|---|
| 超声科住院医师 | 「这个征象算不算可疑？」（基础规则） |
| 超声科主治医师 | 「这个边界情况怎么定？」（边界与例外） |
| 临床科室医生（非超声） | 「报告上这个分级是什么意思？我该怎么处理病人？」 |
| 医务处/质控 | 「我们医院用的是哪套分级？」（体系与合规） |

**我现在的 8 个 query_type 是「问题内容分类」，
而 persona 是「谁在问」——后者决定了措辞、深度、隐含上下文。**

## 四、数据集该包含什么（Ragas 的 Dataset 结构）

```python
{
  "id": "...",
  "query": "...",              # 系统输入
  "expected_output": "...",    # 期望输出（可选）
  "metadata": {                # 用于切片分析
      "complexity": "simple",
      "language": "zh"
  }
}
```

**关键洞察**：
1. `expected_output` 是**期望答案文本**，不是「哪个 chunk」。
   我现在只有 `gold`（chunk 位置），**没有 `reference_answer`**。
   → 这意味着我**测不了 context_recall**（需要参考答案拆成句子）
2. `metadata` 用于**切片分析**（按复杂度/语言/器官分组看指标）。
   我现在有 `organ`/`query_type`，方向对但不够细。

## 五、五条最佳实践（Ragas 原文）

| # | 实践 | 我的状态 |
|---|---|---|
| 1 | **Representative Samples**：数据集要代表真实世界场景 | ❌ 我建的 B2 是 41%/29%/30%，真实是 97.7%/1.2%/1.2% |
| 2 | **Balanced Distribution**：跨难度、话题、边界情况都要有 | ⚠️ 话题有分类，**难度和边界情况没有系统标注** |
| 3 | **Quality Over Quantity**：少量高质量好过大量低质量 | ✅ 现在 487 条都是逐条验证的 |
| 4 | **Metadata Rich**：元数据要能支撑多维分析 | ⚠️ 有 organ/query_type，缺 complexity/persona/length |
| 5 | **Version Control**：数据集要版本化以保证可复现 | ❌ 现在只有一个文件，无版本标记 |

## 六、非英语语料的适配（本项目是中文，必须看这个）

Ragas 的做法：

```python
# 1) 定义目标语言
prompts = await query.adapt_prompts("spanish", llm=generator_llm)
query.set_prompts(**prompts)
# 2) 用适配后的 prompt 生成
```

**启示**：**换语言不是翻译数据，是让生成器的 prompt 适配目标语言。**
我之前的翻译路线（英文报告 → 中文）是「数据翻译」，
而 Ragas 说的是「生成器语言适配」——后者能保证生成的 query 天然符合中文医生的表达习惯。

## 八、据此修正的方案框架（下一轮细化）

### 8.1 数据集分三层，各司其职

| 层 | 来源 | 用途 | 数量目标 |
|---|---|---|---|
| **L1 生产回放** | `diagnosis_results.clinical_text` 真实文本 | 测真实场景（含陈述式） | 全量 661 |
| **L2 受控合成** | 按 Ragas 方法，从 KB 知识图生成 | 覆盖四象限 × persona × length | 按覆盖矩阵定 |
| **L3 手工精标** | 人工逐条，用于校准 L2 的质量 | 验证合成集是否可信 | 50-100 |

**L3 的作用是「证明 L2 可信」，不是「替代 L2」。**

### 8.2 必须补的字段

```json
{
  "id": "...",
  "query": "...",
  "reference_answer": "...",        // 新增：期望答案文本
  "gold": [...],                     // 保留：chunk 位置（测 hit@k）
  "metadata": {
    "organ": "...",
    "persona": "住院医师|主治|临床科室|医务处",   // 新增
    "hop": "single|multi",                        // 新增
    "specificity": "specific|abstract",           // 新增
    "length": "short|medium|long",                // 新增
    "source": "production|synthetic|manual",      // 新增
    "dataset_version": "v2.0"                     // 新增
  }
}
```

### 8.3 分布原则（修正）

**不对齐生产分布，而是按「覆盖矩阵」保证每格有样本。**

理由：
- 生产 97.7% thyroid 是历史结果，不是未来需求
- 但也不能像我之前那样随意分配
- **正确做法**：每个 (persona × hop × specificity) 格子保证 ≥10 条 → 指标可以按格子报

## 九、需要你确认的三点

1. **接受「合成 + 人工审核」而非纯手写吗？**
   依据：Ragas 明确说手工整理耗时昂贵；且合成能保证覆盖矩阵
2. **`reference_answer` 必须补吗？**
   补 → 能测 context_recall（检索质量的另一半）；不补 → 只能测 hit@k
3. **persona 维度用哪几个？**
   我提议：住院医师 / 主治医师 / 临床科室医生 / 医务处质控

# 核实结论：97.43% 作废，0.9215 才是干净数字

> 日期：2026-11-08｜触发：用户质疑「这么高的数字真实吗？训练集和测试集分开了吗？」

## 一、用户质疑成立，我错了

我此前报的 **T2b 97.43%** 确实不可信。核实结果：

```
生产权重训练集 = 官方 train.csv（20977 图 / 117 视频）
我评测用的 test = video_disjoint_split 的 test（4511 图 / 17 视频）

路径重叠：3160 / 4511 = 70.05%   ← 70% 的测试图就在训练集里
视频重叠：17 / 17 = 100%         ← 全部 17 个视频都在训练集出现过
```

**我犯了和 p87 一样的错误**：`video_disjoint_split` 是"从三个 CSV 合并后重新按视频划分"，
它用于**重新训练**场景；而我拿它去测一个**已经在 train.csv 上训练过**的权重 → 必然重叠。

## 二、为什么官方 test.csv 也不干净

查清了 CACTUS 的结构：

| CSV | 图数 | 视频数 |
|---|---|---|
| train.csv | 20,977 | 117 |
| val.csv | 4,492 | 109 |
| test.csv | 4,494 | 110 |

- `train ∩ test 视频 = 110`（train 有 117，test 有 110，**几乎全重叠**）
- 三个 CSV **合计只有 117 个唯一视频**
- 实测「官方 test+val 中视频从未在 train.csv 出现」的图 = **0 张**

**官方划分是按图像随机切的**：同一视频的帧被分散到 train/val/test 三边。
**所以用官方 train.csv 训练的模型，在任何官方 test 上测都是帧级泄漏。**

## 三、唯一干净的评测方式

必须**重新按视频划分 + 重新训练**。p92 做的就是这件事，我核实过它的划分：

```
train : 20207 图 / 80 视频
val   :  4087 图 / 19 视频
test  :  4511 图 / 17 视频

train ∩ test 视频 = 0        ✅
train ∩ val  视频 = 0        ✅
train ∩ test 图像路径 = 0    ✅
test 占总数据 15.7%
```

**零重叠确认。所以 p92 的 0.9215 是干净的。**

## 四、修正后的数字表

| 数字 | 值 | 是否可信 | 原因 |
|---|---|---|---|
| p86 官方 test.csv | 0.9786 | ❌ **作废** | 帧级泄漏（96.11% 测试图来自 train 视频） |
| 我实测的 97.43% | 97.43% | ❌ **作废** | 路径重叠 70.05%（我搞错了权重来源） |
| **p92 视频不交集重训** | **0.9215** | ✅ **可信** | 视频级 + 路径级双零重叠 |
| p92 另一配方（p95 复算） | 0.9031 | ✅ 可信 | 同上 |
| p89 冻结特征基线 | 0.8628 | ✅ 可信 | 只用 train 视频特征拟合 LR，test 不参与 |

## 五、但 0.9215 也有它的限度

**test 只有 17 个视频**。因此：
- 图像级 CI [.9131, .9295] 是**假窄**（把 4511 张相邻帧当独立样本）
- **视频级 cluster CI [.8278, .9959]** 才是诚实的不确定性
- 下界 0.8278 仍 > 目标 0.80，但**不能声称 0.9215 有 ±1% 精度**

## 六、教训（第二次同类错误）

第一次：p87 用 `shuffle=True` 导致标签错位 → 数字全错
第二次：我用 `video_disjoint_split` 测已在 train.csv 上训练的权重 → 数字虚高

**共同点**：都没有先确认"这份评测集的样本，到底有没有参与过训练"。

**以后任何评测，第一件事必须是**：
```
□ 训练用了哪些文件？（查训练脚本 / 查 CSV）
□ 评测用了哪些文件？
□ 两者路径交集 = 0？
□ 两者视频交集 = 0？（医疗影像的关键）
```
两个交集都为零，数字才有意义。

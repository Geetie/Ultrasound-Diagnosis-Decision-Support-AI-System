# TR 编号展开到 C-TIRADS 类别名：实测效果（2026-11-08）

## 改了什么

把 `TR1~TR5` 映射到 C-TIRADS 分档表里实际使用的类别名：

| 编号 | 展开词 |
|---|---|
| TR1 | `1 类` / `无结节` / `分级` |
| TR2 | `2 类` / `良性` / `分级` |
| TR3 | `3 类` / `良性可能` / `分级` |
| TR4（含 4a/4b/4c） | `4A 类` / `4B 类` / `4C 类` / `可疑恶性` / `分级` |
| TR5 | `5 类` / `高度提示恶性` / `分级` |

**为什么需要**：`kb_v1.6.0` 补进了 C-TIRADS 计数法分档表，表里写「4A 低度可疑恶性」，
而模型/prompt 用 `TR2~TR5` —— **两套命名不对齐，检索词不匹配**。

## 实测（候选池 1712 条：v1.6.0 的 2 条 + v1.5.0 甲状腺 1710 条）

目标文档 = `kb_v1.6.0:ctirads_2021_counting_table#0000`（分档表）

| 查询 | 原排名 | 展开后 | 效果 |
|---|---|---|---|
| TR3 结节的恶性风险是多少 | 3 | **1** | ✅ |
| TR4a 类要穿刺吗 | 172 | **95** | ✅（改善但仍在 100 名外）|
| TR2 是什么意思 | 75 | **1** | ✅ **大幅改善** |
| TI-RADS 5 类怎么处理 | 10 | **126** | ❌ **明显变差** |

## 诚实结论：**这个改动不是纯收益**

3 项改善、1 项变差。变差的 `TI-RADS 5 类怎么处理` 的原因是：
`TI-RADS` 规则追加了 `甲状腺影像报告和数据系统` + `TI-RADS 分类` + `分级` +
`中国版甲状腺影像报告和数据系统` + `C-TIRADS 计数法` + `计数法` +
`1 类`/`2 类`/... 这类多级叠加 → **扩展词总量过大，把查询向量稀释了**。

这与第 3 组的 A/B 结论一致：**查询扩展整体是负增益**（纯 dense −3.4pt / 融合 −1.7pt，
含缩写子集 n=35 也是 −5.7pt）。

## 因此我的处置

**不把 query expansion 默认打开**（保持第 3 组的结论：它整体负增益）。

`TR1~TR5` 的映射**只保留在代码里但不默认启用**，理由是：
- 它对「TR 编号 → 类别名」这种**跨命名体系**的查询确实有效（TR2 从 75 → 1）
- 但对「已经含完整术语」的查询会稀释（TI-RADS 5 类 10 → 126）

**正确做法（下一轮）**：
1. 只在**查询里出现裸 TR 编号且无类别名**时才展开（条件化展开，而非全局）
2. 扩展词数量设上限（比如最多 3 个），避免累积稀释
3. 用 B2 全集做 A/B 验证后再决定是否默认开

## 反思

我这个改动是在「补了分档表、但检索不到」的直觉下做的，**没有先做 A/B 就写进了代码**。
实测发现它 3 正 1 负 —— 如果直接默认启用，会重复第 3 组已经踩过的坑。

**教训：任何检索侧改动，先 A/B 再上线，不能凭"这应该有用"就默认打开。**

# 决定：分块改造怎么评估（2026-11-09）

> 阶段1 Agent 报「结构化+父子块 hit@10 −18.9pp，不上线」，问走哪条路。
> 我核实后认为：**它的实测是对的，但这个 A/B 在方法论上测不出它想测的东西。**

## 一、先确认它做对的三件事

1. **自己抓出并作废了一个假数字**：首次跑 hit@10=0.06，发现是 B2 的 gold 绑在
   旧分块器的 `chunk_index` 上 → 金标失配。按 `evidence_quote` 全语料重锚后重跑。
   **这个自查动作比结果本身更有价值。**
2. **发现部分改善是真的**：孤儿表格块 12 → **0**、`4A 低度可疑恶性` 0→2、
   `4C 高度可疑恶性` 0→2、C-TIRADS 计数表 8 个分档行 + 表头落在**同一个 chunk**。
3. **负增益不上线、如实报告**，并按纪律把 `rag_use_parent_expansion` 默认改 False。

## 二、但这个 A/B 有一个方法论硬伤：**测的东西不对**

### 硬伤

B2 的 gold 是**句子级**的：
```
evidence_quote 长度：n=155，min=4，P50=23 字，max=103
中位数 23 字 —— 这是**一句话**，不是一段
```

而它的判据是「命中 = 该句所在的 chunk 出现在 top-k」。

**于是**：
| 库 | 块数 | child 中位 | 你说它"变差" |
|---|---|---|---|
| kb_v1.4.0 | 3511 | 486 tok | hit@10 0.8348 |
| kb_v2.0.0 | 6477 | 346 tok | hit@10 0.6455 |

**候选池近 2 倍 + 单块信息量小 29%** → 在"找到含某句话的块"这个任务上，
命中率**数学上必然下降**。这与"分块策略好不好"**无关**。

**打个比方**：把一本书从 100 页拆成 200 页（字号缩小），
"翻到第几页能找到某句话"的概率当然会降——但读者拿到的信息没变少。

### 真正的空位

**分块改造的价值不在"能不能找到"，在"找到之后答案够不够用"。**

而这恰恰是 retrieval 指标（hit@k / MRR / NDCG）**测不出来的**。

## 三、我的决定：路 2 的变体

Agent 给的三个选项，我选**路 2 但加上先后顺序**：

### 立刻做（无争议，不做 A/B 也能上）
1. **MinerU 解析**（保留换行与结构）—— 这修的是**上游正确性**，
   不是"策略选择"。pypdf 抽出的 `85%～<br>100%` 是**错的**，MinerU 是对的。
2. **表格原子保护**（整表不切）—— 孤儿块 12→0 是**可机检的正确性指标**。
3. **元数据**（source_set / chunk_type / parent_chunk_id）——
   阶段3 的并列能力依赖它，已回填 6477 条。
4. **保持旧分块尺寸与装箱策略**——因为新尺寸的负增益已实测，不符证据。

### 暂不做（需要新的评测口径才能判断）
- 父子块（`parent_chunk_id` 列已建、元数据已写，但**不启用扩展**）
- 更小的 child 尺寸
- 结构化切分的额外收益

### 理由
前三项是**正确性修复**（做错了就是错的），后几项是**策略选择**（需要证据支持）。
**没有证据的策略改动，不做。**

## 四、要真正评估分块改造，需要补什么

| 缺什么 | 为什么需要 | 怎么做 |
|---|---|---|
| **答案完整性指标** | hit@k 测不出"块变小后信息够不够" | 用 gold 引文所在块的**上下文完整度**：该块能否覆盖引文前后 ±N 句 |
| **块级 gold**（而非句级） | 现在 gold 是句子，块变小就吃亏 | B2 扩充时同时标注"回答该问题需要哪一段" |
| **n ≥ 487** | 阶段5 功效分析：n=117 只能判 ≥10pt | 扩 B2（thyroid 优先，它 hit@10 最低） |
| **生成侧指标** | 最终价值在答案质量 | faithfulness/幻觉率（当前 n 太小，不可用） |

## 五、给阶段1 Agent 的执行指令

**按下列顺序收尾，不需要再问我**：

1. **只上 MinerU 解析 + 表格原子保护 + 元数据**，
   **保持旧分块器的尺寸（256/512）与装箱策略不变**
2. 建 `kb_v2.1.0`（不是 v2.0.0 那个实验库）
3. **验证标准换成可机检的正确性指标**（不是 hit@k）：
   - 孤儿表格块 = 0
   - `4A 低度可疑恶性` / `4C 高度可疑恶性` 可检索（>0）
   - `85%~100%`（半角）可检索
   - **KB chunk 平均换行数 > 0**（现在是 0，这是根因）
4. **B2 回归只作为"没有明显退化"的守卫**，
   判据放宽到「hit@10 下降 ≤5pp 可接受」——因为块数变化本身会拉低它。
   若下降 >5pp，报给我再定。
5. 报告里明确写：**hit@10 的变化不能作为分块策略优劣的证据**，附本次方法论分析。

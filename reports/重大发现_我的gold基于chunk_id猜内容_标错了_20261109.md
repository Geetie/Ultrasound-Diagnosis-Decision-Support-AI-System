# 重大发现：我的 gold 是基于 chunk_id "猜" 的，实际内容对不上

> 日期：2026-11-09｜这一轮找到了新条目 hit@1 低的**真正原因**，而且是**我的错误**

## 一、决定性证据

对 3 条新条目，把「我的 gold 内容」与「精排 top-1 内容」并排看：

### zh-ret-121「C-TIRADS 计数法怎么换算分值？」

| | chunk | 实际内容 |
|---|---|---|
| **我的 gold** | `pdf_thyroid_ctirads_2021_0009#0000` | 「三、甲状腺结节的超声分类系统…**(一)C-TIRADS的建立过程**…」❌ |
| **精排 top-1** | `ctirads_2021_counting_method#0000` | 「# C-TIRADS 计数法：**可疑恶性超声特征**（计入分值）：- 实性 - 微钙化…」✅ |

**精排排第一的那块才是正确答案。我的 gold 指的那块讲的是"建立过程"，与问题无关。**

### zh-ret-125「TIRADS 分类能被医生经验修正吗？」

| | chunk | 实际内容 |

**我的 gold 那块讲的是"点状强回声分类"，与"能否人工修饰"完全无关。**

## 二、根因：我用 chunk_id 的编号"猜"内容，没有实际打开看

我写条目时的流程是：
1. 用 `p116` 工具拿到候选 `chunk_id` + `quote`
2. 把 quote 填进 gold
3. **但没有核对"这个 quote 是否真的在它标的那个 chunk 里"**

**验证结果**：这正是我一开始做 `p117` 时发现的「KB 里 0 命中」——
那些 0 命中不是"换行差异"，是 **quote 与 chunk_id 根本不匹配**。

## 三、为什么 p117 修了 30 条之后 hit@1 仍不变

因为我的修复方式是**"把引文改成能在 KB 里找到的形式"**，而不是**"把 chunk_id 改到引文真正所在的位置"**。

```
我的修法：让引文迁就 chunk_id（改成该 chunk 里存在的片段）
正确修法：让 chunk_id 迁就引文（找到引文真正所在的 chunk）
```

**方向反了。** 所以 p117 的问题率降了（引文能找到了），但 hit@1 一点没变
（因为 chunk_id 仍是错的）。

## 四、这也解释了所有之前的困惑

| 之前的困惑 | 真正原因 |
|---|---|
| 新条目 hit@1 只有 0.2128 | **gold chunk_id 标错** |
| 精排 depth 加大 hit@1 不变（0.4255 锁定） | gold 不在任何 depth 的 top-1，因为它内容不对 |
| p117 修 30 条后 hit@1 不变 | 修的是引文不是 chunk_id，方向反了 |
| 97.9% 的 gold 在 top-50 内 | 部分条目 quote 碰巧在标注的 chunk 里，部分不是 |

## 五、正确修法

对每条新条目：
1. 拿 `evidence_quote`（真实原文片段）
2. **全文搜 KB，找到它真正所在的 chunk**
3. **用那个 chunk 的 (doc_id, chunk_index) 替换 gold**
4. 验证：替换后 `quote in chunk.content` 必须为 True

**这不是"改引文去适应 chunk"，是"改 chunk 去寻找引文"。**

## 六、我的错误模式（第 N 次）

**我在写数据时假设了"工具给的 chunk_id 一定含这个 quote"，没有做最基础的一致性校验。**

这与本项目反复出现的错误同源：
- 看到 `TR2` 0 条就说"分块切碎"（没查语料里有没有这个词）
- 看到 32.72% 就说"不完整"（没查分母）
- 看到引文 0 命中就说"换行差异"（没查 chunk_id 是否对）

**共同点：跳过了"最基础的一致性检查"就往下推断。**

## 七、立刻修

写脚本：对每条新条目，用 quote 全文搜 KB，把 gold 改成**真正包含该 quote 的 chunk**。
然后重测——这次 hit@1 应该会有实质变化。

## 八、修正后的效果（本轮实测）

### 8.1 修法

对 47 条新条目，用 `evidence_quote` 全文搜 KB，把 gold 的 `(doc_id, chunk_index)`
改成**真正包含该引文的 chunk**。

```

新条目 gold 数 均值 2.06
```

### 8.2 指标变化

| 指标 | 修正前 | **修正后** | 变化 |
|---|---|---|---|
| 整体 hit@1 | 0.4573 | **0.4756** | +1.8pt |

### 8.3 关键：修正后精排开始生效了

| 阶段 | 新条目 hit@1 | hit@5 | hit@10 |
|---|---|---|---|
| dense top-10（原始） | 0.2128 | 0.4894 | 0.6596 |

**精排让新条目 hit@1 从 0.2766 → 0.4043（+12.8pt），hit@5 → 0.8723。**

**这证明：之前"精排对 top-1 完全无效（+0.0pt）"不是精排的问题，
是 gold 指向错误位置导致的**——精排把真正正确的块排到第一，
但那个块不在（错误的）gold 里，所以判为未命中。

## 九、完整因果链（三轮才查清）

```
第 1 轮：发现指标下降 → 以为是"系统变差"，做了 gold 补多块（+3.0pt，部分有效）

        → 修正 chunk_id → hit@1 +6.4pt
        → 再测精排 → **+12.8pt（精排一直是好的，是我标错了位置）**
```

# B2-real 建设方案（含英文翻译路线）

> 日期：2026-11-09｜用户指出「为什么不能翻译成中文来测？这算什么阻碍？」——我之前的判断不完整

## 一、先承认：我把它当阻碍是错的

176 条英文 liver/cardiac 是**真实提交过的临床文本**，翻译成中文后：
- 病种真实（门静脉血栓、肝包膜下血肿、心包填塞…全是真会遇到的）
- 结构真实（超声报告式的描述顺序）
- 长度真实（66-194 字，与生产一致）

**所以翻译路线成立，我之前的"数据不够"说法是错的。**

## 二、但翻译后暴露一个更深的问题：陈述 vs 提问

我把 6 条真实英文报告译成中文后实测检索：

| 译文 | top-1 |
|---|---|
| 肝内未见局灶性病变；但符合门静脉及脾静脉血栓形成。 | 肝纤维化超声所见…（相关度中） |
| 肝实质超声表现正常。 | 肝实质回声增粗、增强…（不相关） |
| 心脏超声示右心室舒张期塌陷，提示心包填塞。 | 心脏结构和血流的声像图描述…（不相关） |

**原因不在翻译，在这些文本是「陈述」而不是「提问」。**

数据统计（661 条真实文本）：
```
英文 293 条：含提问标记 0 条     ← 全部是陈述
中文 258 条：含提问标记 135 条   ← 一半是提问
```

**英文那批全是报告体陈述**（`No focal liver lesions are identified…`）。

## 三、陈述式与提问式是两种任务，不是同一件事

| | 陈述式输入 | 提问式输入 |
|---|---|---|
| 例子 | 「肝实质未见异常」 | 「4A 类 12mm 要不要穿刺」 |
| 医生意图 | 让系统**生成报告/判读** | 让系统**回答问题** |
| RAG 的作用 | 找指南条款**支撑本次判读** | 找到**含答案**的条款 |
| 该测什么 | 生成的报告是否引用了正确条款 | **hit@k**（当前 B2 测的） |

**所以「把英文陈述译成中文」得到的是「中文陈述」，
它测的仍是「陈述式输入」，不是「提问式输入」。**

## 四、修正后的 A+C 方案（三部分，各测各的）

### A 部分：中文真实提问（135 条）

从 DB 里筛出**含提问标记**的中文真实文本（135 条，几乎全是 thyroid）：
- 直接用作文 query
- gold 由「检索 top-k + 人工审核」产生（不编造）

### B 部分（新增）：翻译英文陈述（293 条 → 176 条 liver/cardiac + 117 thyroid）

**用途不是测 hit@k**，而是：
1. **测意图抽取**：陈述式长文本 → 抽取到检索意图 → 能否找到支撑条款
2. **测端到端生成**：给定陈述，系统生成的判读报告是否引用了正确指南条款

**这是生产真实场景**（医生就是粘一段报告让系统判读）。

### C 部分：把陈述改写成提问（用真实病种）

从 176 条英文 liver/cardiac 陈述里**提取真实的病种与场景**，改写成医生会问的问题：

```
素材：'Ultrasound reveals a fluid collection in the subcapsular region of the liver,
      consistent with a hematoma.'   (真实提交过的病例)
↓ 改写成提问
query: 「肝包膜下积血（血肿）在超声上怎么与腹水鉴别？要不要紧？」
gold:  KB 里「肝包膜下积液/血肿」相关条款（逐字核对）
notes: 「源自 2026-09-29 真实提交的病例（肝包膜下血肿），
        转写为医生查房时会问的鉴别诊断问题」
```

**每条 notes 必须写明素材来源**，不冒充真实提问。

## 六、分布问题：不对齐 97.7%，理由

生产分布 97.7% thyroid 是**历史结果**（只有 thyroid 做过中文测试），不是**未来需求**。

如果按 97.7% 对齐，liver/cardiac 各只有 3 条 → 任何改动都判不动。

**所以分器官报指标，不报"总 hit@1"。**

## 二、4.2 幻觉率

### 2.1 口径（写死，先定义再跑）

**幻觉定义**：结论里出现了**知识库中不存在的具体事实**，且属于四类"硬事实"之一：

1. **百分数/风险区间**（`10-50%`、`约 5%`）；
2. **分级-分值映射**（`4 分 → TR4`、`0-2 分为 TR2`）；
3. **阈值类判定**（`≥1cm 建议 FNA`、`>10mm`）；
4. **药物/剂量**（`mg`/`ml`/`μg`）。

**明确排除（不算幻觉）**：影像所见里的测量值（`大小约 8x6mm`，来自输入）、
系统派生字段（`总分`/`置信度`）、纯定性描述与建议。

**检测方法**：正则抽硬事实 → 归一化子串检索 → 三条来源腿：

* ① 该记录**当时送进 prompt 的检索块**（`knowledge_ids` 快照，可解析 279/284）；
* ② 该器官 **`kb_v1.4.0` 全库**（601/346 chunks，`ILIKE` 实查）；
* ③ **生产 prompt 模板**（`app/agents/prompts/{thyroid,cardiac,liver}.md`）。

**分级-分值映射单独处理**：`N 分 → TRk` 不是知识断言，它是**对 prompt 里那张评分表的
规则应用**。所以对这类只判一件事：**模型给的分级是否违反 prompt 的分档表**。

| 分级 | prompt 里的区间（`thyroid.md:45-49`） |
|---|---|
| TR2 | **2 分** |
| TR3 | **3 分** |
| TR4 | **4–6 分** |
| TR5 | **≥ 7 分** |

**编造规则的 3 条实证**（`req_20261103_a05f4ed5` / `req_20261103_d743a70e` / `req_20261107_2e39fb76`）：

### 2.3 报哪个数（这是关键）

* **不能报 23.08% 当"幻觉率"** —— 12/15 是"算分算错"，把它算成幻觉会**高估 5 倍**；

**另有一条重要旁证**：15 条候选**全部来自 2026-10-25 ~ 11-07 的新判读**（II-Medical-8B 期，逐条日期见下），
旧模型期（9 月）0 条。→ 这不是历史遗留问题，**现网模型仍在犯**：
`10-25` 6 条（全是算分错）、`11-03` 6 条、`11-07` 1 条；3 条"编造规则"分别在 `11-03` 两条、`11-07` 一条。

## 三、4.3 faithfulness

### 3.1 口径（= `p44` 的 A 口径，写死）

1. **只算知识断言**：把结论拆成原子断言，分三桶
   `knowledge / image / advice`；**影像所见与建议不进分母**——
   这是 A.69 的实测结论（结论 = 影像所见 + 知识建议，影像所见永远不在知识库里）。
2. **再剥一层"输入复述"**：断言里**每个**数字都能在 `clinical_text` 里找到 → 判为
   `image`（本次新增的 `rebucket_by_input`，共改判 **5 条**）。
   不加这一层，`LVEF 60%`、`大小约 8x6mm` 这类**来自输入**的断言会被算进知识断言分母。
3. 断言生成 / NLI 用 **RAGAS 官方 prompt**（`scripts/prompts/ragas_faithfulness.py`），
   判官 = **Qwen3-8B @8006**，`/no_think`，**要求中文断言**（否则跨语言错配把分数压死）。
4. `answer_mode=derived_stripped`（剥掉 `分级/总分/置信度` 这类系统派生字段）。
5. `faithfulness = 有支持的知识断言 / 知识断言总数`；某条样本知识断言为 0 → 记 `None`
   （**不写 1.0**）。

## 四、4.4 分级一致率

### 4.4.1 口径

* **同输入跑 2 次**；**N 次分级全相同且都能解析 = 一致**；
  `consistency = 一致输入数 / 总输入数`。
* 走**生产同一条生成路径**：直接实例化 `ThyroidSpecialistAgent` / `CardiacSpecialistAgent`，
  只把 `knowledge_agent` 换成"返回固定块"的替身 →
  prompt 拼装、思考剥除、分级解析、**结构化重试**全部复用生产代码。
  唯一被我控制的是"检索结果固定"（这就是"同一输入"的定义）。
* **为什么离线跑**：`/api/v1/diagnosis/request` 限流 10/min，且每次会新建 DB 记录
  —— 评测不应往生产写数据；那条路径还含融合层/安全网关，一致率就不再是"生成侧稳定性"。
* 超时**显式放宽到 180s / 重试 1 次**（生产是 30s / 3 次），并在报告 `caliber` 里写明。

## 七、顺带挖出的 4 个生产缺陷（不在本组计划内，但必须报）

1. **生产 30s 超时 + II-Medical-8B（p50 46s）⇒ 判读必然超时熔断**。
   **可复算的硬数字**：p107 的 104 次生成调用里，**93 次（89.42%）耗时 > 30s**
   （生产 `INFERENCE_TIMEOUT_SECONDS=30`）；**52 个输入里 49 个至少有一次采样 > 30s**；
   p50 **46.0s** / p90 **94.1s** / max **101.4s**（`p107` 报告 `latencies_s` 字段，
   脚本 `_g4_timeout_math.py` 三行可复算）。
   首轮用生产超时（30s/3 次）实测直接触发 `E2002_TIMEOUT` → `circuit_breaker_open`
   → 后续请求 `circuit_breaker_open_reject`（整批跑不下去）。
   本次为拿到数，显式放宽到 180s/1 次（已写进报告口径，属**偏离生产**的处置）。
2. **II-Medical-8B 默认进思考模式，且 `enable_thinking=false` 与 `/no_think` 都压不住**：
   实测 `max_tokens=700` 时 **finish_reason=length**，整段 token 全花在 `<think>` 里，
   引擎侧剥除后**正文为空**（→ 生产侧表现为 `grade_unparseable`/空结论）。
   **只有 `/no_think` 生效时**（同一 prompt 加该后缀）才能拿到 55 token 的正文。
   生产 prompt 目前**不带 `/no_think`**（`grep no_think app/` = 0）。
3. **模型会输出"只有分级码、无正文"的退化结论**（`甲状腺 · TR1`），占 40 条输入的 **32.50%**，
   而生产守卫**不拦**（它既不空也不回显）。
4. **模型会自造分档规则并写进结论**（`（注：0-2 分为 TR2）`），KB 与 prompt 均无此规则 ——
   这是 4.2 里唯一"真幻觉"，且**现网（10/25–11/07）仍在发生**。

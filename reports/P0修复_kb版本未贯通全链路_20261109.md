# P0 修复：kb_version 从未贯通到检索全链路

> 日期：2026-11-09｜来源：端到端暴露「模型引用 kb_v1.2.0」

## 一、症状

已把 `RAG_KB_VERSION` 切到 `kb_v2.1.0`，但真实端到端检索返回的 chunk_id 是：
```
kb_v1.3.0:pdf_thyroid_thyroid_cancer_guideline_2022_0003#0000
kb_v1.4.0:pdf_thyroid_thyroid_cancer_guideline_2022_0003#0000
kb_v1.5.0:pdf_thyroid_thyroid_cancer_guideline_2022_0003#0000
kb_v1.2.0:pdf_thyroid_thyroid_cancer_norm_2018_0007#0000
```
**一条 kb_v2.1.0 都没有。** 模型因此引用 `kb_v1.2.0:...`。

## 二、四个断点（逐层查出来的）

| # | 断点 | 证据 | 修法 |
|---|---|---|---|
| 1 | `knowledge.py::_query_uncached` 构造 `RetrievalRequest` 时**没传 kb_version** | 该函数上方已算出 `kb_version` 用于缓存键，但请求体里没有 | 加 `kb_version=self._current_kb_version()` |
| 2 | `main.py` 预热 BM25 时**不传版本** | 日志 `bm25_index_built kb_version=None num_chunks=9990`（全表 9 个版本） | 传 `settings.rag_kb_version` → 变成 `num_chunks=3745` 单版本 |
| 3 | **Qdrant 里没有 v2.1.0 的点** | `points/scroll` 抽样 2000 → 只有 v1.5.0(1475) 和 v1.4.0(525) | `qdrant_reindex_kb.py --kb-version kb_v2.1.0` 重灌 + 删旧点 |
| 4 | **Redis 缓存留着旧结果** | `kb:cache:*` 8 个 + `rag:cache:*` 23 个 | 清掉 |

## 三、关键教训

**「改了配置」不等于「配置生效」——要逐层验证到最底层。**

我改 `settings.rag_kb_version` 后看到 `/api/v1/health` 200 就以为成了，
但实际有 4 层各自独立地忽略了它：

```
settings.rag_kb_version  ✅ 改了
    ↓ 断点1：RetrievalRequest 没接
    ↓ 断点2：BM25 预热没接
    ↓ 断点3：Qdrant 索引里根本没这个版本
    ↓ 断点4：缓存还存着旧结果
真正生效  ❌
```

**这和三天前那次「`INFERENCE_TIMEOUT_SECONDS` 代码改 180 但 `.env` 是 30」
是同一类错误**：改了一处，以为全局生效。

## 四、最终验证

```
knowledge_ids: 全部 kb_v2.1.0 ✅
  kb_v2.1.0:pdf_thyroid_thyroid_cancer_guideline_2022_0003#0000
  kb_v2.1.0:pdf_thyroid_thyroid_cancer_norm_2018_0007#0000
  kb_v2.1.0:norm2018_s01#0004

BM25:  bm25_index_built kb_version=kb_v2.1.0 num_chunks=3745
Qdrant: 抽样 3748 → 全部 kb_v2.1.0
```

## 五、测试影响

改动前后 `tests/unit/agt + tests/unit/rag`：
```
改动前基线: 10 failed / 1505 passed
改动后:     10 failed / 1505 passed    ← 零回归
```

（中途曾因在 `specialist/base.py` 多加 `kwargs["kb_version"]` 导致 165 个 TypeError ——
`KnowledgeAgent.query()` 签名不含该参数，它内部自己取版本。已撤销并注释说明。）

## 2. CACTUS —— 心脏切面分类（CC BY 4.0，可商用）

### 2.1 三个数字，含义完全不同

| # | 脚本 | 协议 | 准确率 | 95%CI | 能不能对外 |
|---|---|---|---|---|---|
| ① | `p86` | 部署中的 8003 vs **官方 test.csv** | **0.9786** | 0.9742–0.9826 | ❌ **受污染上界** |
| ② | `p87` | **视频不交集**从头重训（同配方） | **0.2099** | 0.1982–0.2221 | ⚠️ 说明部署模型在未见视频上不可用 |
| ③ | `p89` | **不训练**：冻结 BiomedCLIP + LR | **0.8628** | 0.8530–0.8721 | ✅ **可辩护的泛化数字** |

参照：多数类基线（永远猜 A4C）= **0.2099** —— 与 ② 完全相同。

### 2.2 为什么官方数字不能用（泄漏实证）

29,963 张图来自约 **117 段视频**（其中 116 段的文件名可解析出视频键；另有 175 张命名不含
`frame_` 无法解析），而 `t2b_cactus_prep.py` 是**按图像**随机切分的
（文件名形如 `1_D14_frame_765_v2.jpg`）。审计（`p87 --audit-only`）：

- 官方 test 4494 张里，**4319 张（96.1%）** 所属视频在 train 中出现过；
- **4215 张（93.8%）** 与 train 中同视频某帧**帧号相差 ≤5 帧**（30fps 相邻帧肉眼无差别）；
- `videos_in_test_not_in_train = 0`（可解析的 4319 张里，一段没进过训练的视频都没有）。

部署的 visual tower 恰在 train 上微调过 → 等于拿"见过的视频里相邻的帧"当 held-out。

### 2.3 三条数字合起来说明什么

`p89` 的三条基线用的是**与 ② 完全相同的视频不交集划分**，只是不训练：

| 基线 | 准确率 | 宏 F1 |
|---|---|---|
| 冻结特征 + LR（③） | 0.8628 | 0.8623 |
| zero-shot 文本对齐 | 0.6881 | 0.6752 |
| 多数类 | 0.2099 | — |

→ **任务本身是可分的（86.3%），不是任务难**。
→ **是 T2b 的微调配方把 BiomedCLIP 特征训坏了**（86.3% → 21.0%）。
   配方 = 3 epoch / lr 3e-6 / batch 256 / open_clip ClipLoss，训练集只有 80 段视频。
→ **结论：部署在 8003 上的 T2b 切面头在未见视频上不可用，必须重训。**
   （注：`t2b_cactus_train.py` 的 `eval_split` 是**样本内**打分——探针在同一份特征上
   fit 再算 accuracy，这也需一并修。）

### 2.4 其余已知局限

- 发布版缺 **PSAV** 一类（README 虚标 6 类，实收 5 类：A4C/PL/PSMV/Random/SC）；
- `Random`（非标准切面）是模型自己的一类，不是拒识类别；
- 只有约 117 段视频，视频级切分下 test 仅 17 段 / 4511 张，**方差大**；
- `p87`/`p89` 的划分丢弃了 175 张命名无法解析视频键的图（占比 0.6%），报告 `split` 块已记；
- 质量分级 MAE 0.8779（仅标准切面，n=3550）来自受污染的 test 集，同样不可对外。

## 3. CAMUS —— 心脏分割 + LVEF（CC BY-NC-SA 4.0，**非商用，只能评测**）

**脚本** `scripts/audit/p88_camus_seg_formal.py`
**报告** `reports/p88_camus_seg_formal.json`

### 3.1 分割：跑通，且复现历史

按患者 80/20（400/100 患者，2400/600 帧），复跑训练脚本的同一 test 集：

| 指标 | 值 | 95%CI |
|---|---|---|
| LV 腔 Dice | **0.8395** ± 0.0624 | 0.8341 – 0.8444 |
| LV 腔 IoU | 0.7280 | 0.7206 – 0.7350 |

**与历史对比**：`reports/camus_seg_baseline.json` 记录 LV DSC 0.8395 / IoU 0.7280 →
**本次逐位一致（Δ=0）**。最差病例 patient0056 DSC 0.6739。

**口径澄清（推翻仓库里一处错注释）**：`scripts/seg_gt_iou.py` 的注释称
「`unet_camus.pt` 分割目标其实是心肌 MYO」。实测**否定**该说法：
同一权重 LV（label=2）DSC **0.8395**、MYO（label=1）DSC **0.0696**。
权重目标确为 LV 腔，与 `app/inference/organ_segmentation.py` 注册表一致。

### 3.2 LVEF：**做不了准确性评测**（如实说明）

CAMUS 官方 EF 真值在 `patient_info_*.xlsx`，**本机没有这份文件**
（全盘 `find` 确认：无 `patient_info*` / `*lvef*` / `*.cfg`；两个 zip 里也没有）。
**没有真值就算不出 MAE / RMSE / 相关系数 —— 不编。**

能做的、有意义的是**误差传播**：同一面积-长度法（`V=(8/3π)·A²/L`）分别作用于
GT 掩膜与预测掩膜，500 患者成对比较：

| 指标 | 值 |
|---|---|
| EF MAE | 0.117（95%CI 0.1090–0.1251） |
| EF RMSE | 0.1477 |
| 平均偏差 | −0.0149 |
| Pearson r | 0.5539 |

> 这不是临床 EF 验证，是"分割误差传到 EF 有多大"的测量。EF 均值
> GT 0.366 / 预测 0.351 —— 绝对数值也不保证与 CAMUS 官方口径一致。

### 3.3 其余已知局限

- 非商用（CC BY-NC-SA 4.0），**只能评测，不能进商用链路**；
- 1000 half_sequence 是子集（官方 500 患者 × 2CH/4CH）；
- 评测分辨率 256×256（与训练协议一致，低于临床 512）。

## 4. 复现命令（服务器 `~/uai/src`，需 8003 就绪）

```bash
cd ~/uai/src
export PYTHONPATH=$HOME/uai/src:$HOME/uai/src/scripts CUDA_VISIBLE_DEVICES=0
P=$HOME/uai/venv/bin/python

# AUL（~8 秒）
$P scripts/audit/p85_aul_holdout_formal.py \
   --report reports/p85_aul_holdout_formal.json \
   --manifest tests/reports/t2a_aul_manifest.json \
   --baseline-json ~/uai/reports/t2a_aul_holdout.json

# CACTUS ①受污染 ②视频隔离 ③基线（②③各 ~7-12 分钟）
$P scripts/audit/p86_cactus_view_formal.py --report reports/p86_cactus_view_formal.json
$P scripts/audit/p87_cactus_video_disjoint.py --report reports/p87_cactus_video_disjoint.json
$P scripts/audit/p87_cactus_video_disjoint.py --audit-only      # 只跑泄漏审计（秒级）
$P scripts/audit/p89_cactus_baselines.py --report reports/p89_cactus_baselines.json

# CAMUS（~10 分钟）
$P scripts/audit/p88_camus_seg_formal.py --report reports/p88_camus_seg_formal.json \
   --baseline-json ~/uai/reports/camus_seg_baseline.json
```

8003 启动（**必须带 `--clip-format open_clip`**，否则 transformers 会把本地目录当 HF repo id 报错）：

```bash
export CUDA_VISIBLE_DEVICES=0 T2B_FT_WEIGHTS=$HOME/uai/src/reports/t2b_cactus.pt \
       T2B_PROBES_DIR=$HOME/uai/models/t2b
$HOME/uai/venv/bin/python -u scripts/start_embedding_services.py \
  --service ultrasound-clip --clip-format open_clip --max-length 256 \
  --model-dir $HOME/uai/models/biomedclip-base-patch16-224 --port 8003 --device cuda
```

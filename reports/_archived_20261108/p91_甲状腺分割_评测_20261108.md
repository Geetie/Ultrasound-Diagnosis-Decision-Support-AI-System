# TN3K 甲状腺结节分割独立评测（p91，2026-11-08）

## 一句话

**甲状腺分割是主线科室唯一一个"数字好看且干净"的能力：DSC 0.7960 [0.7782, 0.8120]。**

## 一、为什么需要这个评测

`scripts/tn3k_seg_unet.py` 里已有完整评测逻辑（`evaluate()`，含 A.88 的乐观/保守双口径），
但它**只在校验训练时顺手跑一次**，从没产出过独立报告（`reports/tn3k_seg_unet.json` 不存在）。

TN3K 是甲状腺唯一的分割公开集。没有独立报告 = **主线科室的分割能力没有可辩护数字**。

## 二、做法（不重复造轮子）

新建 `scripts/audit/p91_tn3k_seg_eval.py`，**复用** `tn3k_seg_unet.py` 的
`list_pairs / load_pair / build_unet / evaluate / _summarize`，只补三样：

1. **不训练**，直接加载已训权重（`~/uai/models/nodule_seg/unet_tn3k.pt`，17.4 MB）
2. **bootstrap 置信区间**（2000 次、固定种子 20261108）
3. **per-image 分位数**（P10/P50/P90），避免只看均值被极端值掩盖

**没有给生产加 HTTP 分割端点**——分割权重本来就只在 app 进程内用，
为了评测去改生产架构是舍本逐末。

## 三、结果（官方 614 test 全量，无抽样）

| 指标 | 值 |
|---|---|
| **DSC（Dice）** | **0.7960** [0.7782, 0.8120] |
| **IoU** | **0.7002** |
| DSC 分位 | P10 0.5178 / **P50 0.8791** / P90 0.9539 |
| IoU 分位 | P10 0.3494 / P50 0.7843 / P90 0.9119 |
| 评测耗时 | 7.3 s（CPU） |

## 四、这个数字为什么可信

### 4.1 空掩膜构成全部为 0
```
empty_both = 0    empty_pred = 0    empty_gt = 0    normal = 614
```

A.88 曾指出：`evaluate()` 早期把"预测与金标准都为空"记 1.0，会**抬高均值**。
本次 614 例中**一次都没发生**，因此：
```
dice_mean = 0.7960
dice_mean_strict = 0.7960    ← 完全一致
```
**乐观口径与保守口径相同 → 这个数字不靠"空对空"撑着。**

### 4.2 中位数远高于均值
P50 = 0.8791 而均值 0.7960，说明**少数难例拉低了均值**（P10 仅 0.5178）。
这是分割任务的正常形态，不是异常。

## 五、与甲状腺其他能力的对照（同一器官，三种能力）

| 能力 | 指标 | 值 | 判读 |
|---|---|---|---|
| **分割**（TN3K） | DSC | **0.7960** | ✅ 可用 |
| **分类**（TN5000 病理） | AUC | **0.6303** | ❌ 接近随机 |
| **分级**（DDTI） | — | ⛔ blocked | 无分级输出 |

**同一个器官，分割能做、分类做不好**——因为分割模型是在**甲状腺数据**（TN3K trainval 2879）
上训的，而分类模型的视觉塔是在**肝脏数据**（AUL）上微调的。
这进一步支持前述「跨器官迁移失败」的推测。

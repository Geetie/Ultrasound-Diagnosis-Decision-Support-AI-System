# 更正：句末完整率真实值 75.90%（不是 32.72%）+ 换行 bug 已修

> 日期：2026-11-09｜我亲自下场做阶段1 最关键的修复

## 一、换行 bug：找到具体代码行并修好

### 根因（两处叠加）

`app/knowledge/chunker.py::SentenceBoundaryChunker`（**生产默认策略**）：

1. `_split_sentences` 用 `p.strip()` 把每个片段的**换行首尾都剥掉**
2. `_flush_buffer` 用 `" ".join(buffer)` 用**空格**连接句子

### 实测证据

```
源 json:  '|||||男性|||||\n|---|---|---|\n|参数|总数<br>n=678|...'   换行 21
修复前:   '|||||男性||||| |---|---|---| |参数|总数<br>n=678|...'  换行 0    ← 拍平
修复后:   '|||||男性|||||\n|---|---|---|\n|参数|总数<br>n=678|...'  换行 19   ✅
```

### 修法

- `_split_sentences`：只压缩**行内**连续空格，**保留 `\n`**
- `_flush_buffer`：用 `"\n".join(buffer)` 而不是 `" ".join(buffer)`

### 验证

| 指标 | 修复前 | 修复后 |
|---|---|---|
| sentence_boundary 换行数 | **0** | **19**（源 21，差 2 是首尾空行） |
| 全库平均每块换行 | **0** | **32.95** |
| `tests/unit/knowledge + data` | — | **393 passed** |

**含实质内容的 `|` 行从源侧 684 → chunk 侧 771**（之前是 0 行可区分）。

## 二、更正：句末完整率的真实值是 75.90%

阶段5 报的 **32.72%** 把我误导了。按中文正文过滤后重算：

| 长度层 | n | 句末完整率 |
|---|---|---|
| <300 字 | 683 | **96.19%** |
| 300-600 字 | 197 | **82.23%** |
| 600-1000 字 | 154 | 37.66% |
| >1000 字 | 240 | 37.50% |
| **中文正文整体** | **1274** | **75.90%** |

### 为什么原口径偏低

那 32.72% 的分母是**全部 3745 个 chunk**，其中包含：
- 英文参考文献（`City, Utah; Ikoyi, Lagos, Nigeria; Hartford, Connecticut`）
- 目录页（`··············· 9`）
- DOI/URL 行（`https://doi.org/10.1016/j.echo.2018.06.004`）

**这些文本本来就不会以句号结尾。**

### 真正的短板在「长块」

```
<300 字:  96.19%   ← 短块几乎都完整
>1000 字: 37.50%   ← 长块不完整
```

**说明问题不在"换行"，在"max_chars 截断"** —— 长块在 `max_chars` 边界被硬切，
而不是在句子边界切。这是另一个独立问题。

## 三、这修正了阶段1 Agent 的一个判断

它说「句末完整率 0.3272」并归因到"旧分块器几乎只在段落边界切"。
**真实原因有两层**：
1. 换行被吃（我已修）→ 影响表格与行结构
2. **长块在 max_chars 硬切** → 影响句末完整性（未修）

**第 2 条才是句末完整率的主因**，与换行无关。这也解释了为什么修完换行，
句末完整率（按原口径）仍是 32% —— 因为长块的硬切没变。

## 四、下一步（长块硬切该怎么修）

`SentenceBoundaryChunker` 的逻辑是：
```
for sentence in sentences:
    if len(sentence) > max_chars:
        # 超长句 → 走 FixedWindowChunker 硬切
```

**问题**：`max_chars` 是**字符数**，而医学文档里"一个句子"可能包含大量
表格行/列表项，导致单句超过 max_chars → 硬切 → 句末不完整。

修法候选：
- (a) 长块切分时**优先在换行处切**（表格/列表天然有行边界）
- (b) 用 token 数而不是字符数判超长
- (c) 长块允许略微超出 max_chars，但必须在句末或换行处收尾

**我倾向 (a)+(c)**：换行是比句号更强的结构边界，且表格必须整行保留。

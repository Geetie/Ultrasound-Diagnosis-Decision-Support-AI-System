## 二、我挖到一个比 Agent 报告更精确的结论

Agent 说「kb_v1.4.0 甲状腺 601 块里**没有任何分档表**」。我核实后发现**需要更精确的表述**：

### 实测（v1.4.0 与 v1.5.0 都是 0）

```
TR2 / TR3 / TR4 / TR5 : 各 0 条
"2分" / "2 分" / "积2分" : 各 0 条
"分档"                  : 0 条
```

### 但知识库**有**类别风险表

```
[pdf_thyroid_thyroid_cancer_guideline_202]
|4a||具有1种恶性征象|5%～<br>10%|
|4b||具有2种恶性征象|10～<br>50%|
|4c||具有3～4种恶性征象|50%～<br>85%|
|5|恶性|超过4种恶性征象…|85%～<br>100%|
|6|恶性|经病理证实的恶性病变|无|
```

`TIRADS` 25 条 / `TI-RADS` 10 条 / `C-TIRADS` 12 条 / `5类` 4 条。

### 所以真实缺口是**两层**，不是一层

| 层 | 有没有 | 说明 |
|---|---|---|
| **① 类别 → 恶性风险** | ✅ **有** | `4a/4b/4c/5/6` 各自的风险区间与征象数 |
| **② 征象计分 → 类别**（计数法分档表） | ❌ **没有** | `积 2 分 = TR3` 这类映射**只活在 prompt 里** |
| **③ 命名不一致** | ⚠️ | 知识库写 `4a/4b`，prompt 写 `TR2~TR5` —— **检索时词不匹配** |

**这解释了模型为什么自造分档规则**：它要输出 `TR3`，但知识库里只有 `4a/4b` 的写法、且没有计分映射 → 检索不到 → 只能从 prompt 里抄或编。

## 三、由此产生的三个可执行的修法

### 修法 1：把计数法分档表补进知识库（根因修复）
C-TIRADS 2021 原文有完整的计数法表（`有结节 0/±1`、`实性 +1`、`微钙化 +1` 等，累计分数对应类别）。
**这是知识库该有但缺失的**，补上后模型可以检索到，不必编。

### 修法 2：统一分级命名（消掉词不匹配）
知识库 `4a/4b/4c` ↔ prompt `TR3/TR4/TR5` 是两套写法。
应在检索时做同义词扩展，或统一入库时同时写两种形式。

### 修法 3：`output_guard` 加一条「分档规则溯源」检查
模型输出 `（注：0-2 分为 TR2）` 这类自造规则时，若 KB 与该 chunk 都无出处 → 拒收。
**这条比修 faithfulness 指标更直接地止血。**

## 四、关于 Agent 提的两个待拍板问题

### 问题 1：先修 4 个生产缺陷再重测 4.4？

**我的判断：是，而且优先级排序是：**

| 序 | 缺陷 | 为什么优先 |
|---|---|---|
| **1** | **30s 超时 vs p50 46s** | 这是**系统性熔断**：93/104 次调用（89.42%）超时。<br>不修这个，任何生产指标都是在测"熔断率"不是"模型能力" |
| **2** | **思考模式压不住**（`enable_thinking=false` 与 `/no_think` 实测均无效） | 导致 `finish_reason=length`、正文为空 —— 这与缺陷 3 是同一根因 |
| 3 | "只有分级码无正文"占 32.50% | 是缺陷 2 的表现，不是独立缺陷 |
| 4 | 模型自造分档规则 | 用修法 1+3 处理 |

**必须排第一的是超时** —— 因为它污染所有下游指标。

### 问题 2：faithfulness 是否改主指标为「引用覆盖率」？

**我的判断：是。** 理由（Agent 的三层分解给了决定性证据）：

```
201 条知识断言：
  derived 101 条  → 0 支持（系统自己推导的，语义上不是"忠实度"）
  selfref  34 条  → 指代自身
  pure     66 条  → 9 支持（0.1364）
```

**分母里一半是系统派生推导**，这量的是"推导是否忠实于原文"，而不是"模型是否忠实于知识库"。

**引用覆盖率**（句级带来源标记的比例）语义更干净：
- 分子分母都清楚
- 不依赖"派生推导算不算知识断言"这种争议判定
- 与工程可操作性直接对应（没有引用就是没有依据）
